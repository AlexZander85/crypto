# ПРОЕКТ: «КриптоНавигатор» из одного HTML-файла → глобальный SaaS на бесплатном стеке Cloudflare

Версия документа: 1.0 · Дата: 24.08.2026
Базис: текущий продукт `index.html` V6 (134 урока, 145 виджетов, 21 мини-игра, блок Психологии, прогресс в `localStorage`, ключи `cn_*`).

---

## 1. Цель и конечный результат

Онлайн-сервис обучения: пользователь регистрируется, бесплатно проходит демо-часть (Фаза 0 + Психология), оплачивает разово полный доступ — и получает **навсегда** весь курс + все будущие обновления + облачный синхронизируемый прогресс на любом устройстве. Языки интерфейса и контента: русский (источник) → английский → испанский → португальский (далее по спросу).

Продукт остаётся «офлайн-friendly»: контент кэшируется в браузере (PWA), сеть нужна только для логина/синка/оплаты.

## 2. Итоговая архитектура

```
Пользователь
   │  https://cryptonavigator.app  (домен ~10 $/год)
   ▼
Cloudflare Pages ── статика: index.html (движок), /app/*, /locales/*.json, PWA/service-worker
   │                    бесплатные лимиты: запросы не лимитируются жёстко, трафик ок
   ▼
Cloudflare Workers ── API: /api/auth/*, /api/progress, /api/content/manifest,
   │                   /api/content/pack/<locale>/<name>, /api/pay/webhook/*
   ▼                     free: 100 000 запросов/день (хватит на тысячи пользователей)
Cloudflare D1 (SQLite) ── таблицы ниже; free: 5 ГБ, 5 млн чтений/день
Cloudflare KV ── кэш манифестов контента (опционально)
```

Почему это выгодно именно тебе: **ничего не засыпает** (в отличие от Supabase/Firebase free), один провайдер закрывает хостинг+API+БД, домен и TLS включены, деплой — `git push`.

## 3. Ключевой рефакторинг №1: отделить КОНТЕНТ от ДВИЖКА

Сейчас уроки зашиты в `index.html`. Для SaaS и перевода они становятся **контент-паками**:

```
/content/
  manifest.json            ← версия, список пакетов, размеры, хэши
  ru/
    core.json              ← LESSONS фаз 0–6 + PSY + MATH (как есть сейчас, вырезанные из HTML)
    terms.json             ← TERMS (глоссарий)
    tests.json             ← PHASE_TESTS
    earning.json           ← EARNING_METHODS (вкладка Заработок)
    ui.json                ← строки интерфейса (см. §6)
  en/ … es/ … pt/ …        ← те же файлы, переведённые
```

Правило: **движок не содержит ни одного русского слова о курсе** — только ключи интерфейса (`t('quiz.check')`). Контент целиком приходит из пакета активной локали.

Что это даёт: перевод = перевод JSON-файлов; обновление контента = публикация нового `manifest.json` (все пользователи получают новые уроки без переустановки); платный гейтинг = сервер отдаёт полные пакеты только пользователям с флагом доступа.

## 4. Ключевой рефакторинг №2: авторизация и права

### 4.1 Регистрация (минимум трения)
- Способ 1 (основной для мира): **Google / GitHub OAuth** через Workers (OAuth-flow руками, библиотека `oauth4api`-подобные паттерны) — один клик, без паролей.
- Способ 2 (основной для РФ): **email + код подтверждения** (письмо через бесплатный тариф Resend/Mailgun — 100–200 писем/день хватает на старт).
- Пароли не храним вообще (только OAuth и магик-ссылки) — минус целый класс рисков.

### 4.2 Сессии
После входа Worker выдаёт JWT (подпись HMAC-секретом воркера, срок 30 дней, refresh по activity). Фронт кладёт его в `localStorage` и шлёт как `Authorization: Bearer`.

### 4.3 Права доступа (гейтинг)
`users.access_tier`: `free | paid`.
- `free`: пакеты `ru/core_demo.json` (Фаза 0 полностью + Психология П1–П8) — твоя витрина;
- `paid`: полный `manifest` всех пакетов и всех локалей.
Вебхуки платёжных систем ставят `paid`. ВАЖНО: контент-пакеты платной части отдаются воркером **после проверки JWT**, а не лежат открытой статикой — иначе «сервис» превратится в скачиваемый файл.

### 4.4 Оплата: два контура
| Рынок | Провайдер | Почему |
|---|---|---|
| Мир | **Lemon Squeezy** или **Paddle** (merchant of record) | сами берут на себя НДС/налоги всех стран — критично для одиночного разработчика |
| РФ | **ЮKassa** (или CloudPayments) | карты МИР/СБП; самозанятость или ИП |
| Опционально, в тему продукта | крипто-платёж (BTCPay Server self-hosted / Cryptomus) | аудитория крипто — конверсия выше, комиссий почти нет; но добавлять во вторую очередь |

Единая цена: **$12 / 990 ₽ навсегда** (округлённые эквиваленты, чтобы бейдж выглядел аккуратно в обеих валютах).

## 5. Схема базы данных (D1, SQLite)

```sql
CREATE TABLE users (
  id TEXT PRIMARY KEY,               -- uuid
  email TEXT UNIQUE,                 -- nullable при OAuth-only
  provider TEXT NOT NULL,            -- 'google'|'github'|'email'
  created_at INTEGER NOT NULL,
  access_tier TEXT NOT NULL DEFAULT 'free',   -- 'free' | 'lite' | 'pro' | 'max'
  locale TEXT NOT NULL DEFAULT 'ru'
);

CREATE TABLE purchases (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id),
  provider TEXT NOT NULL,            -- 'lemonsqueezy'|'yookassa'|'crypto'
  external_id TEXT UNIQUE,           -- id платежа у провайдера (идемпотентность вебхука)
  amount_minor INTEGER NOT NULL,     -- в копейках/центах
  currency TEXT NOT NULL,
  status TEXT NOT NULL,              -- 'pending'|'paid'|'refunded'
  created_at INTEGER NOT NULL
);

CREATE TABLE progress (
  user_id TEXT PRIMARY KEY REFERENCES users(id),
  state TEXT NOT NULL,               -- весь объект cn_* одним JSON (совместимо с текущим localStorage!)
  app_version TEXT,
  updated_at INTEGER NOT NULL
);

CREATE TABLE feedback (              -- свободные отзывы прямо из приложения
  id TEXT PRIMARY KEY,
  user_id TEXT,
  lesson_id TEXT,
  score INTEGER, comment TEXT,
  created_at INTEGER NOT NULL
);

-- Текущий доступ и его срок (для тарифной лестницы §14.1)
-- users.access_tier: 'free' | 'lite' | 'pro' | 'max'
ALTER TABLE users ADD COLUMN access_expires_at INTEGER;  -- для «Макс»: до какого числа оплачено; NULL = навсегда (Лайт/Про)
ALTER TABLE users ADD COLUMN access_changed_at INTEGER;  -- когда последний раз менялся тариф

CREATE TABLE subscriptions (         -- рекуррентные подписки «Макс»
  user_id TEXT PRIMARY KEY REFERENCES users(id),
  provider TEXT NOT NULL,             -- 'yookassa'|'lemonsqueezy'
  external_id TEXT UNIQUE,            -- id подписки у провайдера (идемпотентность вебхуков)
  status TEXT NOT NULL,               -- 'active'|'past_due'|'canceled'
  amount_minor INTEGER NOT NULL,
  currency TEXT NOT NULL,
  current_period_end INTEGER NOT NULL,-- до какого числа оплачено
  started_at INTEGER NOT NULL,
  canceled_at INTEGER
);
```

Красота: `progress.state` — это ровно твой текущий объект настроек из `localStorage`, поэтому миграция существующего функционала сводится к «отправить то, что уже сохраняется локально».

## 6. API (Workers)

```
POST /api/auth/magic-request      { email }                      → письмо со ссылкой
GET  /api/auth/magic-confirm      ?token=…                        → set-cookie/JWT
GET  /api/auth/oauth/google       → redirect
GET  /api/auth/oauth/github       → redirect
GET  /api/me                      → {id, tier, locale}           (JWT)
PUT  /api/progress                {state, app_version}           (JWT, идемпотентно по updated_at)
GET  /api/progress                → state                        (JWT)
GET  /api/content/manifest        → список пакетов для моего tier+locale
GET  /api/content/pack/:locale/:name                             (JWT если пакет платный)
POST /api/pay/yookassa/webhook    ← подтверждение оплаты РФ
POST /api/pay/lemonsqueezy/webhook← подтверждение оплаты мир
POST /api/feedback                {lesson_id, score, comment}
GET  /api/live/orderbook          → нормализованный стакан (прокси к бирже)
GET  /api/live/klines             → живые свечи
GET  /api/live/fng                → индекс страха и жадности + история
GET  /api/live/funding            → ставки фандинга площадок
GET  /api/live/onchain/btc-fees   → комиссии сети BTC / мемпул
GET  /api/live/market             → цены/объёмы/доля рынка (агрегатор)
```

Полная спецификация слоя живых данных и движка объяснений — в `PROJECT_LIVE_MARKET_COACH.md`; расширенный каталог источников для облачной версии — §15 этого документа.
```

Идемпотентность вебхуков — по `external_id` (повторный вебхук не создаёт вторую покупку).

## 7. Мультиязычность: что переводим и как

### 7.1 Три слоя перевода
1. **Интерфейс** (`ui.json`) — подписи кнопок, экранов, тостов: ~300–500 коротких строк. Переводится за один проход.
2. **Контент** (`core/terms/tests/earning`) — уроки, аналогии, квизы: десятки тысяч слов. Основной объём.
3. **Культурный слой** — аналогии («радионяня», «невозвратный билет», ссылки на 115-ФЗ и налоги РФ). Здесь нужен не перевод, а **локализация**: для EN заменить российские примеры на нейтральные/западные, налоговый блок пометить как «RU-specific» и добавить общий блок «check your local taxes».

### 7.2 Пайплайн (реалистичный, дешёвый)
1. Выгрузка JSON-паков → скрипт собирает плоский список строк с контекстом (id блока, тип: concept/analogy/warn…);
2. Перевод моделью (GPT/Claude) **пачками с контекстом целого урока** — так сохраняются терминология и тон «наставника»; системный промт фиксирует: обращение на «ты», никаких англицизмов там, где в источнике их нет, терминологический глоссарий (прикладывается к каждому запросу);
3. Автопроверка: скрипт сверяет структуру (число блоков/квизов совпадает), числа внутри текста не изменились, плейсхолдеры целы;
4. Человеческая выборочная вычитка (носитель или продвинутый уровень) — сначала 20% уроков, приоритет Фазы 0;
5. Публикация как отдельная локаль в манифесте. Баги перевода правятся точечно — это данные, а не код.

### 7.3 Очерёдность языков (по размеру крипто-аудитории)
| Волна | Язык | Обоснование |
|---|---|---|
| v1 | 🇷🇺 русский | источник, запуск сервиса |
| v2 | 🇬🇧 английский | открывает весь мир; самый большой рынок англоязычных новичков |
| v3 | 🇪🇸 испанский | ЛатАмерика — огромная растущая крипто-аудитория |
| v4 | 🇵🇹 португальский | Бразилия |
| далее | турецкий/индонезийский/хинди | по данным посещаемости |

Язык выбирается автоматически (браузер) с переключателем в шапке. Русский контент, которого ещё нет в переводе, показывается с пометкой «RU» — сервис никогда не пустеет.

### 7.4 Скрытая трудоёмкость (честно)
Самая нудная часть проекта — **вынести строки интерфейса из JS-рендереров в `ui.json`**. Их много и они размазаны по шаблонным строкам. Это механическая работа на несколько вечеров, зато после неё добавление языка = только новый JSON.

## 8. Прогресс и офлайн

- Приложение стартует мгновенно на локальном кэше (service-worker + Cache Storage);
- Логин/синк — фоново: `PUT /api/progress` при каждом изменении (debounce 5 сек) и при закрытии вкладки; конфликт решается по `updated_at` (last-write-wins — для одного пользователя достаточно);
- Гость без регистрации играет с чистым `localStorage`; при первом логине локальный прогресс **сливается** в облако (не затирается!) — критично: человек мог начать до регистрации.

---

## 9. Приватность и юридический минимум

- Собираем только email (или провайдер-id), прогресс, платежи. Никакой аналитики третьих лиц на старте — упрощает GDPR-историю («мы почти ничего не храним»);
- Страницы Privacy Policy + Terms (шаблоны + адаптация); для ЕС — упомянуть право на удаление (кнопка «Удалить аккаунт и данные» — реализуется одним DELETE-эндпоинтом);
- РФ-плечо продаж (ЮKassa) требует самозанятость/ИП; позиционирование страницы — «интерактивный симулятор» (см. нюанс реестра онлайн-платформ — проконсультироваться перед запуском продаж в РФ);
- Дисклеймер «это симулятор, не финансовый совет» — уже есть, продублировать на каждом языке.

| Риск | Закрытие |

## 12. Готовые подзадачи для агента-кодера (порядок работ)

1. `content-loader`: fetch manifest → выборка пакета по tier/locale → merge в рантайм вместо зашитых массивов; кэш в Cache Storage; фолбэк на встроенный ru-пакет (офлайн-first сохраняется).
2. Скрипт `extract-content.mjs`: вырезает LESSONS/TERMS/PHASE_TESTS/PSY/MATH/earning из index.html в `/content/ru/*.json` (однократно; дальше источник истины — файлы).
3. `auth.js`: magic-link + OAuth, хранение JWT, экран входа (модалка в стиле приложения), кнопка «Синхронизировать прогресс» + авто-синк.
4. `ui-i18n`: словарь `t(key)` + вынос строк рендереров; страница настроек с выбором языка.
5. `payments.js`: две кнопки покупки (мир/РФ), обработка возврата с вебхука (tier=-paid), экран «Доступ активен навсегда».
6. Playwright-сценарии на каждый пункт (регистрация→оплата-мок→контент открылся→прогресс синкнулся→второе устройство видит тот же прогресс).

Каждая подзадача независима и сдаётся отдельно — агенту можно скармливать по одной.

## 14. Слой «🌍 Живой рынок с наставником» — интеграция в SaaS

Полная методика и механика движка объяснений — в отдельном документе `PROJECT_LIVE_MARKET_COACH.md`. Здесь зафиксировано, как слой встраивается в сервисную модель.

### 14.1 Тарифная лестница и доступ к слою живых данных

| Тариф | Цена | Курс (уроки) | 🌍 Живой рынок + Новости | 🤖 Наставник LLM |
|---|---|---|---|---|
| 🌱 Демо | 0 ₽ (регистрация) | Фаза 0 + Психология П1–П8 | нет | нет |
| 🔑 Лайт | 990 ₽ навсегда | все фазы полностью + конструкторы артефактов | нет | нет |
| 📊 Про | 1 990 ₽ навсегда | всё из Лайт | ✅ стакан, свечи, фандинг, новости с наставником | нет |
| 🤖 Макс | 299 ₽/мес или 1 990 ₽/год | всё из Про | ✅ | ✅ безлимитный наставник |

Логика лестницы: **постоянные расходы закрываются постоянным доходом** — LLM-запросы и расширенные источники оплачиваются подпиской «Макс», а не съедают маржу разовых продаж. Лайт остаётся полноценным курсом (весь обучающий контент), живые данные — надстройка практики. Апгрейды Лайт→Про→Макс идут с зачётом ранее уплаченного.

### 14.2 Встраивание в интерфейс
- Вкладка «🌍 Живой рынок» в группу ПРАКТИКА: лаборатория со живым стаканом/свечами выбранных активов и потоком карточек наставника;
- Кнопка «Попробовать на живом рынке» появляется в тренажёре урока **после его завершения** — гейтинг знанием;
- Панель здоровья источников: каждый канал показывает статус (живой / кэш от HH:MM / недоступен);
- Плашка на каждом живом экране: «Обучение чтению данных · не торговый сигнал».

### 14.3 Гейтинг и продажа
В демо-тарифе живыми становятся детекторы сентимента и комиссий сети (витрина фичи). Полный доступ открывает микроструктуру, фандинг, ончейн-потоки и конструктор заданий по живым данным. Обновления детекторов публикуются как новые версии контент-паков — пользователи lifetime получают их автоматически (аргумент модели «навсегда»).

## 20. Админ-панель и телеметрия (владелец видит всё)

Цель: владелец в любой момент видит расход лимитов AI/Workers, воронку пользователей, выручку и точки оттока — без ручных SQL-запросов. Реализуется на том же бесплатном стеке.

### 20.1 Принципы
1. **Телеметрия встраивается с этапа авторизации** (не потом): каждый значимый вызов пишет событие через `ctx.waitUntil()` — не замедляет ответ пользователю;
2. Админка — отдельная страница `/admin`, защищённая **Cloudflare Access (Zero Trust, бесплатно до 50 пользователей)** по email владельца. Плюс дублирующий `ADMIN_SECRET` в env для API-вызовов;
3. В логах нет контента диалогов с ИИ и текстов учеников — только счётчики, типы событий и псевдонимные id. Email по умолчанию маскируется (a***@mail.ru), раскрытие — отдельным действием;
4. Всё на бесплатном: события копятся в D1, суточная свёртка — Workers Cron (бесплатно), графики — инлайн SVG без библиотек.

### 20.2 События (единый контракт `track(type, user_id?, meta)`)
Модули ОБЯЗАНЫ эмитить (одна строка кода на событие):
| type | Откуда | meta |
|---|---|---|
| signup | auth | provider, locale |
| login | auth | provider |
| tier_change | payments/admin | from→to, reason (purchase/manual_grant) |
| pay_webhook | payments | status, amount_minor, currency, external_id |
| mentor_call | LLM-наставник (все 7 фич) | feature (feynman/rephrase/socratic/taskgen/hint/critic/sparring), ok(bool), filtered(bool — сработал выходной фильтр), chars_in/out |
| live_fetch | Живой рынок/Новости | endpoint, upstream (binance/bybit/…), cache_hit(bool), latency_ms |
| quiz_answer | рендер квизов | lesson_id, correct(bool), hints_used_before_answer |
| lesson_complete | завершение урока | lesson_id, seconds_spent, hints_used, feynman_ai_used(bool) |
| app_error | глобальный хендлер | where, msg_hash (хэш сообщения, не сам текст) |

Хранение: таблица `events(id INTEGER PK, ts INTEGER, type TEXT, user_id TEXT NULL, meta TEXT)` + индекс (type, ts). Объём: даже 1000 DAU × 50 событий = 1,5 млн строк/мес — D1 free (5 ГБ) хватает на годы; чистка старше 180 дней тем же кроном.

Суточная свёртка (Cron, раз в сутки): таблица `stats_daily(day, metric, value)` — signup_count, dau, ai_calls_by_feature, live_cache_hit_rate, revenue_minor, errors_count. Дашборд читает только свёртку — быстро и дёшево.

### 20.3 Расход AI/Workers — что именно видно
- **mentor_calls за день/неделю/месяц** по фичам (feynman/rephrase/socratic/taskgen/hint/critic/sparring);
- Доля заблокированных выходным фильтром ответов (рост доли = сигнал деградации промта);
- Топ-пользователей по вызовам (псевдонимно) — чтобы ловить аномальное потребление лимита;
- Остаток дневной квоты Workers AI (воркер возвращает собственный счётчик нейронов из метаданных ответа; плюс ссылка на официальный дашборд CF);
- live_fetch: hit-rate кэша, латентность по апстримам, число отказов источников (матрица фолбэков в действии);
- Близость к лимитам тарифа: запросы Workers (free 100k/день), чтения D1 — красная зона подсвечивается заранее.

### 20.4 Экраны админки (`/admin`)
1. **Обзор (30 дней / всё время)**: новые регистрации, DAU/WAU, распределение по тарифам (free/lite/pro/max), конверсии шагами (демо→лайт→про→макс);
   **финансовый блок**: разовая выручка (Лайт/Про) по месяцам; MRR подписок «Макс» и число активных подписок; продления/отказы за период; ARPU и средний LTV плательщика; неудачные списания (past_due) — список для ручного обзвона;
   плюс: AI-вызовы всего/по фичам, ошибки;
2. **AI-расход**: график вызовов по дням с разбивкой по фичам, доля отфильтрованных, топ-потребители (id), остатки квот;
3. **Пользователи**: таблица (id, маск-email, тариф, локаль, регистрация, последний вход, уроков пройдено) с фильтрами по тарифу/локали/дате;
   **карточка пользователя — финансовый блок**: текущий тариф + дата его смены; история платежей (дата, сумма, валюта, провайдер, статус); для «Макс» — статус подписки и дата следующего списания; LTV пользователя за всё время; кнопки «продлить подписку вручную», «отменить», «сменить тариф»;
   **учебный блок**: прогресс-сводка, последние события, ошибки по типам — БЕЗ содержимого дневников и диалогов (приватность);
4. **Контент**: топ уроков по завершениям и главные точки оттока (последний урок перед уходом) — прямой вход в улучшение программы;
5. **Действия**: выдать/сменить тариф вручную (гранты, компенсации), пометить вебхук обработанным вручную, удалить пользователя по запросу (GDPR) — каждое действие пишется в audit-лог `admin_actions`.

3. Cron-свёртка + экраны админки — можно позже, данные уже копятся с первого дня (главное правило: данные, которые не собирались, восстановить нельзя).

### 20.7 Приёмка админки
1. Без Cloudflare Access/секрета все /admin/* отвечают 401;
2. Числа обзора совпадают с контрольным SQL-запросом по events (выборочная сверка);
3. Мок-режим ИИ НЕ увеличивает счётчики mentor_calls (или увеличивает с флагом mock=true — зафиксировать поведение);
4. Маскирование email включено по умолчанию; раскрытие требует явного действия и попадает в audit-лог;
5. Удаление пользователя стирает progress/events/email и оставляет анонимную запись о покупке (налоговая необходимость);
6. Дашборд грузится <2 сек на данных за 30 дней.

### 20.8 Управление моделью AI-наставника
Экран внутри раздела «AI-расход»: владелец меняет модель наставника **без передеплоя**.

**UI:** список моделей из белого списка конфига воркера; у каждой карточки — описание характера (быстрая/задумчивая), примерный расход нейронов за типовой запрос и текущий флаг активности; кнопка «Сделать активной». Ниже — история переключений (кто, когда, что→что).

**Хранение и применение:** активная модель живёт в настройках (KV-ключ `ai_model` или таблица settings); воркер читает её при каждом вызове наставника. Смена действует со следующего запроса — деплой не нужен. Если выбранная модель стала недоступна на Workers AI — автоматический откат на дефолт из конфига + красная карточка-алерт в админке.

**Правила безопасности:** выбор только из белого списка (произвольные id запрещены — защита от инъекции через админку); каждая смена пишется в `admin_actions`; мок-режим `?mockai=1` игнорирует модель.

**Эндпоинты (за Access):**
```
GET  /admin/api/ai_model   → {active, allowed:[{id,label,cost_hint}], changed_at}
POST /admin/api/ai_model   {model_id}   ← только из whitelist
```
Примечание: разные модели заметно различаются качеством объяснений и расходом квоты — рекомендация: быстрая дешёвая как постоянная, «задумчивая» включается точечно для проверки Фейнмана, если сравнение покажет пользу.

## 21. Производительность SaaS-версии: бюджеты и правила

Принцип: скорость закладывается архитектурой (§2–§8), а не допиливается потом. Ни одна фича не принимается, если ломает бюджеты этого раздела.

### 21.1 Бюджеты (жёсткие)
| Метрика | Бюджет | Как достигается |
|---|---|---|
| Движок (HTML+CSS+ядро JS) | ≤300 КБ сырых / ≤100 КБ brotli | контент в паках, не в файле |
| Первый показ на среднем Android (Fast 3G) | FCP ≤1 с, готовность к клику ≤2 с | статика на edge, критический путь без ожидания пакетов |
| Открытие урока | ≤150 мс после загрузки пакета | рендер из кэша пакета |
| Любое действие интерфейса | ≤100 мс до отклика | точечные обновления DOM |
| Пакет фазы | ≤150 КБ brotli | один пакет = одна фаза |
| /api/progress | p95 ≤100 мс | D1: одна строка на пользователя |
| Живой рынок | никогда не блокирует интерфейс | снимки из кэша воркера, обновление фоном |
| JS-рантайм | без накопления лагов за 30 мин | дисциплина таймеров/подписок |

### 21.2 Архитектурные решения скорости (уже в проекте)
1. **Статика на edge**: Pages отдаёт движок из ближайшей точки присутствия — TTFB стабильно <200 мс по миру;
2. **Пакеты — неизменяемые и вечнокэшируемые**: имя файла содержит хэш версии (`core.ru.v17.json`), заголовок `Cache-Control: immutable` + Service Worker stale-while-revalidate → повторное открытие мгновенное, офлайн работает;
3. **Префетч следующего пакета** при достижении 70% прогресса текущей фазы;
4. **API тонкий**: progress — одна строка D1; mentor/live — асинхронные, интерфейс показывает скелетон и никогда не блокируется сетью;
5. **Auth локально**: JWT живёт на клиенте, проверки тарифа — в манифесте контента, без лишних round-trip.

### 21.3 Правила рендеринга фронтенда
1. Виджеты урока монтируются лениво при попадании в зону видимости (IntersectionObserver) — урок из 9 блоков не считает все тренажёры сразу;
2. Отрендеренный урок кэшируется (id+версия пакета) — повторное открытие без пересборки HTML;
3. «Живые» зоны (таймеры, счётчики, стакан) обновляются точечно через textContent конкретного узла — никаких пересборок секций;
4. Все интервалы/подписки гасятся при уходе со вкладки — парность setInterval/clearInterval проверяется линтером-скриптом;
5. Запись состояния — debounce 300 мс; объёмные кэши (снимки рынка, архив новостей) — в IndexedDB, в localStorage только прогресс;
6. Анимации только transform/opacity; уважается prefers-reduced-motion.

### 21.4 Ассеты
- Скриншоты/GIF: AVIF+WebP+JPG-fallback, lazy loading, явные width/height;
- Шрифты системные (ноль запросов);
- Инфографики — уже сжаты (см. историю коммитов), подключаются лениво.

### 21.5 Контроль: измерять, а не надеяться
- `performance.mark` на старте, открытии урока, загрузке пакета → события в телеметрию (§20): перцентили FCP/времени открытия по классам устройств видны владельцу;
- В приёмку каждого прохода агента — Lighthouse mobile ≥90 для изменённых экранов;
- Скрипт бюджетов: если движок или пакет превысил лимит — сборка падает с ошибкой (размер проверяется автоматически);
- Регресс-тест «30 минут»: сценарий длительной сессии в Playwright с замером памяти/лагов в конце.

### 21.6 Деградация на плохой сети
Медленная сеть не меняет порядок работы: сначала каркас из кэша, пакеты догружаются с индикатором; при обрыве — офлайн-режим полного доступа к скачанным фазам. Никаких спиннеров вместо контента, который уже в кэше.

## 22. Безопасность: модель угроз и защита

Принцип оценки: у продукта три актива разной ценности, и защищаются они по-разному.
| Актив | Ценность | Главный риск |
|---|---|---|
| Движок (JS) | низкая — открыт по дизайну | копирование не страшно: ценность не в коде |
| **Контент-паки уроков** | **высокая** | слив платной части через API |
| **База пользователей** | высокая (репутация + закон) | утечка email/прогресса, подделка тарифов |
| Секреты воркера | критическая | подделка платежей/тарифов, рассылка спама от твоего домена |

### 22.1 Защита главного актива: платные контент-паки
1. Пакеты платной части НИКОГДА не лежат статикой — только выдача воркером после проверки JWT + access_tier (§4.3);
2. Хранение паков — R2 (10 ГБ бесплатно) с приватным доступом, воркер читает по ключу;
3. **Пер-пользовательский водяной знак**: в выдаваемый JSON встраивается невидимый маркер (id пользователя в поле meta, порядок элементов) — при утечке конкретной копии видно, чей аккаунт слил;
4. Rate limit на /api/content/pack: N пакетов в час на пользователя;
5. Мониторинг аномалий в админке (§20.3): один аккаунт, качающий все пакеты подряд ночью — красный флаг.

### 22.2 Регистрация и вход
- **Turnstile** (бесплатная невидимая капча Cloudflare) на регистрации и magic-link — отсекает ботов-спамеров аккаунтов;
- Rate limit на auth-эндпоинты: по IP и по email (например, 5 попыток/час) — правила Rate Limiting бесплатного тарифа;
- Пароли не храним (OAuth/magic-link) — украдёт базу, паролей там нет;
- Email верифицируется до разблокировки прогресса.

### 22.3 Приложение и API
1. Все SQL — только параметризованные prepared statements D1 (конкатенация строк запрещена);
2. Всё, что рендерится на странице из внешних данных (новости, заголовки, контент-паки) — экранируется; ссылки — rel="noopener";
3. Заголовки безопасности файлом `_headers` на Pages:
```
/*
  X-Frame-Options: DENY
  X-Content-Type-Options: nosniff
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: camera=(), microphone=(), geolocation=()
  Content-Security-Policy: default-src 'self'; connect-src 'self' https://<api-домен>; img-src 'self' data:; object-src 'none'; base-uri 'self'; frame-ancestors 'none'
```
(Честное замечание: движок использует инлайн-скрипты, поэтому script-src остаётся разрешительным — компенсируется строгими connect-src/object-src/base-uri и полным экранированием вывода.)
4. Вебхуки платежей — проверка подписи провайдера + идемпотентность по external_id (уже в §5);
5. Секреты — только Variables/Secrets воркера; в git не попадают; перед каждым мерджем агента — прогон `gitleaks detect` по диффу (одна команда, добавить в чек-лист сдачи);
6. Ротация JWT_SECRET и ключей вебхуков — раз в квартал, процедура описана в деплой-гайде.

### 22.4 Спам и абьюз ресурсами
- Лимиты наставника и живых данных уже душат экономику абьюза (§14.1, §20.3);
- Аномалии видит админка: аккаунт, читающий все пакеты ночью; IP с сотней регистраций;
- Массовые одноразовые почты режутся Turnstile + подтверждением письма до выдачи даже бесплатного контента.

### 22.5 Инцидент-план (кратко)
1. Подозрение на утечку пака → сменить префикс версии манифеста + перегенерировать водяные знаки;
2. Компрометация секрета → ротация в dash (2 минуты), все JWT инвалидируются автоматически;
3. Утечка базы → уведомление пользователей (шаблон), сброс сессий, пост-мортем в канал разработки (честность = часть бренда).

### 22.6 Чего делать НЕ нужно
- Обфускация кода — бесполезна и мешает отладке;
- Платный WAF/DDoS — Cloudflare free уже прикрывает;
- Собственная криптография для хранения — стандартные механизмы достаточны;
- DRM против копирования экранов — экономически бессмысленно (см. §0).

### 22.7 Чек-лист безопасности (в приёмку каждого этапа агента)
□ gitleaks по диффу чист; □ секреты только через env; □ все SQL подготовлены; □ весь внешний вывод экранирован; □ Turnstile на регистрации; □ rate limit на auth/content; □ подпись вебхуков проверяется; □ _headers задеплоены; □ экспорт D1 сделан до миграции.

## 23. SEO и GEO: видимость в поисковиках и нейросетях

Два разных канала с разной механикой и сроками. Технические артефакты (robots.txt с явным Allow ИИ-краулеров, sitemap.xml, llms.txt, hreflang, JSON-LD Course/Organization/FAQPage, страницы терминов) — в Фазе F промта лендинга `PROMPT_AGENT_LANDING_GLOBAL.md`; здесь — стратегия и интеграция в сервис.

### 23.1 Стратегия контента: глоссарий как месторождение
Головные запросы («как выучить крипту») заняты гигантами — туда не идём напрямую. Вместо этого:
- **205 терминов глоссария → 205 публичных страниц** вида `/terms/<slug>/`: определение (уровни 1–2 из контент-пака), пример из жизни, блок «Проверь на тренажёре» со ссылкой на интерактив урока;
- Это сотни страниц уникального экспертного контента под длинные запросы («что такое спред», «почему ликвидация при плече x20 наступает раньше −50%»), написанных уже сейчас;
- Генератор страниц читает контент-паки и собирает статические страницы на этапе деплоя — контент и сайт не расходятся никогда;
- Тарифная логика: страницы терминов публичны (это маркетинг и польза), интерактивы за ними.

### 23.2 Присутствие в корпусах нейросетей
Модели цитируют то, что видели при обучении и находят в живом поиске. Рычаги:
- **Статьи на Habr/vc.ru** (история разработки v1→v7, технические разборы детекторов) — эти площадки сильно представлены в обучающих данных русскоязычных моделей;
- README репозитория как структурированный факт-лист (агенты часто читают GitHub);
- Единое имя «КриптоНавигатор» во всех упоминаниях — модели собирают сущность из повторений;
- llms.txt + чистый серверный HTML ключевых страниц (JS-рендер нейросети не видят);
- Регулярность: одна публикация раз в две недели важнее одного большого поста.

### 23.3 Интеграция в сервис
- Sitemap генерируется из манифеста контента на деплое: новая локаль/уроки автоматически попадают в карту;
- В телеметрию (§20) добавить источник трафика (referrer/ref) — видно, какой канал приводит платящих;
- Языковые версии терминов появляются по мере перевода паков; непереведённые помечаются hreflang-заглушкой без индексации;
- Метрики успеха смотреть в GSC/Яндекс.Вебмастер + вручную: месяц задавать Perplexity/ChatGPT целевые вопросы и логировать, цитируется ли продукт.

### 23.4 Подзадача агенту (добавить к списку §12)
`seo-pages.mjs`: генератор статических страниц терминов из контент-паков (+robots.txt, sitemap.xml, llms.txt, hreflang-каркас). Приёмка: все 205 страниц валидны, попали в sitemap, содержат Course/DefinedTerm разметку и блок перехода в тренажёр.

## 24. Мобильная стратегия: PWA → Capacitor → Натив

Продукт уже адаптивен до 360px и работает офлайн. Мобильная версия строится поверх существующей архитектуры без переписывания — тремя ступенями по мере роста аудитории.

### 24.1 Этап M1 · PWA (один вечер, сразу после контент-паков)

Два новых файла + три строки в `<head>`:

**`manifest.json`:**
```json
{
  "name": "КриптоНавигатор",
  "short_name": "КриптоНавигатор",
  "start_url": "/index.html",
  "display": "standalone",
  "background_color": "#0B1220",
  "theme_color": "#0B1220",
  "icons": [
    { "src": "assets/icons/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "assets/icons/icon-512.png", "sizes": "512x512", "type": "image/png" }
  ]
}
```

**`service-worker.js`:**
```js
const CACHE = 'cn-v1';
const CORE = ['/', '/index.html', '/content/manifest.json'];
self.addEventListener('install', e => {
  e.waitUntil(caches.open(CACHE).then(c => c.addAll(CORE)));
});
self.addEventListener('fetch', e => {
  // stale-while-revalidate: сначала кэш, потом обновление фоном
  e.respondWith(
    caches.match(e.request).then(hit =>
      hit || fetch(e.request).then(r => {
        const copy = r.clone();
        caches.open(CACHE).then(c => c.put(e.request, copy));
        return r;
      })
    )
  );
});
```

**Подключение в `<head>`:**
```html
<link rel="manifest" href="/manifest.json">
<meta name="theme-color" content="#0B1220">
<script>navigator.serviceWorker.register('/service-worker.js')</script>
```

Что получает ученик: заходит на сайт с телефона → браузер предлагает «Установить приложение» → иконка на главном экране → открывается полноэкранно без адресной строки → работает офлайн. Прогресс в localStorage сохраняется между открытиями.

### 24.2 Этап M2 · Capacitor-обёртка (~2 недели после первых продаж)

Тот же index.html упаковывается в нативное приложение через Capacitor:
```
npx cap init КриптоНавигатор app.cryptonavigator
npx cap add android && npx cap add ios
npx cap sync && npx cap open android   ← сборка в Android Studio
```
Что добавляет нативная оболочка:
- Публикация в Google Play и App Store (витрина = доверие);
- Локальные push-уведомления («стрик горит», «сборочный пункт», «наставник ждёт»);
- Биометрия для входа (Face ID / отпечаток);
- Тактильная отдача при правильных ответах;
- Хранение прогресса в нативном хранилище вместо localStorage.

Изменения кода: один интерфейс `StorageAdapter` (get/set/remove) с тремя реализациями — localStorage (web), Capacitor Preferences (мобильный), серверный API (облачный синк).

### 24.3 Этап M3 · Нативные фичи (по спросу)
Только если пользователи просят:
- Виджет стрика на главном экране телефона;
- Оффлайн-карты живого рынка;
- Интеграция с системным календарём для графика обучения.

### 24.4 Контент-паки на мобильных
Пакеты бандлятся внутрь Capacitor-приложения (обновляются через App Update) или кэшируются service-worker'ом (PWA). В обоих случаях формат тот же JSON — движок не знает разницы.

## 25. Онбординг нового пользователя (SaaS)

Первые 3 минуты после регистрации решают, останется ли человек. Онбординг — не «обучение», а **проводник по интерфейсу**: показать где что лежит, дать первую победу за 5 минут, и выпустить в самостоятельное плавание.

### 25.1 Когда запускается
- Автоматически после первой успешной регистрации (флаг `cn_onboarded` отсутствует);
- Один раз. Кнопка «Показать тур снова» — в настройках профиля;
- Пропуск доступен на каждом шаге.

### 25.2 Пять шагов онбординга
| Шаг | Экран | Что показывает |
|---|---|---|
| 1 | Шапка | «Это твой прогресс и ранг. Начинаешь стажёром — станешь управляющим.» |
| 2 | Вкладка Уроки | «134 урока в 9 фазах. Начни с Фазы 0 — она бесплатная целиком.» |
| 3 | Первый урок Фазы 0 | Открывается урок 0.1 полноэкранно: «Вот так выглядит урок. Читай, жми тренажёры, отвечай на квиз.» |
| 4 | Симуляторы | «Отдельные симуляторы для практики: стакан, ликвидации, фандинг и другие.» |
| 5 | 🤖 М. в уроке | «Наставник отвечает на вопросы по материалу урока. Доступен на тарифе Макс.» |

Каждый шаг: полупрозрачный оверлей + карточка с текстом + кнопки «Далее» / «Пропустить тур». После шага 3 — урок 0.1 реально открывается (первая победа за 5 минут).

### 25.3 Реализация
```js
// tour_steps.json — массив {selector, title, body} 
// overlay: position:fixed, z-index:99999, background:rgba(0,0,0,.65)
// highlight: box-shadow вокруг целевого элемента через outline
// кнопка "Далее" → следующий селектор; "Пропустить" → finish()
function startTour(){ if(localStorage.getItem('cn_onboarded')) return; render(); }
function finish(){ localStorage.setItem('cn_onboarded','1'); }
```
Функции `startTour`/`finish` экспортируются глобально. Кнопка «Показать тур снова» — в настройках профиля.

### 25.4 Приёмка
□ Тур показывается один раз новому пользователю; □ пропустить можно на каждом шаге; □ после тура урок 0.1 открыт; □ флаг cn_onboarded записан; □ кнопка «показать снова» работает.
