Криптик — единственный «человек» рядом. Мы хотим, чтобы вы оценили с позиции педагогики: **где наставник реально помогает пониманию и усвоению, а где он декорация**; и спроектировали его развитие с учётом того, что «мозг» будет слабой моделью — значит, вся магия должна держаться на заготовках, структуре и правильных вопросах, а не на «умных» длинных ответах, которых слабая модель не даст.

## 2. Как устроен наставник (факт, без кода)

### 2.1. Архитектура одним абзацем (алгоритм)

Криптик = **персона (рендер и реплики) + несколько «мозгов»**. Персона всегда локальна и детерминирована. «Мозги» разные по точкам: (а) в панели урока — запрос к внешнему AI-сервису (слабая модель через наш Cloudflare Worker) с **заранее собранным контекстом урока**, с локальным фолбэком без сети; (б) в психологии — **локальный поисковый движок по базе знаний** (RAG без нейросети: поиск, сборка ответа из готовых блоков); (в) в Python-песочнице — детерминированные заготовки по типу ошибки; (г) в квизах — банка реплик. Общий принцип: **слабая модель получает уже собранный контекст и узкую задачу** (оценить/перефразировать/спросить), а не «общаться свободно».

### 2.2. Персона: аватар и характер

- **Аватар** — компактный SVG (круглая «голова» с антенной, два глаза, рот). 4 эмоции переключаются классами: `neutral`, `happy`, `doubt`, `surprise`. Глаза/рот анимируются CSS. На панелях — 32–48 px, в лендинге — до 120 px.
- **Банка реплик** — около 20 категорий, в каждой 2–5 вариантов, выбирается случайная (без сида):

| Категория | Примеры реплик |
|---|---|
| error_generic (ошибка в квизе) | «Логично. Неправильно, но логично.» · «Ну-ну. Все через это проходили.» · «Дальше будет проще. Или нет.» |
| error_concept | «Идея не дошла. Перечитай уровень 1.» · «База хромает. Вернись к определению.» |
| error_arithmetic | «Калькулятор изобрели для таких случаев.» · «Посчитай ещё раз. Медленно.» |
| win_easy | «Приемлемо.» · «Так и держи.» · «Не расслабляйся.» |
| win_hard | «Вот это уже интересно.» · «Заслуженно.» |
| hint_used | «Подсказал. Дальше сам.» |
| limit_reached | «На сегодня всё. Завтра продолжим.» · «Мозгу нужен отдых. Это тоже урок.» |
| streak_3 / streak_7 | «Три дня подряд. Уже неплохо.» / «Неделя. Не сорвись.» |
| tour_start / tour_end | «Я Криптик. Покажу где что лежит. 30 секунд — и ты в деле.» / «Разобрался? Хорошо. Дальше сам.» |
| boss_hit / boss_miss / boss_win / boss_lose | реплики в сюжетных симуляторах: «Босс не бессмертный. Дави.» / «Мимо. Соберись.» / «Проигрыш — это данные. Попробуй иначе.» |

- В панели наставника — **живая реакция на состояние запроса**: во время запроса к AI аватар делает «surprise» + статус «Смотрю…»; после вердикта Фейнмана — happy («Приемлемо.») при understood / doubt при провале; при исчерпании лимита — реплика limit_reached; при сетевой ошибке — «Связь шумит. Повтори.».

### 2.3. Панель наставника в уроке («🤖 М.»)

Кнопка появляется в полноэкранном чтении любого урока. На мобильных панель разворачивается снизу на 75% экрана. Шапка: аватар 48px + имя «Криптик» + статусная строка. Тариф «Макс» — остальным показывается модалка-апселл («AI-разбор уроков доступен на тарифе „Макс“. Отвечает только по материалу открытого урока — без прогнозов и рекомендаций»). Подвал: «Вопросы обрабатываются ИИ Cloudflare без привязки к личности. Лимит: 30 действий/день.» Анонимный deviceId генерируется локально. Действий в панели четыре + два контекстных:

**2.3.1. F1 «🧑‍🏫 Проверка Фейнмана».** Ученик объясняет тему урока своими словами в поле (это поле встроено в сами уроки психологии как «проверка Фейнмана»), жмёт кнопку — AI возвращает JSON-вердикт: `verdict: understood | partial | missed`, список пробелов (`gaps`, например «добавь конкретный пример из урока») и `advice`. Если сети нет — работает локальный ДЕМО-вердикт, который **честно помечен**: «🎭 ДЕМО-вердикт (правило „длина > 40 символов“, не ИИ)».

**2.3.2. F2 «🔄 Объясни иначе».** Перефраз фрагмента урока простыми словами (виды: simpler и др.). Работает и по выделенному тексту.

**2.3.3. F3 «🤔 Сократов режим».** Наставник не отвечает, а задаёт вопрос: «какое условие делает это правилом, а не исключением?» — ступени вопросов (step 1/2/3).

**2.3.4. F4 «✍️ Генератор задач».** Генерация учебной задачи по материалу урока («Новая задача: маржа $2 000, плечо ×5. При каком движении против позиции ликвидация?»).

**2.3.5. Контекстные действия (вне панели):** «Объяснить выделенное» (explain по выделению в тексте урока), «💬 Спросить М. по этому наблюдению» (в живом слое), «📚 Спроси по книгам» (§2.5), «Спор»/«Критика»/«Ревизия»/«Диагностика» (экспериментальные действия: spar — 3 стадии дебатов по гипотезе ученика; critique — критика торговой идеи по 6 критериям с вердиктами ok/warn/fail; revise — поиск лазеек в торговом уставе; diagnose — классификация типа ошибки ученика).

**Как собирается контекст урока для запроса.** Клиент сам собирает текст урока: заголовок + уровни concept (level1–4) + аналогия + recap, обрезка до 6000 символов. На сервер уходит: `action`, `lessonId`, `lessonText`, `deviceId`, `payload`. Ответ проходит **клиентский фильтр запретных тем**: если в ответе AI встретились «покупай / продавай / цена вырастет / рекомендую открыть позицию / сигнал к покупке…» — текст целиком заменяется на «Здесь я останусь при материале урока: давай разберём то, что в нём есть».

**Фолбэк без сети:** каждое действие имеет локальный mock-ответ (детерминированный), приложение никогда не «зависает» без AI — просто честно помечает демо-режим.

### 2.4. База знаний: 302 атома из 15 книг (доказательный слой)

Отдельный «мозг» для психологии — **локальный поиск, без нейросети**:

- **Что в базе.** 302 «атома знания» из 15 первоисточников по психологии трейдинга и риска: Tendler, Hougaard, Douglas, Donnelly, Taleb, Steenbarger, Minervini, Zweig, Spiegelhalter, Могилат, Schwager, Edward, Goldstein, Crosby, Housel. Каждый атом — структурированная карточка: автор, книга, номер и название главы, раздел; **цитата-якорь** (пересказ идеи, честно помечен `quote_verified: false` — «не дословная цитата»); **суть** (1–2 предложения); **кейс** (пример из книги или учебный пример курса — различаются пометкой); **пошаговый протокол** (что делать); ключевые слова; связанные уроки (П1–П52) и связанные термины глоссария.
- **Как ищет.** Настоящий BM25-поиск (взвешивание терминов) поверх полей атома, с русским стеммингом («стопами» ≈ «стопам» ≈ «стопов») и стоп-словами. Надбавки к оценке: **+6**, если атом привязан к текущему уроку; **+2,5**, если атом привязан к «слабой зоне» ученика (§2.7); **+4** за искомого автора; жёсткий фильтр, если автор запрошен явно. Есть **порог релевантности**: в длинном запросе нужно минимум 2 разных совпадения слов — иначе считается «не найдено» (без порога любой запрос вроде «борщ» получал бы «найдено»).
- **Zero-Hallucination.** Если по запросу ничего не нашлось, наставник честно отвечает: «Честный ответ: в загруженных конспектах 15 книг по этому вопросу конкретных указаний я не нашёл. Попробуй переформулировать через тему (например: „тильт“, „сайзинг после убытков“…)». Никаких выдуманных «мнений от авторов».
- **Действие «📚 Спроси по книгам».** Свободный вопрос ученика → поиск атомов → сборка ответа по шаблону: «📚 Отвечаю по доказательной базе (15 книг). Найдено источников: 2.» → по каждому: «— Источник 1: Джаред Тендлер, „The Mental Game of Trading“, глава 1 „A System To Fix Mental Game Problems“» → «Пересказ идеи (не дословная цитата): …» → «Суть: …» → «Кейс: …» → «Протокол: …» → «Связанные уроки: П5, П12». В онлайн-режиме тот же вопрос можно отправить AI-сервису: контекст собирает тот же движок и прикладывает к запросу с жёсткими правилами (см. §2.5).
- **Готовый контекст для слабой модели.** Движок умеет собирать «промпт-пакет»: доказательная база (найденные атомы, отформатированные) + 5 правил («отвечай только по источникам», «цитируя — указывай автор/книга/глава», «не выдавай пересказ за дословную цитату», «если ответа в источниках нет — честно скажи», «давай адресную подсказку, а не лекцию») + профиль ученика. Капа контекста — 1600 символов, для стабильности кэшируется (один запрос → одинаковый контекст).

### 2.5. Сократовские подсказки в 52 тренажёрах психологии

В каждом психологическом тренажёре-сценарии («Ночью пришло уведомление, сердце стучит — что делать?») рядом с вариантами ответа есть кнопка «💡 Подсказка». Работает в 2 ступени:

- **Ступень 1 (наводящий вопрос, без спойлера):** движок ищет по тексту сценария атом и формирует вопрос из сути: «💡 Наводящий вопрос по методу Джареда Тендлера („The Mental Game of Trading“): прежде чем выбрать ответ — эмоции — это данные, а не помеха. Как это соотносится с ситуацией? Что именно в твоём выборе противоречит этому принципу?»
- **Ступень 2 (принцип автора):** «💡 Принцип Марка Дугласа („Trading in the Zone“, глава …): „…“. Проверь свой выбор этим принципом и выбери ещё раз.»
- **Фолбэк** (ничего не нашлось): универсальные вопросы про «серия против отдельного исхода», «факт против чувства», «какой пункт плана выполняется».
- Подсказка не раскрывает правильный ответ — только принцип для самопроверки.

### 2.6. Память ученика и «слабые зоны»

- Локальная память (`localStorage`): последние 100 ошибок (в каком уроке, какого рода) и 100 запросов подсказок.
- **Профиль ученика** собирается автоматически: сколько психологических уроков пройдено; **слабые уроки** — где точность лучшей попытки тренажёра < 70%; последние ошибки («П12 (ошибка в тренажёре)»). Профиль учитывается в поиске (надбавка атомам слабых зон) и прикладывается к AI-запросам.
- Ошибки в квизах пишутся через обёртку — Криптик реагирует репликой из §2.2.

### 2.7. Наставник в Python-песочнице (QuantDeterministicCopilot)

Полностью детерминированный (без AI-сервиса), 4 уровня помощи по ошибкам кода:

1. **Синтаксический переводчик** — человеческим языком объясняет, что значит ошибка интерпретатора Python (тип, что не так, где).
2. **Квант-грабли** — узнаёт типичные ошибки квант-кода (look-ahead, деление на ноль, окно нулевой длины…) и указывает на концептуальную проблему, не решая задачу.
3. **Сократовский L1–L3** — для известных задач: L1 «вектор мысли» (что считать, без формул), L2 «концепт функции» (какие шаги), L3 «параметрический каркас» (код-скелет с параметрами, ученик заполняет).
4. **Пост-бэктест аудит** — после прогона стратегии указывает на классические дефекты бэктеста.

### 2.8. Что НЕ умеет текущий Криптик (честный список)

- Не видит экран ученика и не комментирует действия в тренажёрах (кроме реплик квиза).
- Не пишет длинных рассуждений: всё держится на коротких блоках.
- Не ведёт диалог серией вопросов (Сократов режим — максимум 3 ступени).
- Не помнит контекст между сессиями, кроме ошибок/подсказок (нет «разговора с продолжением»).
- Панель работает только в полноэкранном чтении урока; из тренажёров и симуляторов её нет.
- В оффлайне F1–F4 — демо-заглушки (честно помечены); «по книгам» и подсказки работают полностью (локальная база).

## 3. Принципы, которые мы сознательно заложили (и почему)

1. **Слабая модель — не приговор, а проектное ограничение.** Вся структура построена так, чтобы модели оставалось немного: контекст собираем мы (урок/атомы/профиль), задача формулируется узко (вердикт/перефраз/вопрос), ответ приходит в JSON. Свободной болтовни нет нигде.
2. **Честность важнее ума.** ДЕМО-пометки на фолбэках; «пересказ, не дословная цитата» на каждом атоме; «в книгах этого нет» при пустом поиске; запрет выдавать пересказ за цитату.
3. **Наставник никогда не даёт торговых советов.** Клиентский фильтр бан-листа заменяет ответ целиком. В панели написано: «Отвечает только по материалу открытого урока — без прогнозов и рекомендаций».
4. **Лимит 30 действий/день** — и защита от выгорания, и экономика тарифа. Реплика при лимите: «Мозгу нужен отдых. Это тоже урок.»
5. **Персона сдержанная.** Криптик не хвалит просто так («Не расслабляйся»), не сюсюкает, шутит сухо. Мы опасались, что «весёлый маскот» подорвёт доверие к серьёзному курсу.
6. **Оффлайн-эквивалентность.** Всё учебное (подсказки, база книг, Python-наставник) работает без сети; AI-сервис — только обогащение.

## 4. Наши сомнения (что уже болит)

- **«Страх остаться одному» снимается ли?** Ученик ошибается в 03:00 в тренажёре — получает реплику из 5 слов. Этого может быть мало: нет ни «ты не первый», ни нормализации ошибки историями из книг (хотя кейсы в базе есть!).
- **Панель спрятана.** Кнопка «🤖 М.» — только в полноэкранном ридере. В тренажёре, где реально сложно, — наставника нет.
- **Сократовские подсказки привязаны только к психологии.** В математике/FT/Py — их нет (кроме Python-песочницы). А страх «я тупой» сильнее всего именно на математике.
- **F1 Фейнман в оффлайне — заглушка по длине текста.** Демо-режим помечен честно, но ощущение «меня оценила машина по длине» может быть хуже, чем отсутствие оценки.
- **Реплики случайные без сида** — при повторной ошибке может выпасть та же фраза (ощущение «залипшей пластинки»).
- **Профиль используется слабо:** «слабые зоны» влияют только на сортировку атомов. Нет «Криптик помнит, что тебе тяжело давалась П12» в явном виде.

## 5. Что мы просим

### 5.1. Формат сдачи — карточки (как в ТЗ-4)

Оцените и предложите улучшения **карточками**, каждая карточка:

```
ID: KR-<NN>
Точка: <тур | панель урока | квизы | психо-подсказки | Python | живой слой | персона/тон | память>
Проблема: <что сейчас не работает на усвоение/одиночество>
Предложение: <что конкретно изменить/добавить>
Тип: <контент (тексты/банки реплик) | структура (куда встроить) | движок (алгоритм) | AI-промпт>
Слабая модель: <как это будет работать на слабой модели — см. 5.3>
Приоритет: <P0/P1/P2> и ожидаемый эффект
```

### 5.2. Два фокуса анализа

1. **Усвоение материала.** Помогает ли каждая из 7 точек (§1) понять и запомнить? Где Криптик должен вмешиваться раньше (до ошибки), где молчать? Как использовать «память слабых зон» для адресных повторений? Нужен ли переход «подсказка → микрозадание → возврат в урок»?
2. **Страх остаться одному со сложной темой.** Что должен делать наставник в момент, когда ученик третий раз заваливает аттестацию / залип на математике / бросил курс на 2 недели? Какие реплики/механики дают «ты не один, это нормальный этап» (у вас в 15 книгах есть кейсы и нормализация ошибок — как их доставить вовремя)? Отдельно: ночь, мобильный, только что проснулся от уведомления бота.

### 5.3. Жёсткие требования (слабая AI-модель)

- **Максимум ~500 токенов ответа**, простые инструкции, структура JSON-вердиктов уже есть — предлагайте форматы, а не «пусть модель порассуждает».
- Длинные объяснения должны быть **заготовками** (контент), а не генерацией: модель выбирает/подставляет, а не пишет с нуля.
- Диалоги «в несколько ходов» — только как цепочка заготовок; свободный мульти-тик запрещён.
- Любое предложение должно указывать фолбэк без сети (локальная заготовка/детерминированная ветка).
- Порог качества: если слабая модель вернула мусор — ученик должен получить заготовку, а не мусор (как проверять — предложите).

### 5.4. Вопросы, на которые ждём явные ответы

1. Персона: текущий тон (сухой, слегка ироничный) — оставить или смягчить для «одиночества»? Где граница между «инструктор» и «друг»?
2. Куда встроить «экраны отчаяния»: (а) 3 провала аттестации подряд, (б) возврат после 7+ дней паузы, (в) ночное уведомление? Что там должен говорить/делать Криптик?
3. Сократовские подсказки в математику и FT: да/нет, и если да — откуда брать «принципы» (в базе только психология)?
4. «Проверка Фейнмана» на слабой модели: какой минимальный честный вердикт она может дать? Может, заменить на чек-лист самопроверки + модель только собирает gaps из заготовок?
5. Реплики: расширить банк? добавить «нормализацию ошибки» (кейс из книги в 1 строку)? сид для неповторения?
6. Должен ли Криптик инициировать контакт сам (сейчас — только реакция)? Где границы, чтобы не превратиться в попап-спам?
7. Память: что ещё запоминать и где показывать («я помню, что тебе тяжело даётся…»)?

### 5.5. Ограничения (что НЕ просим)

- Не просим менять маскота/арт (лендинг закрыт отдельной спекой).
- Не просим «мульти-агентов» и голосовой интерфейс.
- Не просим ломать принципы §3 (честность, запрет советов, лимиты, оффлайн-эквивалентность) — если предложение конфликтует, укажите это явно.
- Код не нужен. Промпты — можно (как тексты).
