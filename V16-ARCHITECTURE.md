## 0. Диагноз: почему «шампур» дальше нельзя

1. **Инструментный порог пройден.** Grep по 8 МБ ненадёжен; файл не читается целиком; каждая правка —
   скрипты `html.find()` + скобочный баланс (`scripts/patch_*.py`, `apply_*.py`). Стоимость правки растёт с объёмом.
2. **Слои-заплатки.** `patchMathIntegration` поверх старого `mountMathWidget`; баг фильтра префикса `widget_m_`
   (18 виджетов **молча** не монтировались — нашлось только рантайм-тестом); исторический кейс 34 невидимых уроков
   Ф1–Ф5 (рендерер не умел старые типы блоков). Монолит прячет такие вещи.
3. **7 контейнеров уроков × 4 механизма привязки виджетов** (карта, `scripts/build_lesson_widget_map.py`):
   блоки `interactive_*` в JSON уроков · ATT-массивы (c2/c2b/v4) · CN_W2-attach с тернарниками ·
   рантайм-`attachMathWidgets` (const MAP, 22 урока). Каждый новый интерактив = решение «через какой из четырёх
   механизмов его втыкать».
4. **Параллельная работа невозможна.** Один файл = один поток; конфликты при пуше уже случались дважды.
5. **Дрейф артефактов.** `saas/`-паки извлекаются из v9 — 178 уроков против 225 в v15.1 (отставание 47);
   v5.1→v15.1 — ~45 МБ снапшотов без читаемых диффов.

## 1. Почему «с нуля» — тоже ловушка

1. **Движок battle-tested**: 225 уроков, 256 интерактивов, 77 типов блоков, живой рынок+новости+наставник,
   Python-песочница (Pyodide+Worker), аркада. Переписать = месяцы повторной QA без защитной сетки.
2. **Миграция на ~80% уже случилась** — см. §2: контент давно живёт вне монолита. «Собрать с нуля» опоздал:
   мы это уже делали по частям.
3. **Офлайн-однофайл — продуктовая фича** (desktop-билд `tools/build_desktop_exe.py` тоже на нём). При
   конвейере она сохраняется навсегда как один из таргетов сборки.
4. Большой взрыв = долгий запуск двух систем без защитной сетки. Вместо него — фазированная пересборка
   под golden-паритетом (§6).

## 4. Канон форматов (фаза 0 — формализовать де-факто существующее)

### 4.1. Урок (lessons.json/<id>.json)

Единый конструктор, покрывающий все 7 текущих контейнеров (LESSONS, MATH_LESSONS_SOURCE,
PY_LESSONS_BLOCK_A/BC, PSY_LESSONS+2, VIBECODING_LESSONS, FT):

```json
{
  "id": "ft04", "num": "FT-04", "module": "ft",
  "title": "…", "minutes": 12,
  "terms": ["stake_amount", "dry_run"],
  "blocks": [
    {"type": "concept", "text": "…"},
    {"type": "interactive_engine", "engine": "e2", "instance": "ft_config_basic", "title": "…"},
    {"type": "interactive_widget", "id": "widget_m_kelly_criterion", "title": "…"},
    {"type": "quiz", "questions": [ … ] }
  ],
  "quiz_normalization": "in-place"   // исторический баг: квиз в blocks vs lesson.quiz — нормализуется сборкой
}
```

- Типы блоков: существующие 77 + 2 новых: `interactive_widget` (прямой вызов `EXPERT_WIDGETS[id]`)
  и `interactive_engine` (двигатель + инстанс-JSON). **Это и есть механическое решение проблемы
  4 механизмов привязки** — все старые механизмы конвертируются сборщиком в эти два типа.
- Конвертация текстов из `content/01-lesson-texts/` → JSON: по карте §6.3 плана (правила переноса
  заголовков/таблиц/врезок в блоки). Один прогон скрипта, результат — ревью дифом.

### 4.2. Виджет (уже канонизирован ТЗ-2)

## 5. Конвейер сборки

```
build.mjs
  ├─ 1. Читает manifest/app.manifest.json (списки уроков/виджетов/двигателей/данных/банков)
  ├─ 2. Собирает LESSONS_* из content/lessons.json/ (конвертация канона → рантайм-массивы)
  ├─ 3. Конкатенирует engine/core → engine/widgets-legacy → engines (E1..E8, порядок из
  │     engines.manifest.json: Glossary/TouchToKnow/LangSwitch/Journal → E1 → E2 → мост → E3..E8)
  ├─ 4. Инлайнит content/data/*.json + widgets/*.js (EXPERT_WIDGETS) + банки
  ├─ 5. Вставляет всё в engine/shell.html в точки-маркеры
  ├─ 6. Прогоняет lint-content.mjs + quiz_lint.py (0 BLOCK) → иначе сборка падает
  └─ 7. Пишет dist/index_v16.html + dist/build.json (хэши, версии, счётчики)
```

- **Никаких бандлеров-трансформаций на старте** (esbuild опционально позже): чистая конкатенация
  сохраняет офлайн-однофайловость и нулевой порог отладки. Маркеры-точки вставки — те же `<script>`
  блоки №1..№40+, что в v15.1 (адресация по маркерам, не по номерам строк).
- **Один источник — два таргета** (см. §8): офлайн-файл и SaaS-паки собираются из одного
  `content/` + `manifest/`, «перенос в платный SaaS» становится опцией сборки.

### 5.1. Диспетчер — единая точка рендера интерактивов

Заменяет 6 параллельных точек (auto-render forEach в renderLessonDetail, ATT-массивы, CN_W2-attach,
attachMathWidgets const MAP, patchMathIntegration-обёртку, window.mountMathWidget):

```js
// engine/core/dispatch.js — ЕДИНСТВЕННЫЙ механизм
function renderInteractive(box, block, lessonId) {
  if (block.type === 'interactive_widget') {
    const w = window.EXPERT_WIDGETS[block.id] || window.MATH_WIDGETS[block.id];
    if (w) return w(box);
  }
  if (block.type === 'interactive_engine') {
    const e = window.ENGINES[block.engine];
    const instance = CONTENT_DATA[block.engine][block.instance];
    if (e && instance) return e.mount(box, instance, engineCtx(lessonId));
  }
  // fallback на legacy-рендер по типу блока (постепенно пустеет)
  return legacyRender(box, block);
}
```

T-4.7 (диспатчер для 48 виджетов ТЗ-2) и T-4.11 (двигатели) реализуются ЭТИМ механизмом —
в v16 не нужен отдельный патч приложения, диспатчер встроен в ядро.

## 6. Golden-паритет с v15.1 (защитная сетка пересборки)

**Принцип: «переезд» и «улучшение» — никогда в одном шаге. Паритет рендера — доказательство
безопасности фазы 1.**

1. **Эталоны:** agent-browser (headless) прогоняет v15.1: все 225 уроков открываются по id →
   DOM-снапшот каждого `lesson-detail` (нормализованный: без timestamp/анимаций) → `build/golden/v15.1/*.json`.
2. **Проверка:** тот же прогон на `dist/index_v16.html` → диф по каждому уроку.
   - Фаза 1 (чистый переезд): цель — **100% паритет** (допустимые отличия — только whitespace).
   - Фаза 2 (замена кода ТЗ-2 на виджеты эксперта): диф ОЖИДАЕМ в 48 виджет-блоках — паритет
     проверяется по остальным ~208 урокам + smoke нового виджета в харнессе.
   - Фаза 3 (двигатели в пустых уроках FT/FAI): диф ожидаем в 26 уроках (было «— ПУСТО»).
3. **Регресс-ликст** (уже существует в плане §8.2): вкладки, поиск, прогресс, помодоро, RAG-ментор,
   Граф знаний — smoke-скрипт по списку экранов.
4. **Карта покрытия перегенерируется** после каждой фазы (`scripts/build_lesson_widget_map.py`):
   статусы ✓/⟳/·/✍ мигрируют в «собрано»; карта остаётся источником истины покрытия.

Зерно инфраструктуры уже есть: `tools/verify_app_browser.mjs`, `tools/verify_quests_browser.mjs`,
smoke-харнесс виджетов, `agent-browser` CLI.

## 7. Интеграционные потоки (как вливать поставки эксперта дальше)

| Поставка | Куда ложится | Что делает агент |
|---|---|---|
| Тексты уроков (fable8+…) | `content/01-lesson-texts/<module>.md` + контент-пак (раздел N, дословно) | конвертация в `lessons.json/<id>.json` по §6.3 плана, ревью дифом |
| Спеки интерактивов (tz3-формат) | `content/02-interactives/tz3-specs/` или per-lesson файл | оценка → создание задачи реализации → двигатели/виджеты |
| Код виджетов (ТЗ-2-формат) | `content/02-interactives/widgets/W-XX__*.js` | node --check + харнесс + строка в manifest → сборка |
| Банки вопросов | `content/03-quizzes/*.md` | quiz_lint (0 BLOCK) → manifest |
| Инстансы-JSON двигателей | `content/data/<engine>/*.json` | lint-content.mjs → manifest |

**С этого момента ни одна поставка не требует хирургии на 8 МБ** — всё ложится файлами в `content/`
и подхватывается manifest'ом. Дуэль «git push» решается merge'ом файлов, а не 8-мегабайтного blob'а.

1. `saas/tools/extract-content.mjs` переключается с `../index.html` (v9!) на `content/lessons.json/`

   `tests` / `earning` — сохраняется, но теперь сигнализируется манифестом, а не regex-вырезанием
   из HTML. Brotli-бюджет ≤150KB/пак (§21.1) проверяется сборкой.
3. `content/data/` (инстансы двигателей) + `content/02-interactives/engines/` → отдельные паки
   `engines` и `data` (догрузка по требованию, гейтинг по тарифу).

   т.к. dist собирается тем же конвейером.

## 11. Почему это дешевле и быстрее обоих отвергнутых вариантов

- **Против «шампура»:** каждая из ~235 предстоящих единиц работы (131 текст + 48 виджетов + 71
  интерактив + 603 позиции + 8 двигателей) ложится файлом в `content/` и строкой в manifest —
  вместо операции на 8 МБ. Очередь T-4.7/T-4.9/T-4.11 превращается из «хирургии» в конвейер.
- **Против «с нуля»:** движок переносится как есть с паритет-доказательством (225/225); риски
  фазы 1 ≈ 0 (логика не меняется), фазы 2 — ниже любой текущей ручной правки монолита, потому что
  впервые под автотестами.
- **Бонус:** параллельная работа (агенты/эксперт/мы) без конфликтов; SaaS-миграция из «проекта»
  становится опцией сборки; исторические файлы v5.1…v15.1 остаются эталонами golden-тестов.
