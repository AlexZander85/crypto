# Детальные спецификации интерактивов О-3 и О-4
Документ для разработчика и методиста. Стандарт тот же, что для всех интерактивов трека: детерминированность (фиксированные наборы данных и seed'ы, никаких запросов к бирже), офлайн-работа, симулированные ряды с реальными датами только там, где это допущено (вопрос 8 первой версии). Тексты интерфейса — на русском; английские термины появляются только в глоссарии «Ткни в непонятное» в скобках и в именах полей для разработчика.

Общие требования к обоим интерактивам:

Первый прогон всегда на настройках по умолчанию (ползунки заблокированы до первого «момента истины»), чтобы ученик увидел базовый вывод до того, как начнёт «подкручивать».
Каждый интерактив пишет в журнал прогресса ученика набор событий (см. раздел «Что фиксируем» в каждой спецификации): они питают КП-ОВ и калибровку Brier.
Все числа, помеченные «проверить на дату», выносятся в отдельный конфиг-файл параметров (params_moex_options.json), чтобы обновлять их без правки логики.
Мобильная версия: таблицы сворачиваются в карточки; графики — не менее 320 px по ширине; анимации можно пропустить кнопкой.
Спецификация О-3 · «IV против RV: страховая компания за 20 кварталов»
1. Паспорт
Поле	Содержание
Урок	О3 «Опционные стратегии, которые может вести бот: карта и хищники»
Тип	стратегия-выбор (симуляция с предварительным прогнозом)
Заблуждение	«Подразумеваемая волатильность обычно выше реализованной — значит, продавать волатильность — стратегия с положительным ожиданием»
Что крутит ученик	выбор стратегии (3 варианта), лимит доли ГО под опционы, ключевая ставка, порядок кварталов (5 фиксированных перестановок)
Что видит	кривую капитала по кварталам с внутриквартальными «усами» просадки, гистограмму квартальных результатов, карточку метрик, сравнение с фондом ликвидности, сверку со своим прогнозом
Момент истины	без хеджа — кривая обгоняет ставку вдвое 19 кварталов и обнуляется в 20-м; с хеджем — результат ≈ ставка минус спред; покупка под события — жива, но ниже ставки; при этом IV была выше RV в 19 кварталах из 20
Данные	фиксированная таблица 20 кварталов (симуляция), профили шоков по образцу реальных дат
Мосты	П24 (индейка), 3.5 (дельта-нейтральность и её скрытые риски), Р9 (ставка как гравитация), О2 (ГО × IV-шок), Б6/Б10 (цена опциона ≈ цена доли исхода), М47 (Келли при редких крупных убытках)
Время	5–7 минут (первый прогон 3 мин, остальное — эксперименты)
2. Педагогическая задача
Ученик должен не «запомнить, что продавать волатильность опасно», а увидеть три вещи одновременно:

Факт, на котором держится заблуждение, — правда: премия за волатильность существует, IV > RV почти всегда.
Эта премия — не альфа, а плата за проданную страховку: одна выплата по страховому случаю съедает 19 квартальных взносов.
После вычета цены хеджа и хвоста «положительное ожидание» превращается примерно в ключевую ставку — третье воплощение идеи Р9.
Интерактив намеренно даёт ученику сначала спрогнозировать исход (Brier), затем показывает 19 «хороших» кварталов в анимации — чтобы он успел почувствовать соблазн «а ведь работает», и только потом 20-й.

5. Расчётная логика
Константы (в конфиге):

text

K0        = 1 000 000 ₽    # учебный капитал
g0        = 0.12           # базовое ГО стрэнгла как доля номинала
c_prem    = 0.065          # премия квартального стрэнгла ±15% как доля номинала на единицу IV
h_hedge   = 0.04           # цена дельта-хеджа за квартал на единицу RV (доля номинала)
gamma_res = 0.12           # остаточная (гамма) доля потерь у хеджированной позиции
strike_d  = 15             # удалённость страйков, %
prem_ev   = 0.04           # премия одного событийного стрэддла как доля выделенного капитала
m_calm    = -0.30          # исход события без сюрприза (тета + схлопывание IV)
m_K5      = +0.80          # событие отчётностей в К5
m_K13     = +2.50          # заседание ЦБ в К13
Для каждого квартала q при текущем капитале стратегии K_q, лимите L и ставке r:

text

A   = L * K_q                       # капитал под опционы
N   = A / g0                        # номинал проданных стрэнглов (переоценивается каждый квартал)
P   = c_prem * IV0 * N              # полученная премия
Rf  = (1 - L) * K_q * r / 4         # доход свободного остатка в фонде ликвидности

# --- А: без хеджа ---
C_peak = P * k_IV * (1 + (J_max/strike_d)^2)         # стоимость закрытия в худшей точке
G_peak = g0 * N * k_GO * sqrt(k_IV)                  # требование ГО в худшей точке
MC     = (C_peak - P + G_peak) > K_q                 # маржин-колл всего счёта
если MC:  PnL_opt = P - C_peak                        # принудительное закрытие в худшей точке
иначе:    PnL_opt = P - max(0, (|J_end| - strike_d)/100) * N
K_{q+1} = max(0, K_q + PnL_opt + Rf)                 # при 0 — надпись «и долг брокеру» (учебно)

# --- Б: с хеджем ---
H        = h_hedge * RV * N
C_peak_h = P * k_IV * (1 + gamma_res * (J_max/strike_d)^2)
G_peak_h = 0.6 * G_peak                                # неттинг с фьючерсом (упрощение)
MC       = (C_peak_h - P + G_peak_h) > K_q
если MC:  PnL_opt = P - C_peak_h - H/2
иначе:    PnL_opt = P - H - P*(k_IV - 1)*0.5 - gamma_res * max(0, (|J_end| - strike_d)/100) * N

# --- В: покупка под события ---
события квартала: [ЦБ1, ЦБ2, отчётности], множители m_e из таблицы (по умолчанию m_calm)
PnL_opt = A * prem_ev * Σ m_e                          # внеплановые шоки не дают позиции
MC      = ложь
Внутриквартальный «ус» на графике: для А и Б — точка K_q - (C_peak - P) (или C_peak_h); для В не рисуется.

Отчётные метрики считаются по массиву квартальных PnL в процентах от K_q; бенчмарк — K0 * (1 + r/4)^20.

Стратегия «перемешать кварталы»: применяется та же таблица в другом порядке; для стратегии В календарь событий переезжает вместе с кварталом.

6. Контрольные значения (приёмочные тесты)
При настройках по умолчанию (L = 25%, r = 16%, исходный порядок):

IV₀ > RV ровно в 19 кварталах из 20.
Стратегия А: капитал после К19 ≥ 2,0·K0; после К20 = 0; маржин-колл в К20; доля прибыльных кварталов 19/20; максимальная просадка 100%.
Стратегия А по лимиту: при L = 10% маржин-колла в К20 нет (квартал −40…−48%); при L ≥ 15% — маржин-колл.
Стратегия Б: маржин-коллов нет при L ≤ 50%; итог за 20 кварталов в диапазоне 0,90–1,15 от бенчмарка ставки; худший квартал К20 в диапазоне −10…−16%; при L = 100% — маржин-колл в К20.
Стратегия В: маржин-коллов нет ни при каком L; итог ниже бенчмарка на 25–45 п.п.; лучший квартал К13; в К9 и К20 результат событийной части ≤ 0.
Перестановка с шоком на позиции 3: капитал А обнуляется в 3-м квартале и линия дальше идёт горизонтально по нулю (не «восстанавливается» за счёт ставки — маржин-колл забрал весь счёт).
При r = 7%: стратегия Б обгоняет бенчмарк; при r = 21% — уступает (проверка «гравитации» Р9).
Отсутствие любых обращений к сети; повторный запуск с теми же настройками даёт побайтово тот же результат.
Разработчик калибрует константы c_prem, h_hedge, gamma_res только в пределах, при которых выполняются все восемь тестов; отклонения фиксируются в журнале изменений интерактива.

7. Что фиксируем в прогрессе ученика
o3.forecast = {p1, p2, p3}; o3.brier; o3.first_run = {strategy, L, r, result_vs_benchmark, margin_call_quarter}; o3.runs_total; o3.shuffle_used (да/нет); o3.limit_explored (минимальный и максимальный L, который пробовал); время до момента истины. Поля o3.brier и o3.forecast.p1 используются в КП-ОВ для сравнения калибровки «до урока / после».

8. Что сознательно не моделируем (текст для блока «Честные упрощения» в интерфейсе)
Вариационная маржа начисляется в модели один раз за квартал (в жизни — два клиринга в день, Р6).
Премия не зависит от ставки и базиса (в жизни зависит слабо; для учебной цели пренебрегаем).
Греки не считаются явно: гамма и вега свёрнуты в множители k_IV и gamma_res (О2 даёт их как «датчики»).
Комиссии биржи и брокера включены в h_hedge; отдельно не показываются (Р5).
Налоги не учитываются (Р14).
Множители ГО и профили шоков — учебные; реальные диапазоны решений биржи — «проверить на дату».
9. Глоссарий «Ткни в непонятное» для экранов О-3
Подразумеваемая волатильность (implied volatility, IV) — волатильность, «зашитая» в цену опциона: сколько движения рынок готов оплатить. Реализованная волатильность (realized volatility, RV) — сколько движения случилось на самом деле. Стрэнгл (strangle) — одновременная продажа (или покупка) пута ниже рынка и колла выше рынка. Дельта-хедж (delta hedge) — позиция во фьючерсе, компенсирующая направленный риск опционной позиции. Гарантийное обеспечение (ГО) — см. Р6. Маржин-колл (margin call) — см. Р7. Стрэддл (straddle) — покупка пута и колла на одном страйке: ставка на движение без направления. Тета (theta) — см. Б5.

2. Педагогическая задача
Ученик уже умеет валидировать свечи (2.6) и знает про выживших (Р8). Здесь ему нужно пережить три специфически опционные ловушки руками:

Инструмента «опцион» не существует — существует серия × страйк, живущая недели и исчезающая. Доска на дату собирается, а не скачивается.
Большинство строк на доске — фантомы: последняя цена месячной давности, ноль сделок за неделю, нет встречной заявки. Бэктест «по последней цене» исполняет сделки в пустоте.
Кривая волатильности — тоже данные с датой: «пересчитанная сегодня» версия содержит будущее, и утечка невидима 95% дней.

4. Модель данных архива
Каждый файл страйка — таблица по дням: дата, последняя_цена, сделок, объём_контрактов, ОИ, лучшая_покупка, лучшая_продажа, теор_цена_биржи.

Правила генерации (детерминированные, seed = хеш кода инструмента):

Интенсивность сделок в день: λ = λ0 · exp(−|m| / 0,06), где m — денежность (страйк/спот − 1); λ0: квартальные 60, месячные 25, недельные 15. Число сделок в день — из таблицы Пуассона по seed. Если сделок 0 — последняя_цена переносится с предыдущего дня (так и делают выгрузки), а поле дата_последней_сделки (вычисляемое) остаётся старым.
Половина спреда как доля теоретической цены: s = 0,03 + 0,40·|m|; при |m| ≥ 0,20 с вероятностью 0,6 (по seed) лучшая покупка отсутствует (пусто) — «нет встречной заявки».
Теоретическая цена биржи считается по кривой волатильности на дату (ниже) и модели цены опциона; конкретная формула — Блэка (для фьючерсных опционов), ставка 0 (упрощение, отмечено).
Открытый интерес: растёт при листинге, падает к экспирации; для страйков с |m| ≥ 0,25 — единицы контрактов.
Период 25.02–23.03: строк нет ни в одном файле (не нули, а отсутствие строк — как в реальных выгрузках).
Кривая волатильности на дату d: σ(m; d) = σ_atm(d) + skew(d)·(−m) + curv·m², curv = 1,2. Параметры по дням: спокойные дни σ_atm 0,24, skew 0,35; с 01.02 нарастание до Д2: σ_atm 0,38, skew 0,55; 22.02: 0,42 / 0,60; 23.02: 0,55 / 0,70; 24.02: 1,10 / 0,90; 24.03 и далее: 0,80 → 0,45 за три недели.

Две версии в архиве:

кривая_на_дату — параметры дня d, как публиковались вечером дня d.
кривая_пересчитанная — те же параметры, сглаженные центрированным скользящим окном ±3 торговых дня (как «удобно построил поставщик данных сегодня»). На Д1 обе кривые совпадают (разница < 0,5 п.п.); на Д2 пересчитанная имеет σ_atm ≈ 0,53 и skew ≈ 0,68, потому что в окно попали 22, 23 и 24 февраля.
Три «источника данных», между которыми переключается ученик:

И1 · «Полный архив по датам» — всё вышеописанное.
И2 · «Выгрузка “ликвидные страйки”» — из архива удалены файлы страйков, у которых за всю историю файла меньше 40 сделок (фильтр применён по всей истории — отбор по будущему). Практически исчезают все путы с |m| ≥ 0,20 — именно те, что стали историей февраля.
И3 · «Выгрузка “инструменты, обращающиеся сегодня”» — в ней нет ни одной серии 2021–2022: все истекли.

Два правила цены исполнения и переоценки:

Ц1 · «По последней цене файла» — вход по последняя_цена, ежедневная переоценка по последняя_цена; в дни без строк — переносится предыдущая.
Ц2 · «Честное исполнение» — вход только если в этот день были сделки и есть лучшая покупка; цена входа = лучшая покупка; переоценка по теор_цена_биржи на дату; в дни приостановки — переоценка по последней опубликованной кривой (24.02); расчёт серии на экспирацию — по цене ФИ первого дня после возобновления (учебное допущение, помечено).

Экран 4 · «Кривая волатильности: на дату или пересчитанная?»

Два графика-«улыбки» для Д2 (ось X — денежность от −30% до +15%, ось Y — IV). Переключатель «Показать те же кривые на Д1» — они совпадают. Текст: «На 47 из 50 дней окна две кривые неотличимы. Посмотри на Д2».

Вариант стратегии с фильтром риска: «Продавать пут, только если IV на центральном страйке на дату входа ниже 45%; иначе — пауза». Ученик выбирает кривую для бэктеста (радио) и запускает:

На кривой «на дату»: 15.02 IV_atm = 34% → вход → результат −55…−65%.
На кривой «пересчитанной»: 15.02 IV_atm (окно захватывает 18.02) = 41% → вход; но при выборе даты входа 21.02 (переключатель «сдвинуть вход на Д2») пересчитанная даёт 53% → пауза → результат +6…+9% (только декабрь).
Чтобы момент истины не зависел от того, попал ли вход в окно, интерактив всегда показывает обе даты входа (15.02 и 21.02) двумя строками. Итог: «Разница результата между кривыми — до 70 п.п. Ничего из неё не заработано на рынке: пересчитанная кривая “знала” о 24 февраля, потому что окно сглаживания ±3 дня включало 24 февраля. Это п. 4 из списка утечек урока 1.7 — центрированное окно — в опционном костюме».

Контрольный вопрос (одиночный выбор, фиксируется в журнале): «Какая кривая допустима в бэктесте?» — «на дату» (верно) / «пересчитанная, она точнее» / «любая, разница мала». Обратная связь на второй вариант: «Точнее — потому что видела будущее. Точность из будущего в бэктесте называется утечкой».

Финальная плашка: «Три правила для валидатора опционных данных (дополнение к 2.6): доска собирается на дату из листингов и экспираций; страйк торгуем только при сделках и встречной заявке в этот день; любая кривая волатильности имеет дату публикации, и в бэктест идёт только она».
