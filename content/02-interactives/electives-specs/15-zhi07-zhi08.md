# Спецификации интерактивов ЖИ‑7 «183 дня» и ЖИ‑8 «Конструктор маршрута года»

Для агента-разработчика. Формат — как для П‑блока: назначение → педагогическая механика → входы/выходы → экраны и состояния → расчётные правила → тексты → данные → приёмочные тесты. Общая часть вынесена в начало, потому что оба интерактива работают на одной модели данных и одной таблице учебных констант.

---

## 0. Общее для обоих интерактивов

### 0.1. Политика честности (не обсуждается)

1. **Ни одного названия страны, банка, программы, визы, площадки.** Страны — только «тип А / тип Б / тип В» + пользовательская метка вида «Страна 2». Статусы — только три категории: *краткосрочный въезд / долгосрочный статус по основанию / постоянный статус*.
2. **Плашка‑дисклеймер** показывается (а) модальным окном до первого запуска, (б) постоянной полосой на экране результата. Формулировка дословно из 4.6:
   > **Учебный контур.** Правила стран, налогов и виз меняются; проверяй на дату первичный источник. Это не замена консультанту.
   Для ЖИ‑7 добавляется вторая строка: «Правила подсчёта дней и пороги — проверить на дату.»
   Для ЖИ‑8: «Условия статусов, сроки краткосрочного пребывания, требования банков — проверить на дату.»
3. **Все числа — учебные константы**, вынесены в один конфиг (0.3) с пометкой ⏱. Редакция обновляет конфиг раз в год (ежегодный ревью Модуля Б), без правки кода.
4. **Домашняя страна.** В интерактивах есть слот «Дом» — это страна типа А с порогом 183 дня по итогам календарного года (опора на 4.6). Слово «Россия/РФ» в интерфейсе не используется, кроме ссылки «см. урок 4.6». Ссылки на конкретные статьи и ставки — только через переход в 4.6, не дублируем.
5. **Стоп‑слова трека** («пассивный доход», «финансовая независимость», «жить на проценты») в текстах не встречаются. Выходной тон — «оператор с зарплатой».

### 0.2. Общая модель данных `StayProfile`

Создаётся в ЖИ‑7, дополняется в ЖИ‑8, читается чекпоинтом ЧП2 и конструктором устава ЖФ (раздел 5 «Налоговый календарь»).

```ts
type CountryType = 'A' | 'B' | 'V';
// A — облагает резидента по всему миру
// B — только доход из местных источников
// V — без подоходного / спецрежим для новых резидентов

type TreatyState = 'active' | 'suspended' | 'unknown'; // соглашение об избежании двойного налогообложения с Домом

interface CountrySlot {
  id: string;            // 'home' | 'c1' | 'c2' | 'c3' | 'c4'
  label: string;         // 'Дом' | 'Страна 2' … (генерируется системой, пользователь может переименовать — см. 0.4)
  type: CountryType;     // для 'home' всегда 'A', не редактируется
  isHome: boolean;
  color: string;         // из фиксированной палитры (6 цветов + серый «не указано»)
  treaty: TreatyState;   // только для type A, по умолчанию 'unknown'
  hasBankAccount: boolean; // в этой стране открыт/планируется счёт
}

interface StayProfile {
  version: 1;
  year: number;                  // календарный год, по умолчанию текущий
  slots: CountrySlot[];          // 1 home + до 4 стран
  weeks: (string | null)[];      // ЖИ‑7: id слота на каждую неделю года или null («не указано»)
  bases?: Base[];                // ЖИ‑8: см. раздел 2.4
  family?: FamilySnapshot;       // из ЧП1: дети (возраст), выбранная категория школы
  createdAt: string; updatedAt: string;
}
```

Хранение: в профиле ученика (как остальные артефакты чекпоинтов). Экспорт: JSON + читаемая «Карточка» (см. 1.8 и 2.8).

### 0.4. Правила для меток стран

- По умолчанию: «Дом», «Страна 2», «Страна 3», «Страна 4», «Страна 5». Тип выбирается переключателем А/Б/В с подсказкой в одну строку под каждой буквой.
- Переименование разрешено (до 12 символов), поле сопровождается подписью: «Без названий стран — это учебная модель. Годится “Море”, “Горы”, “У бабушки”.» Валидации на названия стран не делаем (список не ведём), но в подсказке говорим прямо.
- Палитра фиксированная, цвета различимы при дальтонизме (проверить на симуляторе deuteranopia), к цвету всегда добавляется буква типа в ячейке (А/Б/В/Д).

### 0.5. Общие UX‑требования

- Мобильный первый экран: сетка ЖИ‑7 читаема при ширине 360 px (см. 1.5).
- Полная работа с клавиатуры: ячейки — фокусируемые, стрелки перемещают, пробел красит выбранным цветом, цифры 1–5 выбирают цвет.
- `aria-live="polite"` на панели результата: смена статуса озвучивается текстом флага.
- Никаких таймеров и анимаций, влияющих на результат. Анимация допустима только как подсветка изменившегося флага (300 мс).
- Автосохранение черновика в профиль каждые 5 сек при изменениях.

### 0.6. Аналитика (события)

`life_zhi7_open`, `life_zhi7_disclaimer_ack`, `life_zhi7_scenario_stamped` (ага‑момент сработал), `life_zhi7_status_flip` (payload: from, to, delta_days), `life_zhi7_saved`, `life_zhi7_task_done` (task_id), аналогично `life_zhi8_*` + `life_zhi8_preset_run`, `life_zhi8_lamp_change` (lamp, from, to), `life_zhi8_route_saved`.

## 1. ЖИ‑7 «183 дня» — календарь‑раскраска (урок Ж6)

### 1.1. Назначение

Сломать заблуждение «уехал — значит нигде не плачу» и его зеркало «я примерно помню, сколько был дома». Ученик своими руками убеждается, что резидентство — это счётчик дней, что счётчик хрупок (одна неделя переворачивает статус), что «нигде не резидент» — не лазейка, а красный флаг для банков (мост в Ж8), и что у стран типа А вопрос может встать и раньше 183 дней.

Тип: калькулятор‑раскраска. Сложность: средняя. Не оценивается баллами — оценивается выполнением трёх учебных задач (1.7).

### 1.2. Что ученик делает (сценарий за 6–8 минут)

1. Читает дисклеймер, подтверждает.
2. **Сцена «Алексей на глаз»** (предзаполнено): календарь уже раскрашен так, что Дом = 170 дней. Панель показывает «Дом: 170 дней — нерезидент по итогам года, до порога 13 дней». Кнопка **«Сверить со штампами»**.
3. Нажимает — три недели перекрашиваются на «Дом» (две недели «отпуска у моря» оказались отменёнными, одна неделя «командировки» — на самом деле дома, между поездками). Счётчик становится 191. Статус переворачивается: «резидент, запас 8 дней — хрупкий». Появляется карточка ага‑момента (текст в 1.9).
4. Далее — режим «Мой год»: чистый календарь или копия сцены (на выбор). Ученик задаёт свои страны и красит.
5. Выполняет три учебные задачи (1.7) — каждая закрывается автоматически, когда на экране возникает нужная конфигурация.
6. Сохраняет профиль — это заводит «календарь дней резидентства» для ЧП2 и передаёт слоты в ЖИ‑8.

### 1.3. Входы

- Год (селектор, по умолчанию текущий; влияет только на длины первой/последней неполной недели и високосность).
- Слоты стран: «Дом» (фиксирован, тип А) + до 4 стран (тип А/Б/В, метка, для типа А — состояние соглашения `treaty`: «действует / приостановлено / не знаю», по умолчанию «не знаю»; чекбокс «здесь есть/будет счёт в банке»).
- Раскраска недель: клик/тап/протяжка мышью или пальцем по ячейкам; повторное нажатие тем же цветом стирает («не указано»).
- Режим детализации (кнопка «уточнить дни» на неделе): раскрывает 7 ячеек‑дней внутри одной недели. Нужен для граничных недель и для честности «день въезда и день выезда считаются» — но ага‑момент строится на недельной сетке, и детализация не обязательна.

### 1.4. Сетка

- 12 строк = месяцы; в строке — недели, пересекающие месяц (4–6 ячеек). Неделя, попадающая в два месяца, показывается в обеих строках, но это **одна** ячейка данных (раскрашивается синхронно). Подпись ячейки: число понедельника. Неполные крайние недели года помечены количеством дней («3 дн»).
- Итоговое число дней в году всегда равно 365/366; дни «не указано» выводятся отдельной строкой.
- Инструмент «залить диапазон»: клик по первой ячейке, Shift+клик по последней (на тач — долгое нажатие → «до какой недели?»).

### 1.5. Мобильная раскладка

Строка месяца — горизонтально прокручиваемая не должна быть; ячейка минимум 40×40 px, 6 ячеек + подпись месяца укладываются в 360 px при отступах 4 px. Палитра — прилипающая внизу экрана. Панель результата — под сеткой, сворачиваемая в «пилюлю статуса» (одна строка: «Дом: 191 дн · резидент · запас 8 дн ⚠»), прилипающую вверху при прокрутке.

### 1.6. Расчёт и флаги

Дни по слоту `d[slot] = Σ длина недели` (для детализированных недель — по дням). `unassigned = yearDays − Σ d`.

**Блок «Дом»**

| Условие | Уровень | Текст (кратко; полные тексты в 1.9) |
|---|---|---|
| `d.home ≥ 183` и `d.home − 183 ≥ safeMargin` | зелёный | «Резидент по итогам года. Запас N дней.» |
| `d.home ≥ 183` и запас `< safeMargin` | жёлтый | «Резидент, но запас всего N дней. Одна отменённая поездка ничего не сломает, одна лишняя — сломает.» |
| `|d.home − 183| < fragileDays` (по обе стороны) | доп. метка «ХРУПКО» | «Статус меняется от одной недели.» |
| `d.home < 183` | красный (для Дома — это не «плохо», это «другой набор правил») | «Нерезидент по итогам года. До порога не хватает N дней. Что меняется — см. 4.6 (ставка, вычеты, спецбаза по цифровой валюте).» |
| `unassigned > 0` | серый предупреждающий | «N дней не раскрашены. В жизни они тоже где‑то прошли — статус ниже считается с оговоркой.» |

**Блок «Другие страны» (по каждому слоту)**

| Тип | Условие | Уровень | Текст |
|---|---|---|---|
| А | `d ≥ 183` | красный | «Набрано N дней. По учебному порогу это уже вопрос резидентства в стране типа А.» |
| А | `attention ≤ d < 183` | жёлтый | «N дней. В ряде стран типа А резидентство считают не только по дням: жильё, семья, центр интересов. Вопрос может встать раньше 183.» |
| А | `d ≥ attention` и `treaty = 'suspended'` | усиление до красного | «Соглашение с Домом приостановлено — двойной учёт дохода возможен. ⏱ Перечень приостановленных соглашений — проверять на дату.» |
| А | `d ≥ attention` и `treaty = 'unknown'` | доп. строка | «Не знаешь, действует ли соглашение с Домом? Это первое, что проверяется. ⏱» |
| Б | любой `d` | инфо | «Тип Б облагает доход из местных источников. Вопрос здесь не “сколько дней”, а “откуда доход”: если ты работаешь оттуда — источник может считаться местным.» |
| В | любой `d` | инфо | «Тип В: без подоходного или спецрежим. Обычно требует статуса и своих условий — это территория Ж7. ⏱» |
| любая | `hasBankAccount` и Дом = резидент | жёлтый | «Счёт в этой стране + резидентство Дома = обязанность уведомлять/отчитываться о зарубежном счёте. ⏱ Формы и сроки — на дату. См. 4.6.» |

**Сводные флаги (верх панели, вычисляются после блоков)**

1. **«Нигде»**: Дом < 183 **и** ни одна страна типа А не достигла 183 → красный: «Нигде не набрано 183 дней. Для налоговой это не лазейка: вопрос переедет на другие критерии. Для банков (Ж8) это “непонятный клиент” — ожидай вопросов и ограничений.»
2. **«Двойное резидентство — риск»**: Дом ≥ 183 **и** есть страна типа А в жёлтой/красной зоне → жёлтый: «Дом считает тебя резидентом по дням, а Страна N может посчитать по центру интересов. Так возникает двойное резидентство.»
3. **«Чисто»**: Дом ≥ 183 с запасом, ни одной страны А в зоне внимания → зелёный: «Статус понятен и устойчив. Заведи учёт дней — и держи его таким.»
4. **«Хрупко»** — см. выше, поднимается наверх, если есть у любого слота.

Приоритет вывода наверху: Нигде > Двойное > Хрупко > Чисто.

### 1.7. Учебные задачи (закрываются автоматически)

Отображаются как три карточки справа/снизу; выполненная — зелёная галочка с датой.

| № | Формулировка для ученика | Условие закрытия |
|---|---|---|
| З1 «Устойчивый Дом» | «Проведи не меньше 20 недель вне Дома и останься резидентом Дома с запасом ≥ 14 дней.» | `Σ d[не home] ≥ 140` и `d.home − 183 ≥ 14` и `unassigned = 0` |
| З2 «Нигде» | «Собери год, в котором ты нигде не набрал 183 дня, и прочитай, что скажет банк.» | сработал флаг «Нигде» и `unassigned = 0` |
| З3 «Двойное» | «Останься резидентом Дома и одновременно зажги жёлтую зону в стране типа А.» | сработал флаг «Двойное резидентство» |

Урок Ж6 считается пройденным по интерактиву, если: дисклеймер подтверждён, ага‑момент сцены сработал (`scenario_stamped`), закрыты З1 и хотя бы одна из З2/З3, профиль сохранён.

### 1.8. Выходы и артефакты

**Карточка «Календарь дней» (для ЧП2 и ЖФ, раздел 5):**
- Год; таблица «страна — тип — дней — статус/флаг»; сводный флаг; запас/дефицит дней Дома.
- Поле «Где веду учёт дней» (выбор категории, обязательное для сохранения в ЧП2): «таблица», «приложение‑счётчик», «фото штампов + таблица», «календарь с отметками». Без брендов.
- Поле «Кто ведёт» (оператор / партнёр / оба) — уходит в Семейный устав.
- Блок «⏱ Проверить на дату» — генерируется из конфига: порог дней, ставки и вычеты (ссылка 4.6), перечень приостановленных соглашений, формы и сроки уведомлений о счетах и цифровой валюте.
- Блок «Что упрощает этот калькулятор» (обязательный, сворачиваемый):
  - считает по календарному году; для удержаний в течение года встречается счёт по 12 скользящим месяцам;
  - недельная раскраска округляет; день въезда и выезда обычно считаются днями в стране — уточняй детализацией;
  - краткие поездки на лечение/обучение в ряде правил не прерывают срок — здесь не моделируются;
  - страны типа А различаются критериями (дни / центр интересов / жильё) — здесь одна учебная зона внимания.

Экспорт: кнопка «Скачать карточку» (PDF/печать) и «Передать в Конструктор маршрута» (открывает ЖИ‑8 с этими же слотами).

### 1.9. Тексты (готовые строки)

- Заголовок: **«183 дня: покрась свой год»**
- Подзаголовок: «Резидентство — это не ощущение “я в основном дома”. Это счётчик. Покрась недели — и увидишь, что он показывает.»
- Кнопка сцены: «Сверить со штампами»
- Карточка ага‑момента после сверки: **«170 → 191. Три недели, о которых ты забыл.»** «На глаз было 170 и “уехал — значит не резидент”. По штампам — 191: две отменённые поездки и одна командировка, оказавшаяся дома. Разница — набор правил на весь год (см. 4.6). Учёт дней ведут не для налоговой — для себя.»
- Подсказка при первой раскраске: «Кликни цвет, потом веди по неделям. Повторный клик тем же цветом стирает.»
- Подсказка к типам: «А — облагает резидента по доходу отовсюду. Б — только по доходу из своих источников. В — подоходного нет или спецрежим для новых резидентов.»
- Пустое состояние результата: «Раскрась хотя бы одну неделю — счётчик оживёт.»
- Полоса результата (постоянная): дисклеймер 0.1 + «Правила подсчёта дней и пороги — проверить на дату.»

### 1.10. Состояния и ошибки

- `disclaimer_pending → scenario → free → saved`. Возврат из `free` в `scenario` разрешён кнопкой «Показать сцену снова» (не стирает пользовательский календарь — сцена открывается во вкладке).
- Попытка сохранить с `unassigned > 0`: мягкое подтверждение «N дней не раскрашены. Сохранить как черновик?» — черновик не засчитывается в ЧП2.
- Более 5 слотов — кнопка «добавить страну» скрывается с подписью «В учебной модели до четырёх стран кроме Дома. Больше баз в год — уже тема Ж9 (сон и переезды).»

### 1.11. Приёмочные тесты

1. Год 2027: сумма дней по слотам + не указано = 365; 2028 = 366.
2. Сцена: до сверки `d.home = 170`, статус «нерезидент, не хватает 13»; после — `191`, «резидент, запас 8», метка «ХРУПКО», событие `status_flip {from:'non', to:'res', delta:21}`.
3. Дом = 183 ровно → «резидент», запас 0, «ХРУПКО», жёлтый.
4. Дом = 182 → «нерезидент», не хватает 1, «ХРУПКО».
5. Дом = 100, Страна 2 (А) = 200 → флаг Страны 2 красный, сводный «Нигде» **не** горит (порог набран в А‑стране), выводится «Резидентство по дням — в Стране 2».
6. Дом = 100, Страна 2 (А) = 150, Страна 3 (Б) = 115 → сводный «Нигде» горит, Страна 2 — жёлтая.
7. Дом = 200, Страна 2 (А) = 120, `treaty = suspended` → «Двойное» + усиление флага Страны 2 до красного.
8. Клавиатура: полный цикл раскраски без мыши; скринридер озвучивает смену сводного флага.
9. Мобильная 360 px: строка месяца без горизонтальной прокрутки.
10. Изменение конфига `home.residencyThresholdDays` → все тексты и расчёты подхватывают новое значение без правки кода.

## 2. ЖИ‑8 «Конструктор маршрута года» — треугольник‑лампочки (урок Ж7)

### 2.1. Назначение

Сломать «виза кочевника решает всё». Ученик собирает год из «баз» и видит, что каждая база одновременно трогает четыре вершины: **виза → дни → резидентство → банк**, плюс четвёртую, которую забывают, — **школу**. Главное умение на выходе: смотреть на переезд как на изменение всех лампочек сразу и делать «чек перед сменой базы».

Тип: конструктор с диагностикой. Сложность: средняя. Переиспользует `StayProfile.slots` и расчёт резидентства из ЖИ‑7 (одна функция `computeResidency(daysBySlot, config)` — не дублировать).

### 2.2. Что ученик делает (7–9 минут)

1. Дисклеймер.
2. **Пресет «Удобный маршрут»**: 6 месяцев Страна 2 (тип А, долгосрочный статус) + 6 месяцев Страна 3 (тип А, долгосрочный статус), Дом — 0. Ученик нажимает «Проверить маршрут». Лампочки: Виза — зелёная (оба статуса позволяют), **Резидентство — красная**: «Дом потерян (0 дней), Страна 2 — 181 день и Страна 3 — 184 дня: одна в красной зоне по дням, вторая в жёлтой по центру интересов, соглашения “не знаю”», Банк — жёлтый, Школа — красная (при выбранной очной) или жёлтая (онлайн). Карточка ага‑момента (2.9).
3. Задача «Почини минимальным числом правок» — ученик двигает границы баз/меняет статус, пока Резидентство не станет зелёным. Система считает число правок.
4. «Мой маршрут»: слоты подтягиваются из ЖИ‑7 (если есть), семья — из ЧП1. Ученик собирает свой год, читает панель «этот переезд трогает…», заполняет чек перед сменой базы, сохраняет.

### 2.3. Входы

- Слоты стран — из `StayProfile` (можно править на месте; правки синхронизируются обратно).
- Семья: `children: [{age}]`, `schoolCategory: 'onsite' | 'online' | 'home_cert' | 'none'` — из ЧП1/Ж11 или задаётся тут (если детей нет — вершина «школа» гаснет с подписью «в вашем маршруте не участвует», треугольник остаётся треугольником).
- Базы (2.4).
- Параметры краткосрочного въезда — глобальные из конфига, с возможностью переопределить на слот (поля «макс. дней подряд», «макс. дней за период») — каждое поле с меткой ⏱.

### 2.4. База

```ts
type StatusType = 'short' | 'long' | 'permanent';
type LongBasis = 'work' | 'child_study' | 'investment' | 'nomad' | 'family' | 'other';

interface Base {
  id: string;
  slotId: string;          // страна
  status: StatusType;
  basis?: LongBasis;       // только для 'long'
  startMonth: number;      // 1..12
  months: number;          // 1..12, базы не пересекаются; допустимы пустые месяцы = «не запланировано»
  cityBound?: boolean;     // статус привязан к городу (авто‑true для basis='child_study', редактируемо)
  givesAddress?: boolean;  // статус даёт официальный адрес (авто‑true для long/permanent, false для short)
  preMoveCheck: {          // чек перед сменой базы — заполняется вручную, не влияет на лампы
    exchangeAccessChecked: boolean;   // доступ к площадке с этой территории (4.3 IP‑белый список твоего доступа, гео‑ограничения; 5.7 запасная площадка)
    withdrawalChannelChecked: boolean; // канал вывода в этой базе (Ж8)
    schoolDatesChecked: boolean;      // даты аттестации/учебного года (Ж11)
    note?: string;
  };
}
```

Пересчёт в дни: по фактическим длинам месяцев года (`monthDays`). Дни без базы — «не запланировано», считаются нигде и попадают в предупреждение.

Таймлайн: 12 колонок‑месяцев; база — цветной брусок (цвет слота, буква статуса К/Д/П); края бруска тянутся за ручки; клик по бруску открывает карточку базы; кнопка «+ база» в пустом месяце. Мобильная версия: колонки по 26 px + горизонтальные ручки, карточка базы — нижняя шторка.

### 2.5. Лампочки: правила

Каждая лампочка имеет уровень (зелёный / жёлтый / красный / выкл.), заголовок‑диагноз и 1–3 строки причин. Треугольник рисуется с вершинами Виза (верх), Резидентство (низ‑лево), Банк (низ‑право); Школа — четвёртая точка внутри треугольника («вершина, которую забывают»), соединена пунктиром с Визой и Резидентством.

**Виза**

| Условие | Уровень | Диагноз |
|---|---|---|
| все базы укладываются в свои лимиты | зелёный | «Статусы позволяют такой маршрут (⏱ условия — на дату)» |
| база `short` длиннее `maxContinuousDays` | красный | «База N: краткосрочный въезд не рассчитан на M дней подряд. Нужен долгосрочный статус — или база короче.» |
| сумма `short`‑дней по одному слоту за год > `maxDaysPerPeriod` | красный | «Страна N: суммарно M дней по краткосрочному въезду за год. Повторный въезд не обнуляет счётчик.» |
| `short`‑база в пределах 15 дней от лимита | жёлтый | «База N подходит к лимиту вплотную: задержка рейса или болезнь — и лимит превышен.» |
| две `short`‑базы одного слота подряд с разрывом ≤ 1 месяц | жёлтый | «Выезд‑въезд ради обнуления — известный шаблон, который считают именно так, как он выглядит.» |
| `long` с `basis = child_study` и `months < school.onsiteMinMonths` | жёлтый | «Статус по учёбе ребёнка обычно требует учебного года; база короче.» |

**Резидентство** — вызывает `computeResidency` из ЖИ‑7 по дням из баз. Маппинг сводных флагов ЖИ‑7 на лампу: «Чисто» → зелёный; «Двойное» или «Хрупко» → жёлтый; «Нигде» или страна А в красной зоне при потерянном Доме → красный. Диагноз всегда содержит **где и какое**: «Дом: резидент (запас 21 день). Страна 2: 96 дней — жёлтая зона.» Здесь же строка про соглашения (`treaty`) как в ЖИ‑7.

**Банк** — считается по базам и резидентству, выводит «какого типа счёт реалистичен» по каждой базе и итоговый уровень.

| Ситуация базы | Тип счёта (учебная категория) |
|---|---|
| `status ∈ fullAccountRequires` и `givesAddress` | «полный счёт местного банка вероятен» |
| `long` без адреса | «ограниченный счёт / только с подтверждениями» |
| `short` | «местный счёт маловероятен: карта другой юрисдикции + P2P (гигиена 4.8) + наличные» |

Итог:
- зелёный: есть ≥ 1 база с «полным счётом» **и** Дом резидент (домашние счета работают штатно) — «Основной канал есть, домашние счета без сюрпризов»;
- жёлтый: Дом нерезидент, но есть база с полным счётом — «Домашний банк может запросить статус/адрес и ограничить часть продуктов; основной канал переезжает за границу — проверь Ж8»; либо Дом резидент, но все базы `short` — «Живёшь только на каналы 2–3 (P2P, карта другой юрисдикции): трение вывода растёт (Ж8)»;
- красный: сводный флаг «Нигде» из резидентства **или** (Дом нерезидент и ни одной базы с полным счётом) — «Ни одному банку непонятно, кто ты. Это и есть тот красный флаг из Ж6.»

**Школа** (только если `children` не пуст и `schoolCategory ≠ 'none'`)

| Категория | Условие | Уровень | Диагноз |
|---|---|---|---|
| очная | есть база с `months ≥ onsiteMinMonths` и статус `long/permanent` | зелёный | «Учебный год помещается в базу N.» |
| очная | самая длинная база < `onsiteMinMonths` | красный | «Очная школа несовместима с маршрутом: ни одна база не держит учебный год. Либо база, либо категория школы (Ж11).» |
| очная | база достаточная, но статус `short` | красный | «Учебный год есть, статуса под него нет.» |
| очная | базовая `cityBound` и есть переезд внутри учебного года | жёлтый | «Статус привязан к городу — переезд в марте рвёт и школу, и статус.» |
| онлайн | всегда | зелёный/жёлтый | «Совместимо с любым маршрутом. Жёлтое, если часовые пояса баз разнесены > 6 ч от расписания школы (Ж9).» — пояса не моделируем; выводим жёлтый, если баз ≥ 4 в году («частые переезды — режим ребёнка страдает раньше режима бота») |
| семейное с аттестацией | в `school.certificationMonths` ученик не дома (нет базы «Дом» в эти месяцы) | жёлтый | «Аттестация в домашней системе — обязательство с датами. В апреле–мае маршрут не проходит через Дом. ⏱ даты — на дату.» |
| семейное | иначе | зелёный | «Даты аттестации закрыты.» |

**Общие предупреждения**: непокрытые месяцы > 0 → серая плашка над треугольником; баз ≥ 5 → напоминание «5+ переездов в год — это уже вопрос Ж9 (сон оператора) и Ж11 (дети), не только документов».

### 2.6. Панель «Этот переезд трогает…»

При любом изменении базы (сдвиг границы, смена статуса/страны, удаление) система сравнивает лампы до/после и показывает всплывающую строку на 4 сек + запись в ленту справа:

«Сдвинул конец базы “Страна 2” с июня на август → **Резидентство ↓** (Дом 190 → 129: нерезидент), **Банк ↓**, Виза —, Школа —.»

Стрелки: ↑ улучшение, ↓ ухудшение, — без изменений. Это и есть педагогическое ядро урока — «видеть, какую вершину каждый переезд трогает». Лента хранит последние 10 изменений с кнопкой «откатить».

### 2.7. Задачи

| № | Формулировка | Условие закрытия |
|---|---|---|
| З1 «Прочитай пресет» | «Запусти “Удобный маршрут” и прочитай, почему симметричный год зажёг обе стороны.» | `preset_run` + открыта карточка ага‑момента |
| З2 «Почини за минимум правок» | «Сделай лампу Резидентство зелёной, изменив пресет не больше чем 2 правками.» | resid = зелёный, `editsSincePreset ≤ 2` (например: одна база укорочена до 5 месяцев + добавлен Дом на 2 месяца — не хватит; решение существует: Страна 3 → 3 месяца, Дом 3 месяца; или сменить тип Страны 3 на Б и добавить Дом — фиксируем эталонные решения в тестах) |
| З3 «Мой маршрут без красного» | «Собери свой год так, чтобы ни одна лампа не была красной — или пометь красную как “принято осознанно” с причиной.» | сохранён маршрут; для каждой красной лампы заполнено поле `acceptedReason` (≥ 20 символов) |
| З4 «Чек перед сменой базы» | «Для каждой базы отметь три проверки: доступ к площадке, канал вывода, даты школы.» | все `preMoveCheck.*Checked = true` для всех баз (для семьи без детей — два пункта) |

Урок Ж7 засчитан: дисклеймер, З1, З2, З3 (З4 — рекомендуемая, отмечается звёздочкой; в ЧП2 «Карта доступа» З4 становится обязательной).

Уточнение к З2: `computeResidency` должен давать зелёный при Дом = 183 + 14 = 197 днях минимум. Проверить, что решение в две правки существует при фактических длинах месяцев (пример: Страна 2 → 4 месяца (янв–апр), Дом → 8 месяцев не требуется; достаточно: правка 1 — Страна 3 удалена; правка 2 — добавлен Дом июль–декабрь = 184 дня → запас 1 → жёлтый «хрупко», не зелёный. Значит эталон: правка 1 — Страна 2 сокращена до 5 месяцев (янв–май, 151 день); правка 2 — Дом июнь–декабрь (214 дней, запас 31) → зелёный, Страна 2 — жёлтая зона (151 ≥ 90), сводный «Двойное» → **жёлтый**. Тогда нужна правка 3. Вывод для агента: **порог З2 = 3 правки**, и в тестах зафиксировать эталон: (1) Страна 2 → 2 месяца (янв–фев, 59 дн, ниже зоны внимания), (2) Страна 3 → 3 месяца (мар–май), (3) Дом июнь–декабрь = 214 дн → зелёный. Формулировку задачи скорректировать: «не больше чем 3 правками».)

### 2.8. Выходы и артефакты

**Карточка «Маршрут года»** (в ЧП2 «Карта доступа» и в ЖФ разделы 5 и 6):
- Таблица баз: месяцы, страна (метка + тип), статус, основание, дни; итоговые дни по странам (совпадает с форматом ЖИ‑7 → тот же расчёт резидентства, тот же блок ⏱).
- Четыре лампы с диагнозами и, для красных, поле «принято осознанно: причина».
- «Тип счёта реалистичен» по каждой базе → черновик раздела «Каналы доступа» устава (основной/запасной/аварийный канал заполняет уже Ж8).
- Чек перед сменой базы по каждой базе (три галочки + заметка).
- Лента «какую вершину трогал каждый переезд» — как учебная память (последние 10).
- Блок «⏱ Проверить на дату»: условия статусов по основаниям, сроки краткосрочного пребывания и правила счёта периода, требования банков к нерезидентам/адресу, даты аттестации.
- Блок «Что упрощает конструктор»: базы без пересечений и без «дорожных» дней; лимиты краткосрочного въезда — одинаковые типовые для всех стран, в жизни различаются; «полный счёт» — категория, а не гарантия; школа — по трём категориям, без цен и названий.

Кнопки: «Скачать карточку», «Вернуться в календарь ЖИ‑7 с этими днями» (заполняет недели по базам, чтобы ученик мог детализировать), «Передать в ЧП2».

### 2.9. Тексты

- Заголовок: **«Маршрут года: четыре лампочки на один переезд»**
- Подзаголовок: «Виза задаёт дни. Дни задают резидентство. Резидентство и адрес задают банк. А школа держит за руку всех троих. Собери год и смотри, что загорится.»
- Кнопка пресета: «Собрать “удобный маршрут” 6 + 6»
- Карточка ага‑момента после пресета: **«Симметрично — не значит безопасно.»** «Полгода там, полгода тут: визы разрешают, в голове — “я нигде не задержался”. По дням: Дом потерян, одна страна типа А набрала порог, вторая — жёлтую зону, соглашения — “не знаю”. Две страны получили основания задать вопрос одновременно, а домашний банк — повод переспросить, кто ты. Виза кочевника отвечала только за одну вершину из четырёх.»
- Подсказка к статусам: «Краткосрочный — въехал и уехал в лимит дней. Долгосрочный по основанию — работа, учёба ребёнка, инвестиции, кочевник, семья: даёт срок и обычно адрес, но часто привязывает к месту. Постоянный — почти как дома, добывается годами.»
- Подпись к вершине Школа при отсутствии детей: «В вашем маршруте не участвует. Треугольник — как в теории.»
- Полоса результата: дисклеймер 0.1 + «Условия статусов, сроки краткосрочного пребывания, требования банков — проверить на дату.»

### 2.10. Состояния

`disclaimer_pending → preset → repair(З2) → free → saved`. Пресет всегда доступен повторно (открывается копией, не затирает «Мой маршрут»). Счётчик правок `editsSincePreset` сбрасывается при повторном запуске пресета.

### 2.11. Приёмочные тесты

1. Пресет 6+6 (типы А/А, статусы long, год невисокосный): Дом 0, Страна 2 = 181, Страна 3 = 184 → Резидентство красный с текстом «Дом потерян…», Виза зелёный, Банк жёлтый (есть полный счёт, Дом нерезидент), Школа красный при `onsite`, жёлтый при `online` (2 базы → не ≥4 → на самом деле зелёный; проверить: для пресета `online` → зелёный), при `home_cert` — жёлтый (апрель–май не Дом).
2. Одна `short`‑база 4 месяца (≈121 день) при `maxContinuousDays = 90` → Виза красный с указанием базы.
3. Две `short`‑базы по 85 дней в одной стране с разрывом 1 месяц → Виза жёлтый «выезд‑въезд», сумма 170 < 180 → без второго красного; при трёх таких → красный по лимиту за период.
4. Изменение конца базы вызывает панель «трогает…» с корректными стрелками; откат из ленты восстанавливает прежние лампы.
5. Слоты, отредактированные в ЖИ‑8, видны в ЖИ‑7 при возврате; дни, переданные «в календарь», раскрашивают недели с округлением, и сумма дней сохраняется в пределах ±3 дней на базу (граничные недели детализируются автоматически).
6. Семья без детей: вершина Школа отключена, З4 требует два пункта чека.
7. З2: эталонное решение в 3 правки закрывает задачу; решение в 4 — нет.
8. Красная лампа без `acceptedReason` блокирует З3, но не блокирует сохранение черновика.
9. Смена `bank.fullAccountRequires` в конфиге на `['permanent']` переводит `long`‑базы в «ограниченный счёт» без правки кода.
10. Клавиатурное управление: выбор базы Tab, изменение границ ←/→, статус — Space.

## 3. Технические замечания для агента

- **Один расчётный модуль** `residency.ts` с `computeDaysBySlot(profile)` (два адаптера: из недель, из баз) и `computeResidency(days, slots, config) → {home, perSlot[], summary}`; оба интерактива рендерят его результат. Юнит‑тесты — на модуль, а не на интерфейсы.
- **Никаких сетевых справочников стран.** Единственный источник констант — `life_module_b.json`, с полем `reviewedAt` (дата последнего ревью), которое выводится мелким шрифтом в блоке ⏱: «Константы модуля пересмотрены: дд.мм.гггг».
- **Тексты** — в одном файле локализации `ru.life.json`, ключи с префиксами `zhi7.` и `zhi8.`; в коде строк нет. Термины только по‑русски; латиница допустима лишь в именах полей данных.
- **Производительность** тривиальна; пересчёт лампочек — синхронно на каждое изменение, без дебаунса (ученик должен видеть мгновенную связь «двинул — загорелось»).
