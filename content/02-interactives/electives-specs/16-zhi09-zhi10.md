# Спецификации интерактивов ЖИ‑9 и ЖИ‑10 (урок Ж8 «Доступ к деньгам в чужой стране»)

Общие рамки для обоих интерактивов (наследуются из принципов трека):

- Ни одного названия страны, банка, площадки, карты, сети. Только категории. В свободных текстовых полях — подсказка «без названий и реквизитов».
- Все числа подписаны «учебный диапазон категории, не тариф». Блок «⏱ Проверить на дату» на экране результата.
- Плашка на входе (та же формулировка, что в 4.6): «Учебный контур. Правила стран, банков и площадок меняются; проверяй на дату первичный источник. Это не замена консультанту».
- Стоп‑лист: не употреблять «пассивный доход», «вывести всегда можно», «безопасный канал». Вместо «безопасный» — «канал с меньшим числом точек остановки».
- Единицы: «валюта расходов» (в/р). Дни жизни считаются от годовой планки ЧП1 (Ж1); если ЧП1 не заполнен — от суммы месяца × 12, с пометкой «пока без ЧП1».
- Хранение: локально (localStorage/IndexedDB), ключи `zh8.friction.*` и `zh8.drills.*`. Никаких сумм счетов, только суммы учебные/классы сумм.

## ЖИ‑9 «Трение вывода» — конструктор цепочки

### 1. Паспорт

| Поле | Значение |
|---|---|
| Урок | Ж8, блок «Цепочка и её звенья» → «Трение как статья бюджета» → «Три канала» |
| Тип | Конструктор цепочки из блоков с живым пересчётом метрик + сравнение + стресс‑сценарии |
| Сложность | Средняя |
| Время у ученика | 6–8 мин |
| Ломаемое заблуждение | «Вывести можно всегда, везде и за 0,1%» |
| Чему учит | Путь «биржа → наличные в стране N» состоит из звеньев; у каждого — комиссия/спред, время и «кто может остановить». Трение — статья годового бюджета семьи, сравнимая с комиссиями бота (0.18). Самый дешёвый путь обычно самый длинный и самый хрупкий. Отсюда — правило трёх каналов. |
| Переиспользование | Формула трения из 0.18 (издержки от оборота); табличная механика Б3+; компоненты «сценарии‑кнопки» из ЖИ‑5 «Корзина семьи под ударом» |
| Мосты | 0.18, 1.8, 4.6 (гигиена P2P), 4.8, 5.7 («деньги в пути — обязательство цепочки»), Ж7 (местный счёт требует статуса) |
| Выход | Три сохранённые цепочки (основной / запасной / аварийный) → ЖИ‑10 и ЖФ (раздел «Каналы доступа») |

### 2. Сценарий/герой

Алексей и Марина через два месяца после переезда на базу «тип Б». Алексей уверен: «я всегда выводил через P2P дома, потом переводил — работает». Марина спрашивает: «А сколько это стоит в год и что будет, если домашний банк заморозит входящие?» Игорь (контр‑пример) выводит только по привычной домашней цепочке и однажды сидит 45 дней без доступа. Интерактив отвечает на вопрос Марины числами.

### 3. Модель данных

#### 3.1. Узлы (состояние денег)

```json
[
 {"id":"S0","label":"Стейбл на бирже (торговый контур)","start":true},
 {"id":"S1","label":"Стейбл в своём кошельке / на другой площадке"},
 {"id":"S2","label":"Домашняя валюта на домашней карте"},
 {"id":"S3","label":"Валюта базы на местном счёте","requires":"local_account"},
 {"id":"S4","label":"Средство платежа другой юрисдикции (карта с криптопополнением)"},
 {"id":"S7","label":"Наличные домашней валюты"},
 {"id":"S8","label":"Аварийный запас наличных (уже лежит дома)","start":true,"emergency_only":true},
 {"id":"S5","label":"Наличные в валюте базы","target":true},
 {"id":"S6","label":"Оплата получена напрямую (аренда, услуга)","target":true}
]
```

Цепочка считается **завершённой**, если оканчивается на узле с `target:true`. Палитра звеньев показывает только звенья, чей `from` совпадает с текущим концом цепочки; остальные затемнены с подсказкой «недоступно из текущего состояния».

#### 3.2. Сущности‑стопперы (кто может остановить)

`exchange` (биржа), `network` (сеть/блокчейн), `home_bank` (домашний банк), `local_bank` (местный банк), `card_issuer` (эмитент карты), `p2p_party` (контрагент P2P), `cash_limit` (лимит наличных страны), `border` (граница/декларирование), `counterparty_direct` (получатель прямой оплаты).

Класс серьёзности сущности (для индекса хрупкости): `low=1`, `mid=2`, `high=3`.

#### 3.3. Звенья (учебные диапазоны категории)

Все проценты — [min, typ, max]. Фикс — в валюте расходов (учебно, при базовой сумме месяца; масштабировать не надо — это про «фикс не зависит от суммы»). Время — в часах [min, typ, max].

Тип страны по доступу к наличным (переключатель): `свободный`, `лимитированный`, `жёстко лимитированный`. Учебный месячный лимит снятия для L7: свободный = ∞, лимитированный = 1.5 × сумма месяца, жёстко = 0.5 × сумма месяца (числа условные, подпись обязательна).

Режим оценки: переключатель «типично / пессимистично» → используются `typ` или `max` по всем звеньям (цепочка считается по одному режиму). По умолчанию «типично»; в стресс‑экране принудительно «пессимистично».

### 4. Расчёты

Обозначения: `A` — сумма месяца (в/р), `P` — годовая планка (ЧП1) или `12·A`.

- Трение звена, абс.: `f_i = A·pct_i/100 + fix_i` (для типа «конверсия + комиссия» — суммируются pct).
- Трение цепочки, абс./мес: `F = Σ f_i`; в %: `F% = F/A·100`.
- Трение в год: `F_year = 12·F` (подпись: «если каналом пользуетесь ежемесячно»).
- **Дни жизни в год**: `D = F_year / (P/365)`. Округлять до 0.5 дня.
- Время до наличных: `T = Σ t_i` (показывать typ и max; для L7 с лимитом — добавка «в N заходов»).
- Деньги в пути: `M = A × T_max/24` дней‑денег; флаг красный, если `T_max > 7 дней` ИЛИ сумма, одновременно находящаяся в пути, > `A` (по правилу «ни один канал не держит больше месяца расходов в пути»). Поле «сколько отправляю за раз» по умолчанию = A; ученик может уменьшить → пересчёт числа операций и времени.
- Точки остановки: `S = число уникальных сущностей` в цепочке; **индекс хрупкости** `H = Σ класс(сущность)` по уникальным сущностям.
- Сопоставление с ботом (только если в ЧП1 есть торговый капитал `K`): «Столько же бот платит за `N = F_year / (0.002·K)` торговых кругов» (0.2% за круг из 0.18). Если K нет — строка скрыта.

Валидация: цепочка «не завершена» → метрики серые, кнопка «Сравнить» неактивна. Цепочка с петлёй (одно звено дважды подряд) запрещена, кроме L7 «в несколько заходов» (это не звено, а модификатор).

### 5. Пресеты (кнопка «Собрать за меня»)

| Пресет | Цепочка | Ожидаемо (типично) |
|---|---|---|
| «Как привык Игорь» (через дом) | S0 → L3 → S2 → L6 → S3 → L7a → S5 | ≈4–6 %, 3–5 суток, 5 сущностей, H≈10 |
| «Дёшево» | S0 → L1 → S1 → L4 → S3 → L7a → S5 | ≈2.5 %, до 1–2 суток, 5 сущностей, H≈8 |
| «Быстро» | S0 → L8 → S4 → L9b → S6 (и ветка L7b → S5 для наличных) | ≈3–4 %, ~2 часа, 2–3 сущности, H≈4–5 |
| «Аварийный» (только для слота) | S8 → L14 → S5 + параллельно S0 → L8 → S4 → L9b | 0 % в момент аварии, 0 ч; хрупкость: 1 сущность + запас конечен |

Пресеты — стартовые точки, ученик может править. Числа должны получаться из таблицы, а не быть захардкожены (проверяется тестом).

### 6. Экраны и сценарий

**Экран 0. Вход.** Плашка «учебный контур». Поля: сумма месяца `A` (префилл: зарплата оператора из ЧП1/Ж2; иначе пусто с подсказкой «введите месячные расходы в валюте расходов»); тип страны по доступу к наличным (3 кнопки, короткое описание каждого типа); есть ли местный счёт (да/нет → влияет на доступность S3; при «нет» — подсказка «см. Ж7: местный счёт привязан к статусу»). Кнопка «Собрать цепочку».

**Экран 1. Конструктор.** Три зоны:
- Слева — палитра звеньев (карточки: название, диапазон %, время, иконки стопперов, флаги «проверить на дату»). Доступные подсвечены.
- Центр — цепочка: узлы и звенья горизонтально, текущий конец мигает. Клик по звену в цепочке — удалить его и всё после (с подтверждением, если после него >1 звена). Перетаскивание не обязательно — достаточно клика по карточке палитры (добавить в конец).
- Справа — панель метрик (живой пересчёт): Трение % и в/р в месяц | Дней жизни в год | Время до наличных (тип./песс.) | Точек остановки + список сущностей с классом | Индекс хрупкости (шкала 0–12: зелёный ≤5, жёлтый 6–9, красный ≥10) | Флаг «деньги в пути». Переключатель «типично/пессимистично». Кнопка «Сохранить как…» (основной/запасной/аварийный) — активна только для завершённой цепочки.

Микро‑подсказки при добавлении звена (1 строка):
- L3: «Домашний банк — точка остановки: входящие от физлиц смотрят по 115‑ФЗ (4.6). Только карта самого контрагента».
- L6: «Самое медленное звено: 3–5 суток при типичном сценарии. Три банка на пути — три точки остановки».
- L8: «Быстро, но эмитент карты может прекратить обслуживать регион. Один стоппер — но класс средний».
- L4 без местного счёта: «Нужен местный счёт → статус → Ж7».
- L12: «Наличные в багаже — не канал, а риск. Учебно допускаем только как аварийную ветку».

**Экран 2. Сравнение.** Таблица: строки — «Моя цепочка», три пресета; столбцы — трение %, дней жизни/год, время (тип./песс.), точек остановки, индекс хрупкости, «деньги в пути». Подсветка: лучший в столбце — зелёный, худший — красный. Под таблицей автоматический вывод (генерится из данных, не текст‑заглушка):

> «Дешёвый путь экономит тебе **X дней жизни в год** по сравнению с быстрым, но идёт **в Y раз дольше** и проходит через **на Z точек остановки больше**. Игорева цепочка — и дороже, и дольше: привычка стоит **W дней в год**».

Это и есть **ага‑момент №1**.

**Экран 3. Стресс («Что, если…»).** Режим принудительно «пессимистично». Кнопки‑сценарии (каждая помечает сущности недоступными на срок):

| Сценарий | Сущность | Срок |
|---|---|---|
| Биржа приостановила выводы | exchange | 10 дней |
| Домашний банк заморозил входящие | home_bank | 45 дней |
| Местный банк закрыл счёт | local_bank | бессрочно (нужен новый счёт: время Ж7) |
| Эмитент карты прекратил обслуживать регион | card_issuer | бессрочно |
| Страна ввела лимит наличных | cash_limit → high, лимит = 0.25·A | бессрочно |
| Контрагент P2P не выходит на связь | p2p_party | 2 дня + деньги в пути под вопросом |

Для каждой сохранённой цепочки и пресета показывается: «жива / стоит N дней / мертва». Счётчик внизу: «Из твоих каналов пережили сценарий: k из 3». Если k=0 при любом одиночном сценарии → красная плашка «Один стоппер кладёт все три канала — каналы не независимы». **Ага‑момент №2**: дешёвая цепочка гибнет от большего числа сценариев.

**Экран 4. Мои три канала.** Три слота. Требования (проверяются, не блокируют, но подсвечивают):
- Основной и запасной не делят ни одной сущности класса `high` и делят не более одной сущности вообще (общая `exchange` допускается — она стартовая; тогда подсказка «оба начинаются с биржи — аварийный не должен»).
- Аварийный не начинается с S0 (не зависит от биржи) — либо S8‑запас, либо S1‑кошелёк.
- Шкала независимости: «независимы / частично / зависимы».
Кнопки: «Сохранить в ЧП2 и ЖИ‑10» (пишет `zh8.friction.channels`), «Экспорт для устава» (текстовый блок раздела 6 ЖФ: три канала категориями, плановое трение, плановое время, стопперы, максимум денег в пути).

Блок «⏱ Проверить на дату»: лимиты наличных, доступность фиатных шлюзов и карт для региона, правила P2P площадок, статус международных переводов.

### 7. Состояния и граничные случаи

- ЧП1 не заполнен: работать от `12·A`, всюду подпись «дни жизни считаются без ЧП1 — заполни Ж1»; кнопка‑ссылка в Ж1.
- `A` не введена → конструктор недоступен, подсказка.
- Незавершённая цепочка → метрики серые, сохранение неактивно.
- Более 8 звеньев → предупреждение «длинная цепочка: проверь, не собираешь ли ты Игореву привычку».
- Цепочка только с L10 в цель S6 → предупреждение «редкий канал», не даёт сохранить как основной.
- Аварийный слот с цепочкой от S0 → предупреждение, сохранение разрешено, но шкала независимости = «зависимы».
- Возврат на экран — состояние восстанавливается из локального хранилища.

### 8. Честность и формулировки

- Каждая карточка звена: серым «учебный диапазон, не тариф». Никаких ссылок на конкретные сервисы.
- Стресс‑сценарии — «категория событий, не прогноз». Не давать вероятностей событий, только последствия.
- Не рассчитывать «оптимальный маршрут» за ученика: кнопка «Собрать за меня» даёт стартовые точки, не рекомендацию. Формулировка кнопки: «Собрать пример».
- Не показывать «безопасно/опасно»; показывать «точек остановки: N».

### 9. Критерии приёмки

1. Из таблицы 3.3 пресет «Дёшево» даёт трение в диапазоне 2–3.5 % (типично), «Быстро» — 3–4.5 %, «Игорь» — 4–7 %; время «Быстро» < 6 ч, «Дёшево» 4–30 ч, «Игорь» ≥ 72 ч. Пересчитывается из данных (юнит‑тест на калькулятор).
2. Смена типа страны на «жёстко лимитированный» при A > лимита увеличивает время L7 и добавляет пометку «в N заходов».
3. Палитра показывает только совместимые звенья; попытка добавить несовместимое — невозможна.
4. Дни жизни = F_year/(P/365) с P из ЧП1 при его наличии (тест на связку с хранилищем ЧП1).
5. Стресс «домашний банк 45 дней» убивает «Игоря», не трогает «Быстро»; сценарий «эмитент карты» — наоборот. Счётчик «пережили k из 3» корректен.
6. Проверка независимости: две цепочки с общей `home_bank` → «зависимы»; аварийный от S0 → предупреждение.
7. Сохранение трёх слотов создаёт запись `zh8.friction.channels` в формате, который читает ЖИ‑10 (схема ниже).
8. Ни одной строки с названием страны/банка/площадки/сети в ресурсах (грепом по словарю запрещённых слов).
9. Плашка «учебный контур» — на входе и на экране результата.

Схема экспорта в ЖИ‑10:

```json
{"version":1,"amount_month":150000,"country_cash_type":"limited",
 "channels":[{"slot":"primary","links":["L1","L4","L7a"],"planned":{"friction_pct":2.6,"time_h_typ":5,"time_h_max":28,"stoppers":["exchange","network","p2p_party","local_bank","cash_limit"],"fragility":8}},
 {"slot":"backup","links":["L8","L9b"],"planned":{...}},
 {"slot":"emergency","links":["L14"],"planned":{...},"cash_months":1}]}
```

### 10. Телеметрия (без персональных данных)

`zh8_fr_start`, `zh8_fr_chain_completed{links,friction,time,fragility}`, `zh8_fr_preset_used{name}`, `zh8_fr_compare_viewed`, `zh8_fr_stress{scenario,survived}`, `zh8_fr_saved{independence}`. Цель — видеть, доходят ли ученики до стресс‑экрана и сохраняют ли три канала (это вход в ЧП2).

## ЖИ‑10 «Три канала — учения» — чек‑лист‑таймер

### 1. Паспорт

| Поле | Значение |
|---|---|
| Урок | Ж8, блок «Учения раз в квартал» (после ЖИ‑9); используется в ЧП2 и ежемесячно в ЖФ |
| Тип | Живой чек‑лист трёх каналов с датами последних учений, таймером реальной микро‑операции и журналом |
| Сложность | Низкая |
| Время | Первое заполнение 3–4 мин; сами учения — в реальном времени вне урока (таймер переживает закрытие вкладки) |
| Ломаемое заблуждение | «Канал есть — значит работает» |
| Чему учит | Канал, не проверенный 90 дней, — предположение о канале. Учения = реальная микро‑операция с замером времени и трения; план (ЖИ‑9) сверяется с фактом — «отклонение доступа» по аналогии с Execution Deviation (4.5). После каждого переезда — учения заново. |
| Переиспользование | «Учения выводов» 5.7 (реальный тестовый вывод + запись в журнал), шкала процесса П33, дизайн статусов из П2 «пять галочек осмотра» |
| Мосты | 5.7, 4.5, 4.6/4.8 (гигиена во время учений), П1 (журнал), Ж7 (переезд), ЖФ (ритуал) |
| Выход | Статус трёх каналов + журнал → галочка «учения не просрочены» в семейной шкале процесса (ЖФ) |

### 2. Сценарий/герой

Марина — держатель «кнопки» (Ж10, Ж12). Она не торгует, но раз в квартал открывает этот экран и видит три светофора. Если жёлтый — просит Алексея провести учения на выходных. Контр‑пример: Игорь «проверял в прошлом году», а после переезда карта другой юрисдикции перестала работать — узнал в аптеке.

### 3. Модель данных

```json
{"version":1,
 "amount_month":150000,
 "drill_interval_days":90,
 "channels":[
  {"slot":"primary|backup|emergency",
   "source":"zh9|manual",
   "links":["L1","L4","L7a"],
   "label_manual":"категория, если без ЖИ‑9",
   "planned":{"friction_pct":2.6,"time_h_typ":5,"time_h_max":28,"stoppers":[...]},
   "cash_reserve":{"months":1,"checked_at":"2026-05-01"},      // только emergency
   "in_transit_now":0,                                         // в/р, вводится вручную
   "drills":[
     {"id":"d1","started_at":"…","finished_at":"…",
      "mode":"real|paper",                                     // реальная микро‑операция / «на бумаге»
      "amount_class":"micro",                                  // фикс. значение, не сумма
      "milestones":[{"key":"sent","at":"…"},{"key":"received","at":"…"},{"key":"cash","at":"…"}],
      "sent_units":100,"received_units":97.4,                  // в учебных единицах или в/р, по выбору; для расчёта % 
      "actual_friction_pct":2.6,"actual_time_h":6.2,
      "result":"ok|partial|fail","note":"без названий и реквизитов"}
   ],
   "needs_recheck_reason":null|"relocation"|"failed"|"stale"}
 ],
 "relocations":[{"at":"…"}]}
```

### 4. Расчёты и статусы

- `days_since = today − last_drill.finished_at` (по последнему учению с `result != fail`; если последнее — fail, статус красный независимо от даты).
- Статус канала:
  - **Зелёный**: `days_since ≤ 60`, последнее учение `real`, `result=ok`, `needs_recheck_reason=null`.
  - **Жёлтый**: `61–90` дней; или учение `paper` (макс. статус жёлтый, подпись «проверено на бумаге»); или `needs_recheck_reason=relocation`; или `result=partial`.
  - **Красный**: `>90` дней; или никогда; или `result=fail`.
- `next_due = last_drill + drill_interval_days`.
- **Отклонение доступа** (по времени): `dev_t = (actual_time_h − planned.time_h_typ)/planned.time_h_typ`; по трению: `dev_f = actual_friction_pct − planned.friction_pct` (п.п.). Пороги: `dev_t ≤ 50%` — норма; `50–150%` — «план оптимистичен, уточни ЖИ‑9»; `>150%` — «канал не тот, что в плане» (жёлтый, даже если ok). Если `actual_time_h > planned.time_h_max` — отдельная пометка «хуже пессимистичного сценария».
- Фактическое трение считается автоматически: `(sent − received)/sent·100` (плюс фикс, если введён отдельно).
- **Деньги в пути**: сумма `in_transit_now` по каналам; если `> amount_month` — красный баннер вверху «В пути больше месяца расходов — нарушено правило Ж8».
- **Аварийный запас**: если `cash_reserve.months < 1` или `checked_at` старше 90 дней — аварийный канал не может быть зелёным.
- Галочка для ЖФ: `drills_ok = all(status != red) && !transit_flag`.

### 5. Экраны и сценарий

**Экран 0. Сводка (главный).** Заголовок «Три канала». Три карточки (основной / запасной / аварийный): светофор, категория цепочки (из ЖИ‑9: «биржа → сеть → P2P база → банкомат»), «последние учения: N дней назад (дата)», «следующие до: дата», «план: X %, Y ч → факт: X' %, Y' ч» (если есть учения), бейдж отклонения. Для аварийного дополнительно: «запас наличных: N мес., проверен: дата». Вверху — строка «Деньги в пути сейчас: Σ / лимит = месяц расходов» с полем ввода. Кнопки: «Провести учения», «Отметить переезд», «Экспорт в устав». Если ЖИ‑9 не сохранён — карточки пустые с кнопкой «Собрать цепочки в «Трении вывода»» и альтернативой «указать категорию вручную» (выпадающий список из тех же звеньев, без метрик плана).

**Экран 1. Учения (визард).**
1. Выбор канала (по умолчанию самый просроченный).
2. Инструктаж — 5 пунктов, короткие, без названий:
   - Сумма — минимальная (микро), не та, что нужна семье.
   - Гигиена 4.6/4.8: только свои реквизиты и реквизиты самого контрагента; никаких «третьих лиц».
   - Засекаем от первого действия до «деньги можно потратить».
   - Не совмещать с реальной нуждой: учения — когда деньги не горят.
   - Всё, что пошло не так, — в заметку, категориями.
   Переключатель режима: «Реальная микро‑операция» / «На бумаге (без денег)» с подписью «на бумаге даёт максимум жёлтый статус».
3. Старт таймера: сохраняется `started_at`; отображается крупный счётчик; кнопки вех соответствуют звеньям цепочки (генерируются из `links`: например «отправлено с биржи» / «пришло на местный счёт» / «наличные в руках»). Таймер живёт в фоне: при возврате на страницу продолжает считать от `started_at`. Уведомление «учения идут» в шапке приложения.
4. Стоп: ввод «отправил (единиц)» / «получил (единиц)» → авторасчёт %; результат ok / частично / не прошло; поле заметки с плейсхолдером «что стало точкой остановки — категорией».
5. Итог: карточка «план vs факт», статус обновлён, следующие учения — дата. Если отклонение по времени >150% — предложение «обновить план: открыть ЖИ‑9 с этой цепочкой» (deep link с предзаполнением).

Для аварийного канала визард другой: «Проверка запаса»: чекбокс «наличные на месяц физически на месте», «карта другой юрисдикции оплачивает покупку» (микро‑покупка с замером), дата → `cash_reserve.checked_at`.

**Экран 2. Журнал.** Таблица всех учений: дата, канал, режим, время, трение, результат, заметка. Фильтр по каналу. Внизу — «отклонение доступа» скользящим по последним 3 учениям канала.

**Кнопка «Отметить переезд».** Подтверждение → всем каналам `needs_recheck_reason=relocation` (статус жёлтый, история не стирается), запись в `relocations`, подсказка «Ж7: сменилась база — местный счёт, лимиты наличных и приём карты могли измениться. Проведи учения по каждому каналу в первые 2 недели». Аварийный запас — на перепроверку.

**Экспорт в устав.** Текстовый блок для раздела 6 ЖФ: три канала категориями, дата последних учений, факт времени/трения, максимум денег в пути, дата следующих учений. Плюс JSON для ЖФ‑конструктора (`zh8.drills.summary`).

### 6. Ага‑момент и тексты

- Первое открытие с пустыми учениями: все три красные, надпись: «У тебя есть план из трёх каналов и ноль проверенных. Пока так — это не каналы, а предположения о каналах».
- После первого учения с отклонением: «План говорил 5 часов, факт — 14. Разница — не ошибка, а информация: обнови план и не рассчитывай на 5 часов в чёрный год».
- При «на бумаге»: «На бумаге канал не ломается. Максимум — жёлтый».
- При переезде: «Канал, который работал на прошлой базе, на новой — снова непроверенный».

### 7. Состояния и граничные случаи

- Таймер запущен и забыт >7 дней → на сводке баннер «учения не закрыты N дней» с вариантами «закрыть как fail / удалить запись».
- Два таймера одновременно запрещены (один активный drill).
- Нет ЖИ‑9 → ручной режим без «план vs факт», отклонение не считается, подпись «план не задан».
- Часовые пояса: хранить в UTC, показывать локально (актуально при переездах — Ж9).
- Удаление учения — только последнего, с подтверждением; история не редактируется задним числом (журнал по П1: «зафиксировано — не переписывается»).
- Ввод `received > sent` → предупреждение «получено больше отправленного — проверь единицы».

### 8. Честность и приватность

- Поля не принимают реквизиты: маска/подсказка; хранение локально; текст «данные не покидают устройство».
- Не подсказывать, «через что» проводить учения — только категорию канала, выбранную учеником.
- Не считать «надёжность канала в %». Только статус по давности, результату и отклонению.
- Учения — не проверка платёжеспособности площадки: плашка «зелёный статус означает «работало в дату учений», не «будет работать всегда» (5.7)».

### 9. Связь с чекпоинтом ЧП2 и ЖФ

- ЧП2 считается пройденным, когда по каждому из трёх каналов есть ≥1 учение в режиме `real` с `result ∈ {ok, partial}`, аварийный запас проверен, и `in_transit_now ≤ amount_month`. Для ученика без капитала (до микро‑лайва) — допускается ЧП2 «на бумаге» с явной пометкой в ЖФ «каналы проверены только на бумаге, срок реальных учений: дата».
- ЖФ ежемесячно читает `drills_ok`; ЖФ‑ревью «после каждого переезда» ссылается на кнопку «Отметить переезд».
- ЖИ‑12 (экстренный протокол) берёт из ЖИ‑10 актуальный «работающий канал» для карточки партнёра (последний зелёный).

### 10. Критерии приёмки

1. Статусы вычисляются по правилам п.4; тест на границы 60/61/90/91 дней и на `paper` → максимум жёлтый.
2. Таймер переживает перезагрузку страницы и закрытие вкладки; вехи привязаны к звеньям выбранной цепочки из ЖИ‑9.
3. Фактическое трение считается из sent/received; отклонение по времени и трению отображается с порогами.
4. «Отметить переезд» переводит все каналы в жёлтый с причиной, не удаляя журнал.
5. Баннер «деньги в пути > месяца» появляется при превышении и исчезает при исправлении.
6. Аварийный канал не может быть зелёным без проверенного запаса ≥1 мес. свежее 90 дней.
7. Экспорт даёт текстовый блок и JSON, читаемый конструктором ЖФ; `drills_ok` доступен как флаг.
8. Без ЖИ‑9 интерактив работает в ручном режиме без падений.
9. Ни одного поля, принимающего/сохраняющего названия и реквизиты (проверка словарём + отсутствие свободного текста длиннее 140 символов в заметке).

### 11. Телеметрия

`zh8_dr_open{statuses}`, `zh8_dr_start{slot,mode}`, `zh8_dr_finish{slot,mode,result,dev_t_bucket}`, `zh8_dr_relocation`, `zh8_dr_transit_flag`, `zh8_dr_export`. Метрика успеха трека: доля учеников с тремя `real`‑учениями в течение 30 дней после Ж8.
