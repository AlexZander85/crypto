# Спецификации интерактивов ЖИ-17 и ЖИ-18 (урок ЖФ)

Ниже — два ТЗ для агента-разработчика. Формат единый: назначение → педагогика → данные на входе → экраны и логика → валидация → выходные артефакты → тексты интерфейса → события аналитики → критерии приёмки → открытые вопросы. Все тексты интерфейса — на русском, без английских терминов; там, где термин из курса имеет английский оригинал, он даётся один раз в скобках в подсказке и больше не используется.

Общие ограничения для обоих интерактивов (наследуются из принципов трека):

- Стоп-лист слов в свободных полях: «пассивный доход», «жить на проценты», «финансовая независимость», «рантье». При вводе — мягкое предупреждение (не блокировка): «В этом курсе доход оператора — зарплата, а не рента. Переформулируй правилом: действие + предел + проверка».
- Ни одного названия страны, банка, биржи, школы, страховой. Только категории.
- Плашка честности на разделе «Налоговый календарь»: та же формулировка, что в 4.6: «Учебный контур. Правила стран, налогов и виз меняются; проверяй на дату первичный источник. Это не замена консультанту».
- Приложение ничего не проверяет во внешних системах: все числа вводит семья руками. Это надо явно писать в интерфейсе (см. тексты).
- Персонажи: примеры и подсказки — на Алексее, Марине, Соне и Тимуре; контрпример — Игорь.

## ЖИ-17. «Конструктор семейного устава»

### 1. Назначение

Финальный артефакт трека. Пошаговый мастер собирает «Семейный устав оператора» из чисел и решений, накопленных в интерактивах Ж1–Ж13 и чекпоинтах ЧП1–ЧП3, и выдаёт три документа: устав (полный), карточку партнёра (одна страница) и календарь ревью. Движок — переиспользованный «Конструктор торгового устава» (5.6): те же шаги-вопросы, тот же принцип «правило = действие + предел + проверка» (П52), та же история версий.

Ломаемое заблуждение: «Договорились на словах — этого хватит».

Ага-момент (закрывающий экран «Проверка паникой»): пользователь видит три бытовые ситуации чёрного года и рядом — что на них отвечает его устав. Если устав молчит — экран показывает: «Здесь решать будет не устав, а тот, кто громче». Это единственный момент, где конструктор «оценивает» — и оценивает не качество семьи, а наличие правила.

### 2. Отличия от движка 5.6 (что менять в форке)

| Параметр | Торговый устав (5.6) | Семейный устав (ЖИ-17) |
|---|---|---|
| Подписанты | один (оператор) | два взрослых; каждый раздел помечен «исполняет: оператор / партнёр / оба» |
| Цикл ревью | по расписанию из устава, изменения со следующего дня | раз в год + после каждого переезда + внеплановые по триггеру ЖИ-18; изменения вступают через 7 дней, кроме раздела 9 (контакты/доступы — сразу) |
| Предзаполнение | из конструктора 4.4 (kill-switch) | из ЧП1, ЧП2, ЧП3 и интерактивов Ж1–Ж13; торговый устав 5.6 подключается только для чтения |
| Выход | документ + charter.yaml | документ + карточка партнёра + календарь ревью + запуск ЖИ-18 |
| Режимы | один | «ядро» (5 разделов) и «полный» (9 разделов + ритуал) |

Не переписывать: шаговую навигацию, историю версий с разницей между версиями, экспорт в печать/файл, компонент «правило из трёх частей».

### 3. Педагогические требования

1. Ни одного поля «свободный текст правила». Каждое правило собирается из трёх обязательных подполей: **Действие** (выбор из списка или короткий текст) + **Предел** (число с единицей / дата / условие из списка) + **Проверка** (кто / когда / чем). Четвёртое подполе **Исключение** — опциональное, но если заполнено, само обязано иметь предел.
2. Детектор лозунгов: правило без числа или даты в поле «Предел» не сохраняется; подсказка показывает пример правильной формулировки на Алексее и Марине.
3. Ссылки на пройденное, не пересказ: у каждого раздела кнопка «Откуда число» — ведёт в соответствующий интерактив (Ж1–Ж13) или чекпоинт. Если интерактив не пройден — раздел доступен для ручного заполнения, но помечается «черновик: числа не проверены тренажёром».
4. Числа семьи никогда не пересчитываются конструктором «по-своему»: он берёт их из источников, показывает источник и дату, позволяет переопределить с обязательной причиной.

### 5. Экраны и логика

#### Экран 0. Вход и выбор режима

- Заголовок: «Семейный устав оператора».
- Первая фраза (ломаемое заблуждение): «Договорились на словах — этого хватит. Не хватит: устав пишется в спокойствии и исполняется в панике (5.6). Семейный отличается одним — половину его правил исполняет не тот, кто его писал».
- Переключатель режима: **Ядро** (5 разделов: планка, зарплата, сейф, уровни тревоги, экстренный протокол — 15–20 мин) / **Полный** (9 разделов + ритуал — 35–45 мин). По умолчанию — режим, соответствующий пройденным урокам: если пройдены только уроки с пометкой «ядро», предлагается ядро.
- Блок «Что уже есть»: список источников с зелёной/серой отметкой (ЧП1, ЧП2, ЧП3, торговый устав 5.6). Если ЧП3 не пройден партнёром — предупреждение: «Аттестация трека потребует тест-драйва партнёра (Ж12). Устав можно собрать сейчас, подпись партнёра — после».
- Поле «Кто заполняет сейчас»: оператор / партнёр / вместе. Влияет только на подсказки (разделы «исполняет партнёр» подсвечиваются, если заполняет оператор один: «Этот раздел лучше заполнять вдвоём»).

#### Экраны 1–9. Разделы

Единый шаблон экрана раздела:

- Заголовок раздела и строка «Исполняет: …».
- Слева — блок «Откуда число» (источник, дата, кнопка перехода).
- По центру — правила раздела (компонент «правило из трёх частей»).
- Справа — «Как это выглядит у Алексея и Марины» (пример заполненного правила) и «Как это ломается у Игоря» (одна фраза).
- Внизу — кросс-проверки раздела (см. §6), кнопка «Дальше» активна только при отсутствии блокирующих ошибок.

Разделы, обязательные поля и предзаполнение:

**Раздел 1. Планка и бюджет** (Ж1). Исполняют: оба.
- Три строки годовых расходов (обязательное / гибкое / роскошь) + валюта. Источник: ЧП1.
- Правило подъёма планки: действие «поднимаем планку», предел «не чаще 1 раза в год и не более чем на N %», проверка «только если сейф ≥ нормы после подъёма; проверяет партнёр по карточке ЖИ-18».
- Доля необратимых трат (показать; если > 40 % — предупреждение из Ж1, не блокировка).

**Раздел 2. Зарплата оператора** (Ж2). Исполняет: оператор; проверяет: партнёр.
- Сумма, валюта (должна совпадать с валютой расходов — иначе предупреждение со ссылкой на Ж4), день выплаты (число месяца), правило пересмотра (раз в квартал, кто инициирует).
- Источник в норме: «прибыль по лестнице траншей (П42)»; источник в просадке глубже порога X %: «сейф». Порог X подтягивается из Ж5 (жёлтый уровень).
- Запрет: «изъятие из торгового капитала вне расписания» — чекбокс обязателен к включению; при снятии — модальное окно «Ты выключаешь главное правило Ж2. Причина?» (причина записывается в версию).

**Раздел 3. Сейф** (Ж3, Ж4). Исполняют: оба.
- Норма сейфа в месяцах (из Ж3), текущее значение (ввод руками), корзина валют с долями (из ЧП1/Ж4; сумма долей = 100 %), где лежит — по категориям (наличные-эквиваленты / банк / холодный стейбл), правило пополнения: «транш при +N % идёт в сейф до нормы, затем в зарплату».
- Запрет «сейф → торговый»: по умолчанию включён. Единственное исключение — обязательно с тремя полями: условие (из списка: «пополнение маржи по уставу 5.6 при просадке не глубже Y %»), лимит (не более Z % сейфа, но сейф после операции ≥ 12 мес), кто подтверждает (оба взрослых, письменно). Без всех трёх полей исключение не сохраняется.

**Раздел 4. Три уровня тревоги** (Ж5). Исполняют: оба; объявляет: устав.
- Таблица 3×4: уровень / триггеры в числах / что режется / что не режется никогда.
- Зелёный: просадка ≤ порога устава 5.6 (подтягивается). Жёлтый: просадка > X % ИЛИ N месяцев без прибыли ИЛИ сейф < норма. Красный: сработали kill-критерии 5.6 ИЛИ сейф < 12 мес.
- Список «не режется никогда» — минимум три пункта; предзаполнено: школа, страховка, пополнение сейфа до нормы. Пользователь может добавить, не может удалить все.
- Обязательная строка: «Уровень объявляет устав по числам; оператор не имеет права отложить объявление». Показывается как нередактируемая.
- Ритуал жёлтого: семейный совет раз в месяц (дата). Красный: план Б — категория «дешёвая база», «дополнительный доход», «ничего не докидываем».

**Раздел 5. Налоговый календарь** (Ж6, Ж7). Исполняет: оператор; ведёт счётчик: назначенный (оператор или партнёр).
- Плашка честности сверху (обязательно, не скрывается).
- Порог дней домашней юрисдикции (по умолчанию 183), кто ведёт счётчик, где ведётся (категория: приложение курса / таблица / бумага), даты отчётности (декларация, уплата — предзаполнено из 4.6 с пометкой «проверить на дату»), где проверяем актуальность (категории источников из Ж6, в порядке: первичный закон → официальный портал → консультант).
- Триггер внеплановой проверки: «перед каждой сменой базы дольше N недель».
- Блок «⏱ Проверить на дату»: список пунктов с датой последней проверки (вводит пользователь).

**Раздел 6. Каналы доступа** (Ж8). Исполняет: оператор; учения — оба.
- Три канала из ЧП2 (роль, тип-категория, дата последних учений, минут до наличных, трение %).
- Правило учений: «раз в 90 дней микро-операция по каждому каналу с замером времени». Максимум «денег в пути»: не более 1 месяца расходов (число подставляется из раздела 1).
- Аварийный запас наличных: N дней расходов (по умолчанию 30), где (категория).

**Раздел 7. Рабочее место** (Ж9). Исполняет: оператор.
- Окна проверки по базам (две в сутки, время), белый список ночи (список из Ж9, редактируемый; минимум 1, максимум 4 пункта — иначе предупреждение «список из 7 пунктов — это не белый список, а будильник»), правило 72 часов после перелёта (включено по умолчанию), состав рюкзака/сейфа — чек-лист из Ж9 «Рюкзак оператора» (что где лежит), «путь до кнопки стоп без интернета» — ссылка на раздел 9.

**Раздел 8. Роли и отчёт** (Ж10, Ж11). Исполняют: оба.
- Уровень вовлечения партнёра (наблюдатель / держатель кнопки / со-оператор). Формат отчёта: набор карточек из Ж10 (кривая с просадкой, лет в сейфе, уровень тревоги, зарплата следующего квартала); скриншоты дня — по умолчанию исключены. Дата отчёта (день месяца).
- «Что говорим детям» — одна фраза, выбор из 3 шаблонов или свой текст (единственное поле, где свободный текст допускается без предела — с подсказкой «без секретности»).
- Дети и здоровье (только полный режим): категория школы, привязка к месту (да/нет), тип полиса, дата окончания полиса, дата аттестации — в виде дат для календаря ревью. Никаких названий.

**Раздел 9. Экстренный протокол** (Ж12). Исполняет: партнёр.
- Пять пунктов карточки партнёра (одна кнопка «всё в стейбл и стоп»; кому позвонить; где сейф и как жить 12 месяцев; чего не делать; где документы и доступы). Предзаполнение из ЧП3.
- Триггеры протокола: «не выходит на связь N часов» (по умолчанию 48), «в больнице/недоступен», «принимает решения, которые сам запретил» (ссылка на журнал вмешательств П1).
- Дата последнего тест-драйва (из ЧП3) и правило: «повторять раз в 180 дней и после каждого изменения доступов».
- Правило вступления изменений: раздел 9 меняется без задержки 7 дней (контакты и доступы должны быть актуальны всегда) — показать явно.

#### Экран 10. Ритуал и подписи

- Пять галочек ежемесячной шкалы (передаются в ЖИ-18): зарплата по расписанию; сейф ≥ нормы; отчёт показан; дни учтены; учения/тест-драйв не просрочены. Пользователь выбирает день месяца для ритуала (по умолчанию — день отчёта из раздела 8).
- Правило внеплановой ревизии устава: «если два месяца подряд ≤ 3/5 — семейный совет и проверка разделов 2–4».
- Подписи: два поля «Имя», два чекбокса «Прочитал(а) и подписываю», дата. Если ЧП3 не пройден — подпись партнёра доступна, но устав получает статус «подписан, не аттестован».
- Дата следующего планового ревью = дата подписи + 12 месяцев; плюс правило «после каждого переезда» (кнопка «Мы переехали» в ЖИ-18 создаёт внеплановое ревью).

#### Экран 11. «Проверка паникой» (ага-момент)

Три ситуации, показываются последовательно. Для каждой система вытягивает из собранного устава релевантные правила и показывает их рядом с ситуацией. Пользователь ничего не выбирает — только читает.

1. «Март. Просадка 34 % и пятый месяц без прибыли. Марина спрашивает: что будем делать?» → устав отвечает: уровень (по разделу 4), источник зарплаты (раздел 2), что режется (раздел 4), когда семейный совет. Если триггеры не заданы: «Устав молчит. Ответ даст тот, кто громче».
2. «Алексей не отвечает 40 часов. Пришло уведомление о просадке, в личку пишет "менеджер биржи".» → раздел 9: триггер по часам, кнопка, кому звонить, «не отвечать поддержке».
3. «Год закрылся +70 %. Хочется снять на большой ремонт.» → раздел 1 (правило подъёма планки), раздел 3 (сначала сейф до нормы), раздел 2 (пересмотр зарплаты раз в квартал).

Итоговая строка: «Устав ответил на N из 3 ситуаций числом». Если < 3 — кнопка «Дописать» ведёт в нужный раздел. Аттестация при N < 3 невозможна.

#### Экран 12. Выход

Три карточки для скачивания/печати + кнопка «Запустить ежемесячную шкалу» (открывает ЖИ-18 с первой отметкой). Показать статус аттестации:

- «Аттестован»: все обязательные разделы режима заполнены без черновиков, N = 3, ЧП3 пройден партнёром, обе подписи, первая отметка ЖИ-18 сделана.
- «Собран, не аттестован»: перечень недостающих условий.

### 6. Валидация и кросс-проверки

Блокирующие (нельзя перейти дальше):
- В поле «Предел» нет числа/даты/условия из списка.
- Сумма долей корзины сейфа ≠ 100 %.
- Жёлтый триггер просадки ≥ красного триггера (просадка) — противоречие.
- Разрешено «сейф → торговый» без всех трёх полей исключения.
- В списке «не режется никогда» меньше одного пункта.
- Максимум «денег в пути» > 1 месяца расходов — блокировка с текстом из Ж8.

Предупреждающие (жёлтая плашка, можно продолжить, фиксируется в версии как «принято с предупреждением»):
- Норма сейфа < 12 месяцев.
- Зарплата × 12 > планка (семья планирует тратить больше планки).
- Валюта зарплаты ≠ валюта расходов.
- Дата последних учений канала > 90 дней назад или тест-драйв партнёра > 180 дней.
- Доля необратимых трат > 40 %.
- Белый список ночи > 4 пунктов.
- Уровень вовлечения «наблюдатель» при том, что «держатель кнопки» в разделе 9 — партнёр (противоречие ролей: «партнёр не может нажать кнопку, не зная, что она есть»).
- Стоп-лист слов в свободных полях.
- Черновики (разделы, заполненные без прохождения интерактива).

### 7. Выходные артефакты

**7.1. Семейный устав** — документ (печатная форма + файл данных):
- Шапка: название, версия (семантическая: major при ревью, minor при точечном изменении), дата подписи, дата следующего ревью, режим (ядро/полный), статус аттестации.
- Разделы в порядке 1–9 + ритуал; каждое правило — в формате «Делаем X, пока Y, проверяем Z (кто, когда)».
- Приложение «Источники чисел»: таблица «число → интерактив → дата».
- Приложение «Принято с предупреждениями» — список с причинами.
- История версий: разница между версиями показывается как в 5.6 (что было / что стало / причина / дата вступления).

**7.2. Карточка партнёра** — одна страница, крупный шрифт, без терминов курса:
- Заголовок: «Если [имя оператора] недоступен(а)».
- Пять пунктов ровно в порядке Ж12. Пункт 1 — одна кнопка/одно действие без выбора. Пункт 4 «чего не делать» — список из 4 запретов.
- Внизу: триггеры (часы без связи), дата последнего тест-драйва, дата следующего.
- Отдельная печать: рекомендация «положить рядом с документами, не в телефон».

**7.3. Календарь ревью** — список событий с экспортом в файл календаря:
- Ежемесячно: ритуал ЖИ-18 (день из раздела 10), отчёт партнёру (раздел 8), выплата зарплаты (раздел 2).
- Ежеквартально: пересмотр зарплаты; учения трёх каналов (90 дней от последних).
- Раз в полгода: тест-драйв партнёра.
- Ежегодно: ревью устава; налоговые даты (из раздела 5, с пометкой «проверить на дату»); окончание полиса, аттестация детей (полный режим).
- По событию: «после переезда» — создаётся кнопкой в ЖИ-18.

### 8. Тексты интерфейса (ключевые)

- Подсказка детектора лозунгов: «"Будем аккуратны с тратами" — это пожелание. Правило: "Планку поднимаем не чаще раза в год, не больше чем на 10 %, и только если сейф после подъёма ≥ 24 мес — проверяет Марина по карточке месяца"».
- Подсказка раздела 3 при попытке снять запрет «сейф → торговый»: «Так разорился Игорь: докинул из подушки дважды. Если очень нужно — опиши единственное исключение с пределом».
- Плашка над разделом 9: «Этот раздел исполняет не оператор. Пиши так, чтобы человек без единого урока курса сделал всё за 10 минут».
- Экран 11, при молчании устава: «Устав молчит. В чёрный год этот вопрос решит не документ, а тот, у кого громче голос и хуже сон».
- Экран честности (на каждом экране мелко внизу): «Приложение ничего не проверяет на биржах и в банках. Все числа вводит семья».

### 9. События аналитики

`fc_started(mode)`, `fc_section_opened(n)`, `fc_rule_saved(section, rule_id, has_exception)`, `fc_validation_blocked(section, code)`, `fc_warning_accepted(section, code, reason_len)`, `fc_source_missing(section, interactive_id, action=manual|go_pass)`, `fc_stopword_hit(field, word)`, `fc_panic_check(answered_of_3)`, `fc_signed(operator, partner)`, `fc_attested(bool, missing[])`, `fc_exported(artifact)`, `fc_revision_created(kind=annual|move|triggered, changed_sections[])`.

### 10. Критерии приёмки

1. Из полностью заполненных ЧП1–ЧП3 и Ж-интерактивов устав в режиме «ядро» собирается за ≤ 20 минут без ручного ввода чисел (только подтверждения и подписи).
2. Ни одно правило не сохраняется без числа/даты в поле «Предел» (проверить 10 попытками ввода лозунгов).
3. Все блокирующие и предупреждающие проверки из §6 срабатывают на подготовленном наборе тестовых данных (передать агенту 12 кейсов).
4. Экран «Проверка паникой» корректно находит правила во всех трёх ситуациях на эталонном уставе и показывает «молчит» при удалении соответствующих правил.
5. Карточка партнёра печатается на одну страницу А4 при любом объёме устава; не содержит слов из глоссария курса (проверка по списку терминов).
6. Изменение раздела 9 вступает в силу сразу; изменение любого другого раздела вне ревью — с датой «через 7 дней» и обязательной причиной; в истории версий видна разница.
7. Ни в одном тексте интерфейса и артефактах нет названий стран, банков, бирж, школ, страховых, площадок (автотест по стоп-списку названий + ручная вычитка).
8. Аттестация недостижима, если ЧП3 не пройден партнёром или «Проверка паникой» < 3/3.

### 11. Открытые вопросы владельцу продукта

- Хранить ли карточку партнёра в аккаунте партнёра отдельно (свой логин) или только экспорт? Рекомендация: отдельный доступ «партнёр» с правом чтения устава, подписи и отметок в ЖИ-18 по пунктам 3 и 5.
- Нужна ли «мёртвая рука» как техническая опция (открытый вопрос № 8 этапа 1)? В ЖИ-17 предусмотреть поле-заглушку в разделе 9: «автоматический безопасный режим при N часах тишины: включён/нет/недоступно».

## ЖИ-18. «Семейная шкала процесса» (ежемесячный ритуал)

### 1. Назначение

Постоянный интерактив (не одноразовый тренажёр): раз в месяц семья ставит пять галочек по уставу и получает оценку **процесса**, а не денег. Переносит двойную отметку П8 и шкалу процесса П33 на масштаб семьи. Подключает уровни тревоги Ж5: по введённым числам приложение показывает, какой уровень объявляет устав, — а не оператор.

Ломаемое заблуждение (то же, что у ЖФ, в разрезе месяца): «Месяц прошёл нормально — значит всё в порядке». Оценка месяца — соблюдение пяти правил, независимо от знака результата.

Ага-момент: месяц с минусом и 5/5 подсвечен зелёным; месяц с плюсом и 3/5 — красным. Через 3–4 месяца сетка истории показывает это наглядно; при первом таком расхождении — всплывающая плашка «Судья считает технику, а не гол (П8)».

Зависимость: доступен только после подписания устава в ЖИ-17 (нужны числа-нормы). Первая отметка — часть аттестации трека.

### 2. Данные на входе (из ЖИ-17)

```json
{
  "charter_version": "1.0",
  "ritual_day": 1,
  "salary": { "amount": 0, "currency": "RUB", "pay_day": 5 },
  "safe_norm_months": 24,
  "monthly_spend": 0,
  "report_day": 1,
  "alert_levels": { "yellow": { "dd_pct": 0, "months_no_profit": 0 }, "red": { "safe_months_below": 12 } },
  "drills": { "channels": [ { "role": "", "last_drill_at": "" } ], "interval_days": 90 },
  "partner_test_drive": { "last_at": "", "interval_days": 180 },
  "residency": { "home_threshold_days": 183, "tracked_by": "оператор|партнёр" },
  "escalation": { "consecutive_low_months": 2, "low_threshold": 3 }
}
```

### 3. Экраны и логика

#### Экран А. Отметка месяца (основной)

Открывается в день ритуала (напоминание) или вручную. Заголовок: «Месяц [название] — карточка семьи». Подзаголовок: «Пять галочек. Деньги — отдельно и в самом конце».

Пять пунктов, каждый — переключатель «да / нет» плюс минимальный ввод:

| № | Пункт | Ввод | Кто отмечает | Авто-логика |
|---|---|---|---|---|
| 1 | Зарплата оператора выплачена по расписанию | дата фактической выплаты; сумма (предзаполнена нормой) | оператор | «да» только если дата ≤ день выплаты + 3 дня и сумма ≥ 95 % нормы; иначе пункт отмечается «нет» автоматически, с полем «источник выплаты: прибыль / сейф / не выплачена» |
| 2 | Сейф ≥ нормы | текущий размер сейфа в месяцах расходов (число) | оператор, подтверждает партнёр | «да» если ≥ норма; если < норма — «нет»; если < 12 — дополнительно поднимается красный флаг Ж5 |
| 3 | Отчёт партнёру показан | дата; чекбокс «в отчёте была кривая с просадкой, лет в сейфе, уровень тревоги» | **партнёр** (если у партнёра нет доступа — оператор с пометкой «со слов оператора») | «да» только при всех трёх карточках |
| 4 | Дни резидентства учтены | дни в домашней юрисдикции за месяц (число) и «счётчик обновлён» | назначенный в уставе | накопительный счётчик за год; предупреждение при приближении к порогу (за 20 дней) |
| 5 | Учения и тест-драйв не просрочены | автоматически из дат; кнопка «провели учения сегодня» обновляет дату канала | оператор | «да» если все каналы ≤ 90 дней и тест-драйв ≤ 180 дней |

Ниже — **отдельный блок «Результат месяца»** (свёрнут по умолчанию, заголовок «Только факт, не оценка»): знак результата торгового контура (плюс / минус / ноль), просадка от пика в % (число), месяцев без прибыли подряд (авто-счётчик по знакам). Эти данные не входят в счёт 5, но питают уровень тревоги.

Кнопка «Закрыть месяц». После нажатия — экран Б.

#### Экран Б. Итог месяца

- Крупно: «Процесс: N из 5». Цвет: 5 — зелёный, 4 — жёлто-зелёный, 3 — жёлтый, ≤ 2 — красный.
- Рядом мелко: «Результат: [знак]» — без цвета, серым. Подпись: «Судья считает технику. Гол — отдельно».
- Блок «Уровень тревоги по уставу»: вычисляется из введённых чисел и норм ЖИ-17:
  - Красный: сейф < 12 мес ИЛИ отмечен «сработали kill-критерии 5.6» (отдельный чекбокс в блоке результата).
  - Жёлтый: просадка > порога ИЛИ месяцев без прибыли ≥ порога ИЛИ сейф < нормы.
  - Иначе — зелёный.
  - Под уровнем — что предписывает устав (цитата из раздела 4 ЖИ-17: источник зарплаты, что режется, дата семейного совета). Формулировка: «Уровень объявил устав. Оператор не выбирал».
  - Если уровень изменился относительно прошлого месяца — обязательное поле «Партнёр уведомлён: дата» (нельзя закрыть карточку без него; это и есть защита от «Марина узнала от жены Игоря»).
- Блок «Что делать в этом месяце»: список пунктов с «нет» и конкретное действие из устава (например, пункт 5 → «провести учения канала "запасной", последний раз 104 дня назад»).
- Кнопка «Сохранить и напомнить через месяц».

#### Экран В. История (сетка)

- Сетка 12 месяцев (строки — год, столбцы — месяцы). Ячейка: цвет по процессу (0–5), маленький значок знака результата (▲ / ▼ / —), точка цвета уровня тревоги.
- Под сеткой: серия месяцев 5/5 подряд (не «стрик» — слово «серия»); число месяцев, где результат отрицательный, а процесс ≥ 4 («держали строй в минус»); число месяцев, где результат положительный, а процесс ≤ 3 («повезло вопреки правилам»). Второе число подсвечивается как повод для семейного совета.
- Клик по ячейке — карточка месяца (только чтение; правка задним числом — см. §5).

#### Экран Г. Эскалация

Срабатывает автоматически при закрытии месяца, если выполнено правило устава (по умолчанию: два месяца подряд ≤ 3/5) ИЛИ уровень красный ИЛИ пункт 3 «нет» два месяца подряд.

- Текст: «По уставу — внеплановый семейный совет и проверка разделов 2–4». Кнопка «Назначить совет» (создаёт событие в календаре) и «Открыть устав на ревизию» (ЖИ-17, внеплановая версия с типом `triggered`).
- Никаких советов по деньгам. Только процедурное действие из устава.

Отдельная кнопка на всех экранах: **«Мы переехали»** → создаёт внеплановое ревью устава в ЖИ-17 (тип `move`), напоминает проверить каналы доступа (Ж8), окна проверки (Ж9), дни резидентства (Ж6).

### 4. Напоминания

- За день до дня ритуала и в день ритуала. Если карточка не закрыта через 7 дней — повторное напоминание партнёру (если у него есть доступ) с текстом: «Карточка месяца не закрыта. По уставу её закрывают оба».
- Напоминания об учениях (за 10 дней до 90-го дня по каждому каналу) и о тест-драйве (за 14 дней до 180-го).
- Напоминание о резидентстве за 20 дней до порога — с плашкой честности «правила подсчёта дней проверяй на дату».

### 5. Крайние случаи

- Месяц пропущен: ячейка серая «не закрыт», считается как ≤ 3 для правила эскалации (пропуск ритуала — нарушение процесса). Закрыть задним числом можно в течение 15 дней после конца месяца; карточка получает метку «закрыта задним числом» (видна в истории). Позже 15 дней — только «пропущен».
- Партнёр без аккаунта: пункт 3 отмечает оператор, метка «со слов оператора»; при аттестации трека это допустимо, при 3 месяцах подряд — подсказка «подключи доступ партнёра».
- Устав пересобран (новая версия): нормы для следующих месяцев берутся из новой версии; прошлые карточки хранят версию, по которой оценивались.
- Смена валюты расходов: пункт 2 пересчитывается пользователем вручную; приложение не конвертирует.
- Отрицательные и нулевые значения в числах — блокируются с подсказкой.
- Пользователь в режиме «ядро»: пункт 4 (дни) присутствует всё равно (это ядро Ж6), пункт 5 включает только каналы и тест-драйв.

### 9. Критерии приёмки

1. Карточка месяца закрывается за ≤ 3 минуты при всех «да»; все пять пунктов имеют авто-логику из §3 (проверить на 8 подготовленных наборах: просроченные учения, сейф ниже нормы, зарплата с опозданием на 5 дней и т. д.).
2. Уровень тревоги вычисляется строго по порогам из ЖИ-17; при изменении уровня карточку невозможно закрыть без даты уведомления партнёра.
3. Счёт процесса никак не зависит от блока «Результат месяца» (юнит-тест: одинаковые галочки при плюсе и минусе дают одинаковый счёт и цвет).
4. Эскалация срабатывает ровно по правилу устава (по умолчанию 2 месяца ≤ 3/5) и при красном уровне; создаёт событие календаря и внеплановую версию в ЖИ-17 типа `triggered`.
5. Кнопка «Мы переехали» создаёт ревью типа `move` и три напоминания (каналы, окна проверки, дни).
6. Закрытие задним числом ограничено 15 днями и помечено в истории; пропущенный месяц отображается серым и участвует в эскалации.
7. Ни одного упоминания названий стран, банков, бирж; ни одного слова из стоп-списка в текстах интерфейса.
8. Первая закрытая карточка передаёт в ЖИ-17 флаг для аттестации трека.

### 10. Открытые вопросы владельцу продукта

- Показывать ли в сетке истории сумму в валюте (например, размер сейфа в деньгах)? Рекомендация: нет — только месяцы расходов и знаки; денежные суммы уводят внимание к результату, против которого построен ритуал.
- Разрешить ли партнёру закрывать карточку одному (без оператора)? Рекомендация: да, для пунктов 3 и 5 и для блока уведомления; пункты 1, 2, 4 — с меткой «со слов партнёра». Это поддерживает сценарий Ж12 «оператор недоступен».
