## Б.1. Схема данных одной задачи и контракт раннера

```yaml
id: py04_signal          # уникальный ID → используется карточками терминов и артефактами
lesson: Py-04
title: Правило покупки на просадке
minutes: 4
seedCode: |              # что видит ученик; строки с "# ✎" или "___" — редактируемые, остальные заблокированы
solution: |              # эталон; ученику показывается только после 4-й неудачи, и то — для перепечатывания руками
params:                  # скрытые прогоны: раннер подменяет значение в строках с "# @param <имя>" и запускает код заново
  - set: {price: 62000}
    expect: {signal: "WAIT"}
tests:                   # выполняются в пространстве имён ученика после его кода
  - assert: signal == "BUY"
    fail: "Текст, который увидит ученик, если условие ложно"
  - stdout: "Сигнал бота: BUY"          # точное сравнение вывода после strip()
sourceChecks:            # регулярные выражения ТОЛЬКО по редактируемым строкам — защита от «вписать ответ числом»
  - must: '^\s*if\b'
    fail: "..."
  - mustNot: 'price\s*='
    fail: "..."
hints:                   # сократовские: L1 — вопрос-указатель, L2 — сужение, L3 — форма без ответа
  L1: ...
  L2: ...
  L3: ...
errorHints:              # по типу исключения; ссылка на тренажёр «Traceback-детектив» (Py-16)
  IndentationError: "..."
```

**Правила показа подсказок:** L1 — после первой неудачной попытки или по кнопке; L2 — после второй; L3 — после третьей; после четвёртой — кнопка «Показать решение», решение не вставляется, а показывается рядом, ученик перепечатывает сам (иначе задача не засчитывается). Успех с первой попытки помечает термины урока как «понято руками» → карточка сразу во второй ящик Лейтнера (часть 3, §4.3).

**Анти-хардкод:** каждая задача имеет минимум один `params`-сценарий с другими данными и `mustNot`-проверку на литерал ответа. Заблокированные строки не участвуют в `sourceChecks`.

### Py-03 · Комиссия и отчёт

```yaml
id: py03_fee_fstring

seedCode: |
  price = 65000        # @param цена BTC, число
  amount = 0.01        # @param объём покупки, число
  fee_rate = 0.001     # комиссия биржи 0.1%

  fee = ___        # ✎ комиссия = цена × объём × ставка
  report = ___     # ✎ текст РОВНО такого вида:  Купил 0.01 BTC по цене 65000$
  print(report)

sourceChecks:
  - must: 'f["'']'

hints:
  L1: "Для комиссии: что из трёх переменных перемножить и каким знаком? Для отчёта: как в уроке вставляли содержимое коробок прямо в текст?"
  L2: "Комиссия — три множителя через *. Отчёт — строка с буквой f перед кавычкой и {фигурными скобками} вокруг ИМЁН переменных, а не вокруг чисел."
```

### Py-04 · Правило покупки на просадке

```yaml
id: py04_signal
lesson: Py-04
title: ЕСЛИ цена ниже уровня — покупаем
seedCode: |
  price = 58000    # @param текущая цена; скрытый тест подставит другие значения
  level = 60000    # уровень покупки на просадке

      signal = "BUY"
  else:

    expect: {signal: "WAIT"}

  - must: '^\s*else\s*:'
    fail: "Запасной план — слово else с двоеточием."
  - must: '<'
    fail: "«Ниже» — это знак «меньше»."
  - mustNot: 'price\s*='
    fail: "Не переназначай price — иначе скрытый тест не сможет подставить свою цену."
hints:
  L1: "Термометр: какой знак задаёт «ниже»? И что должно стоять в конце строки с if, чтобы бот понял — дальше идут действия?"
```

### Py-06 · Конвейер по свечам

```yaml
id: py06_for_counter
lesson: Py-06
title: Сколько свечей закрылись выше уровня
seedCode: |
  closes = [65100, 65050, 64980, 65020, 65120]   # @param
  level = 65000

  greens = 0   # счётчик: сколько закрытий выше уровня
  # ✎ напиши цикл: для каждой цены из closes — если она выше level, прибавь 1 к счётчику

  for price in closes:
      if price > level:
          greens = greens + 1

  - set: {closes: []}
    expect: {greens: 0}

    fail: "Счётчик считает не то. Проверь знак сравнения и что прибавляешь ровно 1 за каждую подходящую свечу."

    fail: "print должен сработать ОДИН раз, после цикла. Если строк вывода несколько — print попал внутрь цикла."
sourceChecks:
  - must: 'for\s+\w+\s+in\s+closes\s*:'
    fail: "Конвейер запускается словами for … in closes:"
  - must: '^\s+if\b'
```

### Py-08 · Паспорт свечи

```yaml
id: py08_dict
lesson: Py-08
title: Размах и тело свечи по паспорту
seedCode: |
  candle = {"open": 65000, "high": 65300, "low": 64800, "close": 65100, "volume": 120}  # @param

    fail: "Размах — high минус low."
  - assert: body == candle["close"] - candle["open"]
    fail: "Тело — close минус open, порядок важен: у красной свечи тело отрицательное."
sourceChecks:
```

## Б.4. Заметки для внедрения

1. **Раннер.** Pyodide в браузере: `seedCode` с подставленными редактируемыми строками выполняется в чистом пространстве имён; stdout перехватывается; затем последовательно выполняются `assert`-выражения. `params` — текстовая подмена значения в строке с маркером `# @param имя` и повторный прогон; ученику показываются сценарии, на которых упало, с подставленными значениями («При price = 62000 ожидали WAIT, получили BUY»).
2. **Заблокированные строки** реализуются как read-only регионы редактора (CodeMirror `readOnly` ranges). `sourceChecks` применяются только к редактируемому тексту.
3. **Ошибки** мапятся на «Traceback-детектив» (Py-16): при исключении показывается `errorHints[тип]`, если он есть, иначе общий совет «читай снизу вверх». Лестница подсказок L1–L3 при исключениях не расходуется.
4. **Артефакт.** Успешное решение Py-14 сохраняется как `alexey_bot_v1.py` в профиль ученика — это первый пункт допуска на уровень «Исследователь» (часть 3, §3.1), и на него ссылаются ВК4 и FT-01 («карта переноса»).
5. **Метрики для авторов.** Считать по каждой задаче: долю решивших с первой попытки, распределение по уровню подсказки, топ-3 текста `fail`. Задача, где больше 40 % доходят до L3, — сигнал, что предшествующий урок объясняет хуже, чем кажется.
