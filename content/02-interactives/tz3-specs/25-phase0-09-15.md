# ТЗ на два интерактива Фазы 0 (для агента-реализатора)

Оба интерактива подчиняются общим принципам ТЗ-3: один интерактив = одно заблуждение; все числа берутся из текста урока; полностью русскоязычный интерфейс; любое английское слово — с русской подписью и кликабельным пояснением.

---

## 0. Общие требования к обоим интерактивам

| Требование | Как выполнять |
|---|---|
| Язык | Весь UI на русском. Английские термины (Maker/Taker, Bid/Ask, drawdown) допускаются только в скобках после русского слова и только как кликабельные токены режима «Ткни в непонятное» (карточка: русское название → одна фраза смысла → ссылка на урок, где введён термин). |
| Числа | Никаких выдуманных чисел: используются значения из уроков 0.4, 0.9, 0.10, 0.12, 0.15, 1.8 (перечислены в каждом ТЗ). Все константы вынесены в конфиг компонента с указанием «источник: урок X». |
| Детерминизм | Любая случайность (перемешивание карточек, порядок доходностей) — через seedable-генератор; при `seed` из URL/пропса результат воспроизводим (для тестов и разбора с учеником). |
| Управление темпом | Анимации: кнопки «Шаг ▸», «Пауза», «Сначала», переключатель скорости ×1/×2/×4. Автопрокрутка по умолчанию выключена (ученик управляет сам). Никаких таймеров, штрафующих за медленность. |
| Адаптив | Ширина от 360 px. На мобильных стакан/график — вертикальная компоновка, кнопки ответа — крупные (≥ 48 px по высоте), под большим пальцем. |
| Доступность | Все действия доступны с клавиатуры (Tab/Enter/Space/стрелки для слайдера). Цвет никогда не единственный носитель смысла: у покупателей/продавцов и у верно/неверно есть иконка и текст. Контраст ≥ 4.5:1. `aria-live="polite"` для текстов обратной связи. |
| Прогресс | Компонент сообщает наружу события `interactive:started`, `interactive:completed`, `interactive:mastered` (см. критерии освоения ниже) и хранит состояние попыток в локальном хранилище ученика по ключу `id` интерактива. |
| Телеметрия | Именование событий: `f0.l09.mt.*` и `f0.l15.river.*`. Никаких персональных данных, только id ученика приложения. |
| Что НЕ делать | Не добавлять индикаторы, плечо, шорты, другие биржи, «реальные котировки». Не показывать проценты годовых и доходности «в целом» — только числа из урока. Не вставлять юмор в тексты ошибок: обратная связь уважительная, короткая, конкретная. |

## 1. Интерактив 0.9 — «Лимитка ≠ мейкер»

### 1.1. Паспорт

| Поле | Значение |
|---|---|
| id | `f0-l09-maker-taker` |
| Урок | 0.9 «Биржевой стакан и типы заявок (Лимитные и Рыночные)» |
| Тип | ИГР (мини-игра с обратной связью через ошибку) |
| Место в уроке | Сразу после блока «▸ Подробнее» (где введена тонкость Limit ≠ Maker) и ПЕРЕД существующим «Интерактивный стакан: Покупка 12 BTC». Логика: сначала ученик учится определять роль заявки, потом видит, как рыночная заявка съедает стакан. |
| Целевое заблуждение | «Лимитная заявка всегда дешевле рыночной, потому что лимитка = мейкер = маленькая комиссия». |
| Учебный результат | Ученик применяет одно правило: **роль заявки определяется не типом (лимит/рынок), а тем, касается ли её цена противоположной стороны стакана.** Может объяснить, почему лимит на покупку по 100 100 при лучшей цене продажи 100 005 — тейкер и по какой цене он исполнится. |
| Критерий освоения (`mastered`) | 6/6 верных ответов в **перемешанном** повторном раунде (первый раунд идёт в фиксированном порядке). Обязательное условие: карточки № 3 и № 5 (пересекающие лимитки) верны. |
| Длительность | 3–5 минут |
| Связи | Вперёд: 0.10 (проскальзывание — «а если объём больше уровня?»), 1.8 (комиссии в bps, Post-Only), Py-11 (bids[0]/asks[0] в коде). Назад: 0.4 (Bid/Ask/спред). |

### 1.2. Исходные данные (конфиг `orderBookSnapshot`)

Пара BTC/USDT. Числа из урока 0.9: лучшая цена продажи (Ask) **100 005**, лимит-пример **100 100**. Лучшая цена покупки (Bid) **100 000** (спред 5 USDT, согласуется с 0.4).

Стакан (5 уровней в каждую сторону):

| Продавцы (Ask), красные | Объём, BTC | | Покупатели (Bid), зелёные | Объём, BTC |
|---|---|---|---|---|
| 100 100 | 5,0 | | 100 000 | 1,0 |
| 100 050 | 3,5 | | 99 995 | 1,5 |
| 100 020 | 2,0 | | 99 990 | 2,2 |
| 100 010 | 1,2 | | 99 950 | 4,0 |
| **100 005** (лучшая) | 0,8 | | 99 900 | 6,0 |

Комиссии (источник: урок 1.8, таблица «Компонент трения»): мейкер **0,02 %**, тейкер **0,05 %**. В конфиге — параметры `makerFeePct`, `takerFeePct`. Все заявки в игре — по 0,5 BTC, чтобы объём никогда не превышал первый уровень (проскальзывание — тема 0.10, здесь его не смешиваем).

### 1.3. Правило классификации (реализовать в чистой функции `classifyOrder`)

```
вход: side ('buy'|'sell'), type ('market'|'limit'), price (для limit), book
если type == 'market'                      → 'taker', fill = лучшая противоположная цена
если side == 'buy'  и price >= bestAsk     → 'taker', fill = bestAsk   (не price!)
если side == 'sell' и price <= bestBid     → 'taker', fill = bestBid
иначе                                       → 'maker', fill = null (встаёт в очередь на своём уровне)
```

Функция покрыта юнит-тестами (см. 1.9). Комиссия: `fill * qty * fee`. Для мейкера показываем «если исполнится: … USDT».

### 1.4. Шесть карточек-заявок

Первый раунд — в этом порядке (нарастание сложности); повторные раунды — перемешивание с seed.

| № | Заявка (текст на карточке) | Верный ответ | Цена исполнения | Комиссия (0,5 BTC) | Что ломает |
|---|---|---|---|---|---|
| 1 | Рыночная покупка 0,5 BTC | Тейкер | 100 005 | 25,00 USDT | Разогрев: рынок = тейкер |
| 2 | Лимит на покупку 0,5 BTC по 99 900 | Мейкер | — (встанет в очередь на 99 900, за 6,0 BTC перед ним) | если исполнится: 9,99 USDT | Разогрев: «классическая» лимитка |
| 3 | **Лимит на покупку 0,5 BTC по 100 100** | **Тейкер** | **100 005** (не 100 100!) | 25,00 USDT | Ядро урока: лимитка, пересекающая стакан |
| 4 | Лимит на продажу 0,5 BTC по 100 200 | Мейкер | — (встанет выше всех продавцов) | если исполнится: 10,02 USDT | Зеркало №2 для продавца |
| 5 | **Лимит на продажу 0,5 BTC по 99 950** | **Тейкер** | **100 000** | 25,00 USDT | Зеркало №3: пересекает сторону покупателей |
| 6 | Лимит на покупку 0,5 BTC по 100 000 (ровно лучшая цена покупки) | Мейкер | — (встанет в очередь на лучшем уровне, за 1,0 BTC) | если исполнится: 10,00 USDT | Граничный случай: «равно лучшему bid» — ещё не касание ask |

Бонус-карточка № 7 (появляется только после `mastered`, кнопка «Ещё один хитрый случай»): «Лимит на покупку 2,5 BTC по 100 010». Три кнопки: Мейкер / Тейкер / **И то, и другое**. Верно: «И то, и другое» — 0,8 исполнится по 100 005 и 1,2 по 100 010 как тейкер (2,0 BTC), оставшиеся 0,5 встанут в очередь на 100 010 как новая лучшая цена покупки — мейкер. Подпись-мостик: «Так заявка съедает несколько уровней — это и есть проскальзывание, следующий урок 0.10».

### 1.5. Экран

Десктоп — две колонки; мобильный — стакан сверху (сжатый до 3 уровней с кнопкой «показать все 5»), карточка и кнопки снизу.

**Левая колонка — стакан.**
- Заголовок: «Стакан BTC/USDT прямо сейчас». Продавцы сверху (красные строки, стрелка вниз к центру), покупатели снизу (зелёные). Между ними полоска «Спред 5 USDT» (кликабельно → термин из 0.4).
- Лучшие цены выделены рамкой и подписаны: «лучшая цена продажи (Ask)» / «лучшая цена покупки (Bid)».
- Слева от каждой строки — маленькая иконка «очередь» (несколько силуэтов), число силуэтов пропорционально объёму (1 силуэт ≈ 1 BTC, максимум 6). Это визуальная опора для «встанет в очередь за 6,0 BTC».

**Правая колонка — карточка и ответ.**
- Прогресс: «Заявка 3 из 6» + шесть точек (серые/зелёные/красные).
- Карточка заявки: крупно тип и направление, цена. Направление подсвечено цветом стороны (покупка — зелёный, продажа — красный) плюс словом.
- Две крупные кнопки:
  - **«Мейкер — встанет в очередь»** (иконка: человек становится в конец очереди) с подписью мелким: *maker — «делатель» ликвидности*
  - **«Тейкер — исполнится сразу»** (иконка: рука забирает из очереди) с подписью: *taker — «забирающий» ликвидность*
- Под кнопками — подсказка-правило, изначально свёрнутая («Подсказка: один вопрос, который всё решает»). Раскрывается: «Спроси: **касается ли цена моей заявки противоположной стороны стакана?** Да → тейкер. Нет → мейкер. Тип заявки (лимит/рынок) сам по себе ответа не даёт». Использование подсказки не штрафуется, но фиксируется в телеметрии.

### 1.6. Сценарий одного хода

1. Появляется карточка. Ученик нажимает кнопку.
2. **Анимация в стакане (1,2 с, пропускаемая кликом):**
   - Мейкер: карточка «влетает» в стакан на свой ценовой уровень и встаёт в конец очереди силуэтов (появляется новый силуэт с меткой «ты»). Если уровень новый (100 200) — строка добавляется.
   - Тейкер: карточка летит к лучшей противоположной цене; часть объёма на этом уровне «сгорает» (0,8 → 0,3 BTC), появляется чек «Исполнено: 0,5 BTC по 100 005».
   - Для карточки № 3 — **обязательный акцент**: сначала карточка летит к уровню 100 100 (куда ученик интуитивно её кладёт), на полпути «останавливается» об лучшую цену продажи 100 005 с подписью: «Дальше идти незачем — здесь уже продают дешевле, чем ты готов купить». Исполнение по 100 005.
3. **Панель обратной связи** (зелёная/красная рамка + слово «Верно»/«Неверно»):
   - Роль: «Тейкер» / «Мейкер».
   - «Что произошло»: одно предложение (см. тексты 1.7).
   - «Цена исполнения»: число или «пока не исполнено — ждёт в очереди».
   - «Комиссия»: число в USDT с пометкой ставки (0,05 % тейкер / 0,02 % мейкер) и разницей: для тейкерских карточек — «на 15,00 USDT дороже, чем если бы заявка стала мейкером».
4. Кнопка «Дальше». После 6-й — итоговый экран.

### 1.7. Тексты обратной связи (обязательные формулировки)

**Верно** — короткое подтверждение + факт:
- №1: «Рыночная заявка не называет цену — она берёт лучшую из стакана. Это всегда тейкер».
- №2: «Цена 99 900 ниже всех покупателей и далеко от продавцов. Заявка встала в очередь — мейкер. Исполнится, только если цена спустится к ней».
- №3: «Ты готов купить по 100 100, а продавцы уже стоят по 100 005. Биржа не даст переплатить: исполнит по 100 005 — но как тейкера, с тейкерской комиссией. Лимитка не спасла от комиссии».
- №4: «100 200 выше всех продавцов — заявка встала в очередь на продажу. Мейкер».
- №5: «Ты готов продать по 99 950, а покупатели дают 100 000. Заявка ушла в покупателей мгновенно — тейкер, исполнение по 100 000».
- №6: «Цена ровно равна лучшей покупке. Ты не трогаешь продавцов — просто встаёшь в очередь за 1,0 BTC на том же уровне. Мейкер».

**Неверно** — назвать конкретную ошибку мышления, а не просто «нет»:
- №3 при ответе «Мейкер»: «Ты решил по типу заявки: „лимитная — значит мейкер“. Но правило другое: **касается ли цена противоположной стороны?** 100 100 ≥ 100 005 — касается. Заявка исполнилась мгновенно как тейкер».
- №5 при ответе «Мейкер»: «99 950 ниже лучшей покупки 100 000. Твоя продажа немедленно нашла покупателя — это тейкер».
- №2/№4/№6 при ответе «Тейкер»: «Цена заявки не дотягивается до противоположной стороны (укажи числа). Никто её сразу не заберёт — она ждёт. Это мейкер».
- №1 при ответе «Мейкер»: «У рыночной заявки нет своей цены — ей нечего ставить в очередь. Она всегда забирает из стакана».

### 1.8. Итоговый экран

- Счёт «Верно 4 из 6» с точками; отдельная строка: «Ключевые карточки (лимитки, пересекающие стакан): 1 из 2».
- **Карточка правила** (сохраняется в «Термины урока»/глоссарий как «прожитое»):
  > **Роль заявки определяет цена, а не тип.**
  > Покупка: цена ≥ лучшей продажи → тейкер. Продажа: цена ≤ лучшей покупки → тейкер. Иначе — мейкер.
  > Тейкер платит больше (здесь 0,05 % против 0,02 %), но получает исполнение сразу. Мейкер платит меньше, но может не исполниться вовсе.
- **Сравнительная табличка «Три способа купить 0,5 BTC»** (закрывает заблуждение цифрами):

| Способ | Исполнение | Комиссия | Риск |
|---|---|---|---|
| Рыночная | сразу, 100 005 | 25,00 USDT | переплата при тонком стакане (→ 0.10) |
| Лимит по 100 100 («чтобы точно купить») | сразу, 100 005 | 25,00 USDT | та же комиссия, что у рыночной |
| Лимит по 100 000 (в очередь) | неизвестно когда | 10,00 USDT | может не исполниться — сигнал упущен |

- Кнопки: «Ещё раз (заявки перемешаются)» и, после `mastered`, «Ещё один хитрый случай» (бонус №7).
- Мостик: «Дальше: что происходит, когда объём заявки больше, чем стоит на лучшем уровне → урок 0.10 и симулятор „Покупка 12 BTC“ ниже».

### 1.9. Тесты и приёмка

Юнит-тесты `classifyOrder`: 6 карточек + бонус + граничные (buy limit = bestAsk → taker; sell limit = bestBid → taker; buy limit = bestBid → maker). Комиссии считаются от цены исполнения, не от цены заявки (для №3 — от 100 005).

Чек-лист приёмки:
- [ ] Карточка №3 анимирует «остановку об 100 005», цена исполнения показана 100 005, комиссия 25,00.
- [ ] Ни одно английское слово не отображается без русского эквивалента; Maker/Taker/Bid/Ask/спред кликабельны.
- [ ] Повторный раунд перемешан; при одинаковом `seed` порядок одинаков.
- [ ] `mastered` срабатывает только в перемешанном раунде при 6/6 и верных №3 и №5.
- [ ] Подсказка-правило доступна на любом шаге и не меняет счёт.
- [ ] Мобильная раскладка: стакан сверху (3 уровня + «показать все»), кнопки ответа ≥ 48 px.
- [ ] Все тексты из 1.7 присутствуют дословно (допускается правка орфографии).

Телеметрия: `f0.l09.mt.answer {card, chosen, correct, hintOpened, round}`, `f0.l09.mt.round_completed {score, keyCardsCorrect, round}`, `f0.l09.mt.mastered`.

## 2. Интерактив 0.15 — «Река глубиной 1 метр»

### 2.1. Паспорт

| Поле | Значение |
|---|---|
| id | `f0-l15-river-1m` |
| Урок | 0.15 «Разброс результатов и стабильность (Дисперсия и Риск)» |
| Тип | АНИМ + СИМ (покадровая анимация с одним управляемым параметром) |
| Место в уроке | Сразу после блока «Аналогия» (про реку с ямой в 5 метров), перед существующим «Интерактивное сравнение двух стратегий». Существующее сравнение показывает разброс; новый интерактив показывает **путь** и цену ямы для человека, который в этой реке плывёт. |
| Целевое заблуждение | «Одинаковое среднее = одинаковый риск» и его следствие: «средний результат я всё равно получу». |
| Учебный результат | Ученик видит, что (1) при равном среднем одна стратегия проходит через яму −20 %; (2) яма опасна не сама по себе, а тем, что в ней **выключают** стратегию — и тогда среднее уже не наступает никогда; (3) глубина ямы зависит от порядка результатов даже при том же среднем. Ученик формулирует: «предел просадки надо записывать до старта». |
| Критерий освоения (`mastered`) | Ученик (а) дошёл до конца анимации, (б) подвигал ползунок так, что увидел оба исхода (Б выключена / Б дожила), (в) верно ответил на итоговый вопрос «Проверь себя». |
| Длительность | 4–6 минут |
| Связи | Назад: 0.12 (асимметрия восстановления: после −20 % нужно +25 %), 0.13 (малая выборка). Вперёд: 1.1 (лог-доходности: −20 и +25 не сокращаются), М8 (те же ряды, стандартное отклонение 0,7 против 22,6), 5.5 (kill-критерии заранее), П4/П10 (выход на дне). |

### 2.2. Исходные данные (конфиг `strategies`)

Из урока 0.15 дословно:

- Стратегия А: **+5 %, +4 %, +6 %, +5 %, +5 %** — среднее +5,0 %.
- Стратегия Б: **−20 %, +25 %, −15 %, +30 %, +5 %** — среднее +5,0 %.

Производные величины (вычисляются кодом, не хардкодятся; эталонные значения для тестов):

| Величина | А | Б |
|---|---|---|
| Капитал по периодам (старт 100) | 105,0 · 109,2 · 115,8 · 121,5 · 127,6 | 80,0 · 100,0 · 85,0 · 110,5 · 116,0 |
| Итог | +27,6 % | +16,0 % |
| Максимальная просадка от пика | 0 % | 20 % (период 1); вторая яма 15 % (от 100 к 85) |
| Стандартное отклонение (выборочное, как в М8) | 0,7 | 22,6 |

Просадка: `dd_t = (peak_t − equity_t) / peak_t`, где `peak_t` — максимум капитала до текущего периода включительно (определение из урока 0.12).

Пятиэлементный ряд — иллюстрация из урока; в интерактиве обязательно есть подпись «5 периодов — это картинка, а не статистика (урок 0.13)».

### 2.3. Экран

Три яруса сверху вниз.

**Ярус 1 — «река» (лёгкая иллюстрация, не интерактив).** Статичный SVG: две дорожки на реке, по каждой плывёт пловец (А — синий круг, Б — оранжевый). Под водой — дно: у А ровное на глубине «1 м», у Б в первом сегменте яма. Подпись: «Средняя глубина у обеих рек одинаковая. Утонуть можно только в одной». Пловцы синхронно двигаются с прогрессом анимации в ярусе 2 (одна общая шкала прогресса, 5 сегментов).

**Ярус 2 — график капитала (главный элемент).**
- Ось X: периоды 0…5 с подписями «старт, 1, 2, 3, 4, 5». Ось Y: капитал 60…140, старт 100 подписан «100 = твои деньги на старте».
- Две ломаные, рисуются поэтапно: А (синяя, тонкая), Б (оранжевая, жирнее). Над каждой новой точкой всплывает результат периода: «+5 %», «−20 %».
- Для Б под кривой рисуется **скользящая красная пунктирная линия «мой предел просадки»**: `y = peak_t × (1 − L)`. Подпись у линии: «черта, ниже которой я выключаю Б». Линия поднимается вслед за пиком — это важный визуальный эффект (предел считают от пика, а не от старта).
- Горизонтальная тонкая серая линия «уровень среднего +5 % за период» (капитал, если бы каждый период давал ровно +5 %: 105, 110,3, 115,8, 121,6, 127,6) — та самая «средняя глубина 1 м». Подписана: «так выглядит „среднее“, которого никто не проживает».
- Управление: «Сначала», «◂ Шаг», «Шаг ▸», «Пауза/Играть», скорость ×1/×2/×4.

**Ярус 3 — панель управления и результата.**
- Ползунок **«Мой предел просадки: N %»**, диапазон 5…35, шаг 1, по умолчанию 10. Подпись под ползунком: «Какую яму от пика ты выдержишь, не нажав „выключить“? Честно». Если анимация ещё не доиграна — ползунок активен, линия на графике меняется в реальном времени.
- Три плитки результата (заполняются после конца анимации или при перемотке в конец):
  1. **«А (плывёшь дальше)»** — «+27,6 %. Ям не было».
  2. **«Б, если бы ты дотерпел»** — «+16,0 %. Худшая яма −20 %».
  3. **«Б с твоим пределом N %»** — динамическая, см. 2.4.
- Под плитками — блок «Что это значит» (текст зависит от исхода, см. 2.5).

### 2.4. Логика выключения (функция `simulateWithLimit(returns, L)`)

Проверка в конце каждого периода: если `dd_t ≥ L` → стратегия выключается в этом периоде, капитал фиксируется на `equity_t`, оставшиеся периоды показываются на графике **призрачной пунктирной линией** («что сделала бы Б без тебя»). Момент выключения отмечается иконкой рубильника с подписью «Здесь ты выключил Б».

Эталонные исходы для тестов:

| L | Выключение | Зафиксировано | Упущено после выключения |
|---|---|---|---|
| 5…20 % | период 1 (dd = 20 % ≥ L) | 80 → **−20 %** | +25 %, −15 %, +30 %, +5 % (Б дошла бы до 116) |
| 21…35 % | не выключена | 116 → **+16,0 %** | — |

Граница «≥» намеренная: «предел достигнут» = выключение. Это сказано в подписи ползунка при L = 20: «Ровно 20 % — это уже твой предел, а не „почти“».

### 2.5. Тексты блока «Что это значит»

**Исход «выключил» (L ≤ 20):**
> Обе стратегии обещали «в среднем +5 %». Но среднее — это итог **всего пути**. Ты вышел из Б на дне, в период 1, с −20 %. Чтобы вернуться к 100, ей нужно было +25 % (урок 0.12) — и ровно +25 % она сделала в следующем периоде. Без тебя.
> Итог: А — +27,6 %, Б без вмешательства — +16,0 %, твоя Б — **−20 %**. Одинаковое среднее не защитило: **риск — это глубина ямы, а не средняя глубина реки.**

**Исход «дотерпел» (L > 20):**
> Ты выдержал яму −20 % и получил +16,0 %. Два замечания. Первое: это 5 периодов — картинка, а не статистика (урок 0.13); в жизни яма могла быть глубже, чем твой предел. Второе: даже дотерпев, ты получил меньше, чем А (+27,6 %) при том же среднем +5 %. Почему −20 % и +25 % не сократились до нуля — урок 1.1.
> Проверь: нажми «Перемешать порядок Б» — среднее не изменится, а яма может стать глубже твоего предела.

Постоянная сноска под блоком (оба исхода): «Предел просадки — цифра, которую записывают **до** старта, спокойной головой. В момент ямы её уже не выбирают, а исполняют (позже: уроки 5.5 и П4)».

### 2.6. Режим «Глубже» (сворачиваемая секция)

Кнопка **«Перемешать порядок Б»**: те же пять чисел в случайном порядке (seedable). Пересчёт: среднее остаётся +5,0 %, итог остаётся +16,0 % (при показе пояснить: «те же множители, тот же итог»), стандартное отклонение то же 22,6, а **максимальная просадка меняется от 20 % до 32 %**. Показать три числа рядом: «Среднее: не изменилось · Итог: не изменился · Худшая яма: было 20 %, стало N %». При выключении по текущему L — рубильник переезжает.

Кнопка «Показать худший порядок» — ставит перестановку `−20, −15, +25, +30, +5` (капитал 80 → 68, просадка 32 %) и подпись: «Те же пять результатов. При твоём пределе N % ты выключил бы Б здесь».

Плашка чисел разброса (из М8, чтобы цифры совпадали между уроками): «Стандартное отклонение: А — 0,7; Б — 22,6. Это и есть математическое имя ямы; подробнее — Матфак М8–М9».

### 2.7. Итоговый вопрос «Проверь себя» (обязателен для `mastered`)

«Две стратегии дали в среднем +5 % за период. Что из этого верно?»
1. У них одинаковый риск — среднее одно и то же.
2. Среднее наступает только для того, кто дошёл до конца пути; глубина ямы решает, дойдёшь ли ты. ✓
3. Стратегия с ямой всегда прибыльнее, потому что после падения обязан быть рост.
4. Предел просадки лучше выбирать по ситуации, когда яма уже началась.

Обратная связь на неверные: 1 → «Среднее — про итог, риск — про путь; ты только что видел −20 % при среднем +5 %». 3 → «Рынок никому ничего не обязан (урок 0.13); совпадение +25 % — иллюстрация, не закон». 4 → «В яме решение принимает страх; цифру пишут до старта».

### 2.8. Состояния и переходы

`idle` (график пуст, видна только сетка и стартовые 100) → `playing`/`paused` (по шагам) → `finished` (плитки заполнены, блок «Что это значит») → `deeper` (перемешивание) → `quiz` → `completed`.
Смена ползунка в `finished` мгновенно пересчитывает плитку 3, рубильник и призрачную линию без перезапуска анимации. Смена ползунка в `playing` — двигает только красную линию.

### 2.9. Тесты и приёмка

Юнит-тесты: `equityPath`, `maxDrawdown`, `simulateWithLimit` на эталонных значениях из 2.2 и 2.4; проверка, что перемешивание не меняет итог (116,03 ± 0,01) и среднее; худший порядок даёт просадку 32 %.

Чек-лист приёмки:
- [ ] Красная линия предела рисуется от **скользящего пика**, а не от 100 (при L = 10 после периода 4 линия у Б стоит на 99,45, у пика 110,5).
- [ ] При L ≤ 20 рубильник в периоде 1, плитка 3 = −20 %, призрачная линия доводит Б до 116.
- [ ] При L > 20 рубильник отсутствует, плитка 3 = +16,0 %.
- [ ] Серая линия «среднего» заканчивается ровно на 127,6 (совпадает с А только потому, что у А почти нет разброса — это допустимо и даже полезно).
- [ ] Пловцы яруса 1 синхронны с прогрессом графика; яма под Б — в первом сегменте.
- [ ] Тексты 2.5 и подписи ползунка присутствуют; сноска про «цифру до старта» видна в обоих исходах.
- [ ] Перемешивание воспроизводимо по `seed`; кнопка «худший порядок» даёт 32 %.
- [ ] Клавиатура: стрелки на ползунке шаг 1, Shift+стрелки шаг 5; «Шаг ▸» — клавиша →.
- [ ] `mastered` = дошёл до конца + видел оба исхода (L ≤ 20 и L > 20) + верный ответ на вопрос.

Телеметрия: `f0.l15.river.finished {limit}`, `f0.l15.river.limit_changed {from, to, outcome}`, `f0.l15.river.shuffled {seed, maxDD}`, `f0.l15.river.quiz {chosen, correct}`, `f0.l15.river.mastered`.
