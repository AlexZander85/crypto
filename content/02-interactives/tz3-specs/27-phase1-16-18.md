# Спецификации интерактивов Фазы 1 для реализации агентом

Ниже — два ТЗ в едином формате: цель и заблуждение → канонические числа урока → экран → модель (формулы + псевдокод) → сценарий прохождения → тексты обратной связи → языковой слой → критерии освоения → тесты и приёмка. Всё, что показывается ученику, — на русском; английские токены только через режим «Ткни в непонятное».

---

## Общие требования к обоим интерактивам

| Требование | Реализация |
|---|---|
| Место в уроке | Вставляется отдельным блоком после абзаца «Подробнее», перед существующими симуляторами урока (не заменяет их) |
| Числа | Только из текста урока (см. таблицы «Канон» ниже). Любое производное число подписывается «получено из …» |
| Язык | Интерфейс полностью русский. Каждый английский токен в коде/подписях — кликабельный (движок E1 «Терминал-переводчик»: клик → русская карточка 1–2 предложения + ссылка на термин урока) |
| Переключатель языка кода | «англ. / рус. подписи / оба» (по умолчанию — «оба»: код слева, русская подпись каждой строки справа) |
| Сквозной персонаж | Депозит Алексея 1000 $ используется как база для всех «в деньгах» |
| Состояние | Всё состояние в URL-параметрах (шаринг сценария) + localStorage последнего набора |
| Вычисления | В Web Worker; UI не блокируется |
| Адаптив | ≥ 360 px; на мобильных панели идут вертикально, графики — свайпом |
| Аналитика | События: `open`, `preset_applied`, `toggle_*`, `slider_release`, `quiz_answer`, `complete` (payload — текущие параметры) |
| Доступность | Все ползунки — `<input type=range>` с `aria-valuetext` на русском; цветовые различия дублируются формой/штриховкой |

# ТЗ-1.6 «Кассир против сканера»

## 0. Паспорт

| Поле | Значение |
|---|---|
| ID | `sim_1_6_cashier_vs_scanner` |
| Урок | 1.6 «Архитектура векторного бэктеста» |
| Тип | СИМ + мини-ИГР (финальная проверка) |
| Заблуждение | **«Быстрее = правильнее»**: ученик приравнивает векторизацию к честности (и наоборот — считает медленный цикл «более честным», как в аналогии урока «событийный — честный») |
| Целевое понимание | Скорость определяется методом расчёта; честность определяется сдвигом на один бар и учётом издержек. Это две независимые оси. Векторный и построчный расчёт при одинаковых правилах дают **идентичную** кривую капитала; утечка будущего одинаково ломает оба |
| Длительность | 4–6 минут |
| Движки | E1 (переводчик кода), E8 (двуязычные метрики), опционально E3 (шаг «что видел бот») |

## 1. Канон — числа и код из урока

| Источник в уроке | Значение | Как используется |
|---|---|---|
| Блок «Числа» | 1 000 000 минутных баров ≈ 2 года; цикл `for` — 18,5 с; векторное умножение — 3,2 мс; ускорение ≈ ×5 700 | Коэффициенты секундомера: **18,5 мкс/бар** (цикл), **3,2 нс/бар** (вектор). Отношение 5 781 → подпись «≈ ×5 700 (как в уроке)» |
| Код «минимальный честный векторный бэктест» | `signal = close > rolling(50).mean()`; `pos = signal.shift(1).fillna(0)`; `gross = pos * log_ret`; `turnover = pos.diff().abs()`; `cost_bps = 7.5`; `net = gross − turnover*cost_bps/10000`; `equity = exp(cumsum(net))` | Единственная модель расчёта. Окно 50 и 7,5 bps — дефолты, не редактируются (только показываются) |
| «Подробнее» | «сдвиг на один бар обязателен, иначе ты торгуешь по цене, которую в момент решения ещё не знал» | Текст на переключателе утечки |
| «Важно» | «Главная опасность векторного бэктеста — случайный look-ahead bias при неаккуратном применении shift()» | Финальная подпись |
| Урок 1.7, «Числа» | утечка → Sharpe 9,8; после исправления → −0,42 | Только как справка «порядок величины» в карточке результата (не воспроизводится, у нас другой генератор) |
| Аналогия | «кассир пробивает 1 миллион товаров поштучно… сканер — контейнер за один импульс» | Визуальная метафора секундомера |

## 2. Экран

Три зоны сверху вниз (на десктопе — 2 колонки: слева управление+код, справа графики).

### Зона А — «Секундомер» (верх)
- Ползунок **«Сколько баров»**: дискретный, значения 10⁴ / 10⁵ / 10⁶; подписи «10 000 (≈ 7 дней минуток)», «100 000 (≈ 70 дней)», «1 000 000 (≈ 2 года — как в уроке)».
- Две дорожки-анимации:
  - **«Кассир (цикл for)»** — иконка кассира, лента товаров, счётчик «пробито: 0 / N», секундомер.
  - **«Сканер (вектор)»** — иконка сканера, весь контейнер, одна вспышка, секундомер.
- Кнопка **«Запустить оба»**. Анимация идёт в сжатом времени: экранная секунда = 1 реальная секунда цикла на 10⁴, далее ускоряется (для 10⁶ анимация кассира длится ≤ 8 с с индикатором «×2,3 быстрее реального»). Секундомеры показывают **расчётное** время по коэффициентам урока (не реальное время браузера).
- Под секундомерами строка: «Разница: **×5 700**. Это — про скорость. Сейчас проверим, про честность ли она».
- Свёрнутый блок **«Глубже: замерить в моём браузере»** — реальный замер JS-цикла и векторного (TypedArray) расчёта в Worker, вывод с подписью: «В браузере другие цифры (не Python и не pandas), но пропорция та же: метод меняет скорость».

### Зона Б — «Честность» (середина)
Матрица 2×2 переключателей, визуально таблица:

|  | Честно (`shift(1)`) | Утечка (без сдвига) |
|---|---|---|
| **Сканер (вектор)** | `pos = signal.shift(1)` | `pos = signal` |
| **Кассир (цикл)** | `pnl[i] = pos[i-1] * ret[i]` | `pnl[i] = pos[i] * ret[i]` |

- Один общий тумблер **«Убрать сдвиг на бар (заглянуть в будущее)»** — переключает обе строки сразу; отдельный маленький переключатель «применить только к…» (вектор / цикл / оба) для продвинутого режима.
- Тумблер **«Учитывать издержки 7,5 bps»** (по умолчанию включён; при выключении подпись: «так выглядит бэктест, который забыл про урок 1.8»).
- Панель кода (E1): показывается **тот вариант, который сейчас активен**, с подсветкой изменённой строки; каждая строка — русская подпись справа. Клик на любой токен (`shift`, `fillna`, `rolling`, `log_ret`, `cumsum`, `exp`, `turnover`, `bps`) — карточка.
- Кнопка **«Новый шум»** (перегенерировать ряд, seed отображается: «шум №…», можно ввести вручную).

### Зона В — «Результат» (низ)
- График кривой капитала: 4 линии (кассир-честно, сканер-честно, кассир-утечка, сканер-утечка). Честные — сплошная, утечка — пунктир; кассир — синий, сканер — оранжевый. Совпадающие линии рисуются со смещением 1 px, чтобы было видно «две линии лежат друг на друге». Подпись при наведении: «Кривые совпадают до последней цифры».
- Карточки метрик (E8, каждая с русским именем, формулой и зоной):
  - «Итог, %» (equity[-1]−1)
  - «Шарп, годовой» (mean/std × √(365·24·60) для минутных баров)
  - «Сделок» (сумма turnover / 2)
  - «Издержки съели, %» (Σ turnover·7,5/10 000)
  - «Время расчёта» (из зоны А)
- Строка-вердикт (динамическая, см. §5).
- Мини-шаг «Что видел бот» (E3-light): слайдер по 30 барам вокруг случайного сигнала; для активного режима стрелка показывает, **какая доходность** умножилась на сигнал — `ret(t+1)` (честно) или `ret(t)` (утечка), с подписью «свеча t ещё не закрылась, когда бот "решил"».

## 3. Модель

### 3.1 Генератор данных
```
seed → PRNG (mulberry32)
N ∈ {1e4, 1e5, 1e6}
log_ret[t] ~ Normal(μ=0, σ=0.0006)      # минутный BTC-масштаб (σ дневная ≈ 2.3%)
close[t] = exp(cumsum(log_ret))
```
Чистый шум без памяти — по замыслу: честная стратегия на нём ≈ 0 минус издержки; утечка рисует прибыль из ничего (потому что `close[t] > SMA[t]` коррелирует с `ret[t]`).

### 3.2 Расчёты (в Worker, Float64Array)
```
sma[t] = mean(close[t-49..t])                  # t ≥ 49, иначе NaN → signal 0
signal[t] = close[t] > sma[t] ? 1 : 0

# ВЕКТОР
pos_v  = honest ? shift1(signal) : signal      # shift1: pos[0]=0
gross_v[t] = pos_v[t] * log_ret[t]
turn_v[t]  = |pos_v[t] − pos_v[t-1]|
net_v[t]   = gross_v[t] − (costs ? turn_v[t]*7.5/1e4 : 0)
equity_v   = exp(cumsum(net_v))

# ЦИКЛ (тот же результат, другой способ)
for i in 1..N-1:
    p = honest ? signal[i-1] : signal[i]
    g = p * log_ret[i]
    tr = |p − p_prev|
    net_l[i] = g − (costs ? tr*7.5/1e4 : 0)
    p_prev = p
equity_l = exp(cumsum(net_l))
```
Инвариант: при одинаковых флагах `max|equity_v − equity_l| < 1e-9`. Показывать эту разницу в подписи «расхождение методов: 0.000000000».

### 3.3 Секундомер (расчётный)
```
t_loop_sec = N * 18.5e-6
t_vec_sec  = N * 3.2e-9
ratio      = 5781 → подпись «≈ ×5 700 (в уроке округлено)»
```
Форматирование: < 1 мс → «0,03 мс»; < 1 с → «185 мс»; иначе «18,5 с».

### 3.4 Метрики
```
total_pct = (equity[-1] − 1) * 100
sharpe    = mean(net) / std(net) * sqrt(365*24*60)
trades    = sum(turn) / 2
cost_pct  = sum(turn) * 7.5 / 1e4 * 100
```

## 4. Сценарий прохождения (направляемый режим — по умолчанию)

Шаги открываются последовательно; каждый — короткая подсказка сверху, кнопка «Дальше» активируется по действию.

1. **«Запусти оба»** → секундомеры. Подсказка: «Сканер быстрее в тысячи раз. Запомни это число — и посмотри на кривые внизу».
2. Раскрывается зона В: две **честные** кривые совпадают. Подсказка: «Обе линии — одна линия. Метод не изменил ни одного числа результата. Он изменил только время».
3. Тумблер **«Убрать сдвиг на бар»**. Подсказка: «А теперь заглянем в будущее — сразу в обоих методах». Появляются пунктирные кривые, резко вверх. Вердикт: «Кассир и сканер солгали одинаково. Утечка — не свойство метода, а свойство одной строки кода».
4. Возврат сдвига, выключение **издержек**. Подсказка: «И последнее: честный сдвиг без комиссий — тоже фантазия, только скромнее». Кривая приподнимается; карточка «издержки съели» обнуляется.
5. Финальная проверка (§6).

Свободный режим доступен после прохождения или по кнопке «Пропустить подсказки».

## 5. Тексты обратной связи (динамическая строка-вердикт)

| Состояние | Текст |
|---|---|
| честно + издержки | «Две кривые совпадают. Итог ≈ {total}%: на чистом шуме честная стратегия зарабатывает ноль и платит {cost}% комиссий. Скучно — и правильно» |
| утечка (оба) | «Итог {total}%, Шарп {sharpe}. Эту кривую нельзя получить деньгами: бот умножал сигнал свечи t на доходность той же свечи t, а знать close(t) в момент решения невозможно. Для сравнения: в уроке 1.7 такая же ошибка давала Шарп 9,8» |
| утечка только у цикла | «Медленный ≠ честный: цикл подсмотрел в текущую свечу и нарисовал {total}%, а быстрый вектор со сдвигом остался в нуле» |
| утечка только у вектора | «Быстрый ≠ честный: вектор без shift(1) нарисовал {total}%. Цикл с честным индексом i−1 — в нуле» |
| без издержек | «Без 7,5 bps за смену позиции кривая приподнялась на {Δ}%. Столько твоя стратегия "заработала бы", если бы биржа работала бесплатно. Об этом — урок 1.8» |
| после шага 4 (итог) | «Скорость — про метод. Честность — про сдвиг и издержки. Векторный бэктест выбирают за скорость отсева идей, а не потому, что он "честнее" или "нечестнее" цикла. И помни: даже честный вектор оптимистичен — он не знает про очередь в стакане и частичное исполнение (это уже событийный бэктест)» |

## 6. Критерий освоения (мини-ИГР)

Экран из трёх утверждений, выбрать все верные (multi-select), затем «Проверить»:
1. «Векторный расчёт даёт более точный результат, чем цикл» — ✗
2. «Цикл по свечам честнее, потому что идёт бар за баром, как реальная торговля» — ✗
3. «Честность бэктеста определяет строка `pos = signal.shift(1)` и учёт издержек, а не способ расчёта» — ✓
4. «Если убрать shift(1), результат вырастет и в цикле, и в векторе» — ✓

Обратная связь на неверный выбор ссылается на шаг сценария («вернись к шагу 3: кассир и сканер солгали одинаково»). Интерактив считается пройденным при 4/4; при ошибке разрешена повторная попытка после повторного просмотра шага.

Дополнительно (опционально, режим «ТРН»): собрать из чипов честную строку: `pos` `=` `signal` `.shift(1)` `.fillna(0)` — ловушка-чип `.shift(-1)` с объяснением при выборе.

## 7. Словарь «Ткни в непонятное» (минимум)

| Токен | Карточка (RU) |
|---|---|
| `shift(1)` | «Сдвинуть столбец на одну строку вниз: решение свечи t действует на свече t+1. Это и есть "торгуй по цене, которую уже знаешь"» |
| `shift(-1)` | «Сдвиг вверх — подсмотреть следующую свечу. В бэктесте — утечка будущего» |
| `fillna(0)` | «Первая строка после сдвига пустая — считаем "позиции нет"» |
| `rolling(50).mean()` | «Среднее последних 50 свечей — скользящая средняя» |
| `log_ret` | «Логарифмическая доходность свечи (урок 1.1): её можно складывать» |
| `turnover` | «Оборот: сколько раз позиция сменилась. За каждую смену платим издержки» |
| `bps` | «Базисный пункт: 1 bps = 0,01 % (урок 0.10)» |
| `cumsum` / `exp` | «Накопленная сумма лог-доходностей → обратно в проценты капитала» |
| `for i in range(...)` | «Цикл: перебираем свечи по одной — кассир» |
| `Sharpe` | «Шарп: средняя доходность / разброс, годовая (урок 1.10)» |

## 8. Тесты и приёмка

Юнит-тесты (golden):
- `timer(1e6) → {loop: 18.5, vec: 0.0032, ratio≈5781}`; `timer(1e4) → {loop: 0.185, vec: 0.000032}`.
- Для любого seed и любых флагов: `max|equity_v − equity_l| < 1e-9`.
- Для честного режима с издержками на 1e5 барах, среднее по 20 seed: `total_pct ∈ (−15%, +5%)`; для утечки: `total_pct > +30%` и `sharpe > 3` (иначе пересмотреть σ генератора).
- Выключение издержек увеличивает `total_pct` ровно на `cost_pct` (в лог-пространстве: разница `cumsum(net)` равна `Σ turn·7.5e-4`).

Приёмка UX:
- 1e6 баров: расчёт всех четырёх вариантов ≤ 2 с в Worker, UI не замирает.
- Совпадающие честные линии визуально различимы как две (смещение/легенда), при наведении — подпись о совпадении.
- Все английские токены на экране — кликабельны; режим «рус. подписи» не оставляет ни одной непереведённой подписи, кроме имён переменных.

# ТЗ-1.8 «Наценка 5, доставка 8»

## 0. Паспорт

| Поле | Значение |
|---|---|
| ID | `sim_1_8_markup5_delivery8` |
| Урок | 1.8 «Учёт трения: комиссии Maker/Taker, слиппедж» |
| Тип | СИМ (с преднастроенными сценариями) + мини-ИГР |
| Заблуждение | **«Мейкер-комиссия 0 % — это бесплатно»**: ученик видит строку тарифа и не видит, куда переезжает издержка — в пропущенные сигналы, погоню за ценой и худшее качество исполненных заявок |

| Целевое понимание | Издержки считаются в bps на транзакцию и умножаются на их число за год; переход на лимитные заявки переносит стоимость из «комиссии» в «неисполнение»; сравнивать нужно не тарифы, а годовой итог с учётом доли исполненных сигналов |
| Длительность | 5–7 минут |
| Движки | E1, E8 |

## 1. Канон — числа из урока

| Источник | Значение | Роль |
|---|---|---|
| Код урока | `trades_per_year=1000`, `gross_bps=5.0`, `fee_bps=5.5`, `spread_bps=1.0`, `slip_bps=2.0` → `cost=8.5`, `net=−3.5`, `annual=−35%` | **Пресет №1** «Пример из кода урока» — дефолт при открытии |
| Блок «Числа» | 2 сделки/день = 4 транзакции → 1 460 в год; taker 0,055 % + слиппедж 0,02 % = 0,075 % на транзакцию; 1 460 × 0,075 % = **109,5 %** депозита; сырые **+120 %** → **+10,5 %** | **Пресет №2** «Две сделки в день». gross_bps = 120·100/1460 = 8,22 bps (подписать «получено из +120 %») |

| «Подробнее» | мейкер дешевле, «иногда комиссия отрицательная — ребейт», но «часть сигналов ты просто пропустишь» | Модель мейкера |
| «Важно» | «если ордер не успеет исполниться… бот либо пропустит сделку, либо исполнит её по маркету с двойной комиссией» | Две политики неисполнения |
| Таблица | Taker 0,045–0,06 % (BTC/ETH), 0,06–0,10 % (альты); Maker 0,015–0,02 %; слиппедж 0,01–0,03 % / 0,05–0,30 % | Кнопки-подсказки «BTC/ETH» / «альты» на ползунках |
| Аналогия | «наценка 5 рублей, доставка 8 рублей… чем быстрее крутишь, тем быстрее теряешь» | Визуальная метафора и название |
| Глубже | `cost = fee + half_spread + k·√(size/ADV)`; delay cost | Только упоминание в подсказке «Глубже» (без ползунка ёмкости — это урок 5.2) |

**Соглашение единиц (показывается один раз в шапке и в подсказке):** «Транзакция — одна сторона сделки (вход или выход). Полный круг = 2 транзакции. Все bps — на одну транзакцию, как в коде урока».

## 2. Экран

Две колонки (десктоп): слева «Склад» (управление), справа «Касса» (результат). Сверху — полоса пресетов.

### Полоса пресетов
Кнопки: **«Пример из кода урока»** · **«Две сделки в день»** · **«Мейкер обещает 0 %»** · **«Мейкер + догнать маркетом»** · **«Своё»**. При нажатии — плавная анимация ползунков к значениям, подпись источника («из блока "Числа" урока»).

### Левая колонка — «Склад» (управление)

**Блок 1 «Что зарабатываем»**
- Ползунок **«Сырой край на транзакцию, bps»** (gross): −5…40, шаг 0,5, дефолт 5. Подпись-иллюстрация: «наценка на единицу товара».
- Ползунок **«Транзакций в год»**: 50…10 000 (лог-шкала), дефолт 1 000. Под ним авто-подписи: «≈ {N/2} кругов, ≈ {N/365:.1f} в день».

**Блок 2 «Что платим (доставка)»** — три ползунка с иконками:
- **«Комиссия биржи, bps»** fee: 0…12, дефолт 5,5. Чипы: «BTC/ETH тейкер 4,5–6» · «альты тейкер 6–10» · «мейкер 1,5–2» · «ребейт −0,5».
- **«Полспреда, bps»**: 0…10, дефолт 1,0. Чипы: «ликвидная пара 0,5–1».
- **«Проскальзывание, bps»**: 0…30, дефолт 2,0. Чипы: «BTC/ETH 1–3» · «альты 5–30».
- Сумма под блоком: **«Доставка одной транзакции: {cost} bps»** (обновляется живо), рядом «за круг: {2·cost} bps».

**Блок 3 «Как исполняем»** — переключатель **Тейкер (по рынку) / Мейкер (лимитка в стакане)**.
При «Мейкер» разворачиваются:
- Ползунок **«Комиссия мейкера, bps»**: −1…3, дефолт 0 (для пресета «обещает 0 %»); подсказка «в таблице урока 1,5–2; ребейт — отрицательная».
- Ползунок **«Доля исполненных сигналов»** p_fill: 10…100 %, дефолт 60 %. Чипы: «вход на откате (лимитка ждёт) 70–85 %» · «вход на импульсе/пробое 25–40 %».
- Радио **«Что делаем с неисполненными»**: «Пропускаем сигнал» / «Догоняем рыночной заявкой».
  - при «Догоняем» — ползунок **«Наценка погони, bps»** 0…10, дефолт 2 (подсказка: «цена уже ушла; сверху платим полный тейкер-набор: комиссия + полспреда + проскальзывание»).
- Свёрнутое **«Глубже: неблагоприятный отбор»** — ползунок **«Потеря края на исполненных лимитках, bps»** 0…5, дефолт 1,0. Подсказка: «Лимитка исполняется охотнее, когда цена идёт сквозь неё — исполненные заявки в среднем чуть хуже (урок М21). Число неизвестно из бэктеста, измеряется в dry-run».
- В режиме «Мейкер» полспреда и проскальзывание из блока 2 отображаются перечёркнутыми с подписью «мейкер не платит» — но продолжают использоваться для расчёта «погони».

### Правая колонка — «Касса» (результат)

**Столбчатая диаграмма года** (3 столбца): **Брутто** (зелёный), **Издержки** (красный, из трёх штрихованных сегментов: комиссия / спред / проскальзывание; в режиме мейкера добавляются сегменты **«потерянный край на пропущенных»**, **«погоня»**, **«отбор»**), **Нетто** (зелёный или красный). Подписи в % от депозита и в долларах Алексея (×1000 $/100).

**Карточки (E8):**
- «Нетто на транзакцию, bps» (net_bps) — зона: <0 красная, 0–2 жёлтая («один сбой тарифа — и минус»), >2 зелёная.
- «Годовой итог, %» и «в деньгах Алексея, $».
- «Издержки съели, % от брутто» (cost/gross; при gross ≤ 0 — «край отрицательный: издержки лишь ускоряют»).
- «Точка безубыточности: край ≥ {cost} bps» (тейкер) / «… доля исполнения ≥ {p*} %» (мейкер).
- **Только мейкер:** «Исполнено сигналов: {N·p} из {N}», «Реальная комиссия с учётом всего: {eff_cost} bps» — главная карточка режима, подпись: «то, что на ценнике "0 %", а в кассе — столько».

**Ярлык-обманка:** в режиме мейкера над кассой висит бирка **«Комиссия 0 %»**; при первом наведении/тапе она переворачивается, показывая обратную сторону: «Пропущено: {…}% сигналов · Погоня: {…} bps · Отбор: {…} bps».

**Лента сигналов (визуал):** 20 иконок-заявок за «месяц»: тейкер — все закрашены; мейкер — p_fill закрашены, остальные пустые (пропущены) или красные с молнией (погоня). Подпись: «из 20 сигналов месяца исполнилось {k}».

**Кривая «тейкер против мейкера»:** маленький график годового итога (%) по оси p_fill 10–100 % — горизонтальная линия тейкера и наклонная мейкера (для обеих политик), с точкой пересечения p*. Показывает, что мейкер выигрывает не всегда, а начиная с порога, и что политика «догонять» может сдвинуть порог за 100 %.

## 3. Модель

```
# единицы: bps на транзакцию; N — транзакций в год
cost_taker = fee_taker + half_spread + slip

# ТЕЙКЕР
net_taker_bps   = gross − cost_taker
annual_taker_%  = N * net_taker_bps / 100          # как в коде урока, без сложного процента
gross_%         = N * gross / 100
cost_%          = N * cost_taker / 100

# МЕЙКЕР
exec_bps   = gross − adverse − fee_maker            # исполненная лимитка
miss_bps   = policy == 'skip'  ? 0
           : gross − chase − cost_taker             # догнали рыночной
E_net_bps  = p_fill * exec_bps + (1 − p_fill) * miss_bps
annual_maker_% = N * E_net_bps / 100

# декомпозиция издержек мейкера (для столбца «Издержки»)
fee_part     = p_fill * fee_maker * N/100
adverse_part = p_fill * adverse * N/100
missed_part  = policy=='skip'  ? (1−p_fill) * gross * N/100 : 0      # недополученный край
chase_part   = policy=='chase' ? (1−p_fill) * (chase + cost_taker) * N/100 : 0
eff_cost_bps = gross − E_net_bps                     # «реальная комиссия с учётом всего»

# порог, при котором мейкер (пропуск) догоняет тейкера
p*_skip  = (gross − cost_taker) / (gross − adverse − fee_maker)      # если знаменатель ≤ 0 → «никогда»
# для «догонять»: решить линейно по p из E_net_bps(p) = net_taker_bps
```
Особые случаи:
- gross ≤ 0: карточка безубыточности → «Края нет — издержки не главная проблема».
- p*_skip < 0 или > 1 → подпись «мейкер не сравняется с тейкером ни при какой доле исполнения» / «мейкер лучше при любой доле».
- Отрицательная комиссия мейкера (ребейт) допустима; подпись «ребейт: биржа доплачивает — но только за исполненные».

Округление отображения: bps — 1 знак; % — 1 знак; $ — целые.

## 4. Сценарий прохождения (направляемый)

1. Открытие на **пресете №1**. Подсказка: «Наценка 5, доставка 8,5. Посмотри на кассу». Касса: −3,5 bps, **−35 %/год**, −350 $ у Алексея. Вердикт: «Оборот растёт, отчёт внушительный — денег меньше».
2. Задание: «Сделай стратегию безубыточной, двигая **только** транзакции в год». Ученик двигает — итог меняется пропорционально, знак не меняется. Вердикт по отпусканию ползунка: «Частота умножает знак, но не меняет его. Отрицательный край не лечится оборотом — он им усиливается».
3. **Пресет №2** «Две сделки в день». Подсказка: «Здесь край положительный: +120 % брутто». Касса: 109,5 % издержек → **+10,5 %**. Вердикт: «Издержки съели 91 % результата. 0,075 % на транзакцию — "мелочь", умноженная на 1 460».
4. **Пресет №3** «Мейкер обещает 0 %»: комиссия 0, спред/слип перечёркнуты, p_fill 60 %, пропуск, отбор 1 bps. Сначала показывается бирка «0 %» — предложение «переверни бирку». После переворота — касса: исполнено 600 из 1000, E_net = 0,6·(5−1−0)=2,4 bps → **+24 %**. Вердикт: «Лучше тейкера — но не бесплатно: 40 % сигналов выброшено, а число 60 % ты взял из воздуха. Его знает только dry-run (урок 4.5)».
5. Переключить чип p_fill на **«вход на импульсе 25–40 %»** (ставит 30 %): исполнено 300, +10,5 %. Вердикт: «На импульсных входах лимитка ждёт, пока цена уходит. Тот же "0 %" — втрое меньше сделок и итога».
6. **Пресет №4** «Догоняем маркетом» (p_fill 60 %, погоня 2, отбор 1,5): E = 0,6·3,5 + 0,4·(5−2−8,5) = 2,1 − 2,2 = **−0,1 bps → ≈ −1 %/год**. Вердикт: «Погоня возвращает все тейкерские издержки и добавляет наценку. Мейкер + догон = хуже честного тейкера».
7. Финальная проверка (§6).

## 6. Критерий освоения (мини-ИГР)

Ситуация: «Биржа предлагает тариф: мейкер 0 %, тейкер 0,055 %. Твоя стратегия входит на пробоях уровня (импульс). Что делаешь?»
- «Переключаюсь на лимитки — комиссия 0 %, чистая экономия 5,5 bps» — ✗ («на импульсе исполнится 25–40 % лимиток, остальной край выбросишь»)
- «Оставляю рыночные заявки и считаю, перекрывает ли край 7–10 bps за сторону» — ✓
- «Ставлю лимитки, а неисполненные догоняю маркетом» — ✗ («погоня возвращает тейкерские издержки плюс наценку — хуже честного тейкера, шаг 6»)
- «Ставлю лимитки и измеряю долю исполнения в dry-run, прежде чем менять модель издержек в бэктесте» — ✓

Пройдено при выборе ровно двух верных. Дополнительно (ТРН, опционально): «Собери доставку»: перетащить чипы `комиссия 5,5` `полспреда 1` `проскальзывание 2` в корзину «за транзакцию» и получить «8,5 → за круг 17».

## 8. Тесты и приёмка

Golden-тесты формул:
- `(gross=5, fee=5.5, spread=1, slip=2, N=1000, taker)` → `net=−3.5`, `annual=−35.0`.
- `(gross=8.2192, fee=5.5, spread=0, slip=2, N=1460, taker)` → `gross_%=120.0±0.1`, `cost_%=109.5`, `annual=10.5±0.1`.
- `(gross=5, maker fee=0, adverse=1, p=0.6, skip, N=1000)` → `E_net=2.4`, `annual=24.0`, исполнено 600.
- `(gross=5, maker fee=0, adverse=1.5, p=0.6, chase=2, cost_taker=8.5, N=1000)` → `E_net=−0.1±0.01`, `annual≈−1.0`.
- `p*_skip` для `(gross=12, cost_taker=8.5, adverse=1, fee_m=2)` → `0.389`.
- Декомпозиция: сумма сегментов столбца «Издержки» = `gross_% − annual_%` с точностью 0,01.

Приёмка UX:
- Все пресеты воспроизводят числа урока с точностью до отображаемого знака и показывают источник числа.
- Бирка «0 %» переворачивается один раз по действию, далее остаётся перевёрнутой (состояние в URL).
- В режиме мейкера столбец «Издержки» содержит сегмент «пропущенный край», даже если комиссия 0 — это главный визуальный аргумент интерактива.
- График «тейкер против мейкера по p_fill» перерисовывается при каждом изменении и корректно показывает случаи «пересечения нет».
