# ТЗ на реализацию двух интерактивов Фазы 2

Оба интерактива — браузерные, без бэкенда, детерминированные (seed), русскоязычные. Общие требования вынесены в раздел 0, далее — две полные спецификации.

---

## 0. Общие требования к обоим интерактивам

| Требование | Как выполнить |
|---|---|
| **Один интерактив = одно заблуждение** | Финальный экран каждого интерактива заканчивается одной фразой-опровержением (см. в спеках). Никаких «заодно покажем ещё три вещи». |
| **Числа из текста урока** | Все опорные числа взяты из уроков 2.5 и 2.6 (перечислены в спеках). Придуманные иллюстративные числа помечаются в интерфейсе бейджем «учебная цифра». |
| **Русский новичок без английского** | Режим «Ткни в непонятное»: любой английский токен (OBI, bid, ask, UTC, timestamp, OHLCV, CSV, assert…) — кликабельный, всплывает русская карточка из словаря (список в каждой спеке). Переключатель подписей «рус / англ / оба» в шапке. |
| **Персонаж** | Алексей (депозит 1000 $ / 100 000 ₽) — герой обоих сценариев. |
| **Детерминированность** | Генерация данных по `seed` (uint32). Один и тот же seed → байт-в-байт одинаковый сценарий. Кнопка «Другой сценарий» → новый seed, seed показывается в футере (для баг-репортов). |
| **Воспроизводимость прохождения** | Состояние интерактива сериализуется в JSON (для телеметрии и восстановления при перезагрузке). |
| **Доступность** | Все действия доступны с клавиатуры; цвета дублируются формой/подписью (не только красный/зелёный); минимальный размер клика 40×40 px. |
| **Мобильная версия** | Вертикальная раскладка, панели — во вкладках. Ползунки — с крупным «ползуном» и кнопками ±. |
| **Производительность** | Анимация — `requestAnimationFrame`, расчёты — чистые функции над массивами; 500 свечей / 30 с эпизода стакана без лагов на среднем смартфоне. |
| **Телеметрия** | События: `start`, `slider_change`, `mark_added`, `mark_removed`, `check_run`, `quiz_answer`, `finish` с полями `seed`, `attempt`, `elapsed_ms`, `score`. |
| **Изоляция от существующих симуляторов** | В уроке 2.5 уже есть «Тренажёр: дисбаланс стакана и фильтр спуфинга» (статический снимок), в 2.6 — «Практика: чек-лист валидации данных» (чек-лист). Новые интерактивы **не дублируют** их: 2.5 добавляет ось времени (возраст заявок), 2.6 — поиск дефектов руками в реальном датасете. Ставятся **после** существующих. |

## 1. Урок 2.5 — «Живучесть заявки»

### 1.1. Паспорт

| Поле | Значение |
|---|---|
| ID | `sim-2-5-order-lifetime` |
| Тип | СИМ (симуляция с одним управляемым параметром) + мини-проверка в конце |
| Заблуждение | **«Стакан = обязательства»** (заявка в стакане — обещание купить/продать) |
| Опровержение (финальная фраза) | «Стакан — карта намерений, а не обязательств. Заявку можно снять за миллисекунды. Считай только тех, кто стоит в стакане достаточно долго» |
| Место в уроке | После блока «▸ Глубже» и таблицы метрик микроструктуры, после существующего тренажёра дисбаланса |
| Связи | 0.9 (стакан), 0.10 (ликвидность), 1.8 (издержки 14–20 bps за круг), М13 (ты торгуешь не с графиком) |
| Время прохождения | 6–8 минут |

### 1.2. Числа из урока (обязательны к воспроизведению)

- Формула: `OBI = (V_bid − V_ask) / (V_bid + V_ask)` по топ-N уровней; в интерактиве N = 5, объёмы в BTC (как в примере урока).
- Опорный пример: Bids = 45.0 BTC, Asks = 15.0 BTC → OBI = +0.50 → «вероятность следующего тика по Ask: 64.2 %».
- Спуфер выставляет фейковые заявки «на $10 млн» и снимает их «за 5 миллисекунд до подхода цены».
- Время жизни сигнала OBI: 100 мс – 5 с. WOBI: 500 мс – 15 с.
- Взвешивание уровней `w_i = exp(−k·i)` (для режима «Продвинутый»).
- Издержки полного оборота 14–20 bps (урок 1.8) — используются в тумблере «Учесть издержки».
- Аналогия урока — просмотр квартиры: «двадцать человек пришли, друзья продавца уйдут, как только ты назовёшь цену».

**Учебная калибровка** (не из урока, помечать бейджем): `P(тик вверх) = 0.5 + 0.284 · OBI`, чтобы при OBI = +0.50 получалось ровно 64.2 %.

### 1.3. Сценарная идея

Алексей подключил бота к стакану BTC/USDT. Бот покупает, когда OBI ≥ +0.60. На экране одновременно живут **два бота**:

- **Наивный бот** — считает OBI по всем заявкам стакана.
- **Фильтрованный бот** — считает OBI только по заявкам, простоявшим дольше `T_min` (ползунок ученика).

Эпизод длится 30 «биржевых секунд», проигрывается в замедлении (по умолчанию 0.1×, то есть 5 реальных минут; шаг — 100 мс биржевого времени). В стакан приходит спуфер. Ученик видит, как наивный OBI прыгает, фильтрованный — нет, и как это отражается на сделках двух ботов. Затем ученик подбирает `T_min` и обнаруживает, что фильтр не бесплатен: слишком большой порог пропускает честные короткие сигналы.

### 1.4. Экран

```
┌─────────────────────────────────────────────────────────────────┐
│ Заголовок · переключатель подписей рус/англ/оба · seed          │
├───────────────────────────┬─────────────────────────────────────┤
│ СТАКАН BTC/USDT (5+5)     │ ДВА OBI                              │
│  Ask 5  100 350  ▮▮▮      │  Наивный      [гейдж −1…+1] +0.81   │
│  Ask 4  100 300  ▮▮       │  Фильтрованный[гейдж −1…+1] +0.50   │
│  ...                      │  P(тик вверх): 73.0 % / 64.2 %       │
│  ── спред 5 $ ──          │─────────────────────────────────────│
│  Bid 1  100 250  ▮▮▮▮▮▮▮▮ │ ПОЛЗУНОК T_min: 0…3000 мс            │
│  ...                      │  [0][100][250][500][1000][2000][3000]│
│  Легенда возраста:        │  «Заявка считается, если простояла   │
│  ░ <100мс ▒ <500мс ▓ >1с  │   дольше T_min»                      │
├───────────────────────────┴─────────────────────────────────────┤
│ МИНИ-ГРАФИК ЦЕНЫ (30 с) с метками входов ботов ▲ (наивный ▲, фильтр ▲) │
├─────────────────────────────────────────────────────────────────┤
│ КАРТОЧКИ:  Наивный бот: 3 входа · −11.4 bps                     │
│            Фильтрованный: 1 вход · +3.1 bps · пропущено честных: 0 │
├─────────────────────────────────────────────────────────────────┤
│ ТАЙМЛАЙН [▶ ⏸ ⏭100мс] скорость [0.05×|0.1×|0.25×|1×]  ● ● ●      │
│ Тумблеры: [Показать спуфера — после эпизода] [Учесть издержки]  │
└─────────────────────────────────────────────────────────────────┘
```

**Стакан.** 5 уровней ask сверху (красные с подписью «продают»), 5 уровней bid снизу (зелёные, «покупают»). Каждый уровень — цена, суммарный объём (BTC) и горизонтальная полоса, **разбитая на отдельные заявки**. Заливка сегмента заявки зависит от возраста: три градации (< 100 мс, 100–500 мс, > 1 с), плюс тонкая рамка у тех, кто прошёл текущий `T_min`. Заявки-спуфера **визуально ничем не отличаются** до конца эпизода — в этом суть.

**Гейджи.** Две полукруглые шкалы −1…+1 с порогом входа +0.60 (риска). Под каждой — вероятность по учебной калибровке с бейджем «учебная цифра».

**Ползунок `T_min`.** Дискретные значения 0 / 100 / 250 / 500 / 1000 / 2000 / 3000 мс. Подсказка под ползунком меняется по зонам:
- 0 мс: «Фильтра нет: оба бота видят одно и то же»;
- 100–250 мс: «Ловит грубый спуфинг, но не мигающий»;
- 500–1000 мс: «Рабочая зона в этом сценарии»;
- 2000–3000 мс: «Честные сигналы OBI живут 100 мс – 5 с (таблица урока) — порог начинает их съедать».

**Мини-график цены.** Средняя цена (mid) за 30 с, стрелки входов обоих ботов, полупрозрачная полоса удержания 2 с, подписи результата в bps.

**Карточки ботов.** Число входов, суммарный результат в bps (по умолчанию без издержек), счётчик «пропущено честных сигналов» (только у фильтрованного). Тумблер «Учесть издержки» вычитает 14 bps за круг (нижняя граница из урока 1.8) и добавляет подпись: «после издержек микро-сигнал должен быть куда сильнее — это второй фильтр, о нём в уроке 1.8».

**Таймлайн.** Скраббер 0–30 с, кнопки: старт/пауза, шаг 100 мс, скорость. Точки событий на таймлайне появляются **только после** включения «Показать спуфера» (доступен после первого полного прогона).

### 1.5. Модель данных

```ts
type Side = 'bid' | 'ask';
interface Order {
  id: string;
  side: Side;
  level: 1|2|3|4|5;      // 1 = ближайший к спреду
  price: number;         // USDT
  qty: number;           // BTC
  placedAt: number;      // мс биржевого времени
  cancelledAt?: number;  // мс; undefined = жива
  isSpoof: boolean;      // скрыто до reveal
}
interface Trade { t: number; side: Side; qty: number; price: number; }
interface Episode {
  seed: number;
  scenario: 'honest' | 'spoof' | 'spoof_plus_fast_signal';
  durationMs: 30000;
  tickSize: 5;           // $ между уровнями
  mid0: 100_000;         // стартовая середина
  orders: Order[];
  trades: Trade[];
  midPath: number[];     // mid на каждые 100 мс (301 точка)
}
```

Все расчёты — на дискретной сетке 100 мс (`t = 0, 100, …, 30000`). Внутри шага возможны события с точностью до 1 мс (спуфер снимает за 5 мс) — они влияют на состояние к концу шага.

### 1.6. Три сценария (выбираются по seed, порядок фиксирован при первом прохождении)

**S1 «Честный спрос» (калибровка).** С 0 по 30 с стакан: топ-5 bid суммарно 45.0 BTC, топ-5 ask 15.0 BTC (распределение по уровням: 12/10/9/8/6 и 4/3/3/3/2). Заявки старые (`placedAt` ≤ −2000 мс). Мид медленно растёт на 4 тика за эпизод. Оба OBI = +0.50, оба бота **не входят** (порог +0.60). Цель — привязать формулу к числам урока и показать, что при `T_min` = 0 гейджи совпадают. Длительность показа — 10 с, дальше «пропустить».

**S2 «Спуфер» (главный).** База как в S1, но bid-сторона слабее: 30 BTC против ask 15 BTC (OBI +0.33 — нет сигнала). С t = 8000 мс спуфер начинает **мигающую стенку** на bid-уровне 3: заявка 100 BTC живёт 200–350 мс, снимается, через 100–200 мс ставится снова (6–8 циклов до t = 14000). Наивный OBI при живой стенке: `(130 − 15)/(145) = +0.79` → наивный бот входит на первом же мигании (t ≈ 8100) по best ask, держит 2 с, mid за это время не двигается или откатывает на 1 тик → результат −3…−5 bps (спред 1 тик = 5 $ ≈ 5 bps на 100 000, платим половину спреда + откат). Наивный входит до 3 раз (после выхода — снова сигнал). При t = 14000–14500 мид подходит к уровню стенки (продавцы бьют по bid): стенка снимается **за 5 мс** до касания — визуально «испаряется». На таймлайне после reveal — маркер «−5 мс: стенка снята». Фильтрованный бот с `T_min` ≥ 500 стенку не видит вовсе (максимальная жизнь 350 мс), OBI +0.33, входов 0.

Ожидаемые результаты S2 (для `T_min` = 500): наивный — 3 входа, ≈ −11…−13 bps; фильтрованный — 0 входов, 0 bps.

**S3 «Спуфер + честный короткий сигнал» (трейд-офф).** Как S2 плюс на t = 20000 мс появляется **настоящий** приток заявок: 8 участников ставят bid суммарно 25 BTC на уровни 1–2 и держат их 1200–1800 мс, после чего мид действительно уходит вверх на 3 тика за 2 с (агрессивные покупатели снимают ask). Честный OBI на пике: `(30 + 25 − 15)/(70) = +0.57`... нужно ≥ 0.60 — поставить приток 32 BTC: `(62 − 15)/77 = +0.61`. Фильтрованный бот с `T_min` = 500 входит на t ≈ 20600 и берёт +3 bps; с `T_min` = 2000 — входит только на t ≈ 22000, когда движение почти закончено (+0.5 bps); с `T_min` = 3000 — не входит, счётчик «пропущено честных сигналов» = 1. Наивный бот в S3 входит и на спуф, и на честный сигнал: итог около −8 bps.

Генератор обязан обеспечить эти инварианты при любом seed (seed меняет только тайминги в пределах ±300 мс, номера уровней и точные объёмы ±10 %).

### 1.7. Формулы движка

```
alive(o, t)        = o.placedAt ≤ t && (o.cancelledAt == null || o.cancelledAt > t)
age(o, t)          = t − o.placedAt
V_side_naive(t)    = Σ qty(o) for alive(o,t) && o.side==side && o.level ≤ 5
V_side_filt(t,Tm)  = Σ qty(o) for alive(o,t) && age(o,t) ≥ Tm && side && level ≤ 5
OBI(t)             = (V_bid − V_ask) / (V_bid + V_ask)     // 0, если знаменатель 0
P_up(OBI)          = 0.5 + 0.284·OBI                        // учебная калибровка
signal(t)          = OBI(t) ≥ 0.60 на текущем шаге и на предыдущем (2 шага подряд = 200 мс, защита от одиночного тика)
вход               = market buy по best ask в момент t_signal; qty фиксирована
выход              = через 2000 мс по mid (упрощение, помечено в подсказке)
PnL_bps            = (mid(t_exit) − ask(t_entry)) / ask(t_entry) · 10 000
PnL_net_bps        = PnL_bps − 14                            // тумблер издержек
missed_genuine     = число «честных» сигнальных окон (размечены в Episode как genuine=true),
                     в которые фильтрованный бот не вошёл
```

Режим «Продвинутый» (сворачиваемый блок под гейджами): третий гейдж WOBI с `w_i = exp(−k·i)`, k = 0.5, поверх фильтра по возрасту. Подпись: «взвешивание по расстоянию — второй способ из урока; работает вместе с фильтром живучести, а не вместо».

### 1.8. Ход прохождения (машина состояний)

1. **Интро** (1 экран текста): «Алексей поставил бота на дисбаланс стакана. Бот входит, когда покупателей в стакане заметно больше — OBI ≥ +0.60. Проблема: часть заявок в стакане — не покупатели». Кнопка «Смотреть стакан».
2. **S1** автоматически, `T_min` заблокирован на 0. Всплывающая карточка на t = 3 с: «45 BTC против 15 BTC → OBI = +0.50 → 64.2 %. Это пример из урока». Кнопка «Дальше».
3. **S2**, `T_min` = 0 по умолчанию, ползунок активен. Ученик обязан досмотреть эпизод до t = 15 с (пауза/шаг разрешены). После — итог: «Наивный бот: 3 входа, −12 bps. Что он купил?» — кнопка «Показать спуфера»: заявки спуфера подсвечиваются штриховкой, на таймлайне появляются маркеры «поставил / снял», цитата урока про 5 мс.
4. **Задание А**: «Найди T_min, при котором фильтрованный бот не купит у спуфера». Ученик двигает ползунок, эпизод пересчитывается **мгновенно** для всей длительности (без повторного просмотра) — обновляются гейджи, стрелки на графике и карточки. Проходной критерий: фильтрованный бот 0 входов в S2. Достигается при `T_min` ≥ 500.
5. **S3**. Сообщение: «Теперь в стакане есть и спуфер, и настоящие покупатели». Ученик с текущим `T_min`. **Задание Б**: «Подбери T_min так, чтобы бот: (1) не купил у спуфера и (2) не пропустил честный сигнал». Проходной критерий: фильтрованный бот в S3 — 0 входов на спуф, ≥ 1 вход на честный сигнал, PnL > наивного. Достигается при `T_min` ∈ {500, 1000}.
6. **Мини-проверка** (одиночный выбор, обязательна):
   «Заявка на 100 BTC стоит в стакане. Что это гарантирует?»
   - «Что кто-то купит 100 BTC по этой цене» → неверно: «Заявку можно снять за 5 мс. Стакан — карта намерений»
   - «Что участник готов купить прямо сейчас — пока не передумал» → **верно**
   - «Что цена не упадёт ниже этого уровня» → неверно: «Стенка исчезает ровно тогда, когда цена к ней подходит»
7. **Финал**: карточка с фразой-опровержением + два числа: «Твой T_min: 500 мс. Наивный бот: −8 bps. Фильтрованный: +3 bps» + подпись при включённых издержках. Ссылка-мостик: «Издержки 14–20 bps за круг делают микро-сигналы ещё капризнее — урок 1.8».

### 1.9. Критерий освоения

Интерактив помечается пройденным при одновременном выполнении: задание А выполнено; задание Б выполнено; мини-проверка — верный ответ (допускается вторая попытка). Сохраняется `T_min_final`, число смен ползунка, был ли включён reveal до задания А (флаг «подглядел» — не штраф, но в телеметрию).

### 1.10. Словарь «Ткни в непонятное»

| Токен | Карточка |
|---|---|
| OBI | Дисбаланс книги заявок: (объём покупателей − объём продавцов) / (сумма). От −1 до +1. Урок 2.5 |
| bid / ask | Заявки на покупку (снизу, зелёные) / на продажу (сверху, красные). Урок 0.9 |
| spoofing / спуфер | Крупная заявка без намерения исполнить: поставил, чтобы обмануть, снял до касания ценой |
| WOBI | OBI с весами по удалённости от лучшей цены: дальние уровни весят меньше |
| CVD | Накопленная разница объёма рыночных покупок и продаж — учитывает реальные сделки, а не заявки |
| мс | Миллисекунда, 1/1000 секунды. Биржа живёт в этих единицах |
| bps | Базисный пункт, 0.01 %. 5 $ на цене 100 000 ≈ 5 bps. Урок 0.10 |
| тик | Минимальный шаг цены между уровнями стакана (здесь 5 $) |
| mid | Середина между лучшими bid и ask |

### 1.11. Тесты приёмки

1. `T_min = 0` ⇒ `OBI_naive(t) === OBI_filt(t)` для всех t во всех сценариях.
2. S1: OBI = +0.500 ± 0.005 в течение всего эпизода, P_up = 64.2 %, входов 0 у обоих.
3. S2: пик `OBI_naive` ≥ +0.75; при `T_min` ≥ 500 `OBI_filt` ≤ +0.35 на всём эпизоде; наивный бот делает ровно 2–3 входа с отрицательным итогом; фильтрованный — 0.
4. S2: разница между `cancelledAt` спуф-заявки в финальном цикле и моментом касания mid уровня стенки = 5 мс ± 0.
5. S3: при `T_min` = 500 фильтрованный бот 1 вход на честном сигнале, PnL > 0; при 3000 — `missed_genuine` = 1.
6. Один seed → идентичный `Episode` (глубокое равенство) при повторной генерации.
7. Спуф-заявки не отличимы по любому доступному до reveal полю рендера (проверить снапшотом DOM: нет классов/атрибутов `isSpoof` до reveal).
8. Тумблер издержек уменьшает каждый результат ровно на 14 bps.
9. Клавиатура: пробел — пауза, стрелки — ползунок, `.` — шаг 100 мс.

### 1.12. Чего не делать

- Не показывать спуфера цветом/иконкой во время эпизода.
- Не добавлять случайный шум в наивный OBI, чтобы «драматичнее»: все скачки — только от событий стакана.
- Не давать ползунку непрерывных значений (дискретные метки проще объяснить).
- Не вводить комиссию по умолчанию — она размывает фокус (тумблер).
- Не использовать слово «манипуляция» без объяснения; использовать «спуфер» + карточку.

### 2.1. Паспорт

### 2.2. Числа и правила из урока (обязательны)

Чек-лист валидации из урока — шесть пунктов, они же категории дефектов:
1. все метки времени в UTC и монотонно возрастают;
2. нет дублей и пропусков баров (сверка с ожидаемым числом периодов);
3. нет нулевых или отрицательных цен и объёмов;
4. `high ≥ max(open, close)` и `low ≤ min(open, close)`;
5. выбросы > 10 сигм проверяются вручную — это может быть сбой ленты, а не движение рынка;
6. для мультиактивных тестов список инструментов берётся на историческую дату, а не на сегодня.

Код урока (переиспользуется в фазе 2 дословно):
```
assert df.index.is_monotonic_increasing and df.index.tz is not None
assert not df.index.duplicated().any()
expected = pd.date_range(df.index[0], df.index[-1], freq='1h', tz='UTC')

assert (df['high'] >= df[['open','close']].max(axis=1)).all()
assert (df[['open','high','low','close','volume']] > 0).all().all()
```
Аналогия урока: «весы, которые иногда врут на 5 кг, а иногда показывают вес кота». Названия и подписи интерактива держатся этой метафоры («взвесить датасет», «показания весов»).

### 2.3. Сценарная идея

Алексей скачал часовые свечи BTC/USDT за 3 недели (504 бара) через публичный REST биржи, чтобы прогнать стратегию из Py-14. Файл выглядит нормально. В нём спрятано **шесть дефектов** (по одному на каждый пункт чек-листа) и **два ложных следа** — настоящие рыночные события, которые трогать нельзя. Задача: найти дефекты, назвать категорию, не тронуть настоящее.

### 2.4. Экран

**График.** Свечной, с кистью-зумом. По умолчанию ось X — **по индексу** (как рисуют наивные библиотеки): пропуск баров невидим. Тумблер «по времени» растягивает ось по реальным меткам — пропуск проявляется пустотой, UTC-сдвиг — наложением/обратным ходом. Наивный рендер тела/тени: тень рисуется от `low` до `high`, тело — от `open` до `close` **без коррекции**, поэтому нарушение `high < close` видно как тело, торчащее над тенью.

**Таблица.** Колонки `date, open, high, low, close, volume`; по кнопке добавляется колонка `Δt` (разница с предыдущей меткой в часах). Клик по строке или по диапазону строк (shift-клик) — пометить. Сортировки нет намеренно (сохраняем порядок файла).

**Паспорт датасета.** Карточка с полями, каждая строка кликабельна для пометки:
- Источник: `REST /klines`, биржа «Б», скачано 2026-08-02;
- Инструмент: BTC/USDT, ТФ 1h;
- Период: 2022-04-25 00:00 — 2022-05-15 23:00 UTC (504 бара);
- Часовой пояс файла: «UTC (по документации API)»;
- **Список пар для мультитеста: топ-10 по объёму на 2026-08-01**: BTC, ETH, SOL, XRP, BNB, DOGE, ADA, TON, AVAX, LINK (все /USDT);
- Назначение: бэктест стратегии Py-14 на периоде 2022-04..2022-05.

Пункт «список пар» — это дефект 6: период теста — май 2022 (коллапс LUNA/UST, урок 3.6), а список взят «на сегодня» и не содержит LUNA/USDT и других исчезнувших пар. Кнопка «Что торговалось в топ-10 в апреле 2022?» открывает справку (учебная, с бейджем): в топ-10 по объёму тогда входили LUNA/USDT и FTT/USDT — обе пары в списке отсутствуют.

**Панель пометок.** Пометка = {локатор (строка / диапазон / строка паспорта), категория}. Категория назначается перетаскиванием чипа на пометку или выбором из меню. Одна пометка — одна категория. Лимит пометок — 12 (защита от «пометить всё»).

### 2.5. Генерация датасета

Синтетические 504 часовые свечи, детерминированные по seed:

```

log-доходность на бар ~ N(0, 0.006); high/low добавляют |N(0,0.003)| к экстремумам open/close
volume ~ логнормальное, медиана 1 200 BTC; будни ×1.0, выходные ×0.35
```

Дефекты внедряются **после** генерации чистого ряда на позициях, зависящих от seed, но с ограничениями (не в первых/последних 24 барах, не ближе 30 баров друг к другу, не совпадающими с ложными следами):

| № | Дефект | Как внедрить | Пункт чек-листа | Как ловится кодом урока |
|---|---|---|---|---|
| D1 | UTC-сдвиг | Блок из 24 подряд баров получает метки `+3 ч` (записан в MSK). Результат: перед блоком «дыра» 3 ч, после блока метки **идут назад** на 3 ч (3 пересечения) | 1 | `is_monotonic_increasing` → False |
| D2 | Дубль бара | Одна строка повторена полностью со своей меткой | 2 | `duplicated().any()` → True |
| D3 | Пропуск | Удалены 6 подряд баров («техработы биржи»); соседние бары визуально стыкуются | 2 | `expected.difference(df.index)` → 6 меток |
| D4 | Нулевой объём | Один бар с `volume = 0` при ненулевом движении цены (open ≠ close на 0.4 %) | 3 | `(… > 0).all()` → False |
| D5 | Нарушение OHLC | Один бар с `high` на 0.3 % **ниже** `close` (типичная ошибка склейки) | 4 | `high >= max(open, close)` → False |
| D6 | Выброс — ошибка ленты | Один бар: `low = round(open/10)` (потерянный разряд: 3 950 вместо 39 500), `open/close/high` нормальные, объём нормальный. Это ≈ 12σ от типичного размаха тени, цена в следующем баре не «помнит» падения | 5 | Не ловится ассертами урока (все неравенства выполняются) — ловится порогом «> 10σ, проверить вручную» и **в игре относится к категории «выброс — ошибка ленты»** |

Примечание: чтобы дефектов было ровно шесть на экране, D4 и D5 объединяются в один слот? В счётчике интерфейса показывать «найдено X/7 позиций, закрыто Y/6 пунктов чек-листа». Если нужно строго шесть позиций — D4 (нулевой объём) удаляется первым; тогда пункт 3 покрывает D6 частично (не покрывает). **Рекомендация: 7 позиций, 6 пунктов.**

| № | Что | Правильное действие |
|---|---|---|
| F1 | Настоящий обвал: бар с `close` на −9 % к `open`, объём ×6, следующие бары **остаются** на новом уровне (память есть), OHLC согласованы. Дата — внутри 9–12 мая 2022 (LUNA-неделя, урок 3.6) | Пометка допустима только с категорией «выброс — рынок, оставить» (даёт +1 балл «внимательность»); категория «ошибка ленты» — штраф |
| F2 | Выходные: 48 баров с объёмом в ~3 раза ниже, спокойный ход | Пометка любой категорией — штраф; подсказка «Подсветить выходные» объясняет |

Интро: «Алексей скачал свечи и готов запускать бэктест. Ты — контроль качества. В файле 7 подозрительных мест шести типов и 2 настоящих события, которые трогать нельзя. Найди дефекты и назови каждому тип». Инструменты доступны сразу; подсказки — по запросу, максимум 3, каждая −1 балл:
- Подсказка 1: «Включи ось «по времени» и посмотри, где график рвётся или накладывается»;

Кнопка «Проверить пометки» доступна в любой момент, но не более 3 раз (каждая проверка — обратная связь по каждой пометке: «верно», «дефект найден, тип неверный: это …», «это настоящее событие рынка, не дефект»). После третьей проверки — переход к фазе 2 с тем, что есть.

**Подсчёт:** +2 за дефект с верной категорией, +1 за дефект с неверной, −1 за ложную пометку (F1 с категорией «ошибка ленты», F2, любая чистая строка), +1 за F1 с категорией «рынок, оставить», −1 за каждую подсказку. Максимум 15.

### 2.7. Критерий освоения

Пройдено, если: найдено ≥ 6 из 7 позиций; D7 найден обязательно; ложных пометок ≤ 1; фаза 2 — верно указано, что код не ловит D7. При невыполнении — предлагается второй заход с новым seed (обязателен), учитывается лучший результат. Метрика для аналитики курса: доля ложных пометок и число подсказок во втором заходе против первого (цель −50 %).

### 2.8. Словарь «Ткни в непонятное»

| Токен | Карточка |
|---|---|
| UTC | Всемирное время, одинаковое для всех бирж. Москва = UTC+3. Если часть файла в местном времени, метки «прыгают» |
| timestamp / метка времени | Дата и час начала свечи. По ним склеивают историю |
| OHLCV | Пять чисел свечи: открытие, максимум, минимум, закрытие, объём. Урок 0.7 |
| CSV / feather | Форматы файлов с таблицей свечей. Содержимое одно и то же |
| σ (сигма) | Стандартное отклонение — типичный размер колебания. Урок 0.15 и М9 |
| выброс | Значение, необычно далёкое от остальных: ошибка данных или редкое реальное событие. Урок М27 |
| survivorship bias / ошибка выжившего | Тест только на активах, дожитых до сегодня: исчезнувшие выпали из выборки. Урок 0.18 |
| assert | Строка кода «проверь и остановись, если неправда». Урок FT-08 |
| is_monotonic_increasing | «Каждая следующая метка позже предыдущей» |
| date_range | Построить ожидаемый ряд меток без пропусков и сравнить с фактом |
| Δt | Разница времени между соседними барами; для 1h должна быть ровно 1 ч |
| REST / API | Способ скачать данные программой. Урок Py-09 |

### 2.9. Тесты приёмки

1. Генератор для любого seed выдаёт ровно 7 дефектных позиций 6 типов + 2 ложных следа; позиции не пересекаются, отступ от краёв ≥ 24 бара, между дефектами ≥ 30 баров.
2. Чистый ряд (до инъекции) проходит все 6 проверок урока без FAIL.
3. После инъекции проверки дают ровно: монотонность FAIL, дубли 1, пропуски 9 меток (6 + 3), положительность FAIL на 1 баре, OHLC FAIL на 1 баре, порог 10σ — ровно 2 срабатывания (D6, F1).
4. При оси «по индексу» пропуск D3 визуально отсутствует (соседние свечи смежны); при «по времени» между ними пустота 6 ч.
5. Рендер D5: тело свечи выходит за верхнюю границу тени (без авто-коррекции).
6. F1: следующие ≥ 12 баров держатся в пределах ±3 % от `close` бара обвала; D6: следующий бар открывается в пределах ±1 % от `close` бара выброса.
7. Пометка F1 категорией «рынок, оставить» = +1; категорией «ошибка ленты» = −1; пометка F2 любой категорией = −1.
8. Завершение невозможно без пометки D7 в паспорте.
9. Второй заход с другим seed меняет позиции всех дефектов (ни одна позиция не совпадает с первым заходом).
10. Один seed → байт-в-байт одинаковый CSV при экспорте (кнопка «Скачать этот датасет» — для тех, кто захочет прогнать `check_data.py` из FT-08).

### 2.10. Чего не делать

- Не подсвечивать дефекты автоматически на графике до проверки — вся ценность в поиске.
- Не давать сортировку/фильтр таблицы — они спрячут дубль и сдвиг.
- Не придумывать итоговую «доходность на грязных данных» в процентах — последствия объясняются текстом по дефектам.
- Не смешивать категории «ошибка ленты» и «рынок»: это две разные кнопки, различение — часть навыка.
- Не наказывать за пометку F1 категорией «рынок, оставить» — это правильное поведение по пункту 5 чек-листа.
