# Детальные спеки для реализации: интерактивы уроков 2.3 и 2.4

Ниже — два ТЗ для агента-разработчика. Оба интерактива входят в Фазу 2 («Альтернативные данные и микроструктура»), оба построены на одном методическом стержне: **смысл ончейн-события определяется разметкой адресов, а не суммой**. Урок 2.3 закрывает уровень транзакции (пара «откуда → куда»), урок 2.4 — уровень адреса (поведенческая кластеризация → прототип → интерпретация). Между ними есть общий переиспользуемый компонент — **«Досье адреса»** (см. §0.3), его стоит собрать один раз.

---

## 0. Общие требования к обоим интерактивам

### 0.1. Аудитория и язык
- Ученик — русскоязычный новичок без английского. Все подписи, кнопки, сообщения — на русском. Английские термины появляются только внутри режима «Ткни в непонятное» (см. §0.4) и в скобках после русского термина при первом появлении.
- Числа берутся из текста урока или согласованы с ним (5 000 BTC, `Binance-Cold-12 → Binance-Hot-04`, «более 80% крупных транзакций — внутренние», `|netflow_z| > 2`, признаки `avg_tx / tx_per_day / age_days / unique_counterparties`, «число кластеров по силуэту», «кластер 3 ничего не значит без прототипа»).

### 0.2. Сквозной персонаж
Оба интерактива ведутся от лица **Алексея** (депозит 1000 $ / 100 000 ₽, уже знаком ученику по Py-урокам). Он получил тревожный алерт и разбирается, стоит ли что-то делать. Финал каждого интерактива — Алексей **ничего не делает руками** (связка с П1 «мир или голова»).

### 0.3. Общий компонент «Досье адреса» (`AddressDossier`)
Карточка адреса, открывающаяся по клику на любой адрес в обоих интерактивах.

```
┌─ Досье адреса №9 ─────────────────────────────┐
│ Короткий идентификатор: bc1q…7k2m               │
│ Средний размер перевода     5 000 BTC   [?]     │
│ Переводов в сутки           0,03        [?]     │
│ Возраст адреса              1 500 дней  [?]     │
│ Уникальных контрагентов     3           [?]     │
│ ─────────────────────────────────────────────── │
│ Метка разметки: [скрыта до раунда 3 / известна] │
│ Дополнительно (эвристики): [кнопка «Проверить»] │
└─────────────────────────────────────────────────┘
```
- Поля с `[?]` — токены языкового слоя (§0.4).
- Блок «Дополнительно» показывается только там, где спека это разрешает (2.4, раунд 3).
- На мобильных — нижний лист (bottom sheet), на десктопе — поповер.

### 0.4. Языковой слой «Ткни в непонятное»
Единый словарь токенов для обоих интерактивов. Клик по токену → русская карточка: «что это», «пример», «в каком уроке впервые». Минимальный словарь:

| Токен | Русская карточка |
|---|---|
| `Netflow` | Чистый поток = приток − отток. Считается только по размеченным адресам биржи. Урок 2.3 |
| `Inflow / Outflow` | Приток на биржу / отток с биржи. Урок 2.3 |
| `Hot wallet / Cold wallet` | Горячий кошелёк биржи (онлайн, для выводов клиентов) / холодный (офлайн-хранилище). Перевод между ними — внутренняя операция. Урок 2.3 |
| `Custody / кастодиан` | Компания, хранящая чужие монеты (например, Coinbase Custody, BitGo). Урок 0.3 |
| `Bridge / мост, WBTC` | Механизм переноса биткоина в другую сеть: BTC запирается у кастодиана, взамен выпускается токен-обёртка. Маскирует движение. Урок 2.3 |
| `z-score / netflow_z` | На сколько сигм текущее значение отличается от среднего за месяц. Порог значимости из урока: больше 2 по модулю. Уроки 2.3, М44 |
| `k-means` | Алгоритм, который сам делит точки на k групп по близости признаков. Урок 2.4 |
| `silhouette / силуэт` | Оценка от −1 до 1, насколько чисто разделились группы. Число кластеров выбирают по её максимуму. Урок 2.4 |
| `StandardScaler` | Приведение признаков к общему масштабу перед кластеризацией, иначе «контрагенты» (десятки тысяч) задавят «переводов в сутки» (доли). Урок 2.4 |
| `avg_tx`, `tx_per_day`, `age_days`, `unique_counterparties` | Средний перевод, переводов в сутки, возраст адреса, уникальных контрагентов. Урок 2.4 |
| `Common Input Ownership` | Если у транзакции несколько входов — их подписал один владелец. Урок 2.4 |
| `Cold-to-Hot Sweep` | Регулярные переводы ровными суммами с холодного кошелька биржи на горячий. Шум. Урок 2.4 |
| `Dormant Whale` | Адрес, не двигавший монеты 3–5 лет. Пробуждение — значимый сигнал. Урок 2.4 |
| `Market maker / MM` | Участник, котирующий в обе стороны; его переводы между площадками — операционные, не про намерение держать/продать. Уроки 2.4, М14 |

### 0.5. Аналитика (события)
Оба интерактива отправляют события: `start`, `phase_enter(phase)`, `answer(item_id, chosen, correct, attempt)`, `hint_used(item_id)`, `token_tap(token)`, `dossier_open(address_id)`, `finish(score, mastered:boolean, duration_s)`, `retry`. Метрика цели по разделу 7 исходного пакета: число ошибок на 2-й попытке ниже на 50%.

### 0.6. Сохранение
Состояние сохраняется локально по завершению фазы, чтобы обновление страницы не сбрасывало прогресс. Флаг `mastered` записывается в профиль ученика и открывает отметку «прожито» у терминов урока (глоссарий-паутина).

# ТЗ №1 · Урок 2.3 · «Грузовики у склада»

## 1. Паспорт

| Поле | Значение |
|---|---|
| ID | `int_2_3_trucks` |
| Тип | ТРН (тренажёр) + встроенный элемент ИГР (счёт, штраф) |
| Длительность | 6–8 минут |
| Заблуждение | «Крупный перевод = сигнал» |
| Что ломает | Ученик учится классифицировать транзакцию по паре «откуда → куда» и убеждается, что 94% объёма в ленте — шум, а знак netflow после разметки меняется на противоположный |
| Место в уроке | После абзаца «Аналогия: грузовики у ворот склада», ПЕРЕД существующим «Тренажёр: чтение притоков и оттоков бирж» (существующий тренажёр читает уже посчитанные потоки — новый учит их считать) |
| Зависимости | `AddressDossier` (§0.3), словарь токенов (§0.4) |
| Критерий освоения | ≥ 7 из 8 карточек верно с первой попытки + верный бонус-вопрос; иначе повтор с перемешанными карточками и изменёнными суммами, где требуется 8/8 |

## 2. Педагогическая логика (одна фраза на фазу)

1. **Крючок**: наивный радар кричит «приток 14 820 BTC — шорт!».
2. **Действие**: ученик размечает те же 8 переводов по паре «откуда → куда».
3. **Разоблачение**: честный netflow = −820 BTC, знак перевернулся; z = −0,9 — даже честный поток внутри шума.
4. **Перенос**: бонус — перевод без разметки нельзя интерпретировать вообще.
5. **Ритуал**: Алексей записывает в журнал «мир не изменился» и ничего не делает.

## 3. Сценарий по фазам

### Фаза 0 — Крючок (10 сек, без взаимодействия)
Текст-вставка:
> Алексею прилетел алерт от «радара китов»: **«За последние 2 часа через биржевые адреса прошло 16 000+ BTC. Приток на биржи!»** Он открывает журнал переводов. Прежде чем решать что-то — разметим каждый перевод.

Кнопка: **«Открыть журнал переводов»**.

### Фаза 1 — Наивный радар (показ)
Левая панель: таблица 8 переводов, только столбцы «Сумма» и «Куда» (адрес без владельца). Правая панель — «Наивный радар»:

```
Приток на биржи:   14 820 BTC   ████████████████
Отток с бирж:       1 290 BTC   █
Чистый поток:     +13 530 BTC   → «МЕДВЕЖЬЕ ДАВЛЕНИЕ. ШОРТ?»
```
Подпись мелким: «Радар считает: получатель — биржевой адрес → приток; отправитель — биржа → отток. Владельца он не проверяет.»
Кнопка: **«Проверить разметкой →»**.

### Фаза 2 — Разметка (основное действие)
Экран делится на **ленту карточек** (сверху, горизонтальная прокрутка / по одной карточке на мобильном) и **три полосы склада** (внизу):

```
┌── Карточка перевода №1 ───────────────────────────────┐
│  5 000 BTC                                            │
│  ОТКУДА: Binance · холодный кошелёк Cold-12           │
│          [чип: биржа] [чип: холодное хранилище]        │
│  КУДА:   Binance · горячий кошелёк Hot-04             │
│          [чип: биржа] [чип: тот же владелец]           │
│  [Досье отправителя] [Досье получателя] [Подсказка]   │
└───────────────────────────────────────────────────────┘

 ┌─ 🚚 ЗАЕЗЖАЮТ ГРУЖЁНЫЕ ─┐ ┌─ 🚚 ВЫВОЗЯТ ТОВАР ─┐ ┌─ 📦 ПЕРЕКЛАДЫВАЮТ КОРОБКИ ─┐
 │ Приток на биржу        │ │ Отток с биржи      │ │ Шум (владелец не изменился)│
 │ давление продавцов     │ │ сжатие предложения │ │ или биржа → биржа, мост    │
 └────────────────────────┘ └────────────────────┘ └────────────────────────────┘
```

- Десктоп: drag&drop карточки в полосу. Мобильный: три кнопки под карточкой. Оба варианта обязательны.
- Карточка после размещения уезжает в полосу как «грузовик» (лёгкая анимация 300 мс) и остаётся видимой в полосе (мини-версия: сумма + пара).
- Разрешено переставлять до нажатия **«Проверить разметку»** (кнопка активна только когда все 8 карточек размещены).
- **Подсказка** (по одной на карточку, без штрафа, но фиксируется в аналитике): всегда один и тот же наводящий вопрос «Кто владеет отправителем? Кто владеет получателем? Изменился ли владелец?» + один факт из досье (см. поле `hint` в данных).

### Фаза 3 — Проверка
- Каждая карточка в полосе получает ✅/❌. Неверные подсвечиваются и показывают объяснение (поле `explanation`). Верные — короткое подтверждение.
- Счёт: «7 из 8». Под счётом: **«Суммарный объём шума: 16 450 BTC (94%). Суммарный объём сигнала: 1 760 BTC (6%).»** — это ключевое число интерактива, выделить крупно.
- Кнопка **«Сравнить два радара →»**.

### Фаза 4 — Два радара
Две колонки со столбчатыми диаграммами (одинаковый масштаб оси!):

```
 НАИВНЫЙ РАДАР                 ЧЕСТНЫЙ NETFLOW (после разметки)
 Приток   14 820 ████████████   Приток      470 ▌
 Отток     1 290 █              Отток     1 290 █
 Чистый  +13 530 → «ШОРТ»       Чистый     −820 → небольшой отток

 Контекст месяца: 2-часовые netflow за 30 дней — среднее ≈ 0, σ ≈ 900 BTC
 netflow_z наивный:  +15,0  (невозможное значение — признак ошибки данных, а не сигнала)
 netflow_z честный:  −0,9   (внутри обычной болтанки; порог урока |z| > 2 не пройден)
```
Вывод крупно: **«Знак развернулся. И даже честное значение — не сигнал. Смысл транзакции — в паре „откуда → куда“, а не в сумме.»**

Опционально (P2): переключатель **«Взвесить по возрасту монет»** — карточка №5 (монеты не двигались 4 года) получает пометку «вес выше: старые монеты значимее свежих» без изменения суммы; реализовать как всплывающую пометку, не как пересчёт.

### Фаза 5 — Бонус: перевод без разметки
Карточка №9: **4 000 BTC · неизвестный адрес → неизвестный адрес** (оба без меток, в досье все поля «нет данных»).
Вопрос: «Как учесть этот перевод?»
- Приток — ❌
- Отток — ❌
- Шум — ❌
- **Разметки нет → в netflow не попадает; ставим адреса в очередь на атрибуцию** — ✅

Объяснение: «Без метки владельца пара „откуда → куда“ не определена. Наивный радар посчитал бы это „китом“. Атрибуция — эвристика, и пока её нет, интерпретации нет. Именно поэтому наивные „радары китов“ ошибаются в большинстве случаев (итог урока).»

### Фаза 6 — Итог и ритуал
- Итоговая карточка: счёт, флаг освоения, три тезиса урока.
- Мини-запись в журнал Алексея (только показ, не ввод): «03:14 · Алерт про приток. Разметил: шум 94%, честный z −0,9. Мир не изменился → не делаю ничего. Проверю утреннюю сводку.» Подпись: «Так работает протокол П1: факт, потом действие.»
- Кнопки: **«Повторить с другими суммами»** (см. §5.3) / **«Дальше по уроку»**.

### 4.1. Контрольные суммы (для юнит-теста)
- Наивный приток = Σ карточек с `naive == "inflow"` = 5000 + 8900 + 450 + 320 + 150 = **14 820**
- Наивный отток = 1200 + 90 = **1 290**; наивный чистый = **+13 530**; z = 13 530 / 900 = **+15,0**
- Честный приток = 320 + 150 = **470**; честный отток = **1 290**; честный чистый = **−820**; z = **−0,91**
- Объём шума = 5000 + 8900 + 2100 + 450 = **16 450** (94% от 17 210); сигнал = **1 760** (6%; округление до целых процентов, отображать «94% / 6%»)

## 5. Логика

### 5.1. Проверка ответа
```
score = count(card.correct == chosen[card.id])
mastered = (score >= 7 and attempt == 1 and bonus_correct) 
        or (score == 8 and attempt >= 2 and bonus_correct)
```

### 5.2. Расчёт панелей
```
naive_in  = Σ amount where naive == "inflow"
naive_out = Σ amount where naive == "outflow"
honest_in  = Σ amount where correct == "inflow"
honest_out = Σ amount where correct == "outflow"
z(x) = (x - history_mean_btc) / history_std_btc  // округлять до 0,1
noise_share = Σ amount where correct == "noise" / Σ all amounts
```
Все значения вычисляются из JSON, а не захардкожены, чтобы работал режим повтора (§5.3).

### 5.3. Режим повтора («Повторить с другими суммами»)
- Порядок карточек перемешивается.
- Каждая `amount_btc` умножается на случайный множитель из {0,4; 0,7; 1,6; 2,5}, округляется до десятков. **Метки `correct` не меняются** — это и есть урок: правильный ответ не зависит от суммы.
- Панели фаз 1 и 4 пересчитываются по новым суммам; сообщение в фазе 4 дополняется строкой: «Суммы изменились, ответы — нет».
- В повторе требуется 8/8.

### 5.4. Ограничения
- «Проверить разметку» недоступна, пока не размещены все 8 карточек (подсказка при наведении: «Осталось разметить N»).
- Подсказка на карточку — максимум одна; после открытия текст остаётся на карточке.
- Нельзя пропустить фазу 2 и увидеть фазу 4.

## 6. UI и адаптив
- Десктоп ≥ 1024 px: лента карточек сверху (3 видимых), три полосы снизу во всю ширину; фаза 4 — две колонки.
- Мобильный: одна карточка на экран, свайп между карточками, три кнопки-метки под карточкой; полосы склада свёрнуты в счётчики «Приток: 2 · Отток: 1 · Шум: 3» с раскрытием; фаза 4 — столбцы друг под другом при **одинаковом масштабе оси**.
- Цвета: приток — тёплый (оранжевый), отток — холодный (синий), шум — серый. Не красный/зелёный как «плохо/хорошо»: у ученика не должно сложиться «приток = плохо».
- Иконки грузовиков — декоративные; смысл дублируется текстом.
- Доступность: все drag-действия дублируются кнопками; фокус-порядок карточка → три кнопки → досье; `aria-live` для результата проверки.

## 7. Тексты обратной связи (общие)
- Верно: «Верно: пара „{from_owner} → {to_owner}“ → {label}.»
- Ошибка «шум как приток/отток»: «Ты поверил сумме. Проверь владельцев: {from_owner} и {to_owner} — {same_owner ? "один и тот же" : "оба биржи"}. Владелец/доступность не изменились → шум.»
- Ошибка «сигнал как шум»: «Здесь владелец изменился: {from_type_ru} → {to_type_ru}. Это {label}, пусть и небольшой.»
- Ошибка перепутан приток/отток: «Направление наоборот. На биржу = становится доступно для продажи (приток). С биржи = уходит из продажи (отток).»

## 8. Критерии приёмки
1. Контрольные суммы §4.1 совпадают с отображаемыми на панелях (юнит-тест на функции расчёта).
2. При повторе с множителями суммы меняются, правильные ответы — нет; панели пересчитываются корректно.
3. Все три метки доступны как кнопками, так и drag&drop; на мобильном drag не требуется.
4. «Проверить» неактивна до полной разметки.
5. Каждый токен из §0.4, встречающийся на экране (Netflow, Hot/Cold, Custody, Bridge/WBTC, z-score), кликабелен и открывает русскую карточку.
6. Бонус-вопрос показывается только после фазы 4; верный вариант — четвёртый.
7. `mastered` вычисляется по §5.1; событие `finish` содержит `score`, `bonus_correct`, `attempt`.
8. Ни одного английского слова в кнопках и заголовках вне токенов.

## 9. Тест-кейсы
- Все 8 верно + бонус верно → «8 из 8», mastered=true, предложение повторить — необязательное.
- 6 верно → mastered=false, кнопка «Повторить с другими суммами» обязательна, «Дальше по уроку» доступна с пометкой «не освоено».
- Ученик ставит №1 в «Приток» → объяснение про Cold-to-Hot Sweep, в фазе 4 честный поток всё равно считается по `correct`, а не по ответам ученика (панель показывает истину; ответы ученика показаны отдельно как «твой netflow: +…» — добавить третью мини-строку «Твоя разметка: чистый поток = X» для рефлексии).
- Обновление страницы посреди фазы 2 → размещённые карточки восстановлены.

```
│ Ось Y: [Уникальных контраг. ▼]│  │    размер точки = средний перевод)  │
│ [✓] Нормализовать признаки    │  │                                      │
│     (log + z-score)           │  └──────────────────────────────────────┘
│                               │  ┌─ Сколько кучек? ────────────────────┐
│ Число кластеров k: ●──────    │  │ k=2 ▂ 0,41  k=3 ▄ 0,52  k=4 █ 0,71  │
│          2  3  4  5  6        │  │ k=5 ▅ 0,55  k=6 ▃ 0,47   (силуэт)   │
│ [Зафиксировать k = 4]         │  └──────────────────────────────────────┘
└───────────────────────────────┘
```
- Ползунок k перекрашивает точки по `assignments[k]` с анимацией.
- Чекбокс «Нормализовать признаки» по умолчанию **выключен**: при выключенном — точки раскрашены по результату k-means на сырых признаках (тоже предрасчитать: там всё определяется одним признаком «контрагенты», и кластеры бессмысленны — например, 15 адресов в одном кластере). Всплывающая подсказка: «Без нормализации признак „контрагенты“ (десятки тысяч) задавил остальные. Это StandardScaler из кода урока». Кнопка «Зафиксировать k» активна только при включённой нормализации.
- Столбики силуэта: подсветить максимум **только после** фиксации — иначе игра решается за ученика. При наведении на столбик: «Силуэт — насколько чисто разделились группы».
- Фиксация k≠4: разрешена, но появляется предупреждение: «Силуэт при k=4 выше. Уверен?» с кнопками «Оставить k=N» / «Взять k=4». Если оставил k≠4 — штраф −1 к итогу и в раунде 2 будет объединённый кластер, который невозможно назвать одним прототипом (там появляется правильный ответ «Смесь: нужно увеличить k» — добавить его в список прототипов только для этого случая; выбор возвращает в раунд 1).

### Раунд 2 — «Назови прототип» (ИГР, «штраф за кластер 3»)
Для каждого кластера — карточка профиля:
```
┌─ Кластер 3 · 4 адреса (№6, №7, №8, №9) ─────────────────────┐
│ Радар профиля (4 оси, медианы кластера в z-шкале)            │
│ Средний перевод 780 BTC · Переводов/сутки 0,03               │
│ Возраст 1 700 дн · Контрагентов 4                            │
│ Прототип: [ выбрать ▼ ]   [Открыть досье адресов]            │
└──────────────────────────────────────────────────────────────┘
```
- Выпадающий список из §3.3 (7 пунктов, порядок перемешан).
- Кнопка «Дальше к переводам» активна всегда, **но**: если хотя бы один кластер оставлен «Пока не знаю», всплывает модальное окно:
  > «Кластер 3» ничего не значит. В раунде 3 переводы, которые касаются безымянного кластера, можно будет пометить только «Недостаточно данных». Назвать сейчас или идти так?
  [Назвать] / [Идти так]
- Ошибочный прототип (в т.ч. дистрактор) не сообщается сразу: последствия проявятся в раунде 3, а разбор — в итоге. Исключение: мгновенная реакция на дистрактор «Майнерский пул» / «Смарт-контракт моста» — лёгкая подсказка «Посмотри на контрагентов: у пула их сотни в день, у моста — кастодианы» без раскрытия ответа (одна подсказка на кластер).

### Раунд 3 — «Инкассаторы» (ИГР)
Макет одной транзакции:
```
┌─ Перевод T1 · 5 000 BTC ────────────────────────────────────────────┐
│ 🚚  №9 ─────────────────────────────▶ №1                             │
│     [Кит-накопитель]  (твоя метка)      [Биржевой горячий кошелёк]   │
│     [Досье №9]  [Проверить эвристики]   [Досье №1]                   │
│                                                                      │
│ Наивный радар сказал: «Кит завёл 5 000 BTC на Binance → шорт»        │
│                                                                      │
│ Твой вердикт:                                                        │
│ ( ) Подготовка к продаже   ( ) Уход в накопление                     │
│ ( ) Внутренняя/операционная (шум)   ( ) Недостаточно данных          │
│ [Ответить]                                                           │
└──────────────────────────────────────────────────────────────────────┘
```
- Над каждым адресом — **метка ученика из раунда 2** (не истинная). Если кластер безымянный — метка «Кластер N» серым, и три содержательных варианта ответа заблокированы с подписью «нельзя интерпретировать безымянный кластер» (штраф проявляется как невозможность заработать очко).
- «Проверить эвристики» открывает блок «Дополнительно» досье обоих адресов (§3.2, столбец «Досье») и список из 4 эвристик урока с автоматической проверкой ✓/✗:
  - Exchange Cold-to-Hot Sweep — регулярные ровные суммы на один и тот же горячий адрес
  - Dormant Whale Awakening — монеты не двигались > 3 лет
  - Common Input Ownership — несколько входов в одной транзакции
  - Change Address — возврат сдачи отправителю
  Использование бесплатно, но фиксируется. Для T1 без проверки эвристик верный ответ практически недостижим — это намеренно: игра учит, что кластер — не финал протокола.
- После ответа: ✅/❌, объяснение из §3.4, плюс строка «Что сказал бы наивный радар: …» для контраста.
- Аналогия из урока показывается один раз при входе в раунд: «Инкассаторская машина везёт деньги из отделения банка в его же хранилище — событие нулевой важности, хотя сумма огромная».

## 5. Логика и подсчёт

```
score_r1 = (k_fixed == 4) ? 1 : 0                    // + предупреждение
score_r2 = count(cluster.prototype == majority_true_prototype(cluster))  // max 4
score_r3 = count(answer[t] == correct[t])            // max 6
penalty_unnamed = count(clusters with prototype == "unknown")  // отражается автоматически: очки r3 по ним недостижимы
mastered = k_fixed == 4 and score_r2 == 4 and score_r3 >= 5 and answer[T1] == "internal"
```
- `majority_true_prototype(cluster)`: мода `true_group` среди адресов кластера с маппингом A→exchange_hot, B_whale/B_exch_cold→whale, C→retail, D→mm.
- Блокировка вариантов в раунде 3: если `prototype(from) == "unknown"` или `prototype(to) == "unknown"` → доступен только `no_data`, и он засчитывается как **0 очков** (не как ошибка, но и не как успех) с текстом «Ты правильно не стал интерпретировать безымянный кластер — но и сигнал потерян. Вернись и назови прототип».
- Метки над адресами в раунде 3 берутся из ответов ученика; если ученик ошибся прототипом (например, назвал MM «китом»), T4 будет выглядеть как «кит → биржа», и ответ «продажа» будет ошибкой с объяснением, ссылающимся на раунд 2: «Ошибка родом из раунда 2: кластер 17–20 — маркетмейкеры (контрагенты — только биржи, баланс около нуля)».

## 6. UI и адаптив
- Scatter: логарифмические оси, тултип по точке с сырыми значениями, клик → досье. Выбор осей — два дропдауна из 4 признаков; по умолчанию X = переводов в сутки, Y = контрагентов (на этой паре A/D/B+C видны хорошо, а B и C сливаются — намёк, зачем 4 признака и k-means, а не глаз).
- Радар профиля кластера: 4 оси в z-шкале, заливка цветом кластера.
- Цвета кластеров нейтральные (4 различимых, не семантических). Прототип после выбора подписывается текстом на легенде scatter.
- Мобильный: scatter во всю ширину, панель управления под ним; карточки кластеров — по одной со свайпом; транзакции — по одной.
- Доступность: значения силуэта дублируются текстом; scatter имеет текстовую альтернативу «Таблица адресов» (та же таблица §3.2 без столбцов true_group и досье) с переключателем «График / Таблица».

## 7. Языковой слой
Все токены §0.4 плюс на экране раунда 1 — подписи осей на русском с английским ключом в скобках при первом показе: «Переводов в сутки (tx_per_day)». Блок кода из урока (`KMeans(n_clusters=4…)`) можно показать в раунде 1 по кнопке «Как это выглядит в коде» с построчными русскими подписями справа — режим «англ. / рус. подписи / оба».

## 8. Критерии приёмки
1. JSON содержит предрасчитанные `assignments` и `silhouette` для k=2…6 на нормализованных признаках и отдельно для сырых; максимум силуэта — при k=4; для k=4 кластеры совпадают с группами A/B/C/D; №9 в кластере китов.
2. При выключенной нормализации фиксация k невозможна и показывается объяснение про масштаб признаков.
3. Оставленный «Пока не знаю» блокирует содержательные ответы по транзакциям этого кластера в раунде 3 и показывает модальное предупреждение при переходе.
4. Верный ответ по T1 — только `internal`; блок «Проверить эвристики» показывает для №9 факт «12 переводов по 5 000 на №1» и метку Binance Cold-12; эвристика Cold-to-Hot помечена ✓.
5. Метки над адресами в раунде 3 отражают выбор ученика, а не истину; ошибки прототипов объясняются в итоге со ссылкой на раунд 2.
6. `mastered` требует k=4, 4/4 прототипов, ≥5/6 транзакций и верный T1.
7. Итоговая таблица показывает три колонки (наивный радар / ученик / истина) и строку «3 из 4 сигналов кита — шум».
8. Все токены кликабельны; в кнопках и заголовках нет английского вне токенов.
9. Есть текстовая альтернатива scatter (таблица).

## 9. Тест-кейсы
- Идеальное прохождение (k=4, 4 прототипа, 6/6 с использованием эвристик на T1 и T3) → mastered=true.
- k=3 оставлен → в раунде 2 объединённый кластер; выбор «Смесь: нужно увеличить k» возвращает в раунд 1; итог −1.
- Кластер B назван «Майнерский пул» → мягкая подсказка; при повторном выборе того же — принимается; в раунде 3 над №6–№9 подпись «Майнерский пул»; T2/T3 при ответе «продажа» засчитываются как верные (истина не зависит от подписи), но в итоге разбор ошибки прототипа.
- T1 отвечен «продажа» без открытия эвристик → ❌ с полным объяснением про Cold-to-Hot; mastered=false даже при 5/6 остальных.
- «Пока не знаю» на кластере C → T5 доступен только как `no_data` → 0 очков, mastered=false, текст-приглашение вернуться.
- Обновление страницы в раунде 3 → сохранены k, прототипы и уже данные ответы.

## 10. Ограничения и что НЕ делать
- Не запускать реальный k-means в браузере: разные реализации дают разные локальные минимумы, что сломает проверку.
- Не показывать истинные группы (`true_group`) до итога.
- Не подсвечивать максимум силуэта до фиксации k.
- Не использовать красный/зелёный для кластеров и для меток приток/отток: цвет не должен подсказывать «хорошо/плохо».
- Не добавлять кнопку «Открыть шорт» — единственное действие Алексея в финале обоих интерактивов: строка в журнал.
