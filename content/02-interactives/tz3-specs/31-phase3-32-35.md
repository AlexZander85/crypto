# ТЗ на два симулятора Фазы 3

Общие требования к обоим интерактивам вынесены в раздел 0; далее — две независимые спеки, каждую можно отдавать агенту отдельно.

---

## 0. Общие требования (обязательны для обоих)

| Требование | Как выполнить |
|---|---|
| **Один интерактив = одно заблуждение** | Каждый экран заканчивается явной фразой-опровержением заблуждения (см. «Финальный вывод» в каждой спеке). Не добавлять функций, не работающих на это заблуждение. |
| **Числа из урока** | Все дефолты — из текста уроков 3.2 и 3.5 (перечислены ниже). Отклонения допустимы только в ползунках, дефолт всегда = число урока. |
| **Воспроизводимость** | Генератор случайности — seeded PRNG (mulberry32 или xorshift). Seed показывается в углу («Сценарий №…»), кнопка «Другой сценарий» меняет seed. Одинаковый seed → одинаковая траектория. |
| **«Что видел бот»** | Всё, что правее текущего бара, скрыто (затемнённая шторка). Никакого «просмотра будущего». |
| **Языковой слой «Ткни в непонятное»** | Любой английский токен в UI (`z-score`, `maker`, `funding`, `MMR`…) — кликабелен → всплывающая карточка: русское имя, определение из «Терминов урока», пример числом. Словарь — единый JSON на приложение (`glossary.json`), интерактив ссылается на ключи. |
| **Персонаж** | Сквозной герой — Алексей. В 3.2 и 3.5 суммы больше его депозита из Py-уроков, поэтому вводная фраза: «Алексей гоняет учебный счёт: цифры — из урока, чтобы ты мог сверить их с текстом». |
| **Три уровня** | Базовый режим виден сразу; блок «Глубже» — за свёрнутым переключателем, не обязателен для критерия освоения. |
| **Доступность** | Все кнопки управляются клавиатурой; цвета дублируются подписями (не только красный/зелёный). Мобильная вёрстка: панели складываются вертикально, график — минимум 320 px шириной. |
| **Производительность** | Один эпизод/сценарий считается синхронно < 50 мс; Монте-Карло (если есть) — в Web Worker, ≤ 1000 траекторий, прогресс-бар. |
| **Телеметрия** | События в единую шину (`interactive.event`): `open`, `decision`, `episode_end`, `campaign_end`, `mastery_pass/fail`, `glossary_click(token)`. Все с `lessonId`, `seed`, `ts`. |
| **Компонент** | Один корневой компонент на симулятор (`PairsCafeSim`, `FundingRentSim`), чистые функции движка отдельно от UI (`engine/*.ts`) — чтобы юнит-тесты гоняли движок без DOM. |

## 1. Урок 3.2 — «Два кафе и цена кофе»

### 1.1. Карточка

| Поле | Значение |
|---|---|
| ID | `sim-3.2-two-cafes` |
| Тип | СИМ + ИГР (решение с обратной связью), сквозная кампания из эпизодов |
| Место в уроке | После абзаца с аналогией про два кафе и ПЕРЕД таблицей «Значение Z-Score → действие». Существующий «Тренажёр: Z-Score спреда» остаётся — он учит считать z, этот учит **что делать при |z|=4**. |
| Заблуждение | «|z| = 4 — это ещё лучший вход» (усредниться, добавить, подождать). |
| Опровержение | «Отклонение на 4 сигмы — не скидка, а сигнал, что связь между активами, возможно, сломалась. Усреднение при 4 удваивает ставку на гипотезу, которую данные уже опровергают». |
| Связи | 3.1 (собака на поводке / двое расходятся), 1.7 (rolling-окно против look-ahead), 1.8 (издержки двух ног), П4 (якорь на цене входа), П24 (индейка: выигрывает чаще, теряет всё), М7 (высокий винрейт ≠ прибыль), 5.6 (правило устава: стоп при |z| ≥ 4 — «единый порог урока»). |
| Оценка объёма | Движок 1 день, UI 2 дня, тексты/тесты 0,5 дня. |

### 1.2. Числа урока (дефолты, менять нельзя)

- Пороги: вход **|z| ≥ 2**, выход **|z| ≤ 0,5**, аварийный стоп **|z| ≥ 4,0**.
- Пример пары: ETH/USDT vs BTC/USDT, вход при **z = +2,3** (ETH переоценен): шорт ETH **$10 000** + лонг BTC **$10 000**.
- Результат примера при возврате к среднему: **+$400 (+4 % на ногу)** — из этого калибруется масштаб: **1σ спреда = 1,75 % от ноги** (2,3σ ≈ 4,0 %).
- Аналогия: обычная разница цен кафе — **в пределах 10 ₽**; **50 ₽** — «одно скоро снизит, второе поднимет»; **300 ₽** — «сменили концепцию».
  Калибровка метафоры: `разница_₽ = 10 + 20·z` → z=2 ⇒ 50 ₽ ✔, z=0,5 ⇒ 20 ₽, z=4 ⇒ 90 ₽, «концепция» ⇒ ~300 ₽ (z≈14,5).
- Half-life > 30 дней — капитал заморожен, фандинг съедает прибыль (используется в «Глубже»).
- Издержки (из 1.8): taker 5,5 bps + полспреда 1 bps + слиппедж 2 bps ≈ **7,5 bps на сторону одной ноги**. Пара = 2 ноги × вход+выход = 4 стороны = **30 bps = $30 на юнит ($10k+$10k)**. Стоимость удержания: **$2/день на юнит** (фандинг/заём 0,01 %/день на ногу).

### 1.3. Пользовательский сценарий

**Экран 0 — Вводная (1 карточка, 15 сек).**
«Алексей торгует пару ETH/BTC по уставу урока: вход при |z| ≥ 2, выход при |z| ≤ 0,5. Устав говорит: при |z| ≥ 4 — стоп. Но рука тянется: «четыре сигмы — это же ещё дешевле!». Проживи 12 эпизодов и реши сам. Правой части графика ты не видишь — как и бот».
Кнопка «Начать кампанию».

**Экран 1 — Эпизод (основной).**
Компоновка (десктоп, 3 колонки):

- **Слева (метафора, 25 %)** — две витрины «Кафе А» / «Кафе Б» с ценниками. Ценник Б фиксирован (150 ₽), ценник А = 150 + `разница_₽`. При |z| ≥ 2 над дорогим кафе подпись «необычно дорого». При |z| ≥ 4 витрина мигает жёлтым: «90 ₽ разницы — откат или сменили концепцию?». При «концепции» (спред ушёл > 8σ) витрина А перекрашивается в новую вывеску «Specialty Roasters» и ценник 450 ₽ — но это показывается **только после конца эпизода**, чтобы не подсказывать.
- **Центр (график, 50 %)** — линия спреда во времени, ось Y двойная: слева «разница, ₽», справа «спред ETH/BTC, % ноги». Горизонтали: μ (0), ±0,5σ (пунктир), ±2σ (зелёный), ±4σ (красный). Маркеры: вход (▲/▼), добавленные юниты, выход. Шторка над будущими барами. Под графиком — плеер: «Шаг», «Авто (1 бар / 0,4 с)», «Пауза», счётчик «День k / 60».
  Тумблер «Кафе ↔ Крипта» меняет подписи оси и иконки, траектория та же.
- **Справа (табло, 25 %)** —
  `z сейчас`, `спред %`, `позиция: 0/1/2/3 юнита`, `нереализованный P&L $`, `издержки $`, `дней в сделке`, `счёт кампании $` (старт **$50 000**), мини-таблица прошедших эпизодов (№, исход, P&L).

**Автоматика эпизода:**
1. Бары 1…k: спред около нуля. Первое касание |z| ≥ 2 — **вход автоматически** (по уставу, 1 юнит). Тост: «Вход по уставу: z = +2,3. Шорт ETH $10 000, лонг BTC $10 000. Издержки входа $15».
2. Если |z| ≤ 0,5 — **выход автоматически**, эпизод завершён (плюс).
3. Если |z| ≥ 4,0 — плеер ставится на паузу, открывается **модалка решения** (см. 1.4).
4. Если после решения «Держать/Усредниться» спред доходит до |z| ≥ 6,0 — модалка повторяется (последний раз; максимум 3 юнита).
5. День 60 — принудительное закрытие всех юнитов по текущему спреду («Риск-офицер закрыл пару: срок удержания вышел» — привязка к half-life).

**Экран 2 — Разбор эпизода (после каждого).**
Шторка снимается: показана полная траектория и тип эпизода (см. 1.5). Три строки: «Ты сделал: …», «Итог: … $», «Если бы стоп при 4: … $» (только если игрок не стопнул) — контрфакт считается на той же траектории.
При типе «Глубокий откат», когда игрок стопнул и упустил прибыль, обязателен текст: «Да, здесь стоп стоил денег. Устав жертвует такими эпизодами сознательно — сейчас увидишь, ради чего».

**Экран 3 — Итог кампании (после 12 эпизодов).**
Четыре кривые счёта на одном графике: **Ты**, **А «По уставу»**, **Б «Держу»**, **В «Усредняюсь»** (операторы-двойники, прогнанные по тем же 12 траекториям). Таблица:

| | Прибыльных эпизодов | Средний плюс | Средний минус | Худший эпизод | Итог |
|---|---|---|---|---|---|

Ожидаемая картина (движок должен воспроизводить порядок, не точные суммы): Б и В **выигрывают чаще** (≈9/12 против ≈7/12 у А), но итог А > Б > В, у В худший эпизод ≈ −$5 000…−$6 000. Под таблицей — **финальный вывод** (1.7) и кнопка «Другой сценарий» (новый seed, та же композиция эпизодов).

### 1.4. Модалка решения при |z| ≥ 4

Заголовок: «Разница 90 ₽ (z = 4,1). Устав говорит: стоп. Что делаешь?»

Три кнопки (порядок фиксирован, «Стоп» не выделен цветом — иначе подсказка):
- **«Усредниться (+1 юнит)»** — подпись мелко: «ещё $10 000 + $10 000 по текущей цене».
- **«Держать»** — «ничего не менять, ждать возврата».
- **«Стоп (закрыть всё)»** — «зафиксировать убыток по уставу».

Под кнопками — обязательное поле-ловушка (движок R1 из пакета, упрощённый): при выборе «Усредниться» или «Держать» появляется строка: «Назови факт: что говорит тебе, что это откат, а не смена концепции?» — свободный текст, минимум 1 символ, иначе кнопка не срабатывает. Текст сохраняется в лог эпизода и показывается на экране разбора рядом с истинным типом эпизода («Ты написал: „уже сильно упало“. Тип эпизода: сменили концепцию»). Смысл: ученик видит, что факт был чувством.

### 1.5. Движок: генератор траекторий

Единица времени — 1 бар = 1 день. Спред `s_t` в % ноги.

**Базовый процесс (Орнштейн–Уленбек, дискретный):**
```
s_{t+1} = s_t + θ·(μ_t − s_t) + σ_ε·ε_t,  ε_t ~ N(0,1)
θ = 1 − 2^(−1/HL),   HL = 8 дней (дефолт)
σ_ss = 1.75 %  (целевая стационарная сигма)
σ_ε = σ_ss · sqrt(1 − (1−θ)²)
z_t = (s_t − μ̂) / σ̂
```
Базовый режим: `μ̂ = 0, σ̂ = σ_ss` — «оценены по 200 предыдущим дням» (показывать эту фразу; отдельно генерировать предысторию не обязательно).

**Типы эпизодов** (композиция кампании фиксирована, порядок перемешан seed'ом: 7 × T1, 2 × T2, 2 × T3, 1 × T4; первый эпизод — всегда T1, чтобы игрок увидел «как оно должно работать»):

| Тип | Название в разборе | Механика | Гарантии |
|---|---|---|---|
| T1 | «Обычный откат» | OU; на баре k∈[5,15] импульс: `s_k = sign·U(2.1, 2.8)·σ_ss`; далее чистый OU | |z| не достигает 4 (если случайно достигло — перегенерировать эпизод) |
| T2 | «Глубокий откат» | импульс до `U(2.1,2.6)σ`, через 2–5 баров второй импульс до `U(4.2,4.8)σ`, затем OU с HL=6 | возврат к |z| ≤ 0.5 до 60-го дня гарантирован (иначе перегенерация) |
| T3 | «Сменили концепцию» | импульс до `U(2.1,2.6)σ`; с бара k+U(2,6) `μ_t` линейно уезжает до `sign·U(12,16)σ` за U(5,10) баров, θ падает до 0.02 | |z| ≥ 4 достигается; возврата нет |
| T4 | «Медленно расходятся» (двое из подъезда, 3.1) | импульс до 2.2σ, затем `μ_t += sign·0.12σ` каждый бар, θ=0.03 | |z| ≥ 4 достигается на баре ≤ 40; к 60-му дню ≈ 6–7σ |

`sign` ∈ {+1, −1} равновероятно; для UI: sign=+1 → «Кафе А дороже» / «ETH переоценен».

**Учёт позиции** (юнит = шорт дорогой ноги $10 000 + лонг дешёвой $10 000; на графике одна ставка на схлопывание спреда):
```
pnl_unit_i = −sign · (s_t − s_entry_i)/100 · 10_000   # $, спред в %
fees_unit  = 30 $ за круг (15 вход + 15 выход)
carry_unit = 2 $ · дней_в_сделке
pnl_episode = Σ_i (pnl_unit_i) − Σ fees − Σ carry
```
Отдельного «маржин-колла» нет: худший случай T3 с 3 юнитами ≈ −$5 200 − издержки; этого достаточно для эффекта, а сложность ликвидации оставлена уроку 3.5.

**Операторы-двойники** (детерминированные, гоняются по тем же массивам `s_t`):
- А: вход 2 → выход 0.5 / стоп 4 (1 юнит).
- Б: вход 2 → выход 0.5, стопа нет, принудительно на 60-м дне.
- В: вход 2, +1 юнит на 4, +1 на 6 → выход 0.5, принудительно на 60-м.

**Юнит-тесты движка (обязательны):**
1. Seed фиксирован → 12 траекторий побайтно совпадают при повторе.
2. Композиция типов = {T1:7, T2:2, T3:2, T4:1}.
3. T1 никогда не достигает |z| ≥ 4; T2 всегда возвращается к ≤0.5; T3/T4 достигают ≥4.
4. Для любого seed: `итог_А > итог_Б > итог_В` и `винрейт_Б ≥ винрейт_А`, `винрейт_В ≥ винрейт_А`. Если тест падает на seed — генератор подкручивается (амплитуды T3), а не тест.
5. Пример урока воспроизводится: вход z=2.3, выход z=0 ⇒ pnl_unit ≈ +$400 ± 5 до издержек.

### 1.6. Блок «Глубже» (сворачиваемый, не влияет на критерий освоения)

1. **Ползунок Half-life 3…40 дней** (дефолт 8). При HL > 30 табло подсвечивает `carry` красным: «удержание > 30 дней: заём и фандинг съедают ожидаемый +4 %» (цитата урока). Влияет на θ и на среднюю длительность T1.
2. **Тумблер «Скользящее окно z (60 дней)»** — вместо фиксированных μ̂/σ̂ используется rolling-оценка. Демонстрирует ловушку: после смены концепции z «возвращается к нулю» через ~40 дней, хотя спред стоит на +14σ. Оператор Б в этом режиме выходит «по сигналу z ≤ 0.5» с большим убытком; подпись: «z вернулся, спред — нет. Выход по z — правильное поведение бота, прибыли тут не было и не могло быть». (Связка с 1.7: rolling против look-ahead и с итогом урока «среднее и сигма считаются в скользящем окне».)
3. **Стоимость стопа «в среднем»**: после кампании — кнопка «Прогнать 200 кампаний» (Web Worker): гистограмма итогов А/Б/В. Ожидаемо: у А узкое распределение около небольшого плюса, у В — правый горб чаще, левый хвост глубже. Подпись: «Усреднение покупает частые маленькие победы ценой редкого разорения — это индейка из урока П24».

### 1.7. Тексты обратной связи (обязательные формулировки)

- Вход: «Вход по уставу. Ставка не на ETH и не на BTC, а на то, что расстояние между ними вернётся к обычному».
- Модалка при 4 (см. 1.4).
- Разбор T3 после «Усредниться»: «Ты дважды купил гипотезу, которую рынок уже опроверг. Первый юнит — сделка; второй — упрямство; третий — П4: якорь на цене входа».
- Разбор T2 после «Стоп»: «Стоп стоил $X. Это плата за страховку от следующего экрана».
- **Финальный вывод кампании (всегда одинаков):**
  «Операторы Б и В выигрывали чаще тебя-по-уставу — и закончили хуже. |z| = 4 не означает „дешевле“: это точка, где вероятность „связь сломалась“ уже сопоставима с вероятностью „откат“. Ставка на схлопывание без факта о причине расхождения — не арбитраж, а мартингейл. Единый порог урока: |z| ≥ 4 — стоп, и он записан в устав ДО сделки, а не выбирается в модалке».

### 1.8. Критерий освоения (гейт к следующему блоку урока)

Засчитывается, если выполнено **оба**:
1. В кампании не более 1 решения «Усредниться» **после** первого разбора T3 (т.е. ученик учится на первом же примере). Если первый T3 пришёл 12-м — засчитывается автоматически, кампания предлагает вторую (короткую, 6 эпизодов).
2. Контрольный вопрос после итога: «Спред ETH/BTC на +4,3σ. Какие данные позволили бы вменяемо предположить откат, а не поломку?» Варианты: (а) «цена уже сильно отклонилась — значит, вернётся» ✗; (б) «нет новостей о хардфорке/взломе/делистинге, ликвидность обеих ног в норме, а спред движется на общем падении рынка — но по уставу всё равно стоп, гипотезу проверяют на следующем входе» ✔; (в) «RSI по ETH перепродан» ✗. Правильный ответ намеренно содержит «всё равно стоп».

### 1.9. Приёмка (чек-лист QA)

- [ ] Одинаковый seed даёт одинаковые 12 эпизодов и одинаковые итоги двойников.
- [ ] Шторка скрывает будущее в любом состоянии плеера, включая паузу в модалке.
- [ ] Кнопки «Усредниться/Держать» не срабатывают при пустом поле факта.
- [ ] Ось метафоры и ось крипты синхронны: z=2 ⇔ 50 ₽ ⇔ 3,5 %.

### 2.2. Числа урока (дефолты)

- Депозит **$100 000**; спот BTC **$50 000** + шорт перп BTCUSDT **$50 000**.

- Отрицательный фандинг на медвежьем рынке: **−0,02 % неделями**; защита — авто-выход при переворотe средней ставки.

- Интервал фандинга: 8 ч (на части бирж 1 ч) — параметр.
- MMR по умолчанию **0,5 %** с обязательной подписью урока: «запас до ликвидации — грубая оценка, зависит от MMR биржи, режима маржи и доли позиции в стакане».

### 2.4. Движок

Обозначения: `N = 50 000` (нотионал ноги), `C = 100 000` (капитал), `f` — ставка за интервал, `k = 24/интервал_ч` интервалов в день, `L` — плечо шорта, `m = N/L` — маржа шорта, `free = C − N − m` — свободные USDT.

**Базовый поток:**
```
daily_income(t)   = N · f(t) · k                          # $30 при f=0.02%, k=3
entry_cost        = N·(fee_spot + fee_perp) + spread_cost # maker: 5+10+15=30; taker: 25+25+15=65
exit_cost         = аналогично
breakeven_entry   = min d : d·daily_income > entry_cost   # maker→2, taker→3 (совпадает с уроком)
breakeven_round   = min d : d·daily_income > entry_cost + exit_cost  # maker→3, taker→5
cum(t)            = Σ_{τ≤t} daily_income(τ) − entry_cost − [закрыто? exit_cost : 0] − потери
apy               = f·k·365                                # 21.9 %
```
Пороги «Безубыток» пересчитываются при любом изменении комиссий/ставки; при `daily_income ≤ 0` показывать «никогда».

**Событие 1 — переворот ставки:**
`f(t) = f_neg` для `t ∈ [D₁, D₁+W)`, иначе `f₀`.
Если защита выкл.: доход становится −$30/день, кривая ломается вниз. Тост на день D₁+7: «Жилец не платит уже неделю; ты платишь ему $30 в день, потому что „схема же безрисковая“».
Если защита вкл.: на день `D₁+3` (средняя за 3 дня < 0) позиция закрывается, платится `exit_cost`, статус «выведен по правилу»; после возвращения ставки в плюс на 3 дня — повторный вход (снова `entry_cost`). В табло — «Кругов за период: 2, издержки кругов: $…». Вывод: правило спасает, но каждый круг стоит безубытка заново.

**Событие 2 — памп:**
```
liq_move        = 1/L − MMR                                # 2x → 49.5 %
liq_move_prot   = (m + free)/N − MMR   (если авто-перевод вкл.)  # при C=100k, L=2: 99.5 %
liquidated      = pump_pct > (защита ? liq_move_prot : liq_move)
```
Если не ликвидирован: дельта = 0, ничего не меняется, тост «Спот +$40 000, перп −$40 000, фандинг капает. Вот это и обещала дельта-нейтральность». (Важно показать хороший исход — иначе интерактив учит «памп = смерть».)
Если ликвидирован: потеря = использованная маржа (`m`, либо `m+free` при защите); шорт исчез; остаётся спот на `N·(1+pump)` — **дельта ≠ 0**. Если тумблер отката вкл.: на следующий день цена −30 % → спот теряет `N·(1+pump)·0.30`; табло: «Дельта-нейтральная схема закончилась голым лонгом на $90 000, который на откате потерял $27 000». Спот считается проданным по цене конца дня D₂+1 (упрощение, подписать). Фраза урока: «шорт ликвидируется до того, как спот успеют продать».

**Событие 3 — стоп выводов:**
`t ∈ [D₃, D₃+H)` — статус «заморожено»: капитал недоступен, фандинг продолжает начисляться (тумблер «начисляется» вкл. по умолчанию), кривая рисуется серым, поверх — «деньги на бирже = обязательство биржи (5.7)».
Если «площадка не вернулась»: на день D₃ потери = `share · C` (доля капитала на площадке × весь капитал, включая накопленный доход). При share=100 % итог = −$100 000 + 0; статус «потерян». Табло показывает рядом контрфакт: «При доле 20 % (лимит урока 5.7) потеря составила бы $20 000 — больно, но схема живёт на второй площадке».

**Комбинации:** события независимы и могут включаться вместе; порядок применения — по дням. При ликвидации (событие 2) события 1 и 3 продолжают влиять на остаток (замороженный спот).

**Юнит-тесты движка:**
1. Дефолт maker: `breakeven_entry = 2`, `breakeven_round = 3`, `daily_income = 30`, `apy ≈ 21.9`.
2. Дефолт taker: `breakeven_entry = 3`, `breakeven_round = 5`.
3. L=2, защита выкл., pump 80 → ликвидация; защита вкл. → нет; L=1 → нет при любом pump ≤ 99.
4. Переворот без защиты, W=21 → cum(D₁+21) − cum(D₁) = −630 (21·30).
5. Haircut 100 % при share 100 % → итог = −C; share 20 % → −0.2·C.
6. Все три выключены → cum(90) = 90·30 − 30 = 2670 (maker, без закрытия).

### 2.5. Блок «Глубже» — «Год аренды» (Монте-Карло, Web Worker)

Кнопка «Прожить 1000 лет аренды». Каждая траектория — 365 дней:
- режим ставки: марковская цепь «бычий» (f ~ N(+0,03 %, 0,015)) ↔ «медвежий» (f ~ N(−0,005 %, 0,015)), переключение с вероятностью 1/60 в день;
- памп ≥ +80 %: вероятность **0,25/год** (учебная), размер U(80,120);
- стоп выводов: 0,05/год, из них половина — с haircut U(30,100) %;
- параметры защит/плеча/доли берутся из текущих тумблеров.

Вывод: гистограмма годового результата, подписи «медиана», «5-й процентиль», «доля лет с убытком», «худший год». Рядом — та же гистограмма при «уставных» настройках (L=1, оба авто-правила вкл., доля 20 %) для сравнения. Обязательная плашка: «Частоты событий — учебные, взяты для формы распределения, не для прогноза». Финальная подпись: «Средний год положительный. „Безрисковый“ — это про среднее. Левый хвост — про то, доживёшь ли ты до среднего (1.2, П24)».
