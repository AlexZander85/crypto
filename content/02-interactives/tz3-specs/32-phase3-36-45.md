# Детальные спеки для реализации: интерактивы 3.6 и 4.5

Общие соглашения для обоих спеков (чтобы агент не переспрашивал):

- **Язык интерфейса** — только русский. Все английские термины показываются в режиме «Ткни в непонятное»: клик по подчёркнутому слову → всплывающая карточка «русское имя — одна фраза — пример — ссылка на урок». Словарь карточек приведён в конце каждого спека.
- **Числа берутся из текста урока**, интерактив обязан воспроизводить их точно (контрольные значения и допуски указаны). Никакой случайности: все расчёты детерминированы, при одинаковых входах — одинаковая картинка.
- **Персонаж и капитал:** там, где нужна сумма, — целевой капитал курса 6 000 000 ₽ (урок 5.3); допускается переключатель на 1 000 $ Алексея.
- **Технически:** framework-agnostic, чистый SVG/Canvas + rAF для анимаций, без внешних API и тяжёлых библиотек; компонент должен работать на ширине 360 px (мобильная вёрстка стеком), поддерживать клавиатуру (ползунки — стрелками, кнопки — Tab/Enter) и `prefers-reduced-motion` (анимация заменяется пошаговым режимом).
- **Интеграция:** компонент экспортирует `onComplete({score, answers, params})` для прогресса урока и `onJournal(entry)` для движка журнала E5 (опционально). События аналитики перечислены в конце.

## СПЕК A · Урок 3.6 · «Пять выходов — один коридор»

### 0. Паспорт

| Поле | Значение |
|---|---|
| ID | `INT-3.6-EXITS` |
| Тип | АНИМ + СИМ (управляемая анимация с ползунками) + мини-ИГР в финале |
| Целевое заблуждение | «Диверсификация работает всегда: пять независимых стратегий = пять независимых страховок» |
| Что должен вынести ученик | (1) корреляции — не константа, в крах они схлопываются к 1; (2) просадка портфеля «на бумаге» 11 % превращается в 21 % не из-за плохих стратегий, а из-за общего коридора; (3) единственная защита — считать связь **по худшим дням** и ограничивать суммарный риск под эту оценку, а не под штиль |
| Время прохождения | 4–6 минут |
| Движки | самостоятельный компонент; при наличии E8 (веер/гейдж) — переиспользовать гейдж просадки |
| Место в уроке | сразу после абзаца-аналогии «Пять разных выходов из здания…» и до симулятора «Интерактив: портфель vs просадка». Существующий «Матрица корреляций: штиль vs крах» **не удалять**: он остаётся справочной статикой; новый интерактив — сценарный. Если хотите один компонент — существующая матрица становится Актом 3 (см. ниже) |

### 1. Сценарий прохождения (три акта + проверка)

**Акт 1. «Штиль: что обещает бумага».** Ученик видит здание с пятью выходами, по которым спокойно выходят пять потоков «людей» (пять стратегий), корреляционную матрицу 5×5 в холодных тонах (средняя связь 0,06) и гейдж «оценка просадки портфеля» = **11,0 %** (660 000 ₽ на 6 млн). Подпись: «Так портфель выглядит на всей истории. Именно эту цифру ты покажешь себе и инвесткомитету». Кнопка **«Наступил крах-день ▶»**.

**Акт 2. «Крах-день».** Анимация 8 секунд (или пошагово): корреляции в матрице разогреваются до красного, коридоры здания сливаются в один, у единственной двери образуется пробка, гейдж ползёт с 11 % до **21,0 %** (1 260 000 ₽). На гейдже висит маркер **«Мой лимит просадки»** (по умолчанию 15 %, перетаскивается). В момент пробоя лимита — стоп-кадр с подписью: «Лимит 15 % пробит при средней корреляции 0,37 — задолго до паники. Аварийный выключатель (урок 4.4) уже сработал бы». В конце — плашка: «Разница 600 000 ₽ — цена иллюзии диверсификации». Ползунок «Средняя корреляция» позволяет протянуть состояние вручную туда-обратно.

**Акт 3. «Как увидеть это заранее».** Переключатель «Матрица посчитана по: ● все дни истории / ○ худшие 5 % дней». Во втором положении матрица показывает 0,78–0,95, оценка просадки ≈ **20 %**. Подпись: «Считая связь только по худшим дням, ты увидел бы 20 из 21 % заранее — и подобрал бы веса под эту цифру». Три пункта «что делать» (из итога урока).

**Проверка.** Один вопрос с четырьмя вариантами; за неверный вариант A показывается расчёт «шестого выхода» (см. §7).

### 4. Расчёты

Оценка просадки портфеля при матрице корреляций ρ:

```
DD(ρ) = sqrt( Σ_i Σ_j w_i · w_j · L_i · L_j · ρ_ij )
```
где `L_i = crashLoss`, `w_i = weight`. Это та же портфельная формула, что в уроке 3.4 (риск-паритет), поэтому в тултипе к гейджу — ссылка «как считается → урок 3.4».

Интерполяция для ползунка «Средняя корреляция» и анимации (параметр `t ∈ [0,1]`):

```
ρ_ij(t) = ρ_calm_ij + t · (1 − ρ_calm_ij)      // диагональ всегда 1
avgCorr(t) = среднее внедиагональных ρ_ij(t)   // отображается на ползунке
```

**Контрольные значения (юнит-тесты обязательны):**

| Состояние | DD | Допуск | ₽ при 6 000 000 |
|---|---|---|---|
| `t = 0` (штиль, corrCalm) | 10,99 % → показывать **11,0 %** | ±0,1 п.п. | 660 000 ₽ |
| `t = 1` (crash, все ρ = 1) | **21,0 %** | ±0,05 п.п. | 1 260 000 ₽ |
| corrWorst5 (Акт 3) | 19,93 % → показывать **≈20 %** | ±0,2 п.п. | ≈1 196 000 ₽ |
| Пробой лимита 15 % | при `t ≈ 0,326`, avgCorr ≈ **0,37** | ±0,01 по t | — |
| Средняя связь штиль | avgCorr(0) = 0,06 | точно | — |

Промежуточная формула для проверки: `DD(t)² = 120,77 + 320,23·t` (в %²) — агент может использовать как assert.

Пробой лимита при произвольном лимите `Lim` (пользователь двигает): `t* = (Lim²·10⁴ − 120,77) / 320,23`; если `t* < 0` → «лимит ниже даже бумажной оценки — портфель не проходит уже в штиль»; если `t* > 1` → «лимит не пробивается даже при полном схлопывании — но проверь, не слишком ли он щедрый для депозита (урок 0.12: после −25 % нужно +33 %)».

Рубли: `DD × capital`, форматировать с пробелами-разделителями, без копеек.

### 5. Анимация Акта 2 (таймлайн)

Длительность 8 с при `play`; `t` меняется по функции `easeInCubic` (паника ускоряется к концу). Управление: **▶ / ⏸ / шаг ±0,05 / ползунок-скраббер**. При `prefers-reduced-motion` — только кнопки «шаг» и ползунок.

Синхронные слои:

1. **Матрица.** Цвет ячейки: линейный градиент по значению 0 → 1 (холодный синий `#DBEAFE` → красный `#DC2626`); текст ячейки обновляется каждые 0,05 t с двумя знаками. Диагональ серая, не участвует.
2. **Здание.** 5 коридоров-полос от центра к 5 дверям. При росте `t` двери 2–5 смещаются к двери 1 (позиция двери k: `x_k(t) = x_k(0) + t·(x_1 − x_k(0))`), ширина проёма `w(t) = w₀·(1 − 0,8t)`. Потоки «людей» (по 12–16 кружков цвета стратегии) движутся к своей двери; при `t > 0,6` кружки разных цветов скапливаются перед единственной дверью (радиус скопления растёт). Без физики — достаточно позиций по кривым Безье с задержкой.
3. **Лента событий** (подписи под зданием, по порогам t; текст — из урока, числа не выдумывать):
   - t = 0: «09:00 — обычный день, стратегии независимы»
   - t = 0,3: «Ликвидность уходит, спреды расширяются»
   - t = 0,6: «Каскад ликвидаций: BTC −37 % за день, фандинг −0,15 %, спреды ×15 (12 марта 2020)»
   - t = 0,9: «Все продают одновременно — пять выходов ведут в один коридор»
4. **Гейдж просадки.** Заполнение растёт; постоянные маркеры: «На бумаге 11 %» (пунктир), «Мой лимит» (перетаскиваемый треугольник), текущая цифра + рубли. При пересечении лимита: заполнение краснеет, короткая вибрация подписи (не анимировать при reduced-motion), автопауза 1,5 с с плашкой пробоя (§1), затем продолжение.
5. **Финальная плашка** при `t = 1`: «На бумаге: 11 % (660 000 ₽). В крах-день: 21 % (1 260 000 ₽). Разница 600 000 ₽ — не ошибка стратегий, а один коридор для всех».

### 6. Акт 3 — переключатель метода оценки

Сегмент-контрол «Матрица посчитана по: **все дни истории** | **худшие 5 % дней**». При переключении матрица кроссфейдом меняется на `corrWorst5`, гейдж — на ≈20 %, здание фиксируется в состоянии `t = 0,9` (коридоры почти слиты — «вот что видно в худшие дни»).

Текст-вывод (три пункта, без воды):
- «Считай корреляции стратегий отдельно по худшим 5 % дней рынка — это и есть твоя рабочая матрица.»
- «Ограничивай суммарный одновременный риск так, чтобы оценка-по-крахам (20 %) укладывалась в твой лимит, а не оценка-по-штилю (11 %).»
- «Гоняй портфель через реальные крах-дни: март 2020, май 2021, май 2022 (LUNA), ноябрь 2022 (FTX).»

### 7. Мини-проверка (критерий освоения)

Вопрос: **«Портфель обещал 11 % просадки, твой лимит — 15 %. Что реально защитит в крах-день?»**

| Вариант | Верно? | Обратная связь |
|---|---|---|
| A. Добавить шестую лонг-стратегию на альтах — больше выходов | ✗ | Живой расчёт: добавляется карточка «Моментум альтов-2, −28 %», равные веса 1/6 → DD в крах = (105+28)/6 = **22,2 %**. Подпись: «Шестой выход ведёт в тот же коридор. Стало хуже, а не лучше.» |
| B. Считать корреляции по худшим 5 % дней и подобрать веса/лимиты так, чтобы оценка-по-крахам укладывалась в 15 % | ✓ | «Да. Проектируем под момент паники, а не под обычный вторник. Матрица по худшим дням показала бы 20 % заранее.» |
| C. Поднять лимит до 25 % — раз всё равно падает всё | ✗ | «После −25 % нужно +33 % только чтобы вернуться (урок 0.12). Ты не защитился, ты разрешил себе тонуть глубже.» |
| D. Отключить самую волатильную стратегию руками в день краха | ✗ | «В день краха ты узнаёшь о нём, когда стопы уже сработали. Решение принимает аварийный выключатель по порогам, записанным заранее (4.4), а не рука в 03:00 (П1).» |

Проходной критерий: верный ответ B (с любой попытки; фиксируется число попыток). `onComplete({score: попытка==1 ? 1 : 0.5, ...})`.

### 9. Приёмочные критерии

- [ ] Контрольные значения из §4 проходят как автотесты (11,0 / 21,0 / ≈20 / t* ≈ 0,326).
- [ ] Ползунок и анимация двигают **одновременно** матрицу, здание, гейдж и рубли; расхождений между слоями нет.
- [ ] Маркер лимита перетаскивается мышью/пальцем и стрелками; плашка пробоя показывает корректную среднюю корреляцию для любого лимита в диапазоне 8–30 %.
- [ ] Переключение капитала (6 000 000 ₽ / 1 000 $) пересчитывает все денежные подписи.
- [ ] Reduced-motion: нет автопроигрывания, есть пошаговый режим; все состояния достижимы клавиатурой.
- [ ] Вариант A проверки показывает живой пересчёт 22,2 %.
- [ ] На 360 px ничего не обрезано; матрица читаема (минимум 11 px в ячейке или горизонтальный скролл).
- [ ] Ни одной английской подписи вне тултипов.

Тест-кейсы: (1) t=0→ассерты; (2) drag лимита на 10 % → сообщение «пробит уже при корреляции 0,17» (проверить формулу: t* = (100−120,77)/320,23 < 0 → ветка «лимит ниже бумажной оценки»; значит корректное сообщение — «портфель не проходит даже в штиль»); (3) лимит 25 % → t* = (625−120,77)/320,23 = 1,57 > 1 → ветка «не пробивается, но…»; (4) выбор A→B: счёт 0,5.

| Тип | СИМ (ползунок → зона → причины → действие) + ТРН «Диагност» (карточки-кейсы) + режим «Свои числа» |
| Целевое заблуждение | «Разница между бэктестом и бумажной торговлей в 15 % — мелочь, главное что в плюсе» |
| Вторичное заблуждение | «Если бумага лучше бэктеста — значит стратегия ещё сильнее, чем думал» |
| Что должен вынести | (1) отклонение исполнения — относительная величина с тремя зонами: <10 % норма, 10–25 % серая, >25 % стоп; (2) сама цифра — не диагноз: диагноз ставится по разбивке (число сделок, слиппедж, винрейт); (3) серая зона запрещает наращивать капитал, красная — запрещает реальные деньги вообще |
| Время | 5–8 минут |
| Движки | E8 (двуязычная таблица метрик) — переиспользовать таблицу-разбивку; E5 — кнопка «записать ED недели в журнал»; E4 — гейт «допуск к микро-лайву» |
| Место в уроке | после абзаца-аналогии про навигатор, **вместо** существующего «Калькулятор Execution Deviation» (его функция полностью покрыта режимом «Свои числа»). Если калькулятор хотят оставить — разместить новый интерактив перед ним |
| Отличие от предложения ТЗ-3 | диапазон ползунка расширен с 0–40 % до **−80…+30 %**: только так воспроизводятся все числа урока (−15 %, −30 %, −80 % = «+20 → +4», и «70 минут») и закрывается вторичное заблуждение про «слишком хорошо» |

### 1. Сценарий прохождения

**Часть 1. Ползунок (СИМ).** Экран разделён на «Навигатор» и «Торговля». Ползунок «Отклонение исполнения» от −80 % до +30 %. Слева — план 40 минут и фактическое время; справа — бэктест +12,0 % и бумажный результат. Под ползунком — цветная шкала зон, карточка «Вероятные причины» и карточка «Что делать сейчас» плюс гейт «Следующий шаг: микро-лайв — разрешён / отложен / запрещён». Стартовое положение: −15 % (пример урока: 12,0 → 10,2).

**Часть 2. «Диагност» (ТРН).** Семь карточек-кейсов с таблицей-разбивкой (как таблица урока). Ученик выбирает зону и главную причину; получает разбор. Итог — 7 баллов.

**Часть 3. «Свои числа».** Поля: результат бэктеста, результат бумаги (или следующей ступени — микро-лайв), опционально число сделок / средний слиппедж / винрейт в обеих колонках. Считается ED, зона, автоподсказка по паттернам (§5). Кнопка «Записать в журнал недели» (E5).

### 3. Расчёты (Часть 1)

```
ED         = (paper − backtest) / backtest            // относительное, в долях
paper(ED)  = backtest · (1 + ED)                      // backtest = 0.12 по умолчанию
minutes(ED)= 40 · (1 − ED)                            // ED=−0.10 → 44 мин; ED=−0.75 → 70 мин; ED=+0.20 → 32 мин
zone(ED):
  |ED| < 0.10            → "норма"
  0.10 ≤ ED_abs < 0.25   → "серая"        (ED < 0)
  ED ≤ −0.25             → "стоп"
  ED ≥ +0.10             → "подозрительно хорошо"   (отдельная зона, см. §4)
```

Шаг ползунка 1 %. Отображение: ED — целые проценты со знаком; paper — один знак после запятой; минуты — целые (округление к ближайшему).

**Контрольные значения (автотесты):**

| ED | paper | минуты | зона |
|---|---|---|---|
| −15 % | +10,2 % | 46 | серая |
| −10 % | +10,8 % | 44 | серая (граница; пояснение «ровно на границе — считаем серой») |
| −9 % | +10,9 % | 44 | норма |
| −30 % | +8,4 % | 52 | стоп |
| −75 % | +3,0 % | **70** | стоп |
| −80 % (бэктест 20) | +4,0 % | 72 | стоп — пример урока «+20 → +4» |
| +20 % | +14,4 % | 32 | подозрительно хорошо |

Поле «Бэктест» в Части 1 редактируемое (по умолчанию 12,0), чтобы ученик мог воспроизвести пример «+20 → +4»; при `backtest ≤ 0` показывать подсказку «отклонение считается только от положительного ожидания; при убыточном бэктесте вопрос не в исполнении, а в самой стратегии».

### 4. Тексты зон (Часть 1)

**Норма (|ED| < 10 %).**
Навигатор: «Планировал 40, вышло 44 — пробки в пределах ожидания.»
Причины: «Штатное трение: реальный спред и проскальзывание чуть выше модели; 1–2 сделки пропущены из-за микро-сбоев сети.»
Действие: «Ничего не менять. Продолжать бумажную торговлю, раз в неделю записывать отклонение. Код бумаги и бэктеста — один и тот же файл.»
Гейт: «✅ микро-лайв разрешён (при выполнении остальных пунктов чек-листа FT-20)».

**Серая (−10…−25 %).**
Навигатор: «Вышло 46–50 минут. Ещё можно ездить, но планировать встречи по этому навигатору уже нельзя.»
Причины: «• модель проскальзывания слишком оптимистична; • часть лимитных заявок не исполняется (очередь в стакане, таймаут); • задержка между сигналом и исполнением съедает движение.»
Действие: «1) пересчитать бэктест с комиссией, завышенной на оценку проскальзывания (FT-13); 2) замерить долю отменённых заявок и задержку; 3) капитал не увеличивать до возврата в норму.»
Гейт: «⏸ микро-лайв отложен».

**Стоп (≤ −25 %).**
Навигатор: «Вышло 70 минут вместо 40. Навигатор не знает твоей дороги — маршрут строился не по этому городу.»
Причины: «• скрытое заглядывание в будущее (look-ahead) в бэктесте; • бэктест на других данных/бирже/тарифе, чем бумага; • стратегия слишком частая или крупная для реальной ликвидности; • разный код в бэктесте и в бумаге.»
Действие: «Запрет на реальные деньги. Вернуться к бэктесту: проверка на подсматривание (FT-11), сверка кода, сверка тарифа и пар. Бумажный результат не воспроизводится — масштабировать нечего.»
Гейт: «⛔ микро-лайв запрещён».

**Подозрительно хорошо (≥ +10 %).**
Навигатор: «Приехал за 32 минуты при плане 40. Либо ехал на красный, либо навигатор считал не тот маршрут — проверь, прежде чем радоваться.»
Причины: «• короткое удачное окно (рынок помог); • периоды несопоставимы (в бэктесте — другой режим); • в бэктест забыли реальные комиссии; • утечка данных при сравнении.»
Действие: «Не масштабировать. Продлить окно наблюдения, сверить периоды и тарифы. Результат лучше ожидания — такой же повод для проверки, как и хуже (FT-16: OOS лучше IS — ищи утечку).»
Гейт: «⏸ отложен до объяснения причины».

Цвета зон: норма — зелёный, серая — жёлтый/янтарный, стоп — красный, подозрительно хорошо — фиолетовый. Иконка маршрута навигатора: пробки на маршруте подсвечиваются тем же цветом (декоративно, без расчётов).

### 5. Правила автодиагностики (для Частей 2 и 3)

На вход — пары значений (бэктест / бумага). Правила проверяются по порядку, первое сработавшее даёт «главную причину»; остальные — «дополнительно». Пороги зашить как константы.

| № | Условие | Главная причина | Ссылка |
|---|---|---|---|
| R1 | Δ сделок ≤ −15 % от бэктеста | «Заявки не исполняются: лимитки не заполняются, таймауты, пропуски сигналов» | FT-06, FT-10 |
| R2 | слиппедж бумаги / бэктеста ≥ 1,5 | «Издержки занижены: модель проскальзывания оптимистична или размер заявки велик для стакана» | FT-13, 5.2 |
| R3 | Δ винрейта ≤ −5 п.п. при отсутствии R1/R2 | «Утечка / заглядывание в будущее / переобучение: исполнение нормальное, а сигнал в жизни не работает» | 1.7, FT-11, 1.10 |
| R4 | ED ≥ +10 % | «Несопоставимое сравнение или удачное окно» | FT-16 |
| R5 | ничего не сработало, зона серая | «Задержка между сигналом и исполнением / спред: измерь задержку и разницу цены сигнала и цены входа» | 2.2, FT-06 |
| R6 | ничего не сработало, зона норма | «Штатное трение — причин искать не надо» | — |

Дополнительно, если число сделок в бумаге < 50: жёлтая пометка «Мало сделок для выводов: доверительный интервал широк (М30). Зона — предварительная.»

### 7. Режим «Свои числа» (Часть 3)

Поля (обязательные): «Результат бэктеста, %», «Результат бумаги/микро-лайва, %». Необязательные: сделок (бэктест / факт), средний слиппедж на вход (бэктест / факт), винрейт (бэктест / факт). Выход: ED со знаком, зона, гейт, главная причина по правилам §5 (только если заполнены соответствующие поля; иначе — «заполни разбивку, чтобы поставить диагноз, а не только зону»). Кнопка «Записать в журнал недели» → `onJournal({type:"execution_deviation", week, backtest, paper, ed, zone, cause})`.

Валидация: числа с запятой или точкой; бэктест ≤ 0 → сообщение из §3; поля сделок — целые ≥ 0.

### 8. Словарь «Ткни в непонятное»

| Токен | Карточка |
|---|---|
| отклонение исполнения (Execution Deviation) | «Насколько фактический результат отличается от расчётного, в процентах от расчётного: (факт − план) / план. → 4.5» |
| бумажная торговля (paper trading) | «Стратегия работает на живых данных, но деньги виртуальные. Проверяет воспроизводимость, а не прибыльность. → 4.5» |
| бэктест | «Прогон стратегии по прошлым данным с моделью исполнения. Почти всегда оптимистичнее реальности. → 1.6» |
| проскальзывание (slippage) | «Разница между ценой, по которой хотел, и ценой, по которой исполнилось. → 0.10» |
| заглядывание в будущее (look-ahead) | «Стратегия в тесте "знает" то, чего в момент решения знать не могла. Код работает, кривая красивая, результат недостижим. → 1.7» |
| винрейт | «Доля прибыльных сделок. Сам по себе ничего не доказывает. → 0.14» |
| лимитная заявка | «"Куплю по такой цене и подожду". Может не исполниться. → 0.9» |
| таймаут заявки | «Время, после которого неисполненную заявку отменяют. → FT-06» |
| микро-лайв | «Первые реальные деньги: 100–200 тыс. ₽, 4–6 недель, руками не трогать. → 5.1» |
| доверительный интервал | «Диапазон, в котором "плавает" оценка из-за малой выборки: чем меньше сделок, тем шире. → М31» |

### 9. Приёмочные критерии

- [ ] Контрольная таблица §3 проходит автотестами; граница 10 % относится к серой зоне, граница 25 % — к стопу (`≤ −0.25`).
- [ ] Ползунок на всём диапазоне синхронно обновляет минуты, бумажный %, формулу с подставленными числами, зону, обе карточки и гейт; позиция −15 % при загрузке.
- [ ] Редактирование поля «Бэктест» пересчитывает всё; пример «20 → 4 = −80 %» воспроизводится.
- [ ] Все 7 кейсов дают ровно указанные ED (допуск ±0,5 п.п. при пересчёте из таблицы) и указанные зону/причину по правилам §5 — правила и кейсы **не должны противоречить** (проверить автотестом: диагностика по правилам на данных кейса = эталонная причина кейса).
- [ ] Кейс 7 показывает пометку про малую выборку.
- [ ] «Свои числа» корректно обрабатывает запятую как десятичный разделитель, пустые необязательные поля и бэктест ≤ 0.
- [ ] Ни одной английской подписи вне тултипов; в таблицах — русские имена метрик, английское — только в карточке.
- [ ] Клавиатура: ползунок стрелками с шагом 1 %, Shift+стрелка — 5 %; чипы причин — радиогруппа.
- [ ] Мобильная раскладка 360 px без горизонтального скролла (таблица кейса — две колонки «бэктест / бумага», метрика — заголовок строки).

Тест-кейсы: (1) ED = −10 % → «серая, граница»; (2) кейс 4 → R1 срабатывает раньше остальных; (3) кейс 6 → R2 (сделок −3 %, R1 не срабатывает); (4) кейс 2 → R3 (сделок −1,7 %, слиппедж ×1,05 — R1/R2 молчат); (5) «Свои числа»: 12 / 10,2 без разбивки → зона серая + подсказка «заполни разбивку»; (6) запись в журнал содержит все поля.

Не добавлять: генерацию случайных кейсов, симуляцию кривой капитала, расчёт статистической значимости винрейта (только текстовая пометка про 1 SE / малую выборку), изменение порогов зон пользователем (пороги — единый норматив урока 4.5 и чек-листа FT-20, менять их нельзя).

## Связи между двумя интерактивами и остальным курсом (для агента — что переиспользовать)

- Гейдж просадки из спека A и гейт «допуск к микро-лайву» из спека B — кандидаты в общие компоненты для FT-17 («Серия из 10 стопов») и FT-20 («Чек-лист 20/20»). Делать их с пропсами `value / markers[] / zones[]`, а не под конкретный урок.
- Таблица «бэктест / бумага / допуск» из спека B — это ровно формат E8 «Двуязычный отчёт»; если E8 уже собран, использовать его, передав русские имена метрик и зоны.
- Правила автодиагностики §5 спека B нужны повторно в FT-20 («Восемь недель dry-run»: ED по неделям 5–12 %) — вынести в отдельный модуль `executionDeviationRules`.
- Оба интерактива завершаются переходом к ритуалу: A → «мой лимит просадки записан в устав» (R7 «Устав как код», 5.6), B → «ED недели записан в журнал» (E5). Если ритуальные движки ещё не готовы — оставить кнопки как заглушки с `onJournal`, без ломки сценария.
