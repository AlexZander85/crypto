# Спецификации интерактивов для реализации: Б4 «Листинг ≠ bid» и Б5 «Тета съедает билет»

Ниже — два ТЗ для агента-разработчика. Формат единый: цель → сценарий → экран → модель (формулы, готовые к переносу в код) → состояния и обратная связь → языковой слой → контрольные числа для тестов → критерии приёмки. Все тексты интерфейса — на русском; английские токены появляются только внутри режима «Ткни в непонятное».

---

## 0. Общие требования к обоим интерактивам

| Требование | Содержание |
|---|---|
| Язык | Весь UI на русском. Ни одного английского слова на кнопках, подписях, легендах. Английские термины — только как всплывающая карточка по клику на подчёркнутый русский термин («Ткни в непонятное»). |
| Персонаж | Сквозной герой Алексей, депозит 1000 $ (100 000 ₽). Все суммы показываются в двух валютах: базовая единица (ETH / $) и рубли по константе курса из конфига приложения (`RATE_ETH_RUB`, `RATE_USD_RUB`, значения по умолчанию иллюстративные, помечены в UI как «условный курс»). |
| Три уровня | Как в уроках: базовый экран (без формул) → «Подробнее» (числа и разложение) → «Глубже» (формула, параметры модели). Формулы никогда не показываются на базовом уровне. |
| Ритуал «Сначала угадай» | Перед первым раскрытием результата ученик обязан ввести свою оценку числом. Это делает заблуждение измеримым (см. метрики). |
| Телеметрия | События: `open`, `guess_submitted {value}`, `reveal {true_value, error_pct}`, `slider_change {id, value}`, `scenario_run {id}`, `mastery_reached`, `term_clicked {token}`. |
| Доступность | Все ползунки управляются с клавиатуры (←/→ шаг, Shift — шаг ×10), у каждого — текстовое поле ввода. Анимации имеют кнопку «Стоп» и режим «без анимации» (мгновенный результат). |
| Мобильная вёрстка | Одна колонка, ползунки сверху, результат снизу, «липкая» строка итога. |
| Детерминизм | Все Монте-Карло с фиксированным `seed`, чтобы результат был воспроизводим при повторном открытии; кнопка «Перемешать» меняет seed явно. |

## 1. Б4 · «Листинг ≠ bid»

### 1.1. Паспорт

| Поле | Значение |
|---|---|
| Урок | 65 · Б4 «NFT: сертификат владения и миф о лёгкой продаже» |
| Тип | СИМ (симуляция) с элементом ИГР («Сначала угадай») |
| Место в уроке | Сразу после блока «Глубже: Почему оценка обманчива» и формулы `realizable_value = best_bid * qty − gas − fees`. Существующий симулятор «NFT: выпустил — теперь продай» остаётся выше; новый интерактив принимает из него количество токенов `qty`, если ученик его проходил (иначе `qty = 1`). |
| Целевое заблуждение | «Оценка площадки — это мои деньги». Ученик приравнивает цену листинга (желание продавца) к реализуемой стоимости (что даст живой покупатель). |
| Что ученик должен унести | Три числа для одной и той же вещи: **оценка** (листинг × количество) → **лучшая заявка** (bid) → **деньги в кошельке** (bid минус роялти, минус комиссия площадки, минус газ). И правило: деньги создаёт только реальный bid. |
| Критерий освоения | На втором прохождении (другие параметры) ошибка оценки «сколько получу в кошелёк» ≤ 20 %. Дополнительно: ученик верно отвечает на итоговый вопрос-ловушку (см. 1.6). |

### 1.2. Сценарий

Алексей выпустил NFT (или купил на хайпе) и видит на площадке: его токен выставлен за **50 ETH**. Лучший bid по коллекции — **3 ETH**. Он хочет «продать по оценке» и купить машину. Интерактив проводит его через три вопроса:

1. **Сколько денег придёт в кошелёк, если продать прямо сейчас?** (продажа в bid)
2. **А если подождать покупателя по 50 ETH?** (ожидание при затухающем внимании)
3. **Что случится с дешёвой коллекцией, когда газ дорогой?** (продать невозможно — дороже комиссии; мост к уроку Б9 «Пыль»)

### 1.3. Экран (зоны)

```
┌──────────────────────────────────────────────────────────────┐
│ A. Карточка токена: картинка-заглушка, «Токен №…», qty        │
│    «Выставлен за: 50 ETH»  «Лучший bid: 3 ETH»  «Флор: 4 ETH» │
├───────────────────────┬──────────────────────────────────────┤
│ B. Панель управления  │ C. Стакан заявок на покупку (bids)   │
│  ползунки:            │   лестница столбиков 3.0 / 2.6 / 2.2 │
│  · Цена листинга      │   / 1.9 / 1.5 / 1.2 / 1.0 / 0.8 ETH  │
│  · Лучший bid         │   подсветка тех, что «съест» продажа │
│  · Количество токенов │                                      │
│  · Роялти %           ├──────────────────────────────────────┤
│  · Комиссия площадки %│ D. Три столбика-«водопад»:           │
│  · Газ за сделку      │   ОЦЕНКА → BID → В КОШЕЛЬКЕ          │
│  кнопки сценариев:    │   с подписями потерь между ними      │
│  [Продать сейчас]     │   и большой цифрой «разрыв: −94,5 %» │
│  [Ждать покупателя]   ├──────────────────────────────────────┤
│  [Газ ×10]            │ E. Строка вердикта + «Подробнее» /   │
│  [Дешёвая коллекция]  │    «Глубже»                          │
└───────────────────────┴──────────────────────────────────────┘
```

### 1.4. Входы

| Параметр | id | Диапазон | Шаг | По умолчанию | Примечание |
|---|---|---|---|---|---|
| Цена листинга, ETH | `listing` | 0,1 – 100 | 0,1 | **50** | число из урока |
| Лучший bid, ETH | `best_bid` | 0 – 20 | 0,1 | **3** | число из урока; лестница бидов масштабируется от него (см. модель) |
| Количество токенов | `qty` | 1 – 8 | 1 | 1 (или из предыдущего симулятора) | |
| Роялти автору, % | `royalty` | 0 – 10 | 0,5 | 5 | термин урока |
| Комиссия площадки, % | `mkt_fee` | 0 – 5 | 0,5 | 2,5 | |
| Газ за одну сделку, ETH | `gas` | 0,001 – 0,1 | 0,001 | 0,005 | кнопка «Газ ×10» ставит 0,05 |
| Флор коллекции, ETH | `floor` | вычисляется | — | `best_bid / 0,75` (= 4,0) | на уровне «Глубже» редактируем |
| Курс ETH→₽ | константа | — | — | из конфига приложения | подпись «условный курс» |

### 1.5. Модель

**Лестница бидов.** Глубина заявок на покупку по коллекции задаётся коэффициентами от лучшего бида:

```
BID_LADDER_K = [1.00, 0.87, 0.73, 0.63, 0.50, 0.40, 0.33, 0.27]
bid[i] = best_bid * BID_LADDER_K[i]           // i = 0..7, по одному токену на уровень
```
(при `best_bid = 3` получаем 3,0 / 2,6 / 2,2 / 1,9 / 1,5 / 1,2 / 1,0 / 0,8 ETH — числа, которые видит ученик в зоне C).

**Сценарий «Продать сейчас» (продажа в bid):**

```
gross      = Σ_{i=0}^{qty-1} bid[i]                     // съедаем верхние qty заявок
fees       = gross * (royalty + mkt_fee) / 100
gas_total  = qty * gas                                  // каждая продажа — отдельная транзакция
net        = gross - fees - gas_total
valuation  = listing * qty                              // «оценка на площадке»
gap_pct    = (valuation - net) / valuation * 100
```
Если `net < 0` → состояние «Продажа невозможна: газ дороже выручки» (см. сценарий 4).

**Сценарий «Ждать покупателя по цене листинга» (Монте-Карло, 200 траекторий, горизонт 90 дней):**

```
H0     = 1.0                       // внимание к коллекции в день 0
TAU    = 20                        // дней, время затухания внимания
H(t)   = exp(-t / TAU)
F(t)   = floor * (0.30 + 0.70 * H(t))          // флор следует за вниманием
B(t)   = 0.75 * F(t)                            // лучший bid — доля флора
P0     = 0.15                                   // базовая дневная вероятность продажи «у флора»
K_OVER = 1.5
p_day(t) = P0 * H(t) * exp(-K_OVER * max(0, listing / F(t) - 1))

для каждой траектории:
  для t = 1..90:
     с вероятностью p_day(t): продано по listing → net_wait = listing*(1-fees%) - gas; стоп
  если не продано к дню 90: net_wait = B(90)*(1-fees%) - gas    // «сдаёшься и продаёшь в bid»
```
Выводы для экрана: доля траекторий, где продано по листингу; медиана `net_wait`; медиана дня продажи (если продано); график F(t) и B(t) на 90 дней (зона D перерисовывается в линейный график).

Контрольная точка модели: при `listing = 50`, `floor = 4` отношение 12,5 → `p_day ≈ 0` → доля проданных за 90 дней < 1 %, медиана денег на день 90 ≈ `B(90)` ≈ 0,75·4·(0,30 + 0,70·e^(−4,5)) ≈ 0,92 ETH·(1 − 0,075) − 0,005 ≈ **0,85 ETH**. Ожидание не приблизило к 50 ETH, а увело от 2,77 к 0,85.

**Сценарий «Дешёвая коллекция»:** пресет `best_bid = 0,02`, `listing = 0,5`, `gas = 0,05` (после «Газ ×10»). Тогда `net = 0,02·0,925 − 0,05 = −0,0315 ETH` → отрицательное число. Подпись: «Продать нельзя: сеть возьмёт больше, чем даст покупатель. Это “пыль” — как в уроке Б9».

### 1.6. Состояния и обратная связь

**Шаг 0 — «Сначала угадай».** Модалка: «На площадке твой токен выставлен за 50 ETH, лучшая заявка на покупку — 3 ETH. Роялти автору 5 %, комиссия площадки 2,5 %, газ 0,005 ETH. Сколько ETH придёт в кошелёк, если продать прямо сейчас?» Поле ввода. Кнопка «Показать». Записываем `guess_submitted`.

**Шаг 1 — Раскрытие «Продать сейчас».** Анимация водопада (зона D): столбик «Оценка 50 ETH» → сжимается до «Bid 3 ETH» (подпись: «−47 ETH: это разница между желанием продавца и живым покупателем») → далее отламываются полоски «роялти −0,15», «комиссия −0,075», «газ −0,005» → итог «В кошельке: **2,77 ETH**». Крупная подпись: «Разрыв между оценкой и деньгами: **−94,5 %**». Рядом: «Ты предположил: X ETH. Ошибка: Y %».

Вердикт (зависит от ошибки ученика):
- ошибка ≤ 20 %: «Ты считаешь, как рынок: деньги — это bid минус издержки.»
- 20–100 %: «Ты заложил издержки, но всё ещё тянешься к оценке. Запомни порядок: оценка → bid → кошелёк.»
- > 100 %: «Ты поверил цифре на площадке. Она ничего не продаёт. Из 50 ETH до кошелька доходит 2,77 — потому что ровно столько готов заплатить живой человек.»

**Шаг 2 — «Ждать покупателя».** Кнопка запускает 90-дневную анимацию (ускоренную, 6–8 секунд, с кнопкой «Стоп»): линия внимания гаснет, флор ползёт вниз, bid — за ним; счётчик «День N, продано по 50 ETH: нет». В конце — веер из 200 траекторий и три числа: «Продано по листингу: в 0 из 200 миров», «Медиана денег на день 90: 0,85 ETH», «А если бы продал в день 0: 2,77 ETH». Вердикт: «Ожидание “своей цены” стоило тебе ~1,9 ETH. Пока ты ждал, внимание ушло, а цену NFT держит только внимание (аналогия урока: автограф ценен, пока звезда на виду).» 

Подсказка ученику попробовать снизить листинг ползунком: при `listing = 4,5` доля проданных за 90 дней становится заметной (> 60 %), медианный день продажи — первые 2 недели. Подпись: «Листинг продаётся, только когда он около флора. Тогда это уже почти bid.»

**Шаг 3 — «Газ ×10» + «Дешёвая коллекция».** Показывает отрицательный итог; зона D красная; подпись: «Здесь нечего продавать: сеть дороже покупателя. Это не редкость для 90 % коллекций после ухода хайпа.»

**Шаг 4 — Вопрос-ловушка (ИГР).** «Друг говорит: “У меня NFT на 50 ETH, я богат”. Что ты спросишь первым?» Варианты: (а) «В какой сети?» (б) «Какой лучший bid по коллекции сейчас?» ✓ (в) «Когда был минт?» (г) «Сколько лайков у коллекции?». Обратная связь на неверные: коротко, по одному предложению.

**Шаг 5 — Второе прохождение.** Автоматически меняем параметры (`listing = 20`, `best_bid = 1,2`, `royalty = 7,5`, `gas = 0,01`, `qty = 2`) и снова просим оценку. Верный ответ: `gross = 1,2 + 1,044 = 2,244`; `fees = 2,244·0,10 = 0,2244`; `gas = 0,02`; `net = 1,9996 ≈ 2,00 ETH`. Ошибка ≤ 20 % → событие `mastery_reached`.

**Уровни «Подробнее / Глубже».**
- «Подробнее»: таблица «Оценка / Bid / Роялти / Комиссия / Газ / В кошельке» в ETH и ₽; пояснение, почему продажа нескольких токенов съедает лестницу заявок (второй токен уходит уже по 2,6, а не по 3).
- «Глубже»: формула из урока `realizable_value = best_bid * qty − gas − fees`, редактируемые `floor`, `TAU`, `P0`, `K_OVER`, seed; пометка «параметры затухания внимания — иллюстративные, взяты не с рынка».

### 1.7. Языковой слой «Ткни в непонятное»

| Русский термин на экране | Английский токен в карточке | Текст карточки (1–2 фразы) |
|---|---|---|
| Листинг (цена выставления) | listing | Цена, за которую продавец хочет продать. Никого ни к чему не обязывает. |
| Заявка на покупку | bid | Сколько реальный покупатель готов заплатить прямо сейчас. Единственное, что превращается в деньги. |
| Флор (нижняя цена коллекции) | floor price | Самый дешёвый листинг коллекции. Ориентир, но не гарантия продажи (термин урока). |
| Роялти | royalty | Процент со вторичной продажи автору (термин урока). |
| Газ | gas fee | Плата сети за транзакцию; берётся независимо от суммы сделки (термин урока). |
| Комиссия площадки | marketplace fee | Доля площадки с каждой продажи. |
| Минт | mint | Выпуск токена (термин урока). |

| Тест | Вход | Ожидание |

| T1 базовый | listing 50, bid 3, qty 1, royalty 5, fee 2,5, gas 0,005 | gross 3,000; fees 0,225; net **2,770**; gap **94,54 %** |
| T2 два токена | как T1, qty 2 | gross 5,610 (3,0 + 2,61); fees 0,42075; gas 0,010; net **5,179** |
| T3 второе прохождение | listing 20, bid 1,2, qty 2, royalty 7,5, fee 2,5, gas 0,01 | net **2,00 ± 0,01** |

| T5 ожидание | listing 50, floor 4, seed фикс. | доля продаж по листингу за 90 дней < 1 %; медиана net_wait 0,80–0,90 ETH |
| T6 ожидание у флора | listing 4,5 | доля продаж за 90 дней > 60 %; медианный день ≤ 14 |

### 1.9. Критерии приёмки

- [ ] Результат не раскрывается до ввода оценки; ошибка вычисляется и сохраняется.
- [ ] Водопад «Оценка → Bid → Кошелёк» анимируется и имеет мгновенный режим.
- [ ] Все шесть тестов из 1.8 проходят автоматически.
- [ ] Ни одного английского слова вне карточек «Ткни в непонятное».
- [ ] Отрицательный итог визуально отличается (красная зона, отдельный текст) и ссылается на урок Б9.
- [ ] Второе прохождение с другими параметрами запускается автоматически; фиксируется `mastery_reached`.
- [ ] Суммы дублируются в ₽ по конфигурируемому курсу с подписью «условный курс».

## 2. Б5 · «Тета съедает билет»

### 2.1. Паспорт

| Поле | Значение |
|---|---|
| Урок | 66 · Б5 «Опционы Call/Put: страховка или лотерейный билет» |
| Тип | АНИМ (покадровое распадение премии) + СИМ (переключатель покупатель/продавец, Монте-Карло «12 билетов») |
| Место в уроке | Дополнение к существующему «Payoff-конструктору опционов»: новая вкладка внутри того же компонента. Вкладка 1 — «Выплата на дату истечения» (существующая), вкладка 2 — «Тета съедает билет» (новая). Общие состояние: `type` (Call/Put), `side` (покупатель/продавец), `S0`, `K`. |
| Целевое заблуждение | «Опцион — дешёвая лотерея: заплатил немного, а выиграть можно много, риск ограничен». Ученик не видит, что цена билета тает каждый день, даже если рынок стоит, и что «ограниченный риск» покупателя на дистанции превращается в системный минус. |
| Что ученик должен унести | (1) Премия — не разовая плата, а тающий актив: при неподвижной цене её съедает время, и всё быстрее к концу срока. (2) У покупателя и продавца зеркальные профили: покупатель — много маленьких минусов и редкий большой плюс; продавец — наоборот, с хвостовым риском (мост к П24 «индейка»). (3) Чтобы билет окупился, рынок обязан пройти к экспирации не «куда-нибудь», а на конкретную величину. |
| Критерий освоения | Ученик верно (±1 день) отвечает, к какому дню билет потерял половину стоимости при неподвижной цене; и правильно выбирает в мини-игре, у кого из двух сторон «редкий большой минус». |

### 2.2. Иллюстративные параметры (обязательно помечать в UI)

Урок Б5 не содержит чисел, поэтому параметры модели — учебные, вынесены в конфиг и подписаны «условный пример»:

| Параметр | id | По умолчанию | Диапазон (уровень «Глубже») |
|---|---|---|---|
| Цена актива в день 0, $ | `S0` | 3000 (ETH) | 1000–100 000 |
| Страйк, $ | `K` | 3000 (у денег) | ±30 % от S0 |
| Срок до истечения, дней | `T_days` | 30 | 7–90 |
| Волатильность, % годовых | `sigma` | 60 | 20–150 |
| Безрисковая ставка | `r` | 0 | фиксировано |
| Размер контракта | `contract` | 1 ETH | 0,1 / 1 |
| Комиссия биржи за сделку, $ | `fee_side` | 1 | 0–10 |
| Депозит Алексея, $ | константа | 1000 | — |

При этих параметрах премия ATM-колла ≈ **206 $** — это 20,6 % депозита Алексея «на один билет». Это число надо показать явно.

### 2.3. Модель

Цена опциона по классической формуле (Блэка—Шоулза, `r = 0`). На базовом уровне название формулы не показывается; на уровне «Глубже» — показывается вместе с формулой.

```
T      = days_left / 365
d1     = (ln(S/K) + 0.5*σ²*T) / (σ*√T)
d2     = d1 − σ*√T
Call   = S*N(d1) − K*N(d2)
Put    = K*N(−d2) − S*N(−d1)
при days_left = 0:  Call = max(S−K, 0), Put = max(K−S, 0)
```
`N(x)` — функция нормального распределения; реализовать через `erf` (в JS — приближение Абрамовица—Стигуна, погрешность < 1e-7). Запрещено использовать линейную аппроксимацию премии: ученик должен увидеть именно ускорение распада.

Производные величины для экрана:

```
premium0        = Price(S0, K, T_days)                 // цена билета в день 0
premium(t)      = Price(S_t, K, T_days − t)            // S_t = S0, если цена неподвижна
lost(t)         = premium0 − premium(t)
theta_day(t)    = premium(t) − premium(t+1)            // «сколько съест следующий день», $
half_life_day   = min t : premium(t) ≤ premium0 / 2     // при S_t = S0
breakeven_call  = K + premium0 ;  move_needed_% = (breakeven_call − S0) / S0 * 100
breakeven_put   = K − premium0 ;  move_needed_% = (S0 − breakeven_put) / S0 * 100
PnL_buyer(t)    = premium(t) − premium0 − 2*fee_side    // если закрыть позицию в день t
PnL_seller(t)   = −PnL_buyer(t)  (комиссии тоже списываются продавцу: −2*fee_side)
```

**Монте-Карло «12 билетов подряд»** (режим лотереи): 1000 прогонов × 12 месяцев; каждый месяц — новый ATM-опцион на `T_days`, цена актива к истечению по геометрическому броуновскому движению с нулевым сносом и `sigma`:

```
S_T = S0 * exp(−0.5*σ²*T + σ*√T*Z),  Z ~ N(0,1)
PnL_month_buyer  = max(S_T − K, 0) − premium0 − fee_side      (для колла; для пута зеркально)
PnL_month_seller = −PnL_month_buyer − 2*fee_side  (комиссия учтена один раз у каждого)
```
Выводы: доля прибыльных месяцев, средний результат за месяц, итог за 12 месяцев (медиана и 5-й/95-й процентили), худший месяц продавца, гистограмма месячных результатов для обеих сторон.

### 2.5. Состояния и обратная связь

**Шаг 0 — «Сначала угадай».** «Алексей купил колл на ETH “у денег” на 30 дней за 206 $ (20,6 % депозита). Цена ETH не двигается ни на доллар. К какому дню его билет будет стоить половину — 103 $?» Поле ввода дня. Ожидаемый ответ: 22–23 (интуиция большинства — «день 15»). Записываем оценку.

**Шаг 1 — Анимация распада (30 кадров, ~6 с, с паузой и пошаговым режимом).** Билет тает; счётчики обновляются. Кадры-остановки с подписями:
- День 0: «Билет стоит 206 $. Это плата за право, а не за результат.»
- День 15: «Полсрока прошло — сгорело не половина, а 60 $ (29 %). Пока кажется, что “ещё есть время”.» 
- День 22–23: «Вот половина. Первые 22 дня съели 103 $, последние 8 дней съедят вторые 103 $.» (метка на шкале)
- День 25: «84 $. Завтра исчезнет 8,4 $ — вдвое быстрее, чем в начале.»
- День 29: «38 $. Последний день заберёт всё.»
- День 30: «0 $. Цена не сдвинулась — билет сгорел полностью. Продавец получил 206 $ просто за то, что время шло.»

Сравнение с догадкой: «Ты назвал день X. Верный ответ — 22. Время съедает билет не ровно, а с ускорением: чем ближе срок, тем дороже каждый день.»

**Шаг 2 — Переключатель «Я — продавец».** Та же анимация, но столбик результата зелёный и растёт: «+60 $ к дню 15, +206 $ к дню 30». Строка правды меняется: «Продавец зарабатывает на ожидании покупателя. Но посмотри, что будет, если цена всё-таки прыгнет →». Кнопка-событие **«Ночью ETH +25 %»** (мост к уроку 1.2 про толстые хвосты): S подскакивает до 3750 в выбранный день; результат продавца — примерно −544 $ (внутренняя стоимость 750 минус полученные 206), что в 2,6 раза больше всей премии. Подпись: «Профиль продавца: много маленьких плюсов, редкий большой минус — та же индейка из урока П24.»

**Шаг 3 — Ползунок цены (снятие галочки «Цена стоит»).** Ученик двигает цену ±15 % в выбранный день и видит, что на день 20 даже +5 % не выводит покупателя в плюс: премия(3150, 10 дней) ≈ 191 $ < 206 $ + комиссии. Подпись: «Мало угадать направление — нужно угадать величину и срок. Три условия вместо одного — вот почему это не “дешёвая лотерея”, а дорогая.»

**Шаг 4 — «12 билетов подряд» (Монте-Карло).** Две гистограммы месячных результатов. Ожидаемые числа при параметрах по умолчанию (seed фиксирован, допуск ±3 п.п.): у покупателя прибыльных месяцев ≈ 32 %, средний результат за месяц ≈ −1…−2 $ (нулевое ожидание минус комиссии), медианный итог за год ≈ −250…−400 $ при широком правом хвосте; у продавца прибыльных ≈ 68 %, худший месяц в 1000 прогонах — сотни долларов минуса. Подписи: над гистограммой покупателя — «много маленьких минусов, редкий большой плюс»; над продавца — «много маленьких плюсов, редкий большой минус». Итог: «Ни одна сторона не получает бесплатные деньги. Покупатель платит временем, продавец — хвостом. Честное применение для инвестора из урока — защитный пут как страховка: ты сознательно платишь премию за спокойный сон, а не за выигрыш.»

**Шаг 5 — Мини-игра «Кто индейка?» (ИГР).** Показаны две кривые капитала за 12 месяцев без подписей: одна — плавно вверх с одним провалом, вторая — пилообразно вниз с одним всплеском. Вопрос: «Какая из них — продавец краткосрочных опционов?» Правильный ответ — первая. Обратная связь при ошибке: «Ровная кривая с редким провалом — продавец: он получает премию каждый месяц, пока не случится движение. Пила с редким всплеском — покупатель.»

**Уровни.**
- Базовый: билет, шкала дней, строка правды, переключатель сторон.
- «Подробнее»: таблица по дням 0/5/10/15/20/22/25/29/30 — премия, съедено, «съест завтра», результат обеих сторон; объяснение половины к дню 22 без формул («стоимость ожидания растёт, как обратный квадратный корень из оставшихся дней»).
- «Глубже»: формула, ползунки `sigma`, `T_days`, `K`, `fee_side`, seed; подпись: «При росте волатильности премия дороже, но и распад в долларах быстрее; удлинение срока замедляет распад на старте, но не отменяет его».

### 2.6. Интеграция с существующим Payoff-конструктором

- Общее состояние через контекст компонента: `type`, `side`, `S0`, `K`. Новая вкладка читает их; изменение в одной вкладке отражается в другой.
- Если в Payoff-конструкторе премия введена вручную и отличается от модельной более чем на 10 %, новая вкладка показывает баннер: «В конструкторе выплат ты задал премию X $; здесь она рассчитана по модели — Y $. Для распада важна форма кривой, а не точная цифра» и предлагает кнопку «Взять модельную».
- На графике вкладки 2 добавляется тонкая пунктирная линия «выплата на день 30 из вкладки 1», чтобы ученик видел: кривая распада приходит ровно в точку известного ему payoff.

### 2.7. Языковой слой «Ткни в непонятное»

| Русский термин | Токен | Карточка |
|---|---|---|
| Колл (право купить) | call | Право купить актив по страйку до срока. Растёт в цене, когда актив дорожает. |
| Пут (право продать) | put | Право продать по страйку. Растёт, когда актив дешевеет. |
| Премия | premium | Цена билета: платит покупатель, получает продавец (термин урока). |
| Страйк | strike | Цена исполнения права (термин урока). |
| Истечение | expiration | Дата, после которой право сгорает (термин урока). |
| Тета (распад во времени) | theta decay | Сколько долларов премии исчезает за один день без движения цены (термин урока). |
| «У денег» | at-the-money (ATM) | Страйк равен текущей цене — самый дорогой по времени вариант. |
| Волатильность | implied volatility | Ожидаемый размах колебаний; чем выше, тем дороже билет. |
| Точка безубыточности | breakeven | Цена актива на дату истечения, при которой покупатель вернул премию. |
| Формула оценки опциона | Black–Scholes | Стандартная модель цены опциона; показывается только на уровне «Глубже». |

### 2.9. Критерии приёмки

- [ ] Кривая премии строится по формуле с нормальным распределением, тесты T1–T9 проходят автоматически.

## 3. Что общего проверить перед сдачей обоих интерактивов

1. **Методический тест «одно заблуждение — один интерактив».** Убрать любую функцию, не работающую на целевое заблуждение (Б4 — «оценка = деньги», Б5 — «дешёвая лотерея»). Если элемент только «показывает механику», он идёт под «Глубже» или удаляется.
2. **Тест новичка без английского.** Пройти оба интерактива с включённым режимом «скрыть английский» — интерфейс должен оставаться полностью понятным.
3. **Тест переноса.** Числа на экране совпадают с числами урока (50 ETH / 3 ETH в Б4; формула `PnL = max(S−K,0) − premium` и профили сторон в Б5); там, где чисел в уроке нет, стоит пометка «условный пример».
4. **Метрики для последующего анализа.** По каждому интерактиву собирать: медианную ошибку первой оценки, долю достигших `mastery_reached`, среднее число кликов по терминам — эти три числа покажут, ломает ли интерактив заблуждение или только развлекает.
