# Детальные спецификации для реализации: П20, П23, П26

Ниже — три ТЗ для агента-разработчика. Формат единый: паспорт → педагогическая цель → математика и данные → экраны и сценарий → тексты → обратная связь и ловушки → технические требования → аналитика → приёмочные тесты → вопросы методисту. Все числа взяты из текста уроков (принцип «числа берутся из урока»); там, где чисел в уроке нет, они выведены из них и помечены как *производные*.

---

## 0. Общие требования ко всем трём интерактивам

| Требование | Содержание |
|---|---|
| Язык | Только русский в интерфейсе. Любой английский термин (винрейт, R, Монте-Карло, survivorship) — через режим «Ткни в непонятное» (раздел 6 предыдущего ТЗ): клик → русская карточка + ссылка на урок. Внутри кода/данных английские ключи допустимы. |
| Детерминизм | Генератор случайных чисел с сидом (seed). Режим по умолчанию — фиксированный сид (одинаковая «прожитая» история у всех учеников, чтобы текст урока и интерактив совпадали). Кнопка «Другой сценарий» → новый сид, показывается в углу («сценарий №…»), чтобы ученик мог воспроизвести. |
| Числа | Рубли с разделителем тысяч пробелом и знаком ₽: «+80 000 ₽». Проценты с одним знаком после запятой. Отрицательные — с минусом, красным. |
| Адаптивность | Минимальная ширина 360 px. На мобильном многопанельные экраны сворачиваются в вертикальную ленту; управление — крупные кнопки ≥ 44 px. |
| Доступность | Все цветовые различия (зелёный/красный/серый) дублируются формой или подписью. Анимации отключаемы (уважать `prefers-reduced-motion`; кнопка «Без анимации»). |
| Состояние | Прогресс сохраняется в профиле ученика: пройден/не пройден, ключевые ответы, «критерий освоения». Повторное прохождение разрешено; хранятся обе попытки. |
| Связка с журналом (E5) | Каждый интерактив заканчивается предложением записать одну строку в «Журнал внутри приложения» (категория указана в спеке). Если E5 ещё не собран — временно писать в локальное хранилище с той же схемой `{lesson, type, text, ts}`. |
| Аналитика | События вида `interactive.<id>.<event>` с полезной нагрузкой; перечень в каждой спеке. Никаких персональных данных. |
| Производительность | Симуляции Монте-Карло (до 1000 серий × 100 сделок, 100 000 участников × 10 раундов) выполняются в Web Worker или синхронно с ограничением ≤ 200 мс на слабом мобильном; при превышении — прогресс-бар. |

## 1. П20 — «Колесо казино»: расширение «Серия из ста»

### 1.1. Паспорт

| Поле | Значение |
|---|---|
| ID | `p20_series100` (расширение существующего `p20_casino_wheel`) |
| Урок | П20 «Пять истин Дугласа: как мыслить как владелец казино» |
| Заблуждение | «4 минуса подряд = система сломалась» |
| Роль | СИМ + ИГР (симуляция с двумя точками решения) |
| Место в уроке | Сразу после блока «Числа» (винрейт 60 %, R 1:2, 100 сделок, риск 1 000 ₽ → +80 000 ₽) и перед «Ситуация-выбор» (4 сделки подряд в минус) |
| Движки | E5 (запись в журнал), опционально E8 (веер) для режима «1000 серий» |
| Время прохождения | 5–7 минут |
| Связи | 5.5 (ожидаемая серия ln N / ln(1/q), Монте-Карло-пороги), П53 (серия без памяти), П1 (протокол двух вопросов), 0.13 (закон больших чисел) |

### 1.2. Педагогическая цель и критерий освоения

Ученик должен прожить серию из 6 убытков подряд внутри исправной системы, дважды принять решение «выключить / продолжить» и увидеть в числах:
1. что итог серии из 100 сделок при 60 % и R 1:2 — +80 000 ₽ (число из урока), несмотря на 40 минусов;
2. что 4 минуса подряд встречаются примерно в трёх из четырёх серий по 100 сделок (производное, ≈ 77 %), 6 подряд — примерно в каждой пятой (≈ 21 %);
3. что правило «выключать после 4 минусов» убивает подавляющее большинство исправных систем.

**Критерий освоения:** ученик (а) прошёл «Прожитую серию» до конца, (б) в режиме «1000 серий» правильно ответил на контрольный вопрос «какая доля серий содержит ≥ 4 минуса подряд» (выбор из 4 вариантов: ~5 % / ~25 % / ~50 % / ~75 %), (в) записал строку в журнал «Моя норма серии». Без (а)–(в) блок «Ситуация-выбор» урока остаётся свёрнутым (мягкая блокировка: доступен по кнопке «пропустить», но фиксируется событие).

### 1.3. Математика и данные

**Параметры из урока:** винрейт p = 0,60; выигрыш W = +2 000 ₽; убыток L = −1 000 ₽; риск на сделку 1 000 ₽ = 1R; N = 100. Стартовый капитал для отображения кривой — **100 000 ₽** (риск 1 % на сделку; согласуется с П26 и Ф5). Матожидание на сделку: 0,6·2000 − 0,4·1000 = **+800 ₽**; за 100 сделок — +80 000 ₽.

**Режим A «Прожитая серия» — фиксированная последовательность** (ровно 60 W и 40 L, максимальная серия убытков ровно 6 на сделках 31–36, остальные серии убытков ≤ 3, итог +80 000 ₽). Хранить как строку из 100 символов (W = прибыль, L = убыток):

```
WWLWWWLWWW WLWWLWLWLW LWWLLLWWLW LLLLLL WWLWWLWLWW WLLWWLWWWL WLWLWLLWWW LWWLWWWLWW WLWWLLWWWL WWLWLWLWLW WLWW
```
(пробелы только для читаемости; позиции 1–10, 11–20, 21–30, 31–36, 37–46, 47–56, 57–66, 67–76, 77–86, 87–96, 97–100).

Контрольные значения для тестов (капитал = 100 000 + накопленный PnL):
- после сделки 10: +14 000; после 20: +22 000; после 30: **+27 000 (пик перед серией)**;
- сделка 34 (4-й убыток подряд): +23 000; сделка 36 (6-й): +21 000 → просадка от пика −6 000 ₽ (−4,7 % капитала);
- после 46: +32 000; после 66: +48 000; после 86: +67 000; после 100: **+80 000**;
- контрфакт «выключил после 34-й»: пропущено +57 000 ₽ (из них −2 000 ₽ на сделках 35–36, затем +59 000 ₽);
- контрфакт «выключил после 36-й»: пропущено +59 000 ₽.

**Режим B «Случайная серия»:** 100 независимых сделок, p = 0,6, сид отображается. Итог не гарантирован равным +80 000 (среднее 80 000, σ ≈ 14 700 ₽ — производное). Обязательно подсказка: «В этом сценарии вышло +N; среднее по тысячам сценариев — +80 000».

**Режим C «1000 серий» (Монте-Карло):** 1000 серий × 100 сделок, p = 0,6. Считать и показывать:
- гистограмму максимальной серии убытков;
- долю серий с максимальной серией ≥ 4, ≥ 6, ≥ 8 (ожидания: ≈ 77 %, ≈ 21 %, ≈ 4 %; ≥ 10: < 1 %);
- ожидаемую длину максимальной серии по формуле урока 5.5: ln(N)/ln(1/q) = ln 100 / ln 2,5 ≈ 5;
- 95-й процентиль максимальной серии (ожидание: 7) — «порог планового разбора»;
- распределение итогов (доля серий с итогом < 0 — ожидание ≈ 0 %);
- **«Счётчик выключателя»:** сколько из 1000 исправных систем было бы выключено правилом «стоп после k минусов подряд» для k = 3, 4, 5, 6, 8 (ползунок k).

Все ожидаемые доли в тестах — с допуском ±4 п.п. при фиксированном сиде и ±6 п.п. при случайном.

### 1.4. Экраны и сценарий

**Экран 0 — прогноз (до старта).** Три вопроса-ползунка, ответы сохраняются для последующего сравнения:
1. «Сколько минусов подряд ты ждёшь в 100 сделках при 60 % побед?» (1…12)
2. «После скольких минусов подряд ты бы выключил бота?» (1…12 или «не выключил бы»)
3. «Каким будет итог 100 сделок?» (три кнопки: «в минусе», «около нуля», «в плюсе»)

**Экран 1 — «Прожитая серия» (режим A).** Компоновка (десктоп — две колонки, мобильный — вертикально):
- Верх: лента из 100 клеток (10×10), заполняется слева направо; зелёная с «+2 000», красная с «−1 000». Незаполненные — серые контуры.
- Середина слева: кривая капитала (ось Y 90 000…185 000 ₽), пунктир — линия матожидания (100 000 + 800·n).
- Середина справа: три счётчика: «Сделка n/100», «Минусов подряд сейчас: k» (крупно, краснеет при k ≥ 3), «От пика: −X ₽ (−Y %)».
- Низ: шкала «Тревога оператора» 0–10 (визуальная, растёт на каждом минусе подряд: +2 за минус, −1 за плюс, ограничена 0–10) и кнопки «Шаг», «Авто ▶» (1 сделка/0,4 с), «Пауза».

**Точка решения №1 — сделка 34 (4-й минус подряд).** Автостоп, модальное окно:
> **Четыре минуса подряд. На экране −4 000 ₽ от пика.** Голос в голове: «что-то сломалось».
> Что делаешь?
> [Выключить бота] [Уменьшить размер вдвое] [Продолжить по правилам]

Перед кнопками — краткое напоминание протокола П1 в одну строку: «Назови факт: что изменилось в мире? (данные, биржа, код). Если факта нет — это погода в голове.»

- «Продолжить» → идут сделки 35, 36 (ещё два минуса) → **Точка решения №2** (сделка 36):
  > **Шесть подряд. −6 000 ₽ от пика, капитал 121 000 ₽.** Теперь точно сломалась?
  > [Выключить] [Продолжить]
- «Выключить» (в любой точке) → лента продолжает заполняться **полупрозрачно** (что было бы), кривая раздваивается: жирная горизонталь «ты» и полупрозрачная «система без тебя». В конце — карточка контрфакта: «Выключил после сделки 34. Сэкономил 2 000 ₽ на двух следующих минусах. Пропустил +59 000 ₽ восстановления. Итог: +23 000 ₽ вместо +80 000 ₽». Кнопка «Прожить заново, не выключая».
- «Уменьшить вдвое» → сделки 35–100 считаются с половинным размером: итог +23 000 + (57 000/2) = +51 500 ₽ (минусы 35–36 тоже половинные: контрфакт считать честно по формуле, тест сверяет). Подпись: «Половинный размер после серии — та же ошибка, но вполовину: ты меняешь правило по ощущению. Если размер надо менять — это решается расписанием, не серией (П3)».

**Экран 2 — итог серии.** Крупно: «100 сделок · 60 побед · 40 поражений · **+80 000 ₽**». Ниже — сверка с прогнозом с экрана 0: «Ты ждал N минусов подряд — было 6. Ты выключил бы после K — по формуле урока 5.5 ожидаемая максимальная серия ≈ 5, и каждая пятая серия даёт 6». Кнопка «А это мне повезло или так всегда?» → экран 3.

**Экран 3 — «1000 серий» (режим C).** Гистограмма максимальной серии; под ней три плашки «≥ 4 подряд: 77 %», «≥ 6: 21 %», «≥ 8: 4 %»; ползунок k «Выключаю после k минусов подряд» → «Ты выключил бы **N из 1000** исправных систем». Контрольный вопрос (критерий освоения) задаётся **до** показа плашек (плашки размыты до ответа). После ответа — плашки открываются с пометкой «верно/неверно».

Дополнительная плашка: «Итог < 0: 0 из 1000. Итог ≥ +50 000: ≈ 98 %». Подпись: «Ни одна из тысячи серий не ушла в минус — и почти в каждой была серия, от которой хочется нажать кнопку».

**Экран 4 — запись в журнал (E5).** Шаблон с автоподстановкой: «Моя стратегия: винрейт __ %, сделок за период __. Ожидаемая максимальная серия убытков ≈ __ (ln N / ln(1/q)). Порог планового разбора (95-й процентиль): __. До этого порога серия — не событие.» Для учебной серии значения заполнены (60 %, 100, 5, 7); ученик может подставить свои. Категория журнала: `pre_committed_rule` («правило, записанное заранее»).

**Кнопка «Другой сценарий»** переключает в режим B: те же экраны, но последовательность случайная; точки решения возникают на первой серии ≥ 4 (если таковой нет — модальное окно «в этом сценарии 4 подряд не случилось; в 23 % серий так и бывает — прожить ещё один?»).

### 1.5. Тексты (микрокопирайт, использовать дословно или близко)

- Подзаголовок экрана 1: «Ты — владелец казино. Перевес известен: 60 на 40, выигрыш вдвое больше проигрыша. Теперь смотри, как выглядит перевес по одной сделке».
- При k = 3: «Три подряд. Пока — обычная погода».
- При k = 5: «Пять. Для 100 сделок это ожидаемая длина худшей серии».
- Итог: «Убыток в отдельной сделке — плата за перевес. Серия убытков — тоже».
- Обучающая подпись к контрфакту: «Отключённый бот не фиксирует убыток и кажется безопасным. Он фиксирует пропущенное восстановление (урок 5.5)».
- Подпись к «Счётчику выключателя»: «Кнопка «после 4 подряд» — не риск-менеджмент, а способ гарантированно выключать работающее».

### 1.6. Ловушки и обратная связь

| Действие ученика | Реакция |
|---|---|
| Выключил на 4 | Контрфакт + возврат к протоколу П1: «Какой факт изменился?» — поле обязательно к заполнению текстом; пустое поле → кнопка «Выключить» неактивна (ритуал R1 в миниатюре). Если написан «факт» — принимается любой текст, но помечается «это факт или чувство?» с двумя кнопками самооценки. |
| Прошёл, не выключая | Похвала не за результат, а за процесс: «Оценка недели — по соблюдению правила, не по знаку (П8)». |
| Ответил «в минусе» на прогноз итога | На экране 2 — явное сопоставление: «Ты ждал минус. 40 поражений из 100 дали +80 000». |
| Пытается кликать «Шаг» очень быстро во время точки решения | Модальное окно блокирует; счётчик «Тревога» не влияет на математику — подпись «Шкала тревоги ничего не знает о матожидании». |

### 1.7. Технические требования

- Модуль: `series100.ts` (чистые функции: `generateSeries(seed, p, n)`, `equityCurve(series, W, L, start)`, `maxLossStreak(series)`, `counterfactualStop(series, stopAt)`, `monteCarlo(runs, n, p, seed)`), отдельно от рендера.
- Фиксированная последовательность — константа с проверкой целостности при старте (60 W / 40 L / max streak 6 / итог +80 000), иначе — исключение в консоль и переход к режиму B с пометкой.
- Монте-Карло 1000×100 — ≤ 50 мс; при мобильном ограничении допустимо 500 серий с масштабированием подписей («из 500»).
- Рендер ленты — CSS-grid; кривая — SVG/Canvas; без внешних библиотек графиков, если стек их не имеет.
- Все параметры (p, W, L, N, стартовый капитал, точки решения) — в конфиге, чтобы позже переиспользовать для 5.5 «Сколько убытков подряд тебя ждёт».

### 1.8. Аналитика

`interactive.p20_series100.start` {mode}, `.forecast` {streak_expected, stop_after, outcome_guess}, `.decision` {trade_index, streak, choice}, `.finish` {mode, final_pnl, switched_off_at|null}, `.mc_answer` {answer, correct}, `.journal_saved` {filled_own_numbers: bool}, `.skip`.

Ключевая метрика по разделу 7 предыдущего ТЗ: доля «выключить» на точке №1 при первом и втором прохождении (цель: падение ≥ 50 %).

### 1.9. Приёмочные тесты

1. Фиксированная серия: длина 100, W = 60, L = 40, максимальная серия убытков = 6 на индексах 31–36 (1-based), других серий > 3 нет, итог +80 000, пик до серии +27 000 на сделке 30.
2. `counterfactualStop(series, 34)` → пропущено +57 000; `(…, 36)` → +59 000; половинный размер после 34 → +51 500.
3. Монте-Карло, сид X: доли ≥ 4 / ≥ 6 / ≥ 8 в пределах 77 ± 4 / 21 ± 4 / 4 ± 3 п.п.; доля итогов < 0 ≤ 0,5 %; 95-й процентиль = 7 (допустимо 6–8).
4. Точки решения появляются ровно один раз каждая; после «Выключить» кнопки «Шаг/Авто» неактивны, полупрозрачная лента доходит до 100.
5. Контрольный вопрос экрана 3: плашки размыты до ответа; после ответа критерий освоения фиксируется в профиле.
6. Режим B без серии ≥ 4 → модальное окно с предложением нового сценария; частота такого исхода ≈ 23 % (проверить статистически на 200 сидах, допуск ±6 п.п.).
7. Кнопка «Выключить» неактивна при пустом поле «факт».

### 1.10. Вопросы методисту

- Оставлять ли режим «Уменьшить вдвое» как отдельный путь или объединить с «Выключить» (риск: ученик решит, что половинный размер — компромисс)? Рекомендация — оставить с жёсткой подписью.
- Нужен ли третий стоп на 3-м минусе (таблица 5.5: «кажется, что-то сломалось»)? Рекомендация — нет, две точки достаточно, третья затягивает.

## 2. П23 — «100 000 бросающих» (анимация + мини-игра)

### 2.1. Паспорт

| Поле | Значение |
|---|---|
| ID | `p23_hundred_thousand` (заменяет/расширяет `p23_monkeys_10000`) |
| Урок | П23 «Ошибка выжившего: почему нельзя верить чужим скриншотам» |
| Заблуждение | «Гуру с 10 подряд — талант» |
| Роль | АНИМ (СИМ) + ИГР («Подпишись на гуру») |
| Место в уроке | После первого абзаца-тезиса (100 000 человек → ~100 с десятью орлами) и перед «Подробнее» |
| Движки | E5 (журнал: чек-лист проверки чужого результата) |
| Время | 4–6 минут |
| Связи | 1.10 (1000 человек и прогноз матча — тот же механизм), 0.18 (чек-лист сигналов: трек-рекорд до результата, просадка, выборка, «гарантия» = скам), П6 (чужие голы), П54 (эвристика доступности), П56 (базовая ставка 1–2 % выживших) |

### 2.2. Педагогическая цель и критерий освоения

Ученик должен увидеть, что при 100 000 участников около 100 человек с десятью «орлами» подряд появляются **неизбежно и без всякого таланта**, что лента показывает только их, а «кладбище» из ~99 900 невидимо; затем — что выбранный им «гуру» с вероятностью ½ проваливается уже в следующем раунде.

**Критерий освоения:** (а) ученик дал прогноз до запуска и увидел сверку; (б) нажал «Показать кладбище»; (в) в мини-игре «Подпишись на гуру» выбрал гуру и досмотрел 5 следующих раундов; (г) в финальном вопросе «Что отличает навык от везения?» выбрал ≥ 3 из 4 верных пунктов чек-листа (трек-рекорд опубликован до результата; показана просадка; известна выборка и период; нет обещаний гарантированного процента) и не выбрал ловушку («10 побед подряд на скриншоте»).

### 2.3. Математика и данные

- Участников N = 100 000 (ползунок: 1 000 / 10 000 / 100 000 / 1 000 000; при 1 000 000 — только расчёт формулой, без по-пиксельной анимации).
- Раунд: каждый участник бросает честную монету; «орёл» — остаётся, «решка» — выбывает. Ожидаемое число выживших после k раундов: N/2^k. После 10 раундов при N = 100 000: **97,7 ≈ 98** («около 100» — как в уроке); стандартное отклонение ≈ 9,9 → типичный разброс 78–118. Показывать формулу и фактическое число прогона.
- «Кладбище»: N − выжившие ≈ 99 900; соотношение «1 гуру : ~1 000 выбывших».
- Продолжение для гуру: после 10 + m раундов ожидаемо 98/2^m: m = 1 → 49, 3 → 12, 5 → 3, 7 → < 1.
- Мини-игра: вероятность, что выбранный гуру «жив» после m раундов = 0,5^m: 50 %, 25 %, 12,5 %, 6 %, 3 %.
- Базовая ставка из урока (для финальной плашки): 75–89 % частных трейдеров теряют, 10 % около нуля, 1–2 % стабильно в плюсе более 3 лет.

Генерация: типизированный массив `Uint8Array(N)`, состояние 1/0; на раунд — проход с RNG (сид). Для N = 100 000 это 1 млн операций за 10 раундов — мгновенно.

### 3.2. Педагогическая цель и критерий освоения

Ученик управляет депозитом 100 000 ₽ в течение 52 недель. В первые 12 недель сценарий даёт «сказочный» рост до ≈ 290 000 ₽ (число урока: «со 100 000 до 300 000 за три месяца»). В любой момент доступны кнопки «Шаг вверх (+25 %)», **«Удвоить размер»** и «Вывести часть прибыли». Скрытая переменная — **внутренняя планка** (термостат), которая подтягивается к счёту только на «плато» (4–8 недель без изменений размера). Чем больше разрыв «счёт / планка», тем выше еженедельная вероятность **самосаботажа** («кондиционер»): один эпизод — и излишек сгорает до уровня планки.

Ученик должен на собственной траектории увидеть: удвоение размера после удвоения счёта широко раскрывает разрыв и почти гарантированно включает кондиционер; плато и вывод части прибыли закрывают разрыв и сохраняют рост.

**Критерий освоения:** (а) прожит хотя бы 1 полный год (52 недели) в ручном режиме, (б) на итоговом экране ученик правильно указал, какое из его решений включило первый кондиционер (выбор из списка своих же решений; если кондиционер не включался — вопрос заменяется на «что удержало разрыв ниже ×1,5?»), (в) записана строка в устав: шаг размера, минимальное плато, правило вывода.

### 3.3. Математика и данные (все производные — из принципов урока)

**Состояние:** `C` — капитал в работе (₽), `T` — внутренняя планка (₽), `B` — выведенная прибыль «в сейфе» (₽), `S` — множитель размера позиции (1,00 = стартовый размер, риск 1 % на сделку), `week` 0…52, `plateau_weeks` — недель подряд без изменения S, `euphoria_weeks` — оставшиеся недели штрафа за прыжок через ступень, `ac_count` — сколько раз включался кондиционер.

**Старт:** C = T = 100 000; B = 0; S = 1; ступени S: 1 → 1,25 → 1,56 → 1,95 → 2,44 → 3,05 (каждая ×1,25; см. 5.2 «транши +20–25 %»). «Удвоить» = переход сразу на S×2 — прыжок минимум через две ступени.

**Недельная доходность (без саботажа):** `r_week = S · r_base`.
- Недели 1–12 — фиксированный сценарий `r_base` (%): +8, +12, −3, +15, +20, +9, −5, +18, +22, +11, −4, +14. При S = 1 даёт ×2,93 → **≈ 293 000 ₽ к 12-й неделе** (урок: «до 300 000 за три месяца»). При S = 2 те же недели дают ≈ ×7,9 — «сказка» с открытым настежь разрывом.
- Недели 13–52 — случайно (сид): `r_base = 0,8 % + 5 % · z`, z ~ N(0,1), обрезка ±2,5. Ограничить `r_week` снизу −40 % (защита от вырождения при S > 3).
- `C ← C · (1 + r_week)`.

**Динамика планки (адаптация):** если на этой неделе S не менялся и саботажа не было: `T ← T + α·(C − T)`, α = 0,20 (за 4 недели планка проходит ≈ 59 % разрыва, за 8 — ≈ 83 %: это и есть «4–8 недель на ступень» из урока). В неделю изменения S: α = 0 («пока меняешь правила — не адаптируешься»). Вывод прибыли: `C ← C − X`, `B ← B + X` — разрыв закрывается немедленно (лесson: «плато на 4 недели и вывод части прибыли»).

**Разрыв и кондиционер:** `g = C / T`. Базовая недельная вероятность саботажа:

| g | p_саботаж |
|---|---|
| ≤ 1,2 | 1 % |
| 1,2–1,5 | 8 % |
| 1,5–2,0 | 20 % |
| 2,0–3,0 | 40 % |
| > 3,0 | 60 % |

Добавки: прыжок более чем на одну ступень (в т. ч. «Удвоить») → `euphoria_weeks = 4`, каждая из них +15 п.п.; шаг на одну ступень при `plateau_weeks < 4` (нарушение регламента) → +5 п.п. на 2 недели. Вероятность ограничена 90 %.

**Эпизод саботажа:** списание `ΔC = max(k·(C − T), 0,15·C)`, k ~ U(0,7; 1,1) — счёт «охлаждается» к планке, иногда с перелётом ниже. Тип эпизода (текст выбирается случайно, на математику не влияет): «Вход на всё без стопа — «ну теперь-то я умею»», «Шесть сделок за вечер в тильте», «Убрал стоп: «пересижу»», «Плечо ×5, чтобы быстрее». После эпизода: `plateau_weeks = 0`, `ac_count += 1`, `T` не меняется (или `T ← min(T, 1,05·C)`).

**Условие досрочного конца:** `C < 50 000` → «Кондиционер выключил и излишек, и половину стартового. Игра окончена на неделе N» (по 0.12: «чтобы вернуться, нужно +100 %»).

**Эталонные боты (считаются той же моделью на том же сиде, показываются в конце):**
- «Лестница»: шаг +25 % только после 6 чистых недель на ступени; после каждого шага выводит 30 % прибыли, накопленной на предыдущей ступени; никогда не удваивает.
- «Джекпот»: удваивает S после каждой недели с ростом счёта ≥ +25 %; никогда не выводит.

**Калибровка (обязанность агента, проверить Монте-Карло на 1 000 сидов):** медиана итога (C + B) «Лестницы» ≥ 1,5 × медианы «Джекпота»; у «Джекпота» P(итог < 100 000) ≥ 35 % и медиана `ac_count` ≥ 3; у «Лестницы» медиана `ac_count` ≤ 1. Если не сходится — подстраивать α и таблицу p, не трогая сценарий недель 1–12.

### 3.4. Экраны и сценарий

**Экран 0 — вводная (30 с).** «Твой депозит: 100 000 ₽. Внутренняя планка тоже 100 000 ₽ — сейчас ты «человек со ста тысячами». Планка растёт, только когда ты **живёшь** на новой ступени 4–8 недель без рывков. Если счёт убегает от планки — включается кондиционер.» Прогноз: «Через год у тебя будет: [< 100 000] [100–200 тыс.] [200–400 тыс.] [> 400 тыс.]».

**Экран 1 — панель оператора.**
- Слева: **термостат** — круглая шкала. Стрелка-планка `T` (синяя), стрелка-счёт `C` (оранжевая), между ними закрашенный сектор «разрыв ×g». При g > 1,5 сектор мигает, появляется иконка снежинки «кондиционер: p = N %/нед.» (вероятность показывать **честно** — это учебный симулятор, а не обман).
- Центр: график двух линий по неделям (C и T) + столбики B (сейф), фоновая заливка зон разрыва.
- Справа: карточка недели: «Неделя 7 · Счёт 176 000 ₽ · Планка 121 000 ₽ · Разрыв ×1,45 · На ступени S=1,00: 7 нед.». Внизу — 5 кнопок:
  - **«Держать плато»** (серая, скучная),
  - **«Шаг вверх +25 %»** (если `plateau_weeks < 4` — жёлтая рамка «нарушение регламента: на ступени меньше 4 недель»),
  - **«УДВОИТЬ РАЗМЕР»** (крупная, яркая, с подписью «ну теперь-то я умею» — намеренная сирена из П3),
  - **«Вывести часть прибыли»** (ползунок 10–50 % от прибыли текущей ступени; блокируется, если прибыли нет),
  - **«Снизить размер −25 %»**.
- Кнопка «Неделя ▶». Решение спрашивается: в конце каждой 4-й недели; после любой недели с ростом ≥ +25 %; после эпизода саботажа. Остальные недели проматываются автоматически с короткой анимацией (0,3 с).

**Событие саботажа** — полноэкранная карточка на 2 с: снежинка, текст эпизода, «−58 000 ₽. Счёт 128 000 → планка 121 000. Кондиционер отработал.» Затем — обязательный микро-вопрос: «Что в последние 4 недели расширило разрыв?» (варианты — реальные решения ученика из лога + «рынок»). Ответ «рынок» принимается только если решений не было; иначе подсказка «Рынок дал рост, разрыв открыл ты».

**Неделя 12 — специальная карточка (сценарий урока):** «Три месяца. 100 000 → ≈ 293 000 ₽. Голос: «удвою-ка размер». Планка сейчас: N ₽ (разрыв ×g).» Кнопки те же; это главная точка заблуждения. Подсказка по П1 в одну строку — не показывается (пусть решит сам); показывается после решения как «правильный ответ урока: плато 4 недели + вывод части».

**Экран 2 — итог года.**
- Крупно: «Итог: C + B = … ₽ (в работе … / в сейфе …)». Кондиционер включался N раз. Максимальный разрыв ×g. Недель на каждой ступени (мини-таблица).
- Три кривые на одном графике: «Ты», «Лестница», «Джекпот» — с итогами. Подпись: «Одинаковый рынок, одинаковые недели. Разница — в том, кто открывал разрыв».
- Сверка с прогнозом экрана 0.
- Плашка урока: «70 % победителей лотерей через 3–5 лет в долгах: планка осталась старой».
- Вопрос критерия освоения (см. 3.2): выбор решения, включившего первый кондиционер.

**Экран 3 — устав (E5/R7).** Шаблон: «Шаг размера — не более +25 %, не чаще чем раз в 4 недели чистого плато. При росте счёта вдвое за месяц: плато 4 недели + вывод __ % прибыли в сейф. Кнопка «удвоить» в моём уставе отсутствует.» Категория: `charter_rule`. Если реализован R11 — предложить также заполнить «Планку «Достаточно»».

Кнопка «Прожить ещё раз» — тот же сид (для сравнения решений) или «Другой рынок» (новый сид для недель 13–52; недели 1–12 всегда сценарные).

### 3.5. Тексты

- Подпись к термостату: «Планка — это не сумма на счёте, а сумма, которую ты уже считаешь своей. Она догоняет счёт медленно и только на плато».
- При выборе «Удвоить»: тост «Размер удвоен. Планка осталась прежней. Разрыв: ×g → кондиционер p = N %/нед.».
- При выводе: «В сейфе +X ₽. Эти деньги кондиционер не достаёт».
- При «Держать плато» 4 недели подряд: «Планка подтянулась до … ₽. Ступень прожита — теперь шаг вверх по регламенту».
- Финал (если ученик ни разу не включил кондиционер): «Скучно? Именно так выглядит удержание выросшего депозита».
- Финал (если включал ≥ 3): «Кондиционер — не невезение. Это регулятор, который ты сам настроил кнопкой «удвоить»».

### 3.6. Ловушки и обратная связь

| Действие | Реакция |
|---|---|
| «Удвоить» на неделе 12 | Сценарий делает разрыв ≥ ×2,4; вероятность саботажа ≥ 55 %/нед. в ближайшие 4 недели — почти наверняка эпизод до недели 16. Карточка эпизода ссылается на решение недели 12. |
| Шаг вверх при плато < 4 | Жёлтая рамка + событие `rule_violation`; штраф +5 п.п. Не запрещать — устав в этом тренажёре ученик ещё не подписал. |
| Только «Держать плато» весь год без шагов | Итог скромнее «Лестницы»; подпись: «Планка догнала, а ты не сделал шаг. Расписание работает в обе стороны: рост риска по регламенту — тоже правило (П3)». |
| Выводит 50 % каждый раз | Итог C + B нормальный, но рост в работе медленный; подпись нейтральная: «Ты выбрал сейф. Это законно; вопрос только в планке «Достаточно» (П39)». |
| Досрочный конец (C < 50 000) | Экран 2 показывается с пометкой «неделя N из 52», эталонные боты — на полном горизонте. |

### 3.7. Технические требования

- Модуль `capitalSteps.ts`: чистая функция `step(state, decision, rng) → state'` + `runPolicy(policy, seed)` для эталонных ботов; UI не содержит математики.
- Сценарий недель 1–12 — константа; конфиг с α, таблицей p, ступенями, k, порогами — в одном объекте `params` с версией (для калибровки).
- Скрипт калибровки `calibrate.ts` (запускается разработчиком, не в проде): 1 000 сидов × 3 политики → печатает медианы, квантили, `ac_count`; критерии из 3.3 проверяются автоматически в тестах.
- Лог решений ученика хранится в состоянии (неделя, решение, параметры) — используется на экране 2 и в вопросе критерия освоения.
- Термостат — SVG; график — Canvas/SVG; на мобильном термостат и карточка недели — сверху, график сворачиваемый.

### 3.8. Аналитика

`interactive.p26.start` {forecast}, `.decision` {week, choice, S_before, S_after, gap, plateau_weeks, violation: bool}, `.ac_event` {week, gap, loss, trigger_decision_week|null}, `.week12` {choice, gap}, `.finish` {weeks, C, B, ac_count, max_gap, vs_ladder, vs_jackpot, early_end}, `.attribution` {chosen, correct}, `.charter_saved` {step_pct, plateau_weeks, withdraw_pct}, `.replay` {same_seed: bool}.

Ключевая метрика: доля «Удвоить» на неделе 12 при первом и повторном прохождении; доля учеников с `ac_count = 0` на втором прохождении.

### 3.9. Приёмочные тесты

1. Недели 1–12 при S = 1 без вмешательств: C на неделе 12 = 293 000 ± 1 000 ₽ (округление по неделям).
2. Планка: 4 недели плато при постоянном C закрывают 59 ± 1 % разрыва; 8 недель — 83 ± 1 %; в неделю смены S планка не двигается.
3. Таблица p: при g = 1,1 → 1 %; g = 1,8 → 20 %; g = 2,5 после «Удвоить» → 55 % (40 + 15); верхняя граница 90 %.
4. Эпизод саботажа: `ΔC ≥ 0,15·C` и `ΔC ≥ 0,7·(C − T)`; `plateau_weeks` обнулён; `ac_count` увеличен.
5. Калибровка на 1 000 сидов: медиана(C + B) «Лестницы» ≥ 1,5 × медианы «Джекпота»; P(итог Джекпота < 100 000) ≥ 35 %; медиана `ac_count` Джекпота ≥ 3, Лестницы ≤ 1.
6. Точки решения появляются на неделях 4, 8, 12, … и после любой недели с ростом ≥ 25 % и после саботажа; в остальные недели решение не запрашивается.
7. Вопрос атрибуции на экране 2 содержит только решения из лога ученика + «рынок»; правильный ответ = ближайшее к эпизоду решение, расширившее g выше 1,5 (или «Удвоить» в любой из предыдущих 4 недель).
8. Досрочный конец при C < 50 000; эталонные боты досчитываются до 52.
9. Повтор с тем же сидом даёт идентичные недели 13–52 при идентичных решениях.

### 3.10. Вопросы методисту

- В курсе три разных цифры о темпе роста риска: П3 («не больше десятой части раз в квартал»), 5.2 («транши +20–25 % каждые 2–3 недели»), П26 («4–8 недель на ступень»). Тренажёр использует **+25 % и минимум 4 недели** и называет это «учебной лестницей». Нужно ли добавить сноску, что для реального капитала выбирается самая консервативная из трёх норм, зафиксированная в уставе?
- Показывать ли вероятность саботажа числом (честный симулятор) или только цветом (ближе к жизни, где вероятность не видна)? Рекомендация: числом в первом прохождении, цветом — в режиме «Другой рынок» (усложнение).
- Эпизод саботажа сейчас «списывает» деньги мгновенно. Альтернатива — растянуть на 2–3 недели с нарастающими нарушениями (ближе к П14 «паутина тильта»). Рекомендация — оставить мгновенный для ясности причинно-следственной связи, растянутый вариант вынести в П14.
