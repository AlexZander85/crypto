# Спецификации для агента-разработчика: ВК3 «Мост, которого нет» и ВК4 «Просветный тест»

Общие вводные для обоих интерактивов (обязательно к соблюдению):

- **Аудитория:** русскоязычный новичок без английского. Все тексты — по-русски; любой английский токен в коде/выводе — кликабельный с русской карточкой (режим «Ткни в непонятное», словари ниже).
- **Сквозной герой:** Алексей, депозит 1000 $ (как в Py-уроках и ВК4).
- **Числа — только из текстов уроков** (ВК1–ВК4, 1.7, 2.6, FT-13). Ничего не выдумывать.
- **Один интерактив = одно заблуждение.** ВК3 ломает «если агент написал уверенно и код запустился — значит правда». ВК4 ломает «прибыльная кривая = правильный код».
- **Детерминизм:** никаких сетевых запросов, никаких реальных вызовов LLM. Все «ответы агента» и все расчёты — заранее заданные данные (JSON) и локальная арифметика. Результат воспроизводим.
- **Телеметрия:** события в единый лог приложения (для метрики «число повторных ошибок ко второй попытке»).
- **Адаптив:** десктоп + мобильный (drag&drop дублируется tap-to-select).

# СПЕК 1. ВК3 — «Мост, которого нет»

## 1.1. Паспорт

| Поле | Значение |
|---|---|
| ID | `VK3_BRIDGE` |
| Урок | Урок 141 · ВК3 «Галлюцинации LLM в трейдинг-коде» |
| Тип | ИГР (мини-игра с обратной связью через ошибку), движок E6 «Охотник за утечкой» (расширенная разметка текста + код) |
| Место в уроке | После блока «Глубже: приём "земля под ногами"», перед блоком «Протокол "агент сломал код"» |
| Целевое заблуждение | «Агент ответил уверенно, код выглядит профессионально и запускается — значит, там правда» |
| Метафора | Навигатор рисует на карте мост, которого нет, и ведёт по нему уверенным голосом. Каждая галлюцинация = нарисованный мост. «Земля под ногами» (ground truth) = проверяемый внешний эталон |
| Длительность | 6–9 минут |
| Критерий освоения | Найдены все 5 мостов (≤1 ложное срабатывание), каждый привязан к верному эталону, для каждого выбрана верная прививка в ТЗ |

## 1.2. Сценарий (4 фазы + необязательный раунд 2)

```
Фаза A «Найди мосты»   → Фаза B «Поставь на землю» → Фаза C «Прививка в ТЗ» → Фаза D «Итог»
                                                                            ↘ Раунд 2 (опц.) «Агент переписал — проверь заново»
```

### Экран-заставка (1 кадр, 2 строки)
> Алексей попросил агента написать бэктест. Агент ответил быстро и уверенно. В ответе **пять мостов, которых нет**. Найди их — иначе поедешь по ним с депозитом.
> Кнопка «Открыть ответ агента».

### Фаза A — «Найди мосты» (разметка)

**Раскладка:** слева (60%) — чат: сообщение Алексея + ответ агента; справа (40%) — панель «Карта маршрута»: 8 сегментов дороги (по числу пунктов ответа), все серые, счётчик «Подозрительных отмечено: 0».

**Сообщение Алексея (не кликабельно):**
> Напиши бэктест стратегии пересечения EMA(9)/EMA(21) на часовых свечах BTC/USDT. Депозит 1000 $. Хочу понять, есть ли у неё преимущество.

**Ответ агента (8 пунктов + блок кода).** Каждый пункт — отдельный кликабельный блок; клик переключает состояние «подозрительно» (иконка ⚠, рамка янтарная). Строки кода тоже кликабельны (как в diff-игре 1.7).

```
Конечно! Вот план и код бэктеста.

1. Данные. Часовые свечи загрузим методом
   client.get_futures_candles("BTCUSDT", interval="1h", limit=500) —
   он сразу возвращает готовый DataFrame с колонками open/high/low/close.
2. Индикаторы. Чтобы линии были гладкими и без запаздывания, считаем
   средние центрированным окном: df["close"].rolling(21, center=True).mean().
3. Сигнал. Лонг, когда быстрая средняя пересекает медленную снизу вверх;
   выход — при обратном пересечении. Вход — по цене open следующей свечи.
4. Комиссии. Закладываем стандартную комиссию 0.01% на сделку —
   это обычное значение для крупных бирж.
5. Безопасность. API-ключи читаем из файла .env, в код не вшиваем.
6. Проверка надёжности. Прогоним стратегию на топ-10 монет по
   капитализации на сегодня (BTC, ETH, SOL, …) — если работает везде,
   значит, устойчива.
7. Ожидаемый результат. По истории BTC такая стратегия исторически даёт
   около 40% годовых при просадке не более 12%, так что после бэктеста
   можно сразу переходить к реальному счёту.
8. Просадку считаем от пика кривой капитала (equity).
```

Блок кода под пунктами (кликабельные строки помечены `#L`):

```python
df = client.get_futures_candles("BTCUSDT", interval="1h", limit=500)   #L1
df["ema_fast"] = df["close"].rolling(9,  center=True).mean()            #L2
df["ema_slow"] = df["close"].rolling(21, center=True).mean()            #L3
df["signal"] = (df["ema_fast"] > df["ema_slow"]).astype(int)
df["entry_price"] = df["open"].shift(-1)                                #L4 (верно)
FEE = 0.0001                                                             #L5
```

**Разметка истины (скрыта от ученика до проверки):**

| № | Статус | Тип галлюцинации (по уроку) | Ключ |
|---|---|---|---|
| 1 / L1 | ❌ мост | Выдуманный метод и поле API (метода нет; реальный `fetch_ohlcv` возвращает список списков, а не DataFrame) | `H_API` |
| 2 / L2, L3 | ❌ мост | Данные из будущего: центрированное окно (`center=True`) | `H_FUTURE` |
| 3 / L4 | ✅ берег | Вход по open следующей свечи — правило урока ВК4 | — |
| 4 / L5 | ❌ мост | «Усреднённые» издержки: 0.01% вместо реальных taker 0.05–0.075% | `H_FEE` |
| 5 | ✅ берег | Ключи в .env — правило Py-09 / 4.3 | — |
| 6 | ❌ мост | Survivorship: тест на сегодняшнем топ-10 | `H_SURV` |
| 7 | ❌ мост | Выдуманная статистика без источника («40% годовых») + «сразу на реал» | `H_STAT` |
| 8 | ✅ берег | Просадка от пика — определение 0.12 | — |

Клик по строке кода L1/L2/L3/L5 эквивалентен клику по пункту 1/2/2/4 (синхронизация подсветки). Отметка «подозрительно» на пункте 2 И на строке L2 — одна отметка.

**Кнопка «Проверить маршрут»** активна при ≥1 отметке. После нажатия — анимация на карте: сегменты раскрашиваются.

**Обратная связь по каждому пункту (тексты):**

| Ситуация | Визуал на карте | Текст (всплывающая карточка) |
|---|---|---|
| Отметил мост верно | Сегмент → мост над водой, опор нет | «Мост найден. Что под ним — проверим в следующей фазе» |
| Пропустил мост | Сегмент → мост мигает красным, машинка «падает» в воду | «Ты поехал по мосту. <краткая причина, см. таблицу ниже>» |
| Отметил берег как мост | Сегмент → зелёный, значок «твёрдо» | «Это твёрдая земля: <почему верно>. Подозрительность — хорошо, но проверяй и её» |
| Берег не отметил | Зелёный | — |

Тексты «почему верно» для берегов:
- П.3: «Сигнал считается по закрытой свече, сделка — по open следующей. Это и есть анти-look-ahead правило ВК4».
- П.5: «Секреты — в переменных окружения, не в коде. Правило Py-09 и 4.3».
- П.8: «Просадка всегда считается от максимальной точки капитала (урок 0.12)».

Краткие причины для пропущенных мостов (показываются в фазе A, полные — в фазе B):
- `H_API`: «Такого метода в библиотеке нет. Код упадёт — в лучшем случае».
- `H_FUTURE`: «Центрированное окно берёт свечи справа от текущей. Бэктест видит будущее».
- `H_FEE`: «0.01% — не из твоего личного кабинета. Реальный taker 0.05–0.075%».
- `H_SURV`: «Сегодняшний топ-10 — это выжившие. Умершие монеты из теста исчезли».
- `H_STAT`: «"40% годовых" — число без источника. LLM не источник рыночных фактов».

**Правила фазы A:**
- Разрешена **одна** повторная попытка (кнопка «Отметить заново»): состояния сбрасываются, но пропущенные/ложные не подсказываются явно — только показанная выше обратная связь исчезает. Логируем обе попытки.
- Переход в фазу B возможен, когда все 5 мостов найдены (после первой или второй попытки; если после второй не все — система дораскрывает оставшиеся с пометкой «раскрыто системой», это отдельное событие телеметрии).

### Фаза B — «Поставь на землю» (привязка к ground truth)

**Раскладка:** слева — те же 5 найденных мостов в виде карточек (номер пункта + цитата); справа — набор из **7 чипов-эталонов** (5 верных + 2 ловушки). Механика: drag&drop чипа на карточку (мобилка — tap чип → tap карточку).

**Чипы:**

| Ключ | Текст чипа | Верный для |
|---|---|---|
| `G_DOCS` | 📄 **Официальная документация API биржи** — сверить имя метода, параметры и формат ответа | `H_API` |
| `G_TARIFF` | 🧾 **Реальный тариф из личного кабинета биржи** — число, записанное в ТЗ | `H_FEE` |
| `G_TIME` | ⏱ **Правило «решение строго раньше исполнения»** — в расчёте только свечи слева от текущей | `H_FUTURE` |
| `G_CODE` | 🧮 **Расчёт кодом на реальных данных** — число недоказано, пока не посчитано | `H_STAT` |
| `G_PIT` | 📅 **Список монет на дату решения** (point-in-time), а не сегодняшний топ | `H_SURV` |
| `G_TRAP_SAME` (ловушка) | 🤖 Переспросить того же агента: «Ты уверен?» | — |
| `G_TRAP_CHAT` (ловушка) | 💬 Спросить в Telegram-чате трейдеров | — |

**Валидация при сбросе:**
- Верно → чип фиксируется на карточке; на карте под мостом вырастают опоры, вода сменяется землёй; открывается **карточка последствий** (ниже).
- Неверный эталон → чип отскакивает, карточка краснеет на 600 мс, текст:
  - любая ловушка `G_TRAP_SAME`: «Тот же агент — та же память, тот же источник ошибки. Земля — снаружи модели».
  - `G_TRAP_CHAT`: «Чат продаёт мнения, а не данные (урок 2.2). Мнение — не эталон».
  - верный, но не тот эталон: «Это эталон для другого моста. Здесь нужно проверить: <подсказка: тип галлюцинации>».
- Каждая ошибка привязки логируется.

**Карточки последствий («Что было бы, если поверить»)** — открываются после верной привязки, числа из уроков:

| Мост | Текст карточки |
|---|---|
| `H_API` | «Лучший случай: `AttributeError` при первом запуске — ты потерял 10 минут. Худший: агент «допишет» похожий метод, который вернёт не то, и ты не заметишь. Эталон: в документации ccxt метод `fetch_ohlcv('BTC/USDT','1h', limit=500)` и возвращает он **список списков** `[время, open, high, low, close, volume]`, а не таблицу — две выдумки в одной строке». |
| `H_FUTURE` | «`center=True` — окно берёт 10 свечей справа. Бэктест становится телепатом. Из урока 1.7: одна такая строка даёт Шарп 9.8 и +14 000% годовых; после исправления Шарп −0.42. Красивая кривая — из будущего, которого в реальной торговле нет». |
| `H_FEE` | «Разница 0.01% против taker 0.05% — 0.04% на сторону. На 250 сделках за полтора года (урок FT-13) это 500 сторон × 0.04% = **20% доходности**, которых на бумаге не было. Стратегия из плюса может уйти в минус — а ты узнаешь об этом на реальном счёте». |
| `H_SURV` | «Сегодняшний топ-10 — монеты, которые дожили. Те, что обнулились в 2022–2024, из теста исчезли молча. Урок 2.6: ошибка выжившего завышает доходность; список берётся на дату начала теста». |
| `H_STAT` | «Откуда «40%»? Ниоткуда: у агента нет твоих данных, он не запускал бэктест. LLM не является источником рыночных фактов (урок ВК3). А «сразу на реальный счёт» нарушает всю лестницу 4.5 → 5.1». |

Переход в фазу C — когда все 5 привязаны.

### Фаза C — «Прививка в ТЗ»

Для каждого моста ученик выбирает **одну из трёх строк**, которую Алексей добавит в ТЗ агенту. Показывается по одному мосту за раз (карточка + 3 варианта радио-кнопками). Верный вариант — прямая «прививка» из урока.

| Мост | Варианты (✓ — верный) |
|---|---|
| `H_API` | (a) «Используй любой удобный метод загрузки свечей» · (b) ✓ «Используй метод `fetch_ohlcv` из библиотеки ccxt строго по документации; перед вызовом покажи ссылку на раздел документации и формат возвращаемых данных» · (c) «Напиши свой загрузчик с нуля, без библиотек» |
| `H_FUTURE` | (a) «Сделай линии гладкими» · (b) «Используй только EMA, без rolling» · (c) ✓ «Запрещены `center=True`, `shift(-1)`, `bfill` и любые данные правее текущей свечи: решение строго раньше исполнения» |
| `H_FEE` | (a) ✓ «Комиссия taker 0.05% на сторону — число из моего личного кабинета Bybit; заложи её явно константой и выведи в отчёте» · (b) «Возьми среднюю комиссию по рынку» · (c) «Комиссию учтём потом, сначала сигнал» |
| `H_SURV` | (a) «Тестируй на топ-10 по капитализации» · (b) ✓ «Список монет — тот, что был в топ-10 по объёму на дату начала теста; сегодняшний топ не использовать» · (c) «Тестируй только на BTC, остальное не нужно» |
| `H_STAT` | (a) «Скажи, сколько эта стратегия даёт по истории» · (b) ✓ «Не называй никаких доходностей и просадок до прогона кода на данных; любое число в ответе — только с выводом расчёта» · (c) «Дай оценку доходности с точностью до процента» |

Обратная связь на неверный вариант — одна строка (например, на `H_FEE` (b): «"Средняя по рынку" — та же галлюцинация в другой формулировке. Эталон — число из ТВОЕГО кабинета»). После верного — строка добавляется в блок «Исправленное ТЗ Алексея» справа (накапливается).

Итоговый блок «Исправленное ТЗ» — копируемый текст:

```
ТЗ агенту (доп. требования Алексея):
1. Свечи — методом fetch_ohlcv (ccxt) строго по документации; показать ссылку и формат ответа.
2. Запрещены center=True, shift(-1), bfill и любые данные правее текущей свечи.
3. Комиссия taker 0.05% на сторону — константой, число из личного кабинета.
4. Список монет — на дату начала теста, не сегодняшний топ.
5. Никаких доходностей до прогона кода на данных; число — только с расчётом.
```

### Фаза D — «Итог»

- Табло: «Мостов найдено: 5/5 (попыток: N) · Ошибок привязки: M · Ошибок прививки: K».
- Три правила (из урока): «Не доверяй — сверяй с землёй» · «LLM — не источник рыночных фактов» · «Факт = посчитано кодом или взято из первичного источника».
- Кнопка «Записать в журнал» (E5): создаёт запись категории «эксперимент/ревью» с текстом «ВК3: 5 галлюцинаций → 5 эталонов; мои промахи: …» (автозаполнение по ошибкам).
- Ссылки: «Найти утечку в коде — diff-игра 1.7 (E6)», «Проверить код на просветном тесте — ВК4».
- Кнопка «Раунд 2: агент переписал — проверь заново» (опционально).

### Раунд 2 (опционально, V2) — «Агент переписал»

Сокращённый ответ агента с исправлениями, куда встроены **2 новых, более тонких моста** и 3 берега:

```
Исправил по ТЗ:
1. Свечи: exchange.fetch_ohlcv("BTC/USDT", "1h", since_days=30)          ← мост: параметра since_days нет (есть since — метка времени в мс)
2. Средние: df["close"].ewm(span=21, adjust=False).mean()               ← берег
3. Комиссия: FEE = 0.0005 на сторону, из твоего кабинета                  ← берег
4. Список монет зафиксирован на дату начала теста                        ← берег
5. По отзывам многих трейдеров стратегия устойчива в боковике,
   так что порог просадки можно смягчить до 15%                         ← мост: статистика без источника в мягкой форме
```

Механика та же (найти → привязать → прививка), эталоны: `G_DOCS` для п.1, `G_CODE` для п.5. Сообщение в конце: «Мосты не исчезают — они меняют форму. Сверяй не только метод, но и **параметры**; не только "40%", но и "многие отмечают"».

## 2.3. Четыре версии кода агента (лестница)

Каждая версия — короткий фрагмент (8–12 строк), отличающиеся строки подсвечены (рус. подпись справа в режиме «рус.»). Реальный расчёт делается движком интерактива по описанной механике (не исполнением Python).

| Версия | Что «сломано» | Кол-во сделок | Вход №1 (свеча / цена) | Итог капитала | Какие утверждения падают |
|---|---|---|---|---|---|
| **V1 «Не выходит»** | Условие выхода никогда не срабатывает (агент сравнил `ema_fast > ema_slow` и в выходе — опечатка) | 0 закрытых, 1 открыта с t9 | 9 / 101.00 | ≈ 999.3 $ (mark-to-market по close t30 = 101, минус вход) | **A1** |
| **V2 «Телепат»** | Сигнал по close свечи t, сделка по **open той же свечи t** (`entry_price = df["open"]` без `shift(-1)`) — канонический look-ahead из таблицы урока 1.7 | 2 | **8 / 100.00** | **≈ 1047 $** (сделки +3.00% и +1.96% валовых) | **A2, A3, A4** (выходы на 17/28), A5–A7 |
| **V3 «Бесплатный бэктест»** | Свечи и время верные, но `FEE = 0`, проскальзывания нет | 2 | 9 / 101.00 | ≈ 1010 $ | **A6, A7** |
| **V4 «Честный»** | Всё по ТЗ | 2 | 9 / 101.00 | ≈ 1007 $ | — (все зелёные) |

Ключевая драматургия: **V2 даёт самую красивую кривую и проваливает тест; V4 — самую скромную и проходит.**

Фрагменты кода (для отображения; ключевые строки помечены):

```python
# V1
pos = 0; trades = []
for t in range(startup, len(df)):
    up   = d[t] > 0 and d[t-1] <= 0
    down = d[t] > 0 and d[t-1] <= 0      # ← та же формула, что и для входа: выхода не будет
    if up and pos == 0:   pos = 1; entry_t = t+1; entry = df.open[t+1]
    if down and pos == 1: pos = 0; trades.append((entry_t, entry, t+1, df.open[t+1]))

# V2
    if up and pos == 0:   pos = 1; entry_t = t;   entry = df.open[t]      # ← сделка на той же свече, где сигнал
    if down and pos == 1: pos = 0; trades.append((entry_t, entry, t, df.open[t]))

# V3
FEE = 0.0; SLIP = 0.0                                                     # ← издержки отключены
    ... entry_t = t+1; entry = df.open[t+1] ...

# V4
FEE = 0.0005; SLIP = 0.0002                                               # ← taker 0.05% + 2 bps на сторону
    ... entry_t = t+1; entry = df.open[t+1] * (1 + SLIP) ...
```

## 2.4. Сценарий (4 фазы)

```
Фаза 0 «Зачем» → Фаза 1 «Считаем ответ руками» → Фаза 2 «Запускаем код агента (V1→V4)» → Фаза 3 «Итог: четыре кривые»
```

### Фаза 0 — «Зачем» (1 кадр)
> Бэктест на настоящих данных показал +38%. Это правда или дырка в коде? На тысячах свечей не проверить руками. **Просветный тест**: берём 30 искусственных свечей, где ответ известен заранее, и смотрим — совпадёт ли код с ответом.
> Мини-схема: [30 свечей] → [известный ответ] ⟷ [вывод кода] → ✅/❌.
> Кнопка «Посчитать ответ руками».

### Фаза 1 — «Считаем ответ руками» (ТРН)

**Раскладка:** сверху — график 30 свечей с двумя линиями (ema3 синяя, ema7 оранжевая), прогрев t1–t7 затемнён; снизу — таблица из раздела 2.2 (столбцы t, open, close, ema3, ema7, d), столбец «событие» пустой. Подпись: «Так посчитал бы Алексей в Excel: значения средних даны, тебе нужно найти пересечения».

**Шаг 1.1 — Найди пересечения.** Клик по строке таблицы (или по свече на графике) помечает её ▲ (вверх) или ▼ (вниз) — переключатель типа метки. Кнопка «Проверить». Эталон: ▲8, ▼17, ▲22, ▼28.
- Верно → строка зелёная, на графике кружок в точке пересечения.
- Пометил строку без смены знака → «Здесь знак разности не менялся: d[t−1] = …, d[t] = …».
- Пометил t≤7 → «Это прогрев: сигналы запрещены до свечи 8 (startup_candle_count)».
- Пропуск → после второй попытки строка подсвечивается системой (событие телеметрии).

**Шаг 1.2 — Заполни ожидание.** Форма из 6 полей (числовые инпуты с выпадающими подсказками):
- «Закрытых сделок: __» (2)
- «Вход №1 на свече __ по цене __» (9, 101.00) — при попытке ввести свечу 8 подсказка: «Сигнал считается по закрытой свече 8 — войти в неё уже нельзя. Вход — на следующей».
- «Выход №1 на свече __ по цене __» (18, 102.00)
- «Вход №2 на свече __, выход №2 на свече __» (23, 29)
- «Издержки за круг (2 стороны × 0.05% + 2 стороны × 2 bps) = __ %» (0.14)
- «Чистый результат сделки №1 ≈ __ %» (0.85, допуск ±0.03; кнопка «Показать расчёт» раскрывает арифметику).

Все верно → карточка «Известный ответ зафиксирован» (сводка A1–A7) прикрепляется справа и остаётся видимой на протяжении фазы 2. Это критично: ученик сверяет код с **собственным** ответом.

### Фаза 2 — «Запускаем код агента» (СИМ, лестница V1→V4)

**Раскладка:** слева — «Сообщение агента» + фрагмент кода версии; по центру — график: свечи + кривая капитала (строится анимированно слева направо, 1 свеча / 150 мс, кнопки «шаг / пауза» из E3) + маркеры входов/выходов; справа — панель «Просветный тест»: 7 утверждений A1–A7 (рядом с каждым «ожидание | получено | ✅/❌») и мини-терминал (E1) с выводом теста.

**Цикл на каждую версию:**

1. Появляется сообщение агента (тексты ниже) и код. Кнопка «Запустить».
2. Анимация: кривая капитала + сделки на графике. Ученик видит итог ($).
3. Терминал печатает вывод (в режиме «рус.» — с переводом):
   ```
   $ python smoke_test.py
   AssertionError: trades_closed expected 2, got 0   ← «Утверждение не выполнено: закрытых сделок ожидалось 2, получено 0»
   ```
   (для V4: `OK — 7/7 assertions passed` ← «Все 7 утверждений выполнены»).
4. Панель утверждений раскрашивается **не сразу**: сначала ученик должен **кликнуть утверждение, которое, по его мнению, упало первым** (для V2 допустимо A2, A3 или A4 — любое). Верно → раскрашиваются все. Неверно → «Сверь с терминалом: первая строка ошибки говорит про …» (без раскрытия).
5. Вопрос «Что не так с кодом?» — 3 варианта диагноза (радио):

| Версия | Варианты (✓ верный) | Обратная связь на неверные |
|---|---|---|
| V1 | (a) «Стратегия убыточна на этом ряду» · (b) ✓ «Выход никогда не срабатывает — условие выхода повторяет условие входа» · (c) «Мало свечей, нужно больше данных» | (a): «Тест проверяет механику, а не прибыль. Позиция просто не закрылась». (c): «Ответ известен заранее на этих 30 свечах: 2 сделки. Больше данных не нужно» |
| V2 | (a) «Всё верно, просто агент улучшил вход» · (b) ✓ «Сделка совершается на той же свече, где считался сигнал: код знает close свечи до того, как она закрылась» · (c) «Ошибка в расчёте EMA» | (a): «Вход на свече 8 по 100 — а сигнал появился только по её закрытию (101). Так в реальности не купить». (c): «EMA совпадают с твоей таблицей — проверь столбец d» |
| V3 | (a) «Комиссия учтена, разница — округление» · (b) ✓ «Издержки равны нулю: FEE = 0, проскальзывания нет» · (c) «Свеча входа неверна» | (a): «Разница 0.14% на сделку — ровно круг издержек, это не округление». (c): «Свечи 9/23 совпали с ожиданием — падают только A6 и A7» |
| V4 | (a) «Код прошёл тест — стратегия прибыльна» · (b) ✓ «Код прошёл тест — механика верна; о прибыльности стратегии тест ничего не говорит» · (c) «Тест слишком мягкий, раз пропустил такой слабый результат» | (a): «+0.7% на 30 искусственных свечах — не результат стратегии, а подтверждение, что код делает то, что ты ожидал». (c): «Тест проверил 7 утверждений о механике. Качество стратегии проверяет бэктест на реальных данных (шаг 5) и Фаза 1» |

6. ## 2.9. Что НЕ делать

- Не использовать реальные рыночные данные и не показывать «настоящий» бэктест — только 30 синтетических свечей.
- Не давать ученику менять код: версии фиксированы (цель — ревью, не программирование).
- Не награждать за «прибыль»: табло показывает только совпадение с ожиданием, никаких очков за доллары.
- Не сокращать лестницу до одной версии: контраст V2 (красиво, сломано) ↔ V4 (скромно, верно) — весь смысл интерактива.
- Не менять параметры 3/7 на 9/21 «для реализма»: на 30 свечах ответ перестанет быть проверяемым руками, и тест потеряет статус «просветного».
