# Спецификации для реализации: М30, М32, М38

Ниже — три самостоятельных ТЗ. Каждое построено по одной схеме: паспорт → цель и критерий освоения → данные и математика → экран → сценарий → тексты обратной связи → ловушки и валидация → технические требования → телеметрия → приёмка. Числа взяты из текстов уроков (принцип «интерактив воспроизводит расчёт, который ученик только что прочитал»).

---

## 0. Общие требования ко всем трём интерактивам

| Пункт | Требование |
|---|---|
| Язык | Все подписи, кнопки, подсказки, ошибки — по-русски. Единственный допустимый английский — идентификаторы в блоке «Глубже: код», и там включён режим «Ткни в непонятное» (клик по токену → русская карточка). |
| Детерминизм | Все случайные ряды генерируются из seed. Первый заход — фиксированный seed (чтобы числа совпадали с уроком); кнопка «Другая выборка» → новый seed, показанный мелко в углу (для воспроизводимости в поддержке). |
| Структура блока | Заголовок → одна строка «Что ломает этот тренажёр» (формулировка заблуждения) → тело → панель «Итог» с 2–3 буллетами, которая раскрывается только после прохождения. |
| Длительность | 3–5 минут на первое прохождение. Повторное прохождение — с новой выборкой/новым кейсом. |
| Адаптив | Десктоп: две колонки. Мобильный: одна колонка, графики не уже 320 px, слайдеры с крупными хватами (≥44 px). |
| Доступность | Все графики имеют текстовый эквивалент в `aria-live`-области (обновляется при каждом изменении). Управление слайдерами клавишами ←/→. Контраст ≥ 4.5:1. Цвета не единственный носитель смысла (дублировать формой/подписью). |
| Персонаж | Где уместно — Алексей (депозит 100 000 ₽ / 1000 $), уже знакомый по Py-урокам. |
| Производительность | Никаких вычислений тяжелее O(n·k) при n ≤ 2000, k ≤ 50. Пересчёт при движении слайдера — ≤ 16 мс (кэшировать предгенерированные шумы, менять только коэффициенты). |
| Телеметрия | Единый формат события: `{lesson, widget_id, event, payload, ts}`. Список событий — в каждой спеке. |
| Хранение | Состояние «пройдено/не пройдено» и последний результат — в общем прогрессе ученика. |

## 1. М30 — «Оценка плавает»

### 1.1. Паспорт

| Поле | Значение |
|---|---|
| ID | `m30_estimate_floats` |
| Урок | 120 · М30 «Стандартная ошибка: почему оценки плавают» |
| Тип | АНИМ (управляемая анимация с двумя режимами и одной проверкой) |
| Заблуждение | «Больше данных = правильно автоматически» |
| Что должно остаться в голове | (1) Ширина интервала падает как 1/√n: чтобы сузить вдвое — данных в 4 раза больше. (2) Сужение — это точность, а не правильность: при систематической ошибке интервал сужается вокруг неверного числа. |
| Связи | М10 (закон больших чисел «усиливает то, что есть в данных»), М24 (μ=8, σ=20, n=100 → σ/√n=2), М31 (интервал 8 ± 3,9), М43 (пять сделок не запрещают стратегию — запрещают крупный размер), 1.7 (утечка будущего), 1.8 (издержки) |
| Размещение | Сразу после абзаца «Глубже: … Она просто уменьшает случайную неопределённость при прочих равных условиях», до существующего симулятора «Стандартная ошибка на пальцах». Существующий симулятор не трогаем. |

### 1.2. Данные и математика

Единицы — как в уроках М24/М31: результат сделки в процентах.

```
Истинное среднее (население):   μ = 8
Разброс одной сделки:            σ = 20
Стандартная ошибка среднего:     SE(n) = σ / √n
Полуширина интервала:            h(n) = 1.96 · SE(n)
Сетка n (лог-шкала, 8 ступеней): 5, 10, 25, 50, 100, 200, 400, 1600
Веер: K = 40 выборочных средних на каждой ступени n
```

Опорная таблица (использовать в подписях; проверять в тестах с допуском ±0,05):

| n | SE | ±h | интервал при x̄=8 |
|---|---|---|---|
| 5 | 8,94 | 17,5 | −9,5 … 25,5 |
| 25 | 4,00 | 7,8 | 0,2 … 15,8 |
| 100 | 2,00 | 3,9 | 4,1 … 11,9 |
| 400 | 1,00 | 2,0 | 6,0 … 10,0 |
| 1600 | 0,50 | 1,0 | 7,0 … 9,0 |

**Режим Б «Сломанный прибор».** Добавляется систематическая ошибка b: каждая наблюдаемая сделка = истинная + b. Варианты (переключатель):
- «Утечка будущего» — b = +5 (сигнал считали по цене, которую ещё не знали, урок 1.7);
- «Забыли комиссии» — b = +2 (0,2 % за круг × 10 ≈ масштаб урока; ученику подпись: «издержки не вычли»);
- «Выбросили худшие дни» — b = +3 (М27: удалили «неудобные» наблюдения).

В режиме Б выборки берутся из N(μ+b, σ). Интервал строится вокруг выборочного среднего. Вычисляется и показывается «Доля интервалов из 40, накрывших истинное μ»: в режиме А ≈ 95 % на всех n; в режиме Б падает до 0 % при росте n (при b=5: n=100 — примерно 30 %, n=400 — ~0 %).

Генерация: Box–Muller, seed по умолчанию `20240808`; предгенерировать матрицу шумов [8 ступеней × 40 средних] один раз; при переключении режима только сдвигать на b (без пересемплирования — так ученик видит «те же точки, но сдвинутые»).

### 1.3. Экран

```
┌──────────────────────────────────────────────────────────────┐
│ Оценка плавает                                               │
│ Что ломает: «больше данных = правильно автоматически»        │
├───────────────────────────────┬──────────────────────────────┤
│ (A) Числовая ось от −15 до 30 │ (B) График SE от n           │
│  ─ пунктир «истинное среднее  │   ось X лог: 5…1600          │
│    8 (в жизни неизвестно)»    │   ось Y: 0…9                 │
│  ● 40 точек-средних (веер)    │   кривая 20/√n               │
│  ┣━━━━━━┫ скобка ±1,96·SE     │   ● бегунок текущего n       │
│    вокруг среднего из средних │   пунктир: «в 2 раза уже»    │
├───────────────────────────────┴──────────────────────────────┤
│ (C) Ступени n:  [5][10][25][50][100][200][400][1600]  ▶ авто │
│     кнопка «×4 сделок»                                       │
│ (D) Показания: n=100 │ SE=2,0 │ интервал 4,1…11,9            │
│     «уже, чем при n=25, в 2,0 раза — сделок в 4 раза больше» │
│ (E) Режим:  ◉ Честные данные   ○ Сломанный прибор [▾ утечка] │
│     Доля интервалов, накрывших истину: 95 %                  │
├──────────────────────────────────────────────────────────────┤
│ (F) Проверка (2 вопроса) → панель «Итог»                     │
└──────────────────────────────────────────────────────────────┘
```

Детали элементов:
- **(A)** Точки веера «падают» сверху на ось с лёгким ускорением (200–400 мс, случайная задержка 0–150 мс на точку), как шарики в доске Гальтона. Скобка интервала анимированно сжимается при переходе к большему n (плавно, 400 мс). Пунктир истинного μ виден всегда, подпись: «истинное среднее — 8. В жизни его никто не знает, здесь показано для наглядности».
- **(B)** Кривая SE(n) рисуется полностью при загрузке; бегунок скользит по ней. Горизонтальные пунктиры от текущего SE и от SE/2 с подписью «чтобы попасть сюда, нужно в 4 раза больше сделок».
- **(C)** Кнопка «×4 сделок» — главное действие: перескакивает n → 4n (5→20 не в сетке, поэтому при нажатии из 5 идёт на 25 с подписью «≈ в 4 раза»; из 25 → 100 → 400 → 1600). Кнопка «▶ авто» проигрывает все ступени по 1,5 с.
- **(E)** Переключатель режима. В режиме Б меняется цвет точек (с синего на оранжевый + иконка ⚠) и появляется вторая подпись под осью: «наблюдаемое среднее ≈ 13, истина 8».

### 1.4. Сценарий взаимодействия

1. Загрузка: режим А, n=5. Падают 40 точек — разброс огромный (интервал −9,5…25,5). Подпись: «5 сделок: стратегия могла показать и −9 %, и +25 % на сделку — при истинных +8».
2. Ученик нажимает «×4 сделок» трижды (или ▶ авто). Каждый шаг: точки падают кучнее, скобка сжимается; в (D) явно пишется коэффициент сужения «в 2,0 раза».
3. Всплывающая подсказка после второго нажатия: «Заметил? Каждые ×4 сделок — интервал вдвое уже. Не ×2, а ×4: так работает корень».
4. После n=1600 в режиме А появляется кнопка «А если прибор сломан?» (мягкий призыв). Клик → режим Б с выпадающим списком причины (по умолчанию «утечка будущего +5»).
5. В режиме Б ученик снова проходит ступени. Ключевой момент на n=1600: интервал 12,0…14,0, узкий и уверенный, истина 8 далеко снаружи. Показатель «накрыли истину: 0 %» горит красным. Подпись: **«Точность выросла. Правильность — нет. Ты очень точно измерил неправильную вещь»** (цитата смысла из М10).
6. Открывается проверка (F).

### 1.5. Проверка (F)

Вопрос 1 (выбор): «Интервал при 100 сделках ±3,9. Сколько сделок нужно, чтобы стало ±1,95?»
- 200 → «Нет: удвоение данных сужает лишь в √2 ≈ 1,4 раза».
- **400** → «Верно: ширина падает как 1/√n, вдвое уже — вчетверо больше данных».
- 1000 → «Слишком много: хватит 400. Но заметь — ты переоценил, а не недооценил: это безопасная ошибка».

Вопрос 2 (выбор, показывается скриншот-состояние режима Б при n=1600): «Интервал 12,0…14,0 по 1600 сделкам. Что можно сказать?»
- «Стратегия точно приносит около 13 % на сделку» → «Интервал говорит о случайной погрешности, а не о том, честно ли собраны данные. Если в них утечка — 1600 сделок лишь укрепят иллюзию».
- **«Случайная погрешность мала, но систематическая ошибка интервалом не ловится»** → верно.
- «Нужно ещё больше сделок» → «Больше данных не лечит утечку: интервал сузится ещё, а центр останется неверным».

Оба ответа верны → панель «Итог»:
- Ширина интервала ∝ 1/√n: вдвое уже — вчетверо больше сделок.
- Малая выборка не опровергает стратегию, она запрещает крупный размер (М43).
- Интервал измеряет случайную погрешность. Утечку, забытые комиссии и выброшенные дни он не видит — их ловят руками (1.7, 1.8, М27).

### 1.6. Ловушки и валидация

- При n=5 интервал по формуле нормальной аппроксимации формально некорректен — показывать его, но с меткой «на 5 сделках формула приблизительна (М31: для малых выборок честнее бутстрап)». Не усложнять — просто метка.
- В режиме Б запрещено давать подсказку до n ≥ 100: пусть ученик сначала увидит «красивое» сужение, и только потом — что оно мимо истины.
- Кнопка «Другая выборка» пересемплирует шумы, но истина 8 и b неизменны.

### 1.7. Опциональный слой «Глубже» (низкий приоритет)

Режим В «Сделки зависимы»: ученик включает «усреднение позиции» — сделки идут пачками по 4 с общим шумом; эффективное n = n/4; интервал по формуле σ/√n оказывается уже, чем реальный разброс средних (показать оба: «формула обещает ±2,0, факт ±4,0»). Связь с М10 «независимые ставки» и М45. Реализовать только если бюджет позволяет; в приёмку не входит.

### 1.8. Технические требования

- Размер холста: 720×420 (десктоп), масштабируемый SVG/Canvas.
- Пересчёт при смене n — только выбор строки из предгенерированной матрицы; анимация — requestAnimationFrame.
- Состояние: `{mode: 'honest'|'broken', bias_kind, n_index, seed, quiz: {q1, q2}}`.
- Кнопка «Сбросить» возвращает к n=5, режим А, seed по умолчанию.

### 1.9. Телеметрия

`m30_open`, `m30_step {n, mode}`, `m30_autoplay`, `m30_mode_switch {bias_kind}`, `m30_quiz {q, answer, correct}`, `m30_complete {duration_s, reseeds}`.

### 1.10. Критерии приёмки

- [ ] При seed по умолчанию и n=100 показания совпадают с уроком: SE=2,0, интервал 4,1…11,9.
- [ ] Коэффициент сужения между n и 4n отображается как 2,0 (±0,01).
- [ ] В режиме Б при n=1600 доля накрытий = 0 %, в режиме А — 90–100 % (при 40 повторах допустим разброс).
- [ ] Переключение режима не пересемплирует шум (точки сдвигаются, а не перемешиваются).
- [ ] Панель «Итог» недоступна до двух верных ответов.
- [ ] Текстовый эквивалент в aria-live содержит n, SE, границы интервала и режим.
- [ ] Ни одного английского слова в интерфейсе.

## 2. М32 — «Настроение → гипотеза»

### 2.1. Паспорт

| Поле | Значение |
|---|---|
| ID | `m32_mood_to_hypothesis` |
| Урок | 122 · М32 «Гипотеза: „Кажется, здесь есть закономерность"» |
| Тип | ТРН (многораундовый тренажёр с блокировкой «до данных») |
| Заблуждение | «Ощущение — уже гипотеза» |
| Что должно остаться в голове | Гипотеза = условие с числом + измеряемый исход с горизонтом + утверждение против базы + порог «эффект есть» + дата фиксации ДО данных. Если хотя бы одного нет — это настроение. Поправка порога после взгляда на данные — вторая гипотеза, а не уточнение первой. |
| Связи | М4 (условная vs безусловная: 12/20 = 0,6 против 60/100 = 0,6, сдвиг 0), М18 (сдвиг меньше издержек — шум), М33 (H₀/H₁), М36 (множественные проверки), М42 (тест трогаем один раз), 1.5 (паспорт гипотезы), 1.8 (издержки 14–20 bps за круг), 2.2 (всплеск упоминаний z>3 как измеримый заменитель «все орут») |
| Движки | E5 «Журнал» — экспорт карточки гипотезы; R12 «Правило одного изменения» — идеология блокировки |
| Размещение | После блока «Глубже: Операционализация…», перед существующим «Конструктором гипотезы». **Отличие от существующего:** тот собирает одну формулировку; этот прогоняет 4 разных настроения, вводит замок «зафиксировано до данных», проверку против базы и издержек и ловушку подгонки. Существующий оставить. |

### 2.2. Ядро механики: «Подсветка размытых слов»

Каждое настроение — предложение, в котором 3–5 слов помечены как размытые. У каждого размытого слова — «слот», который его заменяет. Пока слот пуст, слово подчёркнуто красной волной; когда слот заполнен корректно — слово плавно перекрашивается в зелёный и рядом всплывает его точная замена. Это главная анимация тренажёра: ученик буквально видит, как настроение превращается в формулу.

Слоты (единый набор для всех раундов):

| № | Слот | Что требуется | Пример для канонического раунда |
|---|---|---|---|
| 1 | **Условие** | метрика + оператор + число с единицами + окно измерения | «доходность за предыдущий день < −3 %» |
| 2 | **Исход** | целевая метрика + горизонт | «доходность следующего дня» |
| 3 | **Утверждение** | сравнение с базой (не с нулём!) | «среднее при условии > среднее по всем остальным дням» |
| 4 | **Порог «эффект есть»** | минимальный сдвиг ≥ издержки за круг | «сдвиг ≥ 0,2 % (20 bps)» |
| 5 | **Фиксация** | кнопка «Зафиксировать» → дата/время, замок | «зафиксировано 08.08.2026 14:12» |

Слоты 1–3 собираются из чипов (как в Py-04): чипы метрик, операторов, окон; число вводится в поле. Слот 4 — числовое поле с подсказкой «издержки за круг по уроку 1.8: 14–20 bps». Слот 5 — кнопка.

**Кнопка «Открыть данные» заблокирована до нажатия «Зафиксировать».** Подпись на замке: «Данные откроются после фиксации. Иначе ты подберёшь порог под ответ (М36)».

### 2.3. Банк раундов

Раунд обязательный — №1; далее ученик проходит №2 и любой один из №3/№4 (рандом). Раунд №5 — контрольный, всегда последний.

**Раунд 1 (канонический, из текста урока).**
Настроение: «После **сильного** падения рынок **чаще** **растёт** на **следующий день**».
Размытые слова → слоты: «сильного» → порог условия; «чаще» → утверждение против базы; «растёт на следующий день» → исход и горизонт.
Данные (из М4): 100 дней; 60 растущих / 40 падающих; условие «падение < −3 %» выполнено в 20 днях, из них 12 привели к росту.
Результат проверки: доля роста при условии 12/20 = 60 %; базовая доля 60/100 = 60 %; сдвиг 0 п.п.; средняя доходность при условии +0,05 %, без условия +0,04 %; сдвиг 0,01 % < 0,2 % издержек.
Ожидаемый вердикт: **«сдвиг меньше издержек — шум»**.

Синтетика для средних: генерировать так, чтобы доли были ровно 12/20 и 60/100, а средние отличались менее чем на 0,05 % (seed фиксирован).

**Раунд 2 (неизмеримое слово → измеримый заменитель).**
Настроение: «Когда **все в чате орут** «покупай», обычно **вершина**».
Ожидаемое: «все орут» → «число упоминаний монеты за 5-минутное окно > среднего на 3 стандартных отклонения» (чип из 2.2); «вершина» → «доходность следующих 24 часов < 0 (или медиана ниже базы)». Утверждение: против базы; издержки как обычно.
Данные: 300 эпизодов-всплесков (z>3); средняя доходность 24 ч после всплеска −0,6 % против базы +0,1 %; сдвиг −0,7 % > издержек 0,2 % по модулю; n=300.
Ожидаемый вердикт: «эффект есть по этой выборке — кандидат на проверку на новых данных (не доказательство)».
Учит: заменить ощущение измеримым заменителем; положительный результат — ещё не победа.

**Раунд 3 (окно = календарь).**
Настроение: «По **выходным** биткоин **спокойнее**».
Ожидаемое: условие «день недели ∈ {сб, вс}»; исход «размах дня (high−low)/open» или «|доходность дня|»; утверждение «среднее при условии < среднее в будни»; порог — здесь издержки не при чём, тренажёр подсказывает: «для гипотезы о разбросе порог задаётся долей: например, ниже на 20 %».
Данные: 365 дней; средний размах будни 3,1 %, выходные 2,2 % (на 29 % ниже); n_вых=104.
Ожидаемый вердикт: «эффект есть по этой выборке». Дополнительный вопрос: «Можно ли на этом заработать?» → правильный ответ: «Нет: это гипотеза о разбросе, а не о направлении; она годится как фильтр риска, а не как сигнал».

**Раунд 4 (собственный журнал).**
Настроение: «Мой бот **лучше работает** **утром**».
Ожидаемое: условие «час открытия сделки ∈ 06:00–12:00 UTC»; исход «PnL сделки, %»; утверждение против базы «остальные часы».
Данные: журнал Алексея на 120 сделок; утро — 41 сделка, средний PnL +0,35 %; остальные 79 — +0,30 %; сдвиг 0,05 % < 0,2 %; SE сдвига 0,4 %.
Ожидаемый вердикт: «данных мало и сдвиг меньше издержек».

**Раунд 5 (контрольный: это не гипотеза).**
Настроение: «Рынок сегодня какой-то **нервный**, лучше **не лезть**».
Ожидаемое действие: кнопка **«Это настроение, а не гипотеза»** (доступна во всех раундах, но правильна только здесь). Если ученик пытается заполнять слоты — тренажёр даёт: «Попробуй: что измеряем? за какое окно? с чем сравниваем?» — и если ученик соберёт что-то осмысленное (например, «дневной размах > 5 % → пропустить день»), тренажёр принимает это как *другую* гипотезу: «Ты только что превратил настроение в правило — это и есть работа. Но исходная фраза гипотезой не была».

### 2.5. Сценарий раунда

1. Показ карточки настроения, размытые слова подчёркнуты. Подсказка при наведении на слово: «Что здесь неточно? „сильного" — это сколько?».
2. Ученик заполняет слоты. Каждый корректный слот перекрашивает своё слово.
3. Валидация в реальном времени (см. 2.7): предупреждения появляются под слотом, не блокируют.
4. Нажатие «Зафиксировать»: замок закрывается с анимацией, появляется штамп с датой/временем; поля становятся неактивными; слот 5 зелёный.
5. «Открыть данные» → таблица результата:

```
Выполнено условие:      20 дней из 100
Исход при условии:      рост в 12 из 20 (60 %); средняя +0,05 %
Исход без условия:      рост в 48 из 80 (60 %); средняя +0,04 %
Сдвиг:                  0 п.п. / +0,01 %
Твой порог эффекта:     0,2 %
```

6. Выбор вердикта (4 кнопки): «Эффект есть», «Эффект есть, но нужна проверка на новых данных», «Сдвиг меньше издержек — шум», «Данных мало — вывода нет». Обратная связь по таблице ниже.
7. **Ловушка после данных.** Появляется кнопка-соблазн «Подобрать порог: при −5 % сдвиг больше». Клик → слоты разблокируются, но на карточке появляется красный штамп «изменено после просмотра данных» и счётчик «проверок на этих данных: 2». Текст: «Это не уточнение, это вторая гипотеза на тех же данных. Считай: два теста — вдвое больше шансов найти шум (М36). Новая формулировка проверяется только на данных, которых ты ещё не видел». Кнопка «Открыть данные» для изменённой версии выдаёт: «Новых данных нет. Запиши в журнал как гипотезу №2 и жди следующий месяц».
8. Карточка гипотезы (E) заполняется автоматически; кнопка «Сохранить в журнал» пишет её в E5.

### 2.7. Валидация слотов и ловушки

| Ситуация | Реакция (не блокирующая, кроме отмеченных) |
|---|---|
| Порог без числа (пустое поле) | Слово остаётся красным; «„сильного" — это сколько? Поставь число». |
| Утверждение против нуля | Жёлтое предупреждение: «Сравниваешь с нулём. В бычьем рынке любое условие даст „среднее > 0". Сравнивай с днями, где условия не было (М4)». Не блокирует, но в результатах раунда 1 отдельной строкой показывается: «против нуля: +0,05 % > 0 — „сработало"; против базы: 0 — не сработало». |
| Горизонт исхода не задан | Блокирует фиксацию: «Через сколько измеряем исход?». |
| Условие и исход на одной свече («доходность за день < −3 % → доходность за день > 0») | Блокирует: «Условие и исход — одно и то же окно. Ты проверяешь, что падение — это не рост». |
| Порог эффекта = 0 | Предупреждение: «Порог 0 — значит, любой сдвиг „эффект". Издержки за круг 14–20 bps съедят его». |
| Порог эффекта > 5 % | Предупреждение: «Такого сдвига дневная доходность не даёт; ты заранее гарантировал себе „нет эффекта"». |
| Попытка «Открыть данные» до фиксации | Замок трясётся, тултип из 2.2. |
| Изменение слотов после данных | Штамп «изменено после просмотра», счётчик проверок, запрет новых данных. |
| Кнопка «не гипотеза» в раундах 1–4 | «Здесь фраза переводится: попробуй. Размытые слова подчёркнуты — у каждого есть измеримая замена». |

### 2.9. Технические требования

- Синтетические данные каждого раунда — предвычислены и захардкожены как таблицы (не генерировать на лету), чтобы числа совпадали с уроком и были одинаковы у всех учеников. «Другая выборка» — только для раунда 1: 5 предзаготовленных вариантов, во всех сдвиг 0 ± 0,03 %.
- Дата фиксации — локальное время устройства; хранить в карточке.
- Состояние раунда: `{mood_id, slots{1..5}, locked_at, data_opened, verdict, modified_after_data, checks_count}`.
- Порядок раундов: 1 → 2 → (3|4 случайно) → 5. Повторное прохождение: 1 → 2 → (тот, что не выпал) → 5.
- Клавиатура: чипы доступны через Tab/Enter.

### 2.10. Телеметрия

`m32_open`, `m32_slot_fill {round, slot, value}`, `m32_warning {round, kind}`, `m32_lock {round}`, `m32_data_open {round}`, `m32_verdict {round, chosen, correct}`, `m32_modify_after_data {round}`, `m32_not_hypothesis_click {round, correct}`, `m32_export_journal`, `m32_complete {rounds, duration_s}`.

Ключевая метрика для методолога: доля `m32_modify_after_data` — должна падать от раунда к раунду и при повторных прохождениях.

### 2.11. Критерии приёмки

- [ ] В раунде 1 при базовом seed таблица показывает 12/20 против 48/80, сдвиг 0 п.п.
- [ ] «Открыть данные» недоступна до «Зафиксировать»; после фиксации слоты неактивны.
- [ ] Каждое размытое слово перекрашивается ровно при заполнении своего слота.
- [ ] Утверждение «против нуля» даёт предупреждение и отдельную строку в результате раунда 1.
- [ ] Изменение слота после данных ставит штамп и увеличивает счётчик; повторное открытие данных запрещено с объяснением.
- [ ] Раунд 5 принимает кнопку «не гипотеза» как верный ответ; в раундах 1–4 она даёт отказ с подсказкой.
- [ ] Карточка экспортируется в журнал со всеми 9 полями.
- [ ] Панель «Итог» появляется только после раунда 5.

Панель «Итог»:
- Гипотеза — это число, метрика, горизонт, база, порог и дата. Нет хоть одного — это настроение.
- Сравнивай с базой, а не с нулём: «после падения растёт в 60 % дней» ничего не значит, если растёт в 60 % дней вообще.
- Порог подбирают до данных. После данных — только новая гипотеза и новые данные.

## 3. М38 — «Общий драйвер»

### 3.1. Паспорт

| Поле | Значение |
|---|---|
| ID | `m38_common_driver` |
| Урок | 128 · М38 «Причина и совпадение» |
| Тип | СИМ (лаборатория из трёх экспериментов + детективный финал) |
| Заблуждение | «Вместе = причина» (BTC и ETH ходят вместе — значит, BTC двигает ETH) |
| Что должно остаться в голове | Корреляцию 0,8 создаёт скрытый общий драйвер без всякой причинности. Отличить причину от совпадения можно тремя способами: убрать драйвер (контроль) — связь исчезает; толкнуть одну переменную — вторая не двигается; порядок во времени. Практически: корреляции достаточно для фильтра риска (3.6), но недостаточно для сигнала «догонит» (3.1, парный трейдинг требует коинтеграции). |
| Связи | М37 (корреляция), 1.11 (бета к BTC), 3.1 (корреляция vs коинтеграция), 3.6 (корреляции → 1 в крах), FT-05 (BTC как информативная пара-фильтр) |
| Размещение | После блока «Глубже: Ловушка скрытой переменной…», перед существующим «Общая причина или связь?». **Отличие от существующего:** здесь ученик управляет силой драйвера ползунком, проводит контроль и вмешательство сам и в финале различает два скрытых мира. |

### 3.2. Данные и математика

Два скрытых «мира» с одинаковой наблюдаемой корреляцией, но разной структурой.

**Мир А — общий драйвер (из кода урока):**
```
n = 300 дней
D  ~ N(0, 1)                      # скрытая переменная: «приток денег в крипту» (ликвидность)
ε_b, ε_e ~ N(0, 0.5²), независимы
BTC = a·D + ε_b
ETH = a·D + ε_e
corr(BTC, ETH) = a² / (a² + 0.25)
```
Ползунок a ∈ [0; 1,5], шаг 0,1. Опорные значения: a=0 → 0,00; a=0,5 → 0,50; a=1,0 → **0,80** (число урока); a=1,5 → 0,90.

**Мир Б — прямая причинность BTC → ETH:**
```
BTC = a·D + ε_b,            ε_b ~ N(0, 0.5²)
ETH = β·BTC + ε_e,          ε_e ~ N(0, s²)
```
При a=1 подобрать β и s так, чтобы corr(BTC, ETH) ≈ 0,80: β = 0,8, s² = Var(BTC)·β²·(1/0,64 − 1) = 1,25·0,64·0,5625 = 0,45 → s ≈ 0,67. (Проверить численно в тесте: 0,78–0,82.)

Шумы ε_b, ε_e, D предгенерируются один раз на seed; движение ползунка меняет только a (и в мире Б пересчитывает β/s по формуле, чтобы наблюдаемая корреляция оставалась близкой между мирами при одном a).

**Контроль по драйверу** (два эквивалентных представления, оба показывать):
1. Стратификация: разбить D на 5 квинтилей, посчитать corr(BTC, ETH) внутри каждого, показать среднее. Мир А: ≈0 ± 0,13 (n≈60 на корзину). Мир Б: ≈0,55–0,65.
2. Частная корреляция: остатки BTC и ETH после регрессии на D; corr(остатков). Мир А: ≈0; мир Б: ≈0,6. Формула в «Глубже»: r_xy·z = (r_xy − r_xz·r_yz)/√((1−r_xz²)(1−r_yz²)).

**Вмешательство (do-оператор):** взять текущий день, принудительно сдвинуть BTC на +3σ_BTC. Мир А: ETH не меняется (ETH зависит от D и ε_e). Мир Б: ETH сдвигается на β·3σ_BTC ≈ +2,4σ. Вмешательство в D: оба движутся в обоих мирах.

Метки для ученика: D подписан как «приток денег на рынок (в жизни виден плохо)». BTC/ETH — «дневная доходность, в стандартных отклонениях».

### 3.4. Сценарий

**Шаг 0 — Знакомство (мир А, драйвер скрыт).**
a=1,0. Рассеяние с r=0,80. Подпись: «BTC и ETH: корреляция 0,80. Вопрос: BTC двигает ETH?». Кнопки-ответы: «Да, BTC двигает ETH» / «Нет, есть что-то третье» / «Не знаю — надо проверить». Любой ответ принимается, фиксируется в телеметрии как априор; текст: «Запомни свой ответ. Через три эксперимента вернёмся».

**Шаг 1 — Ползунок драйвера.**
Ученик двигает a. При a=0 облако круглое, r=0; при a=1,5 — вытянутая полоса, r=0,90. Подпись меняется живьём: «Единственное, что ты менял, — силу третьей переменной. Ни BTC, ни ETH друг на друга не влияли». Кнопка 👁 показывает ряд D в (B): видно, что и BTC, и ETH повторяют его форму.
Микро-проверка: «Чтобы получить корреляцию 0,8, сколько прямого влияния BTC на ETH нужно?» → «нисколько» ✓.

**Шаг 2 — Эксперимент 1 «Убрать драйвер» (контроль).**
Кнопка «Разбить по уровню драйвера». Облако раскрашивается в 5 цветов (квинтили D), рядом — 5 мини-рассеяний с r внутри каждой корзины: 0,03; −0,08; 0,11; −0,02; 0,05 (примерно; реальные значения из данных). Среднее ≈0,02. Анимация: цветные подоблака «разъезжаются» по корзинкам и внутри каждой видно круглое облако. Подпись: «Внутри дней с одинаковым притоком денег BTC и ETH не связаны. Вся связь жила в драйвере».
Переключатель «Показать как частную корреляцию»: r после удаления D = 0,02, с полосой шума ±0,13 (М30!). Подпись: «±0,13 — обычный разброс на 60 точках; 0,02 неотличим от нуля».

**Шаг 3 — Эксперимент 2 «Толкнуть».**
Два столбика: BTC и ETH за «сегодня». Кнопка «Толкнуть BTC вверх (+3σ)». Анимация руки, столбик BTC взлетает, ETH стоит. Подпись: «Ты силой поднял BTC — ETH не шелохнулся. Так выглядит отсутствие причины». Кнопка «Толкнуть драйвер (+2σ)»: оба столбика растут. Подпись: «А вот приток денег двигает обоих».
Оговорка (важно, «Глубже»): «В жизни толкнуть биткоин руками ты не можешь. Поэтому у трейдера остаются только контроль и порядок во времени — эксперимент 1 и 3».

**Шаг 4 — Эксперимент 3 «Порядок во времени».**
Таблица лагов: corr(BTC_t, ETH_t) = 0,80; corr(BTC_{t−1}, ETH_t) = 0,01; corr(ETH_{t−1}, BTC_t) = −0,02. Подпись: «Вчерашний BTC не предсказывает сегодняшний ETH. Совпадение одновременно, предсказания — нет». Связь с М37: «причинность проверяют лагом».

**Шаг 5 — Финал «Два мира».**
Показываются две карточки «Мир 1» и «Мир 2» (случайно назначены А и Б), в обеих r ≈ 0,80, ползунок зафиксирован на a=1. Ученику доступны эксперименты 1 и 3 для каждого мира (эксперимент 2 — недоступен, с подписью «в реальности недоступен»). Задача: отметить, в каком мире BTC действительно двигает ETH.
Ответ проверяется; подсказки:
- Если ученик выбрал не проведя контроль: «Ты угадал/не угадал. Без эксперимента это подбрасывание монеты. Проведи контроль в обоих мирах».
- В мире Б контроль показывает r_остатков ≈ 0,6 → «связь пережила удаление драйвера — вот признак прямого влияния». Лаг в мире Б: corr(BTC_{t−1}, ETH_t) всё ещё ≈ 0 (влияние одновременное) — подпись: «Порядок во времени здесь не помог: влияние в тот же день. Контроль — надёжнее».
После верного ответа раскрывается структура обоих миров в виде стрелочной схемы: D→BTC, D→ETH (мир А); D→BTC→ETH (мир Б).

**Шаг 6 — Возврат к априору.**
«В начале ты ответил: „…". Сейчас?» — повтор трёх кнопок. Затем практическая развилка:
«Что из этого можно делать с корреляцией 0,8, не зная причины?»
- «Использовать BTC как фильтр риска: три альта в обвал BTC — одна позиция» ✓ (3.6, FT-18)
- «Покупать ETH, когда BTC вырос: он догонит» ✗ → «„Догонит" — это утверждение о причине и о возврате. Для этого нужна коинтеграция (3.1), а не корреляция».
- «Считать бету ETH к BTC и вычесть из результата стратегии» ✓ (1.11) — «Бета — это описание совместного движения, для неё причина не нужна».

Панель «Итог».

### 3.6. Ловушки и оговорки, которые должен произнести интерактив

1. «Обнулилась при контроле» — не значит «драйвер найден правильно»: в жизни ты контролируешь по *своей догадке* о драйвере. Подпись в эксперименте 1 (сворачиваемая): «Здесь мы знаем драйвер, потому что сами его придумали. В реальности ты подставляешь свою гипотезу драйвера (ликвидность, ставка ФРС, фандинг), и если она неверна — связь не исчезнет, хотя причины всё равно нет».
2. Шум на малых корзинах: полоса ±0,13 обязательна, иначе ученик сочтёт r=0,11 «связью».
3. В крах-дни драйвер резко усиливается (3.6): опциональная кнопка «День обвала (a=3 на 5 дней)» показывает, как r на окне 60 дней прыгает к 0,95 — «корреляция режима, не постоянная величина» (М37).

### 3.7. Технические требования

- Seed по умолчанию `20240128`; матрицы D, ε_b, ε_e размера 300 предгенерированы; при движении ползунка пересчитываются только BTC/ETH (300 умножений) и r.
- Квинтили — по D текущей выборки; внутри-корзинный r считается по Пирсону; если в корзине < 20 точек — не считать (не должно случаться при n=300).
- Частная корреляция — через остатки OLS (две одномерные регрессии), не через формулу (формула — только для показа в «Глубже»).
- Финал: назначение миров случайное, но сохраняется в состоянии до завершения (перезагрузка не меняет).
- Состояние: `{a, driver_visible, world_final_map, experiments_done{1,2,3}, prior_answer, final_choice, posterior_answer, practice_answers}`.
- Рассеяние: Canvas; при a изменении — переход точек с анимацией 250 мс (интерполяция координат).

### 3.8. Телеметрия

`m38_open`, `m38_prior {answer}`, `m38_slider {a, r}`, `m38_reveal_driver`, `m38_exp {id, world}`, `m38_final_choice {chosen, correct, experiments_before_choice}`, `m38_posterior {answer}`, `m38_practice {q, answer, correct}`, `m38_complete {duration_s}`.

Метрика для методолога: доля учеников, сделавших выбор в финале без единого эксперимента (`experiments_before_choice = 0`) — цель < 20 %; сдвиг prior→posterior от «да» к «нет/проверить».

### 3.9. Критерии приёмки

- [ ] При a=1,0 и seed по умолчанию r в мире А равно 0,78–0,82; в мире Б — 0,78–0,82.
- [ ] Контроль в мире А: средняя внутри-корзинная корреляция |r| ≤ 0,08; частная ≤ 0,08. В мире Б: частная 0,5–0,7.
- [ ] Толчок BTC в мире А не меняет ETH (ровно 0); в мире Б меняет на β·3σ.
- [ ] Лаг-таблица: |corr(BTC_{t−1}, ETH_t)| ≤ 0,1 в обоих мирах.
- [ ] Финал не засчитывает ответ без хотя бы одного проведённого эксперимента (принимает, но выдаёт «монетка» и требует повторить с экспериментом).
- [ ] Схема стрелок раскрывается только после верного финала.
- [ ] Полоса шума ±0,13 присутствует на всех внутри-корзинных r.
- [ ] aria-live сообщает текущее a, r, результат каждого эксперимента словами.

Панель «Итог»:
- Общий драйвер даёт корреляцию 0,8 без единой стрелки между BTC и ETH.
- Причину ищут контролем (связь исчезает, когда драйвер зафиксирован), вмешательством (в жизни недоступно) и порядком во времени.
- Корреляции хватает для фильтра риска и беты; для сигнала «догонит» нужна коинтеграция, а не совпадение движений.
