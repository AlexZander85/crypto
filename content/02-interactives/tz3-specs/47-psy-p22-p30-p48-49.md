# Детальные спеки для реализации: П22, П30, П48/П49

## 0. Общие соглашения (действуют для всех трёх интерактивов)

| Пункт | Требование |
|---|---|
| **Персонаж** | Алексей, депозит **100 000 ₽** (в психологическом треке — рубли). 1R по умолчанию = 1 % депозита = **1 000 ₽**. |
| **Язык** | Все подписи, кнопки, оси, подсказки — русские. Английские термины только в скобках при первом появлении и как всплывающая карточка «Ткни в непонятное» (режим из раздела 6 методички). Запрещены: «PnL», «equity», «R-multiple», «tilt» без русского дубля. |
| **Детерминизм** | Все «случайные» миры/дни генерируются PRNG с фиксированным сидом (mulberry32 или аналог). Кнопка «Случайные миры» меняет сид явно и показывает его номер («Мир №1 847»), чтобы ученик мог воспроизвести. |
| **Числа из урока** | Интерактив обязан воспроизвести расчёты, которые ученик только что прочитал (перечислены в каждой спеке). Расхождение с текстом урока — баг. |
| **Движки** | E4 «Ритуал» (цели, стрики), E5 «Журнал» (единая база записей). Если движок ещё не собран — интерактив работает автономно на localStorage, но структура данных совпадает со схемой E5 (см. §3.5). |
| **Персистентность** | Ключ `kn.interactive.<id>.v1` в localStorage + синк в профиль, если пользователь авторизован. Хранится состояние прохождения, ответы мини-игр, выбранные цели. |
| **Адаптив** | Десктоп: две колонки. Мобильный (≤ 600 px): одна колонка, панели складываются в аккордеон, слайдеры крупные (≥ 44 px зона касания). |
| **Доступность** | Все слайдеры управляются клавиатурой (←/→ шаг, Shift — ×10), текущее значение читается вслух (aria-valuetext на русском). Цвета дублируются иконкой/текстом (красный «ноль» = ещё и значок 💀 / подпись «обнулён»). |
| **Телеметрия (общая)** | События: `open`, `step_complete(step)`, `answer(question_id, correct, attempt)`, `mastery_reached`, `goal_set`, `time_spent`. Отправляются батчем. |

## 1. П22 — «Шесть параллельных миров» (СИМ + ИГР)

### 1.1. Паспорт
- **ID:** `p22_parallel_worlds`
- **Урок:** П22 «Альтернативные истории Талеба» (урок 166). Заменяет/дополняет существующий «Генератор альтернативных миров Талеба» — если существующий проще, этот становится основным, старый удаляется.
- **Тип:** СИМ (основной) + ИГР (проверка) + мост в П23.
- **Место в уроке:** сразу после блока «Числа» (сценарии А/Б с 0,99⁵ и 0,8⁵) и перед «Разбор (Нассим Талеб)».
- **Заблуждение:** «Выиграл — значит был прав». Оценивать решение по одному исходу.
- **Что ученик должен унести:** одно и то же решение живёт во множестве возможных миров; решение оценивается по всей совокупности исходов (распределению), а не по тому единственному, что реализовался; вход «на всё без стопа» в большинстве миров = ноль, и повторение гарантирует ноль.

### 1.2. Экран

**Верх — панель решения (3 карточки, переключатель):**

| Карточка | Условия (вход в лонг по мемкоину, горизонт 48 часов) |
|---|---|
| **А «По уставу»** | Риск 1 % депозита. Стоп по цене −5 %, тейк +10 %. Размер позиции = 20 % депозита, без плеча. |
| **Б «Крупно, но со стопом»** | Риск 20 % депозита. Стоп −5 %, тейк +10 %. Позиция = 400 % депозита (плечо ×4). |
| **В «На всё, ×20, без стопа»** | Весь депозит с плечом ×20. Стопа нет. Ликвидация при движении цены −5 % (формула урока 0.16, MMR не учитываем — подпись). Закрытие по горизонту. |

Под карточками мелко: «Комиссии не учитываем: на выводы урока они не влияют, только ухудшают (урок 0.18)».

**Центр — сетка 6 миров (2×3 на десктопе, 1×6 на мобильном).**
Каждый мир — мини-график цены (48 часовых свечей, одинаковые для всех решений!) с наложенными уровнями выбранного решения: линия стопа/ликвидации (−5 %), тейка (+10 %, для А и Б). При проигрыше анимации — свечи рисуются слева направо со скоростью ~0,6 с на мир (все миры параллельно). Момент касания стопа/ликвидации: линия вспыхивает, мир получает статус.

Статус-бейджи (текст + иконка + цвет):
- 🛑 «Стоп, −1 %» / «Стоп, −20 %»
- 🎯 «Тейк, +2 %» / «Тейк, +40 %»
- ⏱ «Горизонт, +0,4 %»
- 💀 «Ликвидация, 0 ₽» (карточка мира затемняется)
- 🚀 «+150 %» (мир подсвечивается золотом)

**Низ — сводная таблица результата по решению** (в рублях от 100 000 ₽ и в %):

| Показатель | А | Б | В |
|---|---|---|---|
| Худший мир | −1 000 ₽ | −20 000 ₽ | **0 ₽ (−100 %)** |
| Лучший мир | +2 000 ₽ | +40 000 ₽ | +150 000 ₽ |
| Медианный мир | … | … | **0 ₽** |
| Средний по 6 мирам | … | … | … |
| Обнулений | 0 | 0 | **5 из 6** |
| Разброс (лучший − худший) | 3 % | 60 % | 250 % |

Строка «Медианный мир» выделена подписью: «Это то, что случилось бы с тобой *обычно*».

**Правая мини-панель «Лента»** (появляется после прогона решения В): одна карточка-пост «🚀 Утроил депозит за 2 дня. Трейдинг — это просто» (мир-везунчик) и пять серых карточек «Не выложил. −100 %». Кнопка «Показать кладбище» раскрывает серые карточки → мост к П23 (ссылка на урок).

### 1.3. Математика и данные

**Генератор пути цены (один на все решения):**
- 48 часовых свечей. Лог-доходность часа `r_h ~ N(0, σ_h)`, `σ_h = 0,12 / √24 ≈ 2,45 %` (дневная волатильность мемкоина 12 % — подпись «мемкоин, урок 0.17»).
- OHLC: `open = prev.close`, `close = open·e^{r_h}`, `low = min(open, close)·(1 − |ε|·0,4·σ_h)`, `high = max(open, close)·(1 + |ε'|·0,4·σ_h)`, `ε, ε' ~ N(0,1)`.
- Касание стопа/ликвидации проверяется по `low`, тейка — по `high`. Если в одной свече задеты оба — **сначала стоп** (worst-case, как бэктест Freqtrade, ссылка FT-09).

**Расчёт результата по решению:**
- А: позиция 0,2 депозита; результат = 0,2·r_price. Стоп → −1 %, тейк → +2 %, горизонт → 0,2·r_48.
- Б: позиция 4,0; стоп → −20 %, тейк → +40 %, горизонт → 4·r_48.
- В: результат = 1 + 20·r_price; если в любой момент `low ≤ P0·0,95` → 0 (ликвидация, необратимо). Иначе горизонт: 1 + 20·r_48 (при r_48 = +7,5 % → +150 % — «мир-везунчик»).

**Два набора миров:**
1. **«Показательный набор»** (по умолчанию) — 6 зашитых сидов, подобранных так, что 5 путей касаются −5 % до +7,5 %, а один (мир № 4) достигает +7,5 %, не коснувшись −5 %. Сиды хранятся в константах; юнит-тест при сборке проверяет свойство набора.
2. **«Случайные миры»** — кнопка перегенерирует 6 сидов. Счётчик обнулений В в этом наборе может быть 3–6. Рядом — подпись, посчитанная фоново на 1 000 случайных миров при загрузке: «В 1 000 случайных мирах решение В обнуляется в NN % (≈ N,N из 6)». Ожидаемое значение ~75–80 %; если Монте-Карло даёт вне диапазона 65–90 % — параметры генератора проверить.

**Этап «Повтори»** (числа из урока, вычисляются по формулам, не хардкодятся):
- Серия из 5 миров-стопов подряд: А `0,99⁵ = 95,1 %` (нужно +5,2 % для возврата), Б `0,8⁵ = 32,8 %` (нужно **+205 %**), В `= 0` уже в первом мире-стопе.
- Кривая выживания В: `P(жив после n раундов) = (1 − p_liq)^n`, где `p_liq` — доля обнулений из Монте-Карло. Слайдер n = 1…12. Подпись: «Из 1 000 Алексеев, каждый раз входящих как В, после 3 раундов останется ≈ N».

### 1.4. Сценарий взаимодействия (шаги с замками)

**Шаг 1 «Один рынок — три решения».**
Открыто решение В (намеренно — оно «яркое»). Кнопка «Прожить 6 миров». После анимации — таблица и «Лента». Подсказка: «Обрати внимание: 5 миров из 6 не выложили скриншот».
Замок: переключить на А и Б **на тех же 6 мирах** (кнопка «Те же миры, другое решение»). Ключевая фраза при переключении, всплывает над сеткой: «Рынок не изменился. Изменилось только решение».

**Шаг 2 «Что ты обычно получаешь».**
Все три решения показаны рядом в таблице. Вопрос-выбор: «Какая строка описывает решение честнее всего?» — варианты: «Лучший мир» / «Медианный мир» / «Средний по мирам» / «Тот, что случился у соседа в соцсети». Правильно: медианный (с пояснением, почему средний по В (+25 %) обманывает: он весь сделан одним миром). 2 попытки.

**Шаг 3 «Повтори — и умри».**
Панель с формулами 0,99⁵ / 0,8⁵ и слайдером n для В. Задача: «Найди n, при котором из 1 000 Алексеев остаётся меньше 10» (ответ автоматически засчитывается, когда ученик доводит слайдер).

**Шаг 4 — ИГР «Оцени решение, а не исход».**
6 карточек по одной: показано решение и итог; ученик жмёт «Хорошее решение» / «Плохое решение». Знак результата в карточке специально крупный (провокация).

| № | Карточка | Верный ответ | Комментарий обратной связи |
|---|---|---|---|
| 1 | Риск 1 %, стоп стоял, закрылась по стопу **−1 000 ₽** | Хорошее | «Качественное решение с плохим исходом. Таких сделок в системе 40–60 %». |
| 2 | Весь депозит, ×20, без стопа, **+150 000 ₽** | Плохое | «Ужасное решение с хорошим исходом. В 5 мирах из 6 это ноль». |
| 3 | Риск 1 %, стоп, тейк **+2 000 ₽** | Хорошее | «Так выглядит обычная работа системы — скучно и правильно». |
| 4 | Весь депозит, без плеча, без стопа, **−35 000 ₽** | Плохое | «Даже без плеча: нет стопа — нет границы худшего мира». |
| 5 | Риск 20 %, стоп есть, тейк **+40 000 ₽** | Плохое | «Стоп был, но размер вне устава (1–2 %). Пять таких стопов подряд = −67 %». |
| 6 | Риск 1 %, стоп убран руками на −3 %, вышел в **0 ₽** | Плохое | «Правило нарушено; результат — везение. Запись в журнал вмешательств (П1)». |

Обратная связь после каждой: правильно/неправильно + одна строка. После всех шести: «Ты оценивал N/6 по решению, а не по знаку». 
**Критерий освоения: ≥ 5/6 с первой попытки** (иначе — карточки перемешиваются, второй круг; засчитывается 6/6 на втором круге).

**Шаг 5 (финал, 1 экран).** Итоговая формула: «Решение = распределение исходов. Исход = один бросок». Кнопка «Записать в журнал»: создаётся запись E5 категории `решение_vs_исход` с текстом-шаблоном «Сегодня я оценил результат, а не решение, когда…» (поле свободное, необязательное).

### 1.5. Языковой слой
Термины с карточками: *плечо*, *ликвидация*, *стоп*, *тейк*, *медиана* (ссылка М26), *везучий дурак (Lucky Fool)*, *альтернативные истории*. Никаких «PnL/equity» на экране — «результат», «капитал».

### 1.6. Технические требования
- Компонент `<ParallelWorldsSim lessonId="p22" deposit={100000} />`.
- Состояние: `{ decision: 'A'|'B'|'C', seedSet: 'demo'|number[], worlds: WorldResult[6], step: 1..5, quizAnswers: [], mcStats: {pLiq, n} }`.
- `WorldResult = { seed, candles: OHLC[48], results: { A: {pct, event, hour}, B: {...}, C: {...} } }`.
- Монте-Карло 1 000 миров — в Web Worker или `requestIdleCallback`, ≤ 300 мс на среднем ноутбуке; UI не блокируется.
- Анимация — canvas или SVG с `requestAnimationFrame`; на мобильном длительность прогона ≤ 4 с; кнопка «Пропустить анимацию».
- Экспорт: кнопка «Скопировать сиды» (для воспроизведения).

### 1.7. Приёмочные тесты
1. Показательный набор: ровно 5 обнулений В, мир № 4 → +150 % (±5 п.п. допуск округления).
2. Один и тот же набор сидов даёт для А худший −1 %, лучший +2 %; для Б −20 % / +40 %.
3. В мире, где В ликвидирован, А и Б **обязательно** закрыты по стопу (совпадение события «касание −5 %»).
4. Свеча с касанием и стопа, и тейка → зафиксирован стоп.
5. `0,99⁵` и `0,8⁵` выводятся как 95,1 % и 32,8 %; «нужно +205 %» рассчитано как `1/0,328 − 1`.
6. Монте-Карло `pLiq` ∈ [0,65; 0,90]; подпись «≈ N,N из 6» = `pLiq·6`.
7. Замок шага 4 не открывается при 4/6.
8. Мобильный: все 6 миров прокручиваются, таблица горизонтально скроллится, слайдер n доступен пальцем.
9. Клавиатура: переключение решений Tab/Enter; ответы мини-игры — 1/2.

## 2. П30 — «Дюймовый червь»: ползунок «худший день» и средняя линия

### 2.1. Паспорт
- **ID:** `p30_inchworm_v2` (расширение существующего «Дюймовый червь: рост мастерства»; если старый — статичная картинка, заменить целиком).
- **Урок:** П30 (урок 174). Место — после «Глубже» (три шага: описать A-game, C-game, цель на месяц).
- **Тип:** СИМ + РИТ (цель на месяц через E4).
- **Заблуждение:** «Расти = поднимать лучший день». Дополнительно: «Подниму лучший день, увеличив размер» (тянет за собой худший).
- **Что унести:** средняя линия и годовой итог поднимаются от подтягивания хвоста сильнее и надёжнее, чем от толкания головы; голова ограничена рынком, хвост — правилами; размер позиции двигает оба конца одновременно.

### 2.2. Экран

**Левая панель — «Червь».**
Горизонтальная ось «Результат дня, % депозита» от −20 % до +10 %. Тело червя — гистограмма 250 торговых дней (полупрозрачная) + контур: хвост (левый край = «Худший день», подпись «C-game — худшая игра»), голова (правый край = «Лучший день», «A-game — лучшая игра»). Вертикальная пунктирная линия **«Средний день»** с числом (например, −0,25 %). Вторая линия **«Годовой итог»** — не на этой оси, а в цифре над червём: «100 000 ₽ → 53 800 ₽ за год» (медиана по симуляции).

Под осью два слайдера:
- **Худший день**: −20 % … −1 %, шаг 0,5 (по умолчанию −8 %).
- **Лучший день**: +1 % … +8 %, шаг 0,5 (по умолчанию +4 %). Зона выше +5 % заштрихована серым с подписью «Рынок редко даёт больше — это не в твоей власти»; слайдер туда двигается, но подпись остаётся.

**Правая панель — «Год Алексея».**
Кривая капитала за 250 дней: жирная — медианная траектория, тонкие серые — 20 случайных траекторий (фиксированный сид), красная зона — 5-й процентиль. Три числа: «Средний день», «Разброс дней (σ)», «Год (медиана)».

**Блок «Предохранители» (чекбоксы, между панелями):**
- ☐ «Стоп в каждой сделке» → худший день не хуже −4 %
- ☐ «Дневной лимит убытка −2 %» → худший день не хуже −2 % (ссылка 5.6)
- ☐ «Стоп-тильт: 2 стопа подряд → стоп-день» → худший день не хуже −3 % (ссылка П14)
Включённый предохранитель рисует «перила» на хвосте: слайдер «Худший день» можно тянуть левее, но значение зажимается (`worst = max(slider, clamp)`), а ползунок визуально упирается в перила с подписью «Правило держит хвост».

**Панель «Подробнее: как ты поднимешь голову?»** (свёрнута по умолчанию):
Слайдер «Размер позиции ×m» 0,5…3,0. При изменении **все** значения дней (голова, тело, хвост) умножаются на m. График «Годовой итог в зависимости от m» — кривая с максимумом (или монотонно убывающая при отрицательном среднем). Подпись: «Голову и хвост держит одна верёвка — размер. Тянешь голову — уезжает хвост» (мост к М47, Келли).

### 2.3. Математика

**Распределение дня** (250 дней, фиксированный сид, 200 траекторий для процентилей):
- Доли: A-дни 15 %, B-дни 70 %, C-дни 15 %.
- A-день: `U[0,5·best; best]`.
- B-день: `N(0,2 %; 0,8 %)`, клип [−2 %; +2 %].
- C-день: `U[worst; 0,4·worst]`.
- **Средний день (аналитически, без симуляции, чтобы линия двигалась мгновенно):**
  `μ = 0,15·0,75·best + 0,70·0,2 % + 0,15·0,7·worst`.
  Проверка: best = +4 %, worst = −8 % → μ = 0,45 + 0,14 − 0,84 = **−0,25 %**.
- Дисперсия — по симуляции; приближение геометрического роста для подписи: `g ≈ μ − σ²/2` на день; год ≈ `100 000·e^{250·g}` (для тултипа «почему разброс съедает»). Основная цифра «Год» — медиана 200 симулированных траекторий.
- Режим «размер ×m»: все дни ×m → `μ_m = m·μ`, `σ_m = m·σ`.

**Два стандартных эксперимента** (кнопки-пресеты, результаты запоминаются в таблицу сравнения):
- **Э1 «Толкнуть голову»**: best 4 → 6 % (worst −8 %). Ожидаемо μ ≈ −0,03 %, σ растёт, год ≈ около 95–100 тыс. или ниже.
- **Э2 «Подтянуть хвост»**: worst −8 → −3 % (best +4 %). Ожидаемо μ ≈ +0,28 %, σ падает, год заметно выше (порядок 180–200 тыс.; точное значение — из симуляции, не хардкодить).
Таблица: строки μ / σ / Год / «на сколько пунктов сдвинул ползунок». Итоговая подпись: «Хвост дал +X ₽, голова дала +Y ₽. При этом хвост — в твоей власти (правила), голова — во власти рынка».

Важно для честности: агент не должен подгонять параметры так, чтобы «хвост всегда выигрывал» независимо от чисел — выигрыш объясняется двумя причинами, обе показываются: (1) хвост можно подтянуть на большую дистанцию, чем голову (перила правил vs потолок рынка); (2) подтягивание хвоста уменьшает разброс, толкание головы — увеличивает, а разброс съедает сложный процент (тултип с `μ − σ²/2`, ссылка 0.12/М47).

### 2.4. Сценарий взаимодействия

**Шаг 1 «Знакомство».** Червь на дефолтах, Алексей в минусе за год. Подсказка: «Лучшие дни +4 %, а год в минусе. Почему?» — ученик двигает любой ползунок 10 секунд свободно.

**Шаг 2 «Два эксперимента».** Кнопки Э1 и Э2 (можно двигать и вручную — результат записывается по кнопке «Зафиксировать»). Замок: оба эксперимента зафиксированы.
Вопрос: «Что сильнее поднялo годовой итог и почему?» — варианты:
а) «Голова: большие плюсы делают год» 
б) «Хвост: он и среднюю поднял, и разброс снял, и он в моей власти» ✓ 
в) «Одинаково, разница в цифрах случайна».
При ошибке — открывается тултип с σ до/после и повтор вопроса.

**Шаг 3 «Одна верёвка».** Раскрывается панель «размер ×m». Задание: «Попробуй поднять лучший день до +8 % размером позиции». Ученик тянет m → голова растёт до +8 %, хвост уезжает к −16 %, год падает. Автоподпись при m ≥ 2: «Голова +8 %, но хвост −16 %: год стал хуже. Это и есть иллюзия „расти = поднимать лучший день“».

**Шаг 4 «Перила» (РИТ).** Ученик включает предохранители, видит перила. Затем блок из урока:
- поле «Моя A-game: как я действую в лучшие дни» (1–3 строки),
- поле «Моя C-game: 2–3 паттерна срыва» (чипы-подсказки: «вход без сигнала», «убрал стоп», «ночная правка», «отыгрыш», «увеличил размер после плюса», «своё»),
- **цель на месяц**: «Ни одного дня хуже −__ %» (значение по умолчанию = текущее worst с перилами). Кнопка «Поставить цель» → E4 создаёт ежедневный ритуал «Вечерняя галочка: был ли день хуже −X %? да / нет / не торговал» на 30 дней со стриком; C-паттерны становятся чипами категорий в дневнике искажений E5 (П44).
**Критерий освоения:** ответ на вопрос шага 2 + записаны ≥ 2 паттерна C-game + цель поставлена.

### 2.5. Тексты обратной связи (ключевые)
- При worst ≤ −12 %: «Один такой день требует +14 % для возврата (0.12). Три таких дня — год потерян».
- При best ≥ 6 %: «Ты можешь нарисовать такой день ползунком. На рынке его назначает не ползунок».
- При включении «Дневной лимит −2 %»: «Это правило из устава 5.6. Оно не улучшает лучшие дни — оно отрезает худшие. Средняя выросла на …».

### 2.6. Технические требования
- Компонент `<InchwormSim lessonId="p30" deposit={100000} />`.
- Пересчёт μ — синхронно при каждом движении (< 1 мс). Симуляция 200 траекторий × 250 дней — при отпускании ползунка (debounce 120 мс), в Worker при необходимости; на мобильном допускается 100 траекторий.
- Состояние: `{ best, worst, guards: {stopEach, dailyLimit, stopTilt}, sizeMult, experiments: {E1?, E2?}, aGame, cGamePatterns[], goal: {threshold, ritualId} }`.
- Интеграция E4: `createRitual({ type: 'daily_check', title, threshold, days: 30 })`; E5: `addChipCategories(cGamePatterns)`.

### 2.7. Приёмочные тесты
1. Дефолт: μ = −0,25 % (±0,01), год < 100 000 ₽.
2. Э2 даёт μ ≈ +0,28 %, σ_Э2 < σ_default; Э1 даёт σ_Э1 > σ_default.
3. Год(Э2) > Год(Э1) на медиане и на 5-м процентиле.
4. Включённый лимит −2 % при ползунке −8 % → фактический worst = −2 %, перила отрисованы, μ пересчитана.
5. m = 2 при дефолте: голова +8 %, хвост −16 %, год хуже дефолта.
6. Один сид → одинаковые траектории при повторном открытии.
7. Цель создаёт ритуал в E4 (или локальную запись) и отображается в «Мои ритуалы».
8. Мобильный: слайдеры на разных строках, червь читаем при ширине 360 px.

## 3. П48/П49 — «Четыре шкалы профессионала» (ВИЗ) + размер по уровню доказательств

### 3.1. Паспорт
- **ID:** `p48_49_four_scales`
- **Уроки:** П48 «Формула Альфа-Трейдера» (урок 192) и П49 «Трёхуровневая модель убеждённости» (урок 193). Один интерактив с двумя вкладками, встраивается в оба урока (в П48 открыта вкладка «Шкалы», в П49 — «Размер»).
- **Тип:** ВИЗ по данным журнала (E5) + ТРН (калькулятор размера).
- **Заблуждения:** П48 — «Ум компенсирует недисциплинированность» / «профессионализм — одно число». П49 — «Чувствую уверенность → беру больше».
- **Что унести:** четыре качества независимы, итог ограничен слабейшим; размер позиции — функция доказательств и ограничений, а уверенность — предмет калибровки, а не аргумент.

### 3.2. Источники данных
Интерактив читает из E5 (или демо-профиля):

```
trades[]        { date, setupType, convictionTier: 1|2|3|null, plannedR, actualR,
                  ruleBased: bool, violations: string[], sizeR, subjectiveConf?: 0.5..0.95 }
weeks[]         { weekStart, processOk: bool, violations: string[], regimeTag: 'тренд'|'флэт'|'шторм' }
interventions[] { date, factNamed: bool }            // П1
forecasts[]     { date, p: 0..1, outcome: 0|1 }      // П25 (Brier)
biasEntries[]   { date, category }                   // П44
meta            { dryRunDays, charterMaxR: 2 }
```

**Переключатель «Мои данные / Демо-профиль».** Демо-профили (жёстко зашитые наборы записей, а не готовые баллы — баллы считаются той же функцией):
- «Алексей, 3 месяца dry-run»: рациональность ~72, опыт ~38, добросовестность ~81, калибровка — «мало данных».
- «Умный любитель» (иллюстрация парадокса П48): ~90 / ~60 / ~45 / ~40.
- «Ветеран»: ~75 / ~95 / ~92 / ~80.
Если у ученика < порога записей по шкале — шкала серая «Недостаточно данных: нужно ещё N записей», и подсказка, какой ритуал их даёт.

### 3.3. Формулы шкал (0–100, все округления до целых)

**Рациональность** (порог: ≥ 20 записей журнала решений):
`R = 100 · (доля решений с ruleBased = true) − штраф_искажений`, где штраф = 5 за каждую категорию из biasEntries, встретившуюся ≥ 2 раз за одну неделю в последние 4 недели, максимум −20.

**Опыт** (порог: ≥ 10 сделок):
`O = 100 · clamp(log10(N_trades) / log10(300), 0, 1) · (0,5 + 0,5 · min(режимов_видено, 3) / 3)`,
где режимов_видено — число различных `regimeTag` в weeks. 300 сделок через 3 режима = 100; 30 сделок в одном режиме ≈ 33. Рядом — «ширина интервала средней сделки ±σ/√n в R» (ссылка М30/М43).

**Добросовестность** (порог: ≥ 4 недели с двойной отметкой):
`D = 100 · (доля сделок без violations) − 10 · (число вмешательств с factNamed = false за 8 недель)`, минимум 0; при этом неделя с `processOk = false` помечает все её сделки как нарушение независимо от результата (правило R5 «прибыльная неделя с нарушением — красная»).

**Калибровка** (порог: ≥ 30 прогнозов или ≥ 30 сделок с convictionTier):
Источник 1 — forecasts: `Brier = mean((p − outcome)²)`. Источник 2 — сделки с tier: tier → заявленная p: 1 → 0,55, 2 → 0,65, 3 → 0,75; outcome = actualR > 0. Объединённый Brier по всем наблюдениям.
`K = 100 · clamp(1 − Brier / 0,25, 0, 1)` (Brier 0,25 = «монетка» → 0).
Дополнительно строится **таблица калибровки**: заявленная уверенность (корзины 50–60, 60–70, 70–80, 80–95 %) → фактическая частота успеха → ∆. Строка с ∆ ≤ −10 п.п. подсвечивается: «Твоя „80 %“ сбывается в 61 % — это переоценка».

**Итог по Доннелли:** `Итог = min(R, O, D, K)` — крупно, с подписью «Слабое звено». Рядом мелко «Среднее = …» и фраза: «Среднее — иллюзия: ум не компенсирует дисциплину». Если какая-то шкала «недостаточно данных» — Итог считается по доступным, но помечается «предварительно».

### 3.4. Вкладка «Шкалы» — экран

Четыре горизонтальные полосы с зонами (0–40 красная «риск», 40–70 жёлтая «рабочая», 70–100 зелёная «профи»), метка значения, слева название по-русски, справа иконка «?» → карточка: формула словами + «Из каких записей журнала это посчитано» (список последних 5 записей, клик открывает E5).

Под полосами — блок **«Слабое звено: <название>»** с одной рекомендацией-ритуалом:
- Рациональность → R1 «Два вопроса перед касанием», R9 «Дневник искажений».
- Опыт → «Только время и сделки: продолжай dry-run; максимум 0,5R до 100 сделок».
- Добросовестность → R5 «Двойная отметка недели», R7 «Устав как код», П46 внешний предохранитель.
- Калибровка → П25 «Калибратор: 3 микро-прогноза в день» (кнопка «Включить» создаёт ритуал в E4).

**Мини-игра «Кто из них?»** (3 карточки-профиля, включая «Умного любителя»): «У кого из троих журнал показывает: R 90, O 60, D 45, K 40. Какой итог по Доннелли?» — варианты 90 / 59 (среднее) / 40 ✓. Обратная связь: «Умный трейдер с добросовестностью 45 теряет деньги из-за несоблюдения собственных правил — это и есть Великий парадокс».

### 3.5. Вкладка «Размер» — калькулятор по уровню доказательств (П49)

**Верх — карточка сделки.** Поля: пара (текст), стоп-дистанция % (число, 1–15), тип сетапа (выпадающий из setupType журнала + «новый»). Переключатель **«Сделка уже открыта»**: если включён — весь калькулятор становится только для чтения с плашкой «Размер не меняется в разгар сделки (П49, П51). Пересчёт — на разборе».

**Середина — чек-лист доказательств** (чекбоксы, каждый со ссылкой на урок):

| Код | Формулировка | Роль |
|---|---|---|
| Д1 | Есть сигнал по моей системе (условие входа выполнено) | обязательный; без него размер = 0, кнопка «Не входить» |
| Д2 | Второй **независимый** фактор подтверждает (другой таймфрейм / режимный фильтр / данные, не производные от первого) | повышает ярус |
| Д3 | Режим рынка соответствует стратегии (П34) | повышает ярус |
| Д4 | Ликвидность: выход не дороже плана, размер < 1 % дневного объёма пары, спред нормальный (П45) | **стоп-фактор** |
| Д5 | Низкая корреляция с уже открытыми позициями (FT-18) | **стоп-фактор** |
| Д6 | Не в просадке ниже порога устава, нет серии стопов ≥ 3 (П14, FT-17) | **стоп-фактор** |
| Д7 | Этот тип сетапа есть в журнале ≥ 30 сделок с известной частотой успеха | повышает до максимального яруса |

**Логика яруса:**
- Д1 = нет → «Не входить».
- Любой стоп-фактор (Д4/Д5/Д6) не отмечен → потолок **0,5R** с подписью «Стоп-фактор: <какой>».
- Д1 только → **0,5R** («одна техническая идея»).
- Д1 + Д2 + Д3 → **1R** («подтверждённая логика»).
- Д1…Д7 все → **до charterMaxR** (по умолчанию 2R; подпись «Максимум задаёт устав, не качество идеи»).

**Ворота из вкладки «Шкалы»** (применяются автоматически, показываются как отдельная строка «Ворота профессионализма»):
- Добросовестность < 70 → потолок 0,5R («Сначала процесс, потом размер»).
- Опыт < 40 → потолок 0,5R; 40–70 → потолок 1R.
- Калибровка < 50 или «мало данных» → ярус 3 приравнивается к ярусу 2 (нет надбавки за чувство).

**Слайдер «Насколько ты уверен?» 50–95 %** — отдельно, с бейджем «Не участвует в расчёте». Под ним живая строка из таблицы калибровки: «В журнале твоя уверенность 80–95 % сбывалась в NN %». Если данных нет: «Пока неизвестно — включи калибратор П25».

**Результат** (крупно):
- «Размер: **1R = 1 000 ₽ риска**» (1R = 1 % депозита Алексея; берётся `charter.riskPerTradePct`, если есть).
- «Позиция: 1 000 ₽ / стоп 4 % = **25 000 ₽**» (формула из 3.3: риск / дистанция до стопа).
- Строка «Почему не больше»: перечисление всех ограничений, которые сработали (ярус, ворота, стоп-факторы).
Кнопка «Сохранить карточку сделки» → запись E5 `tradePlan` с тиром, факторами, заявленной уверенностью (она потом пойдёт в калибровку).

**Тренажёр (3 задачи с проверкой):**
1. «Один сигнал, ликвидность тонкая» → ожидаемо 0,5R и подпись про стоп-фактор.
2. «Сигнал + подтверждение + режим, ты чувствуешь 90 %» → 1R; ученик, выбравший 2R, получает: «90 % — это чувство. Д7 не отмечен: у этого сетапа нет истории».
3. «Все семь факторов, но добросовестность за месяц 62» → 0,5R; пояснение «Ворота: размер растёт только после того, как процесс подтвердил устойчивость (П48)».
**Критерий освоения:** 3/3 в тренажёре + мини-игра «Кто из них?» + один раз открыта карточка «?» любой шкалы.

### 3.6. Языковой слой
Карточки: *R (единица риска)* — обязательно с русской формулой «1R = сумма, которую теряю по стопу»; *Brier (оценка точности прогнозов)*; *калибровка*; *ярус убеждённости*; *стоп-фактор*; *корреляция*. Слово «conviction» на экране не появляется.

### 3.7. Технические требования
- Компонент `<FourScales lessonId="p48"|"p49" defaultTab="scales"|"sizing" />`.
- Модуль расчёта шкал — чистая функция `computeScales(journalSnapshot) → { R, O, D, K, weakest, meta }` с юнит-тестами на демо-профилях; та же функция используется в П33 «Дашборд качества» (Process Score = D) и в R5.
- `computeTier(factors, gates, charter) → { tierR, reasons[] }` — чистая функция, тестируется таблицей случаев.
- Обновление при изменении журнала — подписка на E5 (`onJournalChange`); дебаунс 500 мс.
- Персистентность карточек сделок — через E5; локальный черновик — localStorage.
- Производительность: пересчёт по 1 000 сделок < 50 мс.

### 3.8. Приёмочные тесты
1. Демо «Умный любитель»: `min = 40`, среднее 58,75 → отображено 59; мини-игра принимает только 40.
2. Пустой журнал: все шкалы серые, Итог — «нет данных», калькулятор работает с воротами по умолчанию (потолок 0,5R) и подписью «Пока журнал пуст — 0,5R».
3. Неделя `processOk=false` с прибыльными сделками → сделки считаются нарушением, D падает.
4. Вмешательство `factNamed=false` ×3 → D снижена на 30.
5. Brier = 0,25 → K = 0; Brier = 0,10 → K = 60.
6. Опыт: 300 сделок, 3 режима → 100; 30 сделок, 1 режим → 33 (±1).
7. Калькулятор: Д1 выкл → «Не входить»; Д1..Д7 вкл + D=81, O=95, K=80 → 2R; те же факторы + D=62 → 0,5R с причиной «ворота: добросовестность».
8. Слайдер уверенности не влияет на `tierR` ни при каких значениях.
9. Тумблер «Сделка уже открыта» блокирует все поля и кнопку сохранения.
10. Позиция = риск₽ / стоп%: при стопе 4 % и 1R = 1 000 ₽ → 25 000 ₽; при стопе 2 % → 50 000 ₽, при этом появляется предупреждение, если позиция > 50 % депозита («проверь ликвидность и корреляцию»).
