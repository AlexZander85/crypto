## 1. Учебные константы (вынести в общий `constants.json`, чтобы уроки и вопросы брали одно и то же)

```
BTC_PRICE        = 100 000 $      ETH_PRICE = 2 700 $
USD_RUB          = 90 ₽/$         (в стеме всегда «по учебному курсу 90 ₽/$»)
TAKER_FEE        = 0,10 %         MAKER_FEE = 0,02 %
SLIPPAGE_SIDE    = 2 б.п.         ROUND_TRIP_COST = 24 б.п. (0,1 % + 2 б.п.) × 2
FUNDING_BASE     = 0,01 % / 8 ч   (3 начисления в сутки, 30 дней в месяце, 365 в году)
MMR              = 0,5 % или 1 % — всегда указывать в стеме
RISK_PER_TRADE   = 1 %            DAILY_LIMIT = 2 %
ED_CORRIDOR      = <10 % норма · 10–25 % серая · >25 % стоп
ANNUALIZATION    = √365 (крипта), не √252
1 б.п.           = 0,01 %
```

Правила ответа для движка: поле ввода принимает запятую и точку; единица измерения показывается справа от поля и не вводится; допуск — абсолютный, указан у каждого вопроса; отрицательные ответы вводятся со знаком «−», стем всегда говорит «со знаком». Округление в стеме задаётся явно («до целых», «до десятых»).

Формат записи ниже: `ID · категория · урок-источник · тип` (П — применение, Пер — перенос между темами) → условие → **ответ (допуск)** → разбор → *ловушка* (что покажет объяснение при неверном ответе).

## 3. Линтер для числовых вопросов (дополнение к §7 части 4)

1. У каждого вопроса заполнены `answer`, `unit`, `tolerance_abs`, `rounding_hint` в стеме («до десятых»), `sign_required` (если ответ может быть отрицательным, стем содержит «со знаком»).
2. Все числа стема либо берутся из `constants.json`, либо явно указаны в стеме — никаких «типичная комиссия» без цифры.
3. Ответ вычисляется автотестом из формулы в поле `formula` — ключ не хранится руками (ловит ошибки вроде «$27» и «24,5 %»).
4. Для каждого понятия в банке ≥ 2 варианта с разными числами; викторина урока и аттестация никогда не берут один и тот же ID.
5. Поле `trap_answer` (типичный неверный ответ) заполнено там, где он есть — при вводе именно его ученик получает целевое объяснение, а не общее «неверно».
6. В стеме русский термин первым, английский — в скобках один раз (Execution Deviation → «отклонение исполнения (Execution Deviation)»; VaR/CVaR — оставить, они введены в 1.2 как термины).
7. Порог аттестации по числовым — не «80 % верно», а «нет ошибок в понятиях-предохранителях»: ликвидация, размер позиции от стопа, дневной лимит, лимит на контрагента. Ошибка в любом из них возвращает тему через 2 дня другим вариантом.
