## 2. Ключевые проектные решения

1. **Два счётчика вместо одного.** Сессионный `S.quizAttempts` (Этап 1) не тронут: метка «Попытка N» и подсказка после 2-й ошибки работают в рамках сессии (§12.6 — «на зачёт и геймификацию не влияет», семантика приёмки Этапов 1/3 сохранена). Персистентный накопитель `cn_learn_mist` существует **только для рекомендации** и читается на финале. Принято во внимание: после сдачи квиз блокируется навсегда (`cn_lesson_checks.quizDone`) — накопитель фиксирует борьбу ученика **до** прохождения, что и является сигналом «тема далась непросто».
2. **Паритет по построению, а не по репликации логики.** Хук инкремента — дополнительный слушатель на том же `stepEl`, добавленный обёрткой `attachStepDelegates` ПОСЛЕ родного; срабатывает после родного `setTimeout(0)`, использует тот же `quizPassed()`. Независимого подсчёта нет — расхождение исключено (проверено приёмкой: sess и total растут синхронно).
3. **Карточка финала — полная замена, без строковой хирургии.** Обёртка `lp3CourseFinaleHtml` на время её вызова синхронно глушит `S.quizAttempts[lid]` (Этап 3 рисует свою карточку по сессии), восстанавливает значение, затем добавляет свою карточку по накопителю. Дублей нет (приёмка: ровно 1 карточка), HTML не парсится.
4. **Сброс по CTA = «намерение зафиксировано».** Если ученик нажал «Пройти адаптивную тренировку», накопитель обнуляется независимо от того, довёл ли он сессию до конца (prepost-опрос может быть отменён «Пропустить» — существующая семантика приложения). Альтернатива — сброс после фактического старта сессии — потребовала бы вмешательства в адаптивный контур (§11.9).
5. **Контекст наставника — через payload, а не через правку наставника.** `MENTOR.ask` — публичный API (`window.MENTOR`); payload `{ step, stepTitle, stepText, source }` уходит в существующуюendpoint-логику; mock-режим и лимиты работают без изменений. Авто-контекст включается только когда плеер открыт в режиме урока (`S.active && !TS.active`): вызовы приложения (ридер и пр.) при закрытом плеере дают панель «как раньше», тестовый режим Этапа 2 — панель с контекстом урока без шаговой карточки (порции — вопросы, а не материал).
6. **Апселл z-фикс — сознательное снятие прежней оговорки.** ТЗ §6 фиксировал апселл (z 100 000) под плеером как крайний случай «не чинить». Встройка наставника в поток шагов делает этот случай штатным сценарием: кнопка «💬 Наставник» в demo-тире должна давать видимый отклик. Подъём выполнен разрешённым §6 способом (CSS-фикс `!important` в стиле плеера, без правок чужого JS), по образцу `#termModal` → 1000500.

2. **`mentor_cache_*`** — существующий v10-кэш наставника (TTL 10 мин/1 ч) пишется любым вызовом `MENTOR.ask`, включая новые подсказки по шагу; лимиты и TTL — существующие.
3. **Именование уроков фаз 7–9** — каталог использует `ps_*`/`ft*` (p7_l1/p8_l1/p9_l1 в LESSONS отсутствуют); проверено дампом, автопрогон скорректирован.

## 7. Известные ограничения и предложения

1. Накопитель ведётся только по аттестационным квизам уроков (паритет с Этапом 1); неверные ответы фазовых тестов/экзаменов (Этап 2) и психо-дриллов в рекомендацию не входят — при желании расширяется тем же паттерном (`cn_learn_mist` → общий ключ `lp4:tests`).
2. Сброс по CTA фиксирует намерение, а не факт завершения адаптивной сессии (см. решение 2.4) — если продукт захочет строгую семантику, точка расширения — существующий `onAdaptiveSessionStart`, если появится в контуре.
3. Шаговый контекст наставника передаётся текстом (≤420 символов) через payload; серверная подсказка использует его, если подключена соответствующая логика промпта — в mock-режиме ответ демонстрационный (честно помечен).
4. Бэклог: экспорт конспекта в файл (Э3), «недавние» для тестов, ридер-фиксы (№1, 2, 6, 7), персистентность `_ptStart` (№13).
