- **Персистентность `_ptStart` (№13).** Спидран-таймер фазовых тестов жил только в памяти страницы: после перезагрузки стартовал заново, занижая время попытки. Новый LS-ключ `cn_pt_start` = `{phaseNum: startTs}`: читается при рендере теста в ридере и при resume плеера (таймер продолжается со сохранённого старта), пишется при старте новой попытки и обнуляется после сдачи.
- **Накопитель на тестовые банки.** Персистентный счётчик ошибок `cn_learn_mist` (Этап 4) расширен на тестовые банки: при сдаче фазового теста/мат-теста/капстоуна неверные ответы попытки (`total − correct`) прибавляются к счётчику банка (ключ — testId: `p0`…`exam_capstone`, `math_core`…). Диагностики (`literacy`, `psy_cum`) не считаются — паритет с `lp3FirstUnpassedBank` («диагностика — не несдано»). Подсчёт по факту сдачи: правки ответов в черновике не раздувают счётчик. На экране результата — карточка «🔄 Тест дался непрочно (N неверных ответов за попытку) (всего M с учётом прошлых попыток)» при накопленном ≥3 с CTA на существующий адаптивный контур (сброс именно тестового счётчика) и «Не напоминать».

## 2. Ключевые проектные решения

1. **Ридер-фиксы — минимальные и точечные.** Каждая правка — одна логическая операция с комментарием-меткой `№…` прямо в коде (см. §3); ни одна правка не меняет контент уроков, банки или семантику зачётов. Поведение «до/после» зафиксировано пробами: 426 открытий уроков @35 мс на v12.6 давали 11 ошибок консоли, на v12.7 — 0.
2. **Накопитель тестов — тот же ключ, честная единица измерения.** Уроки считают неверные *попытки* квиза (§12.6), тесты — неверные *ответы* сданной попытки: единица следует за механикой (у теста черновик с правками ответов, пособытийный подсчёт раздувал бы счётчик). Порог карточки единый (≥3 по накопленному итогу), пометка «с учётом прошлых попыток» — по образцу Этапа 4.
3. **Пересдача не обнуляет борьбу.** Как и у уроков (квиз блокируется после сдачи, счётчик остаётся до CTA), у тестов накопитель живёт до нажатия CTA или «Не напоминать» — проходная пересдача не стирает сигнал «тема далась непрочно».
4. **Две точки входа «недавних» закрыты без дублей.** Внутренняя связка `openTest` переприсваивается внутри IIFE (ловит пикер 🏁), window-обёртка ставится поверх существующей цепочки Этапа 3 (ловит хаб/финалы); вызовы через window проходят мимо внутренней обёртки (цепочка держит ссылку на исходную функцию) — ровно один push на открытие (проверено приёмкой: порядок `[math_core, p1]`).
5. **`cn_pt_start` — общий ключ ридера и плеера.** Формат `{phaseNum: ts}` повторяет семантику `window._ptStart` (0 = попытка завершена); ридер восстанавливает старт при перезагрузке, плеер — при resume (устранён задокументированный «ghost» Этапа 2), после сдачи обе поверхности пишут 0 — следующая попытка стартует с нуля.
6. **Экспорт — через штатный markdown-генератор.** Новый код не дублирует форматирование: файл строит тот же `lp3NotesMarkdown()`, что и кнопка «Скопировать» — расхождение форматов исключено.

## 6. Известные ограничения

1. **Порядок «недавних тестов»** — история открытий, не попыток: повторное открытие поднимает карточку наверх, сдача теста сама по себе запись не создаёт (открытие уже в истории).
2. **Карточка рекомендации теста** показывается на каждом экране результата, пока накопленное ≥3 (сброс — CTA или «Не напоминать»); это поведение зеркалит финал урока Этапа 4.
3. **`nqDone`** отмечает факт начисления капитала за `numericQuiz` на профиль; при сбросе прогресса приложения (`cn_lesson_checks`) начисление выполнится заново — согласовано с семантикой остальных зачётов этого ключа.
4. **Селект уровней** (№2) персистентен в рамках сессии страницы — как и задумано исходным кодом ридера; межсессионное сохранение уровня не вводилось (в ридере для этого нет исторического ключа).
5. Унаследованные допущения приёмки сохраняются: `ERR_FILE_NOT_FOUND` (отсутствующие `assets/infographics/img-*.jpg`) и спорадическая гонка rAF/close `renderStep` Этапа 1 (правка запрещена дифф-контрактом Этапа 1; на жёстких автопрогонах воспроизводится и на v12.5).
