## 2. Задача A — `V16-CONTENT-USAGE-REGISTRY.md`: полный реестр экспертного контента

**Единица реестра = минимальный осмысленный блок контента** (не файл, а его часть). Реестр
строится сверху вниз: волны → файлы → единицы. Обязательное покрытие:

| Источник (волна/файл) | Единицы реестра |
|---|---|
| fable.md…fable9.md (тексты уроков, все волны) | каждый урок по id (номер/заголовок/объём/модуль); двойные редакции (2.3/2.4/2.5 и др.) — отдельными строками с пометкой, какая редакция канон (по заметкам редактору) |
| ТЗ-1 (603 позиции банков) | каждый банк по файлам `content/03-quizzes/` + счёт позиций; батчи перезаписей |
| ТЗ-2 (fable_viget.md, 48 виджетов) | каждый W-XX + 3 общих слоя + факт фикса W-35 + судьба W-47 (Б10) |
| ТЗ-3 spec/spec2/spec3 (88 спек + 8 двигателей + языковой слой + E4-каталог 15+7 шаблонов) | каждая спека (FT-xx/FAI-xx/W-E) + каждый двигатель + каждый шаблон ритуала + каждый компонент A–E + seed-токены Lexicon (245+) |
| fable_kriptik.md (29 KR-карточек) | каждая KR-карточка + приложения (промпты/форматы/банк реплик) |
| fable8.md (12 уроков матфака) | каждый урок + каждая из 12 карточек виджетов |
| spec4 = electives-specs (22 файла) | каждая спека РФ-1…16/В-1…3/О-1…4/ЖИ-1…22/Ж7+ + вклады в КП (вопросы «Проверь себя», КП-ОВ 5 вопросов, КП-3 3 вопроса) |
| fable9 (smru/loc-lessons) | каждый урок + викторины (38 Р / 16 Ж) + «Дневник Алексея» (33) + карты переноса + «Ткни в непонятное» (255 строк) |
| fable_landing.md | 19 секций + 6 демо-виджетов + реестр чисел + промпты изображений + SEO/юр-блоки |
| fable_online.md (ТЗ-4 аудит живого слоя) | 12+18 детекторов, 8 упражнений, Г.1–Г.10, Д.1–Д.3 |
| Прочее (fable4/5/6 спеки, APPENDIX_*, бонусы, частные спеки: «Песочница Freqtrade», «Напиши строку сам», «Асфальтоукладчик», steamroller-b11 и т.д.) | каждая спека/датасет (glossary.ft.json, scenario.json, кейсы E6 34 шт. …) |

**Формат строки** (машиночитаемая таблица или JSON+md-таблица — реши сам, но единообразно):

`id` · `источник` (файл волны + анкор контент-пака, напр. `pack16#r5`) · `тип` (урок/вопрос/
спека/карточка/движок/термин…) · `объём` · `куда идёт в v16` (папка/пак/слой + ответственный
агент) · `статус использования`: ☐ не начато / 🔧 в работе (агент) / ✅ использовано (где
именно: файл v16/манифест-строка) / ⛔ не используется (причина: дубль-редакция, устарело,
решение реестра №N, вне v1) — **ПУСТЫХ ПРИЧИН НЕ ОСТАВЛЯТЬ к концу проекта** · `примечание`.

**Метод:** сначала скелет скриптом `scripts/gen_usage_registry.py` (обходит content/,
контент-пак, карту, реестры и генерирует единицы по маркерам: заголовки уроков, `W-XX`,
`FT-xx`, `РФ-xx`, `ЖИ-xx`, `KR-xx`, `R1–R15`, `###` глоссариев…), затем ручная сверка
покрытия по оглавлению пака (17 разделов) и шапке плана. **Контроль полноты: счёт единиц по
категориям против известных чисел** (225+39 уроков, 603 позиции, 48 виджетов, 88 спек,
8 двигателей, 15+7 ритуалов, 29 KR, 19 секций лендинга, 34 кейса, 245+ токенов) — счёт
должен сойтись; расхождения объяснить в примечании.
**Ведение:** реестр живой — статусы обновляются по коммитам агентов 15/16/17/18 (периодическая
сверка `git log` + скан content/); финальная проверка «всё использовано» — перед релизом v16,
вместе со сборщиком (DoD §7 его промта).

## 3. Задача B — `V16-STYLE-CONTRACT.md`: единый стиль, тон и терминология

Эксперт писал в ~10 сессиях без полного контекста — материалы расходятся в тоне, обращении,
терминологии, плотности. Напиши контракт (8–12 разделов, с примерами «плохо/хорошо» из
реальных текстов):

1. **Тон и обращение:** базовый регистр (на «ты» или «вы» — определи по доминирующему стилю
   поздних волн: тексты smru/loc, fable8; зафиксируй с примерами); честная интонация без
   хайпа; ирония Криптика — только в его репликах (регистр «Инструктор»), «Дежурный» — без
   иронии (KR-27).
2. **Структура урока:** стандартные блоки, объём абзацев (3–5 предложений), «Проверь себя»
   с «почему так кажется», «Глубже», плашки ⚑/⏱.
3. **Терминология:** RU-приоритет, EN-дубль при первом употреблении; единый словарь
   соответствий (сверка с Lexicon и terms.json); запрещённые синонимические вилки
   (выпиши реальные расхождения между волнами и дай канон: например «плечо/кредитное плечо/
   leverage» — как в уроках, где термин учится).
4. **Числа и факты:** только с источником; канон чисел course-canon; формат записи
   (разделитель разрядов, валюта, проценты); юр-рискованные — ⚑.
5. **Персонажи:** реестр действующих лиц (Криптик; Алексей и «Дневник Алексея» — только
   Р-трек; Марина/Соня/Тимур/Игорь — только Ж-трек; «семья Алексея» не пересекается с
   Ж-треком) — роли, границы использования, запрет новых биографических фактов.
6. **Стоп-лист:** стоп-слова лендинга ( обещания доходности и пр. — из landing-spec) +

7. **Формат карточек:** SRS-карточка, атом KR-04, спека (паспорт→…→глоссарий), мини-спека —
   единые шаблоны со ссылками на образцовые файлы.
8. **Правило адаптации:** где допустимо менять текст эксперта (перевод в канон-стиль) и где
   недопустимо (числа, факты, определения); все адаптации — с пометкой в реестре использования
   (`adapted: причина`).

Контракт обязателен к чтению агентами 15/17 (контент) и учитывается кодовиком 16 (тексты в
интерфейсах). Обновление контракта — версионируется (v1, v2…) с перечнем изменений.

## 5. Задача D — протокол ревью партий (сквозная работа)

1. **Очередь ревью:** следи за worklog/коммитами агентов 15/16/17. Каждая партия (транш)
   получает твой вердикт в `V16-REVIEW-LOG.md` (создать; одна секция на партию):
   `партия · агент · дата · проверено (что именно) · найдено (противоречия/дубли/стиль) ·
   вердикт: PASS / RETURN (со списком правок) / BLOCK (с эскалацией в worklog)`.
2. **Что проверяешь:**
   - **Противоречия:** числа (между уроками/спеками/банками — против канона), факты
     (юр-даты, механики), термины (вилки синонимов), логика гейтинга/последовательностей
     (предпосылки уроков выполняются).
   - **Дубликаты сущностей:** новый код против каталога §4 и 48 виджетов (механика уже есть?);
     термины (SRS-дубли); банки (вопрос уже есть в 603); изображения (лендинг-медиа).
   - **Стиль/тон:** выборочная выборка против контракта §3.
   - **Полнота реестра:** строки единиц переведены 🔧 → ✅ только при фактическом попадании
     в сборку (сверка с манифестом/дистро сборщика 18).
   - **Использование expert-контента:** партия агента не «сочинила своё» там, где был
     материал эксперта (реестр §2 показывает, что должно было быть взято).
3. **Приоритет твоих решений:** `V16-DECISIONS-REGISTRY.md` §0 — семь принципов (рекомендация
   эксперта = дефолт; детерминированность v1; категории не имена; честность; params не код;
   фазовость). Спорное, не покрытое реестром, — решай по принципам и фиксируй в
   V16-REVIEW-LOG.md; системное (повторится ещё дважды) — выноси в контракт стиля/каталог.
4. **Возвраты:** RETURN с конкретным списком правок (файл/строка/что заменить). После
   правок — повторное ревью. Два RETURN подряд по одной причине = BLOCK + запись в worklog.
