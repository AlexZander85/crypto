## Порядок запуска

```
ЭТАП 0 (параллельно, сразу):
  [05-архитектор]  ── реестр использования + контракт стиля + каталог сущностей
  [01-методолог]   ── Б.1–Б.4 (компиляция из поставленного; не зависит от 05)
  [04-сборщик]     ── Фаза 0 + Фаза 1 НЕ зависят от контентных агентов — старт немедленно

ЭТАП 1 (параллельно, после появления контракта стиля от 05):
  [02-код интерактивов] ── МНОГОСЕССИЙНЫЙ конвейер траншами (порядок в промте §4)
  [03-системные слои]   ── тоже траншами (В.1 = 12 траншей атомов)

ЭТАП 2 (по мере накопления входов):
  [04-сборщик] ── интеграция партий: волны W-A…W-E, треки (РФ-транш 1 → Ж → РФ-транш 2),
                  далее Фаза 2 Vite (ADR-001 §13.5)

КОНТРОЛЬ (сквозной):
  [05-архитектор] ── ревью каждой партии ДО передачи сборщику; ведёт чек-лист использования
```

**Что блокирует что** (детально — `V16-FINAL-CONTENT-GAPS.md` §Д): Фаза 0/1 и Б.5 стартуют
немедленно; Б.1–Б.4 закрывают зазор для чекпоинт-экранов треков; В.1–В.5 не блокируют треки;
«0 ПУСТО» в DoD v16 блокирует В.2 (мини-спеки ~21 урока).

## Как использовать промт

1. Открыть новую сессию с доступом к `/home/z/my-project/`.
2. Первым сообщением: «Прочитай `/home/z/my-project/repo/prompts/<файл>` и выполни его. Task ID: N.»
   (либо скопировать содержимое файла целиком — промт самодостаточен).
3. Агент обязан: прочитать `00-OBSCHEE-KONTEKST.md` → хвост `worklog.md` → свои исходники →
   работать траншами, коммитить и пушить после каждого транша, писать в worklog.
4. Продолжение прерванной работы: тот же промт + «продолжай с транша K по реестру/статусам».

## Опасность изоляции агентов (главный риск этой схемы)

Каждый агент видит только свой промт. Против «изолированного кода и дублирующихся сущностей»
работают три механизма — **не ослаблять их**:

1. **`content/02-interactives/widgets/_registry.json`** — единый машинный индекс виджетов/
   двигателей/инстансов (ведёт агент 16; читают 02, 03, 04, 05).
2. **Контракт стиля и каталог сущностей** от агента 05 (`V16-STYLE-CONTRACT.md`,
   `V16-ENTITY-CATALOG.md`) — обязательное чтение генераторов контента.
3. **Реестр использования** (`V16-CONTENT-USAGE-REGISTRY.md`, агент 05) — сборщик (04) не
   включает в v16 материал без строки реестра; по нему же проверяется «весь контент эксперта
   использован» по чек-листу.
