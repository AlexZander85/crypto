    61→## 1. Главный принцип: НАД, а не ВМЕСТО (см. также §0.1 — контент заморожен)
    62→
    63→**Запрещено трогать:** существующие рендеры (`renderLessonDetail`, `renderPhaseTestView`, `renderMathTestsBox` и др.), механики прогресса/геймификации, адаптивные банки, наставника, RAG, существующий fullscreen-ридер, геймификацию, данные уроков, существующие LS-ключи. Не переименовывать ни одну существующую функцию/переменную. Не «улучшать» попутно существующие рендеры.
    64→
    65→Плеер — **новый автономный модуль** (отдельный `<script>`-блок в конце, IIFE, `'use strict'`, наружу только `window.LearnPlayer`), который **только читает** данные урока и **вызывает существующие функции** для записи результата. Точки входа добавляются обёртками рендер-функций из нового блока (§2) — существующие тела функций не редактируются.
    66→
    67→Следствие: если новый скрипт-блок удалить — приложение работает как v12.1. Это критерий архитектуры (проверяется удалением блока).

    69→## 2. Точки входа
    70→
    71→1. **Кнопка «🎓 Учиться» на карточке каждого урока** (все 213, фазы 0–9) — в обоих режимах каталога: «карточки» и «таблица» (рендерит `renderPhaseLessonsView`). Кнопка — настоящий `<button>`, клик — `event.stopPropagation()` (чтобы не сработал родительский `onclick="openFullscreenLesson(...)"` карточки/строки.
    72→2. **Кнопка «🎓 Учиться» в уроке, открытом в ридере** — в шапке урока рядом с «🏆 Завершить урок» и в нижней навигации рядом с ней же. Открытие плеера изнутри ридера: ридер **закрывается** (`closeFullscreenLessonReader()`), открывается плеер; при закрытии плеера — возврат: если вход был из ридера, снова `openFullscreenLesson(lessonId)`, иначе — текущая вкладка каталога.
    73→3. **Баннер продолжения** на главной вкладке (id вида `#home`, рендер после `renderDailyQuests`): если есть незавершённый урок в плеере — «▶ Продолжить: FT-07 · шаг 5/14»; также панель «🔖 Закладки» рядом с баннером (§4.1).
    74→4. **Deep-link**: `#learn/<lessonId>` — открывает плеер сразу (для ссылок/наставника). Router: свой `hashchange`-listener в блоке плеера (в приложении другого hash-роутинга нет); формат `#learn/<id>` и `#learn/<id>/<stepIdx>`.
    75→5. После завершения урока на финальном экране: «▸ Следующий урок» — открывает следующий урок той же фазы сразу в плеере.
    76→
    77→**Механизм вставки кнопок — только обёртками** (паттерн приложения):
    78→```js
    79→const _origRPLV = window.renderPhaseLessonsView;
    80→window.renderPhaseLessonsView = function(ph){
    81→  const r = _origRPLV.apply(this, arguments);
    82→  LearnPlayer.injectCatalogButtons();   // только добавляет DOM после отрисовки
    83→  return r;
    84→};
    85→```
    86→Аналогично для `renderLessonDetail` (кнопки в шапке/низе урока) и `renderDailyQuests` (баннер). Запрещено редактировать тела этих функций в исходнике.

    88→## 3. Модель шагов (ядро ТЗ)
    89→
    90→Новая чистая функция `buildLessonSteps(lesson)` превращает урок в массив шагов. **1 логический блок = 1 шаг.** Ничего не выбрасывать: плеер обязан показать **все** блоки урока и все значимые поля урока (§A2). Сверка «ни один элемент не потерян» — приёмочный критерий №1.
    91→
    92→**Правило ленивости (v2):** шаги строятся **при каждом открытии урока** из живого массива `LESSONS` (в рантайме он мутирован инжекциями: анимации v11, мост p4_l8, `ACADEMY_UPGRADE`, лабы, виджет-инъекции). Снапшоты уроков на загрузке страницы — запрещены.

   150→## 5. Поведение и состояние
   151→
   152→### 5.1. Позиция и resume
   153→1. Позиция прохождения сохраняется при каждом переходе: LS `cn_learn_pos` = `{lessonId, stepIdx, ts}`. Повторное открытие того же урока — диалог «Продолжить с шага N / Начать сначала». Открытие другого урока — с обложки, без диалога.
   154→2. Восстановление состояния гейта: если `lessonCheckState[l.id].quizDone === true` (существующий LS `cn_lesson_checks`) или урок уже пройден (`lessonsDone[l.id]===1`) — аттестационный шаг сразу помечается «квиз сдан», «Завершить урок» доступна (та же логика, что ридер через `isQuizPassed`). `lessonQuizPassed` — рантайм-переменная без персистентности; плеер НЕ пишет её напрямую.
   155→
   156→### 5.2. Гейтинг
   157→Двигаться дальше по контентным шагам можно свободно; шаг «Аттестация» требует верного ответа для активации «Завершить урок»; повторные попытки — без штрафа (каков фактический уровень строгости ридера: неверный ответ не блокирует повторный выбор). Retry-эргономика — §12.6.
   158→
   159→### 5.3. Запись результата — только через существующие функции (легаси-ID-шов)
   160→
   161→**5.3а. Квиз урока.** Плеер рендерит квиз-шаг с **теми же DOM-id, что ждёт `handleLessonQuizAnswer`**: контейнер `lquiz_opts_<lessonId>`, фидбек `lquiz_fb_<lessonId>`, бейдж `quiz_badge_<lessonId>`, кнопки `lesson_complete_btn_<lessonId>` и `lesson_bottom_complete_btn_<lessonId>`; onclick вызывает `handleLessonQuizAnswer(lessonId, i, correctIdx)`. Тогда запись состояния (`lessonCheckState[...].quizDone`, `save()`, тост, разблокировка кнопок) происходит существующим кодом без правок.
   162→
   163→**Проблема дублей id:** те же id уже есть в DOM урока, открытого в ридере/вкладке под плеером; `document.getElementById` вернёт первый — скрытый — элемент, и UI плеера не отреагирует. Решение — **шов нейтрализации подложки**: при открытии плеера очистить контент контейнера урока (`#lessonContentBox` → пустой плейсхолдер) и `#phaseTestBox` (для Этапа 2); при закрытии плеера восстановить: если под ним был открыт урок — `renderLessonDetail(l)`; вкладка фазы — `renderPhaseLessonsView(currentViewingPhase)`; тесты — `renderPhaseTestView(curPhaseTest)`. Восстановление — вызовами существующих рендеров, состояние не теряется (все данные в LS/переменных).
   164→
   165→**5.3б. Завершение урока.** Кнопка «Завершить урок» плеера вызывает `completeLessonWithMastery(l.id)` **ровно один раз за прохождение** (флаг в состоянии сессии плеера). Причина: функция — **переключатель** (`lessonsDone[id] = lessonsDone[id] ? 0 : 1`, §A5) — повторный вызов снимет пройденность. Если урок уже пройден до открытия плеера — не вызывать функцию вовсе: финальный экран показывает «✓ Урок уже был пройден». После вызова проверить `lessonsDone[l.id] === 1`; если вдруг 0 (сработал alert-путь защиты, например гипотетический `mastery_check`) — показать инлайн-ошибку в плеере и состояние не менять.
   166→Перед вызовом — гарантировать гейт: вызывать только если `lessonQuizPassed[l.id]===true || lessonCheckState[l.id].quizDone===true` (то же условие, что в функции), чтобы нативный `alert()` не срабатывал вообще.
   167→
   168→**5.3в. Счётчики.** `completeLessonWithMastery` сам вызывает `renderPhaseLessonsView(curPhaseLesson)` и `save()→updateHeader()`. Плеер при закрытии/завершении дополнительно вызывает `renderProgressStats()` (перерисовка вкладки «Прогресс») — на случай, если она открыта.

   276→- Точка входа `LearnPlayer.openTest(testId)` — то же окно (§4), тот же z-стек, та же типографика (вопрос 20px, опции 17px, A−/A+). testId: `p0…p5`, `p8`, `capstone` (слот 6), `math_core|math_stats|math_final_map`, `literacy`, `psy_cum`.
