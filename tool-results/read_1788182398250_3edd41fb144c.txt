    70→    70→
    71→    71→1. **Кнопка «🎓 Учиться» на карточке каждого урока** (все 213, фазы 0–9) — в обоих режимах каталога: «карточки» и «таблица» (рендерит `renderPhaseLessonsView`).    151→   151→
   152→   152→### 5.1. Позиция и resume
   153→   153→1. Позиция прохождения сохраняется при каждом переходе: LS `cn_learn_pos` = `{lessonId, stepIdx, ts}`. Повторное открытие того же урока — диалог «Продолжить с шага N / Начать сначала». Открытие другого урока — с обложки, без диалога.
   154→   154→2. Восстановление состояния гейта: если `lessonCheckState[l.id].quizDone === true` (существующий LS `cn_lesson_checks`) или урок уже пройден (`lessonsDone[l.id]===1`) — аттестационный шаг сразу помечается «квиз сдан», «Завершить урок» доступна (та же логика, что ридер через `isQuizPassed`). `lessonQuizPassed` — рантайм-переменная без персистентности; плеер НЕ пишет её напрямую.
   155→   155→
   156→   156→### 5.2. Гейтинг
   157→   157→Двигаться дальше по контентным шагам можно свободно; шаг «Аттестация» требует верного ответа для активации «Завершить урок»; повторные попытки — без штрафа (каков фактический уровень строгости ридера: неверный ответ не блокирует повторный выбор). Retry-эргономика — §12.6.
   158→   158→
   159→   159→### 5.3. Запись результата — только через существующие функции (легаси-ID-шов)
   160→   160→
   161→   161→**5.3а. Квиз урока.** Плеер рендерит квиз-шаг с **теми же DOM-id, что ждёт `handleLessonQuizAnswer`**: контейнер `lquiz_opts_<lessonId>`, фидбек `lquiz_fb_<lessonId>`, бейдж `quiz_badge_<lessonId>`, кнопки `lesson_complete_btn_<lessonId>` и `lesson_bottom_complete_btn_<lessonId>`; onclick вызывает `handleLessonQuizAnswer(lessonId, i, correctIdx)`. Тогда запись состояния (`lessonCheckState[...].quizDone`, `save()`, тост, разблокировка кнопок) происходит существующим кодом без правок.
   162→   162→
   163→   163→**Проблема дублей id:** те же id уже есть в DOM урока, открытого в ридере/вкладке под плеером; `document.getElementById` вернёт первый — скрытый — элемент, и UI плеера не отреагирует. Решение — **шов нейтрализации подложки**: при открытии плеера очистить контент контейнера урока (`#lessonContentBox` → пустой плейсхолдер) и `#phaseTestBox` (для Этапа 2); при закрытии плеера восстановить: если под ним был открыт урок — `renderLessonDetail(l)`; вкладка фазы — `renderPhaseLessonsView(currentViewingPhase)`; тесты — `renderPhaseTestView(curPhaseTest)`. Восстановление — вызовами существующих рендеров, состояние не теряется (все данные в LS/переменных).
   164→   164→
   165→   165→**5.3б. Завершение урока.** Кнопка «Завершить урок» плеера вызывает `completeLessonWithMastery(l.id)` **ровно один раз за прохождение** (флаг в состоянии сессии плеера). Причина: функция — **переключатель** (`lessonsDone[id] = lessonsDone[id] ? 0 : 1`, §A5) — повторный вызов снимет пройденность. Если урок уже пройден до открытия плеера — не вызывать функцию вовсе: финальный экран показывает «✓ Урок уже был пройден». После вызова проверить `lessonsDone[l.id] === 1`; если вдруг 0 (сработал alert-путь защиты, например гипотетический `mastery_check`) — показать инлайн-ошибку в плеере и состояние не менять.
   166→   166→Перед вызовом — гарантировать гейт: вызывать только если `lessonQuizPassed[l.id]===true || lessonCheckState[l.id].quizDone===true` (то же условие, что в функции), чтобы нативный `alert()` не срабатывал вообще.
   167→   167→
   168→   168→**5.3в. Счётчики.** `completeLessonWithMastery` сам вызывает `renderPhaseLessonsView(curPhaseLesson)` и `save()→updateHeader()`. Плеер при закрытии/завершении дополнительно вызывает `renderProgressStats()` (перерисовка вкладки «Прогресс») — на случай, если она открыта.
