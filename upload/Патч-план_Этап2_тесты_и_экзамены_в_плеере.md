### 1.2. Семантика ответов (зеркалим, не «улучшаем»)

- **Фазовые (`p*`, `capstone`)**: ответ окончателен — `checkPhaseTestAnswer` (18248) блокирует ВСЕ кнопки вопроса, ставит `.ok` на верном, `.bad` на выбранном неверном; пояснение `q.explain[optIdx]` показывается сразу. Числовые (`q.type==='numeric'`): `window.checkPhaseTestNumeric` (18275) — допуск `q.absTol` или `±q.tolPct%`, после проверки input блокируется, в контейнер добавляется **скрытый маркер** `span.ans.ok/.bad` (его читает подсчёт).
- **Мат-тесты**: ответ сменяем до «Проверить тест» — `answerMathTest` (27718) просто перезаписывает `mathTestState[ti].answers[qi]=oi`; пояснение `sh.explain` показывается сразу после первого ответа (как в `renderMathTestsBox` 27688).
- **Подсчёт** — только по явной сдаче: `calcPhaseTestResult(ph)` (18305) считает DOM-маркеры `.ans.ok` без `.ans.bad` по контейнерам `ptest_<ph>_<qi>`; `finishMathTest(ti)` (27723) пересчитывает в шафл-пространстве по `mathTestState`.
- Порог считается от фактического числа вопросов: `Math.ceil(len * (ph===6 ? 0.85 : 0.80))`.

### 1.3. Шафл

- Фазовые: соль попытки `_ptSalt = nextShuffleSalt()` (36309, инкремент существующего LS-ключа `cn_shuffle_salt`), перемешанная копия банка кладётся в **`window._ptView[ph]`** (18169–18174): `Object.assign({}, q, {opts: sv.opts, a: sv.a, explain: sv.explain})`, где `sv = shuffledOptions(q, _ptSalt*1000+qi)`. `shuffledOptions` (36315) **детерминирован** (mulberry32+fnv1a от текста вопроса и соли) — одинаковая соль даёт одинаковую раскладку, `explain` переставляется синхронно.
- Спидран: `window._ptStart[ph]` (18166–18167) — метка начала попытки, потребляется и обнуляется в `calcPhaseTestResult`.
- Мат: соль жёсткая — `qi*17+3+ti*9` (27695, 27729), согласована между рендером и подсчётом. Резать нельзя.

### 1.4. Уточнения к ТЗ §11, найденные сверкой с кодом (A16–A20)

- **A16. У `literacy` и `psy_cum` нет интерактивной поверхности.** ТЗ §11.0/§11.3 называют точкой запуска «выпускной блок» — в v12.1 такой поверхности нет: `CRYPTO_LITERACY_EXAM` встречается только в диагностике загрузки (25005/25030), ключ `phaseTestsDone['test_literacy_zero']` — только читается (17578, 17583, 24977, 27066, 27114, 27853) и **никогда не пишется**; `PSY_CUMULATIVE_QUESTIONS` используется только в сборке p8 (дважды). Решение плана: оба банка открываются в плеере в **диагностическом режиме** (подсчёт локальный, в стейт ничего не пишется, в UI — честная плашка «диагностика, на прогресс не влияет»); вход — пикер банков в плеере (P6.5). Писать `phaseTestsDone['test_literacy_zero']` из плеера **запрещено** — этот ключ читают гейты/тиры (27066, 27114, 27853), запись изменила бы семантику допуска.
- **A17. Черновик попытки обязан хранить соль.** ТЗ §11.2 описывал `cn_learn_test = {testId, answers}` — этого мало: ответы фазовых хранятся в **шафл-пространстве**, а соль `nextShuffleSalt()` случайна на попытку. Без сохранённой соли восстановление неверно. Схема: `{testId, ph, salt, pos, answers:{qi:oi}, numeric:{qi:value}, updatedTs}` (для `math_*` — только `{testId, ti, pos}`, ответы уже живут в `mathTestState`). Это данные плеера, не контент — допустимо, отметить в отчёте.
- **A18. Точек перехвата `alert()` — четыре, не две.** В `calcPhaseTestResult` два (успех 18366, провал 18371), в `finishMathTest` два (нет ответов 27725, результат 27731). Все четыре оборачиваются одним паттерном §5 «Перехват alert».
- **A19. `answerMathTest` перерисовывает подложку.** Он вызывает `renderPhaseLessonsView(7)` (27721) — под открытым плеером это скрытый безвредный рендер (обёртки Этапа 1 идемпотентны). Не «чинить», просто знать.
- **A20. После сдачи фазового открывается экран консолидации** (`showConsolidationScreen`, 32451, оверлей `#consolidation_overlay` z 999999, вызов через 600 мс после успеха, 18368) — сегодня на вкладке «Тесты» он виден сразу; под плеером (z 1000001) он окажется невидимым. Решение: CSS-фикс в P1.4 (поднять до 1001500). Побочный эффект — консолидация после завершения урока тоже станет видимой над плеером (сегодня под ридером она невидима — существующая особенность); это педагогически правильно (пауза показывается в момент завершения), оверлей закрывается своей кнопкой «Пропустить». Зафиксировать в отчёте.

## 3. Архитектура: тестовый режим плеера

Модуль Этапа 2 добавляется внутрь того же IIFE `learn_player_js`:

```
LearnPlayer (продолжение)
├── Tests        — openTest(testId), resolveBank(testId), buildTestSteps(bank),
│                  порции по 5, шаг-врата «Сдать тест», режим разбора, пересдача
├── TestRender   — learnRenderTestStep(idx): вопросы/опции/числовой ввод/пояснения;
│                  лок-состояние при resume — прямо в разметке (маркеры .ans.ok/.bad)
├── TestDraft    — LS cn_learn_test (A17): запись при каждом ответе; удаление после сдачи
├── TestSubmit   — staging-DOM со ВСЕМИ вопросами + вызов calcPhaseTestResult/finishMathTest;
│                  onTestResult(text) — приёмник перехваченных alert
├── FC           — карточки §11.7: генерация колоды, режим «Знал/Не знал», LS cn_learn_fc
├── Entry2       — обёртка renderPhaseTestView; расширение обёртки renderPhaseLessonsView(7);
│                  CTA финального экрана; баннер продолжения на главной; пикер банков 🏁
└── Smoke2       — V10.smoke.add('lp2:…') + LearnPlayer.selfTest()
```

Публичный API добавляется к `LearnPlayer`: `openTest(testId)`, `onTestResult(text)`, `openFlashcards(lessonId?)`, `selfTest()`. Больше наружу ничего.

**Инварианты тестового режима:**
- то же окно/та же типографика/тот же z-стек, что в Этапе 1 (ТЗ §11.1); тема/шрифт/фокус-трап/Esc — из каркаса Этапа 1;
- `window.LEARN_PLAYER_ACTIVE` выставляется так же; перехват alert проверяет именно его;
- позиция попытки в `cn_learn_test`, а факты «сдан/лучший» — только в `phaseTestsDone`/`mathTestState`;
- ответы на живые вопросы — только через onclick существующих функций; подсчёт — только по кнопке сдачи;
- ни один порог, ни один банк, ни одна формула подсчёта не дублируются в коде плеера (для отображения прогресса «отвечено X из N» плеер считает только СВОЙ черновик, это не результат).

**Разрешение testId → банк (таблица соответствия):**

```
p0..p5   → PHASE_TESTS.find(t=>t.phase===N)          (ph=N)
p8       → PHASE_TESTS.find(t=>t.phase===8)          (202, рантайм-сборка)
capstone → CAPSTONE_EXAM                             (ph=6 при вызовах, testKey 'exam_capstone')
math_*   → MATH_TESTS.find(t=>t.id===testId)         (ti = индекс в массиве)
literacy → CRYPTO_LITERACY_EXAM                      (диагностика, A16)
psy_cum  → PSY_CUMULATIVE_QUESTIONS                  (диагностика, A16)
```

**Порции:** шаги = `Math.ceil(n/5)` порций по 5 вопросов (p8 → 41 шаг; p0 → 5; capstone → 8; прочие → 2–8) + 1 финальный шаг-врата «Сдать тест». В шапке: «Шаг 3 из 41 · отвечено 12 из 202»; прогресс-бар = доля отвеченных. Карта шагов слева: индикатор «порция отвечена / частично / не отвечена» (ТЗ §11.5).

### P2. Порции и черновик

1. `buildTestSteps(bank)`: массив `{kind:'portion', qs:[qi…], answered:0..5}` + `{kind:'gate'}` в конце. Вопросы не копировать — только индексы `qi`.
2. Новая попытка фазового: `salt = nextShuffleSalt()`; `window._ptView[ph] = test.questions.map((q,qi)=>{const sv=shuffledOptions(q, salt*1000+qi); return Object.assign({}, q, {opts:sv.opts, a:sv.a, explain:sv.explain});})` — **дословно контракт 18171–18174**; `window._ptStart[ph] = Date.now()` (если 0/undefined). Черновик: `{testId, ph, salt, pos:0, answers:{}, numeric:{}, updatedTs}`.
3. Мат-попытка: вид строится как в `renderMathTestsBox` — на каждом рендере вопроса `shuffledOptions(q, qi*17+3+ti*9)` (соль детерминирована, в черновике не нужна); черновик `{testId, ti, pos}`.
4. Черновик пишется при каждом ответе и каждом переходе порции; после сдачи — удаляется из LS, но держится в памяти до конца сессии разбора; «Пересдать» — новый черновик.
5. **Самопроверка:** для каждого банка порции покрывают все вопросы без потерь/дублей (`buildTestSteps` + свёртка `qs` = 0..n-1); `_ptView` воспроизводим: пересобрать с той же солью дважды → deep-equal.

## 9. Риски и краевые случаи (фиксировать в отчёте, не «чинить» молча)

| Риск | Митигация |
|---|---|
| Ответы в шафл-пространстве теряют смысл при другой соли | соль в черновике (A17); resume пересобирает `_ptView` из неё |

| Незавершённая попытка старого UI уничтожается открытием плеера | parity: смена чипа вкладки делает то же сегодня; предупредить не просить, отметить в отчёте |

| Спидран-ghost считает от resume после перезагрузки | известная грань (старый UI попыток не персистит); в отчёт |
| Консолидация (z 999999) под плеером | CSS-фикс 1001500 (A20); поведение при завершении урока меняется на «видимое» — зафиксировать |
