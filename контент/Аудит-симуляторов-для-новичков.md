## 3.2. Калькулятор кредитного плеча и цены ликвидации

### Что хорошо

Это один из самых важных модулей для защиты депозита.

### Что проверить по логике

Для упрощённой изолированной маржи:

#### Long

```text
P_liq = Entry * (1 - 1/Leverage) / (1 - MMR)
```

#### Short

```text
P_liq = Entry * (1 + 1/Leverage) / (1 + MMR)
```

Где:

- `Entry` — цена входа;
- `Leverage` — плечо;
- `MMR` — maintenance margin rate, например 0.005 = 0.5%.

Пример для Long:

```text
Entry = 10,000$
Leverage = 10x
MMR = 0.5% = 0.005

P_liq = 10,000 * (1 - 0.1) / (1 - 0.005)
P_liq ≈ 9,045$
```

Пример для Short:

```text
Entry = 10,000$
Leverage = 10x
MMR = 0.5%

P_liq = 10,000 * (1 + 0.1) / (1 + 0.005)
P_liq ≈ 10,945$
```

### Что нужно обязательно показывать

1. Цену ликвидации.
2. Расстояние до ликвидации в %.
3. Сколько нужно движения цены против позиции.
4. Предупреждение при высоком плече.
5. Разницу между:
   - isolated margin;
   - cross margin;
   - mark price;
   - last price;
   - commission/funding impact.

### Что непонятно новичку

- что такое залог;
- что такое плечо;
- что такое поддерживающая маржа;
- почему ликвидация происходит до полного нуля;
- почему комиссия и фандинг приближают ликвидацию;
- что на разных биржах формулы отличаются.

### Что добавить

Сделать предупреждение:

```text
⚠️ Это упрощённый расчёт для изолированной маржи.
На реальной бирже ликвидация зависит от mark price, комиссий, фандинга, режима маржи и правил биржи.
```

Добавить тест:


## 3.10. Калькулятор и симулятор дробного Келли

### Что хорошо

Правильная тема: показывает, почему full Kelly опасен.

### Что проверить

Формула Келли:

```text
f* = p - q / b
```

Где:

- `p` — вероятность прибыли;
- `q = 1 - p`;
- `b` — отношение средней прибыли к среднему убытку.

Пример:

```text
Win Rate = 50%
Payoff = 2

f* = 0.5 - 0.5 / 2 = 0.25
```

То есть полный Келли предлагает рисковать 25% капитала.  
Это очень много для реального трейдинга.

Если `f* <= 0`, система не имеет преимущества:

```text
Ставку делать не следует.
```

### Что должно быть в симуляторе

1. Если математическое ожидание отрицательное:
   ```text
   Келли = 0. Не торгуй.
   ```
2. Должны быть режимы:
   - Full Kelly;
   - Half Kelly;
   - Quarter Kelly;
   - Fixed risk 1%.
3. Монте-Карло должен показывать:
   - медианный результат;
   - худший сценарий;
   - вероятность просадки 50%;
   - вероятность банкротства;
   - максимальную просадку.
4. Нужно объяснить, что Келли предполагает точное знание вероятностей, чего в реальности нет.

### Что непонятно новичку

- почему математически оптимально не значит безопасно;
- почему оценка вероятности ошибочна;
- почему серия убытков нормальна;
- почему 100 сделок — малая выборка.

### Что добавить

Вывод:

```text
Для реального капитала обычно используют 0.25–0.5 Келли или фиксированный риск 1%.
```

### Приоритет

🟠 Высокий.

## 3.16. Анализатор стационарности рядов

Правильная идея: нельзя использовать только ADF.

```text
Ряд имеет единичный корень, то есть нестационарен.
```

Если `p-value < 0.05`:

```text
Отвергаем единичный корень → ряд может быть стационарным.
```

#### KPSS

Нулевая гипотеза:

```text
Ряд стационарен.
```

```text
Отвергаем стационарность → ряд может быть нестационарным.
```

   - стационарный спред;

2. Для каждого:
   - ADF;
   - KPSS;
   - rolling mean;
   - rolling std;
   - вывод.
3. Если ADF и KPSS расходятся:
   ```text
   Ряд сомнительный. Возможны структурный сдвиг, тренд или режимность.
   ```

## 3.17. Альфа/Бета-декомпозитор и Information Ratio

### Что хорошо

Показывает, что доходность может быть просто ростом рынка.

### Что проверить

Формула ожидаемой доходности по CAPM:

```text
Expected = RiskFree + Beta * (Benchmark - RiskFree)
```

Формула Jensen Alpha:

```text
Alpha = Strategy - Expected
```

Пример:

```text
Стратегия = 40%
Бенчмарк = 30%
Beta = 1.2
Risk-Free = 5%

Expected = 5% + 1.2 * (30% - 5%) = 35%
Alpha = 40% - 35% = +5%
```

### Проблема

Для Information Ratio нужен tracking error:

```text
IR = (Strategy - Benchmark) / Tracking Error
```

Если в интерфейсе нет входа для tracking error или стандартного отклонения активной доходности, то IR считать нельзя.

### Что непонятно новичку

- что такое бета;
- что такое альфа;
- почему “обогнал бенчмарк” не всегда значит “создал альфу”;
- что такое tracking error.

### Что добавить

Если нет данных для IR:

```text
Переименовать модуль в “Alpha/Beta-декомпозитор” без IR
```

Или добавить поле:

```text
Tracking Error / стандартное отклонение активной доходности
```

### Приоритет

🟠 Высокий.

# 6. Конкретные формулы, которые должны быть проверены

Ниже — обязательные математические проверки для симуляторов.

---

## 6.1. Ликвидация

### Лонг

```text
LiquidationPrice = Entry * (1 - 1/Leverage) / (1 - MMR)
```

### Шорт

```text
LiquidationPrice = Entry * (1 + 1/Leverage) / (1 + MMR)
```

Пример:

```text
Entry = 10,000
Leverage = 10
MMR = 0.005

Long:
10000 * 0.9 / 0.995 = 9045.23

Short:
10000 * 1.1 / 1.005 = 10945.27
```

Должно быть предупреждение:

```text
На реальной бирже формула может отличаться из-за маржи, комиссий, фандинга и mark price.
```

---

## 6.2. Фандинг

```text
FundingPayment = Notional * FundingRate
```

Пример:

```text
Нотионал = 10,000$
Ставка = 0.01% = 0.0001

Платёж за 8 часов = 1$
За 24 часа = 3$
За 30 дней = 90$
```

Знак:

```text
Положительный фандинг: лонг платит шорту
Отрицательный фандинг: шорт платит лонгу
```

---

## 6.3. Просадка и восстановление

```text
Recovery = 1 / (1 - Drawdown) - 1
```

Примеры:

```text
-10% → 11.11%
-20% → 25%
-30% → 42.86%
-50% → 100%
-90% → 900%
```

---

## 6.4. Келли

```text
Kelly = WinRate - (1 - WinRate) / Payoff
```

Пример:

```text
WinRate = 0.5
Payoff = 2

Kelly = 0.5 - 0.5/2 = 0.25
```

Если Kelly отрицательный:

```text
Торговать не следует.
```

Для практики:

```text
Quarter Kelly = Kelly / 4
```

---

## 6.5. Волатильность портфеля

Для трёх активов:

```text
σp = sqrt(
w1²σ1² +
w2²σ2² +
w3²σ3² +
2*w1*w2*σ1*σ2*ρ12 +
2*w1*w3*σ1*σ3*ρ13 +
2*w2*w3*σ2*σ3*ρ23
)
```

Нужно проверять:

```text
Сумма весов = 100%
Корреляции от -1 до 1
Матрица корреляций допустима
```

---

## 6.6. Альфа по Джансену

```text
ExpectedReturn = RiskFree + Beta * (BenchmarkReturn - RiskFree)
Alpha = StrategyReturn - ExpectedReturn
```

Пример:

```text
Стратегия = 40%
Бенчмарк = 30%
Beta = 1.2
Risk-Free = 5%

Expected = 5% + 1.2 * 25% = 35%
Alpha = 40% - 35% = 5%
```

---

## 6.7. Information Ratio

```text
IR = (StrategyReturn - BenchmarkReturn) / TrackingError
```

Если `TrackingError` не задан, модуль не должен показывать IR.

---

## 6.8. Стационарность

```text
ADF p < 0.05 → есть признак стационарности
KPSS p < 0.05 → есть признак нестационарности
```

Если расходятся:

```text
Ряд сомнительный, нужен дополнительный анализ.
```

---

## 6.9. OHLC-валидация свечи

```text
High >= Open
High >= Close
Low <= Open
Low <= Close
High >= Low
```

Если нарушено:

```text
Ошибка: свеча не может быть построена.
```

# 18. Краткое резюме

Сильные стороны:

- глубокая методология;
- много интерактива;
- есть тесты, симуляторы, прогресс, правовые модули;
- хорошая структура по фазам;
- много практических тем.

Главные проблемы:

- перегруженность первого экрана;
- нет понятного онбординга для полного нуля;
- часть терминов не расшифрована;
- нет обязательного калькулятора позиции по риску;
- нет модуля безопасности кошельков;
- некоторые формулировки слишком категоричны;
- продвинутые симуляторы смешаны с базовыми;
- нужно проверить счётчики уроков и математические формулы.

Если коротко:

> Проект концептуально сильный, но для новичка его нужно превратить из “большого каталога инструментов” в “управляемый маршрут с объяснениями, подсказками и обязательными проверками”.
